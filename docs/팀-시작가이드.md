## 2. 팀원이 시작하는 법 (한 번만)

### (1) 3레포를 **한 부모 폴더에 나란히** clone
```
Clov/                       ← 아무 폴더 (여기서 하네스 실행)
├── clov-api/               git clone
├── clov-web/               git clone
└── web-design-repository/  git clone
```
> 이렇게 두면 AI가 프론트·백·설계를 **한 번에** 볼 수 있어 계약 어긋남을 스스로 잡는다.

### (2) 내 AI 도구 준비
- Gemini 쓰는 사람 → 각 레포의 `GEMINI.md`를 자동으로 읽음
- Claude / Codex 쓰는 사람 → `CLAUDE.md` / `AGENTS.md`를 자동으로 읽음
- **셋 다 결국 같은 `AGENTS.md`를 봄** → 결과물이 일관됨

### (3) 실행 환경
- `clov-api`: Java 21 + Gradle → `./gradlew bootRun`
- `clov-web`: Node + npm → `npm install` → `npm run dev`

## 3. 매일 작업 사이클 (복붙 가능)

```bash
git checkout main
git pull                                  # 항상 최신부터 (충돌 예방 1순위)
git checkout -b feature/12-signup-api      # 이슈 하나 = 브랜치 하나
# ... 하네스로 작업 ...
# ★ AI가 만든 코드는 반드시 돌려보고 커밋 ★
git add .
git commit -m "회원가입 API 구현 (#12)"
git push -u origin feature/12-signup-api
# → GitHub에서 Pull Request 생성 → 리더 리뷰 → Merge
```

**규칙 5가지**
1. `main`에 직접 커밋 금지 — 무조건 브랜치 → PR
2. PR은 **작게** 자주 (AI는 코드를 빨리 뽑으니 크게 모으면 충돌·리뷰 폭발)
3. **계약(API·DB) 수정은 리더만** — 바꿀 게 있으면 이슈로 제안
4. 새 라이브러리 추가 전 물어보기
5. `.env`·시크릿 건드리지 않기

## 4. 역할 (기능 세로 슬라이스)

한 명이 **기능 하나를 프론트+백 끝까지** 맡는다 (프론트팀/백팀으로 안 가름).

| 사람 | 담당 기능(예시) |
|---|---|
| 리더 | 인증/회원가입 + 계약·DB 소유 + 전 PR 리뷰 |
| 팀원 1 | 우정공간 / 대시보드 |
| 팀원 2 | 추억피드 / 인생4컷 |
| 팀원 3 | 행운편지 / 일정계획 |

> ⚠️ 아직 각자 기능을 **동시에 시작하지 말 것.** 리더가 **로그인 1개를 끝까지(워킹 스켈레톤)** 만든 뒤, 그걸 본보기로 팬아웃한다.

## 5. 리더가 아직 할 일 (팀 결정 후)

| **계약 통일** | ⚠️ 아래 결정 필요 |
| 로그인 워킹 스켈레톤 | 계약 확정 후 |

### 🗳️ 팀이 정할 것 (다음 회의)
1. **입장 흐름**: 가입 신청→수락(5분 되돌리기) vs 코드 넣으면 즉시 입장 — 어느 쪽?
2. **인증**: 이메일+비번 **+** 소셜 vs 소셜만?

> 현재 실제 레포 계약(`docs/API-CONTRACT.md`)은 옛 버전(즉시입장·소셜만)이라, 위를 정하면 리더가 최신 계약으로 통일한다.
