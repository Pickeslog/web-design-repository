# Clov. 기능 및 접근성 상세 명세서

> **문서 목적**: 서비스 기획자와 UI/UX 엔지니어가 개발·디자인 시 즉시 참고할 수 있도록, Clov.의 서비스 구조 원칙과 접근성(Accessibility) 요구사항을 하나의 기준으로 정리한다.
> **서비스 개요**: Clov.는 친구 간의 추억을 기록하고 인증(약속 제안 → 인생4컷 필름 인증 → 추억 피드)하는 프라이빗 감성 SNS다. 방장이나 대표자가 없는 완벽한 수평적/동등한 멤버 구조를 아키텍처 특징으로 삼는다.
> **근거 자료**: 본 문서는 `Clov 화면 와이어프레임.pdf`(전 9개 화면군)와 `Clov_화면명세서.md`에 실제로 설계된 화면·모달·문구를 근거로 작성했다. 화면 참조 번호(예: `7a`, `6d`)는 와이어프레임 문서의 화면 ID를 그대로 따른다.

# 1. 서비스 철학 및 방 구조

## 1.1 수평적 구조의 원칙

Clov.의 우정공간은 위계 없는 동등한 관계를 전제로 설계된다. 방장·대표자·관리자 개념을 두지 않으며, 이는 UI상의 정책이 아니라 서비스 전반의 설계 원칙이다.

- **방장 없음**: 모든 멤버는 동등한 권한을 가진다. 방 미리보기 모달의 멤버 리스트(3d)에도 "가입 신청/퇴장 테스트 · 방장·관리자 구분 없음"이 명시적으로 노출된다.
- **전원 액션 허용**: 방 이름 변경, 테마 수정 등 방 설정에 관한 모든 액션은 특정 인물이 아닌 전원에게 허용된다.
- **실시간 알림 공유**: 방 프로필 편집 화면(2c 뷰2)에는 "바꾼 내용은 모든 멤버에게 알림으로 남아요(방장 없음)"라는 안내 문구가 저장 버튼 위에 항상 노출되어, 권한이 없어도 정보 비대칭이 발생하지 않도록 한다.

## 1.2 진입 장벽 — 신중한 초대 승인

방장이 없는 구조에서도 아무나 무분별하게 입장하지 않도록, 진입에는 다음 절차를 둔다.

- **최소 1명 승인 원칙**: 방 입장은 기존 멤버 중 최소 1명의 명확한 승인으로 확정된다. 가입 신청 카드(7a)에는 "방장 권한 없음: 참여 멤버 중 1명만 수락해도 즉시 입장"이라는 안내가 함께 노출되어, 특정 인물의 배타적 승인권이 아님을 매번 상기시킨다.
- **5분 되돌리기**: 실수로 승인한 경우를 대비해, 승인 직후 "되돌리기 4:47"처럼 5분(300초)에서 카운트다운되는 타이머를 제공한다(7b). 안내 문구는 "실수로 수락했다면 5분 안에 되돌릴 수 있어요. 방장이 없으니 강퇴 대신 되돌리기로만 취소해요"로, 강퇴 기능 부재(1.3)와 되돌리기가 한 쌍의 대안임을 화면에서도 직접 설명한다.
- **경합 처리**: 다른 멤버가 먼저 같은 신청을 처리하면 "이미 처리된 신청이에요 🙌" 토스트로 무효 처리를 알린다(7b). 승인권이 여러 명에게 동시에 열려 있는 구조이므로, 동시 처리 충돌은 오류가 아니라 정상 동작으로 취급된다.
- **거절의 비파괴성**: 거절은 세션 메모리에만 반영되며, 새로고침 시 다시 대기 상태로 복원된다(7b). 강퇴가 없는 것처럼 거절도 되돌릴 수 없는 파괴적 행위로 설계하지 않는다.

## 1.3 강퇴 기능 부재와 대안 설계

수평적 가치를 지키기 위해 강퇴(추방) 기능은 의도적으로 배제한다. 대신 아래 세 가지 대안으로 갈등 상황과 콘텐츠 문제에 대응한다.

| 상황 | 대안 | 세부 동작 |
|---|---|---|
| 멤버 자진 퇴장 | 데이터 보존(익명화) | 탈퇴 유저의 데이터는 파괴적 삭제 대신 '언노운(Unknown)' 처리하여 남은 친구들의 추억 기록을 보존한다. |
| 멤버 간 갈등 발생 | 전원 합의 기반 동결 | 멤버 전원 투표를 통해 방을 읽기 전용 아카이브(동결) 상태로 전환할 수 있다. 특정 인물의 일방적 결정이 아니다. |
| 부적절한 콘텐츠 | 신고 및 블라인드 | 타 멤버가 신고하거나 '내 화면에서 가리기'로 개인 단위 차단이 가능하다. 누적 신고 시 플랫폼 차원의 이용 제한이 적용된다. |

> **설계 의도**: 세 대안 모두 "특정 한 사람의 권한 행사"가 아니라 "당사자의 자발적 행동" 또는 "전원 합의"를 전제로 한다는 공통점을 가지며, 이는 1.1의 수평적 구조 원칙을 갈등 상황에서도 일관되게 유지하기 위한 장치다.

# 2. 스크린 리더 & 시각 접근성 명세

## 2.1 감성 요소 대체 텍스트 (WAI-ARIA)

Clov.는 인생4컷 필름, 미션 완료 도장, 감정 스탬프 등 시각적 감성 장치를 핵심 UI로 사용하므로, 시각 정보에 의존하지 않는 사용자를 위한 대체 텍스트 설계가 특히 중요하다.

- **구체적 맥락 포함**: 이미지의 존재만 알리는 것이 아니라, 누가·언제·무엇을 인증했는지까지 담은 `aria-label`을 매핑한다.
  - 예: `aria-label="홍길동 님의 3월 15일 인증 인생4컷 사진"`
  - 인생4컷 필름 카드(6a, 6c)의 4프레임(1.제안하기 2.일정 맞추기 3.약속 확정 4.만남)은 프레임마다 단계명·상태(잠김/활성/완료)를 함께 읽어줘야 한다. 예: `aria-label="2단계 일정 맞추기, 인증 완료"`, `aria-label="3단계 약속 확정, 잠김 — 이전 단계 완료 후 열림"`.
  - 약속 여정 영수증(6a, 6d)의 D-day 도장은 상태별로 의미가 다르므로(2.3의 영수증 도장 4상태 규칙 참조) `aria-label="D-3, 아직 완료되지 않은 약속"` / `aria-label="D+12, 완료되고 인생4컷까지 완성된 약속"`처럼 색상(빨강/초록) 정보를 텍스트로도 전달한다.
- **아이콘 전용 버튼 라벨링**: 텍스트 없이 아이콘만 있는 버튼에도 동작을 직관적으로 설명하는 라벨을 반드시 부여한다. 와이어프레임에서 실제로 아이콘만 사용하는 대표 사례:
  - 알림 모달(7a)의 🔔 트리거 → `aria-label="알림 열기, 대기 중인 가입 신청 3건"`(배지 수치 포함)
  - 사용자설정 개인정보 pane(8a)의 비밀번호 표시 토글 👁 → `aria-label="비밀번호 표시하기"`/`"비밀번호 숨기기"`(상태에 따라 전환)
  - 행운편지 편지함 trigger(5a, 우체통/선물상자 SVG) → `aria-label="행운 편지함 열기, 5통 도착"`
  - 받은 편지함 카드의 ⭐ 토글(5c) → `aria-label="즐겨찾기 추가"`/`"즐겨찾기 해제"`
  - 방 목록 편집 모드의 🗑 삭제, ⠿ 드래그 정렬 핸들(2b) → 각각 `aria-label="단짝친구 방 삭제"`, `aria-label="단짝친구 순서 변경, 드래그하여 이동"`
- **적용 범위**: 인생4컷 필름 카드의 각 프레임, 약속 여정 영수증의 도장, 행운편지의 감정 스탬프, 추억 여권(4c)의 상태 도장 등 서비스 전반의 시각적 상징물에 동일한 원칙을 적용한다.

## 2.2 실시간 상태 낭독 (aria-live)

키보드/스크린 리더 사용자의 초점을 방해하지 않으면서, 시간에 민감하거나 실시간으로 변하는 정보를 놓치지 않도록 알린다.

- **적용 대상**:
  - '5분 되돌리기' 카운트다운(7b, "되돌리기 4:47") — 숫자가 매초 바뀌지만, `aria-live`는 매초가 아니라 분 단위(예: "4분 남음")로만 갱신해 낭독 폭주를 방지한다.
  - 경합 처리 토스트 "이미 처리된 신청이에요 🙌"(7b), 거절 안내 "OO님의 가입 신청이 거절되었습니다"(7b) — 사용자가 다른 입력을 하던 중에도 놓치지 않도록 낭독한다.
  - 새 D-day 저장 시 대시보드 배너 동기화(6d), 인증 사진 업로드 시 여정·여권·일정계획 탭 동시 갱신(6d) — 화면 전환 없이 여러 위치가 동시에 바뀌는 지점이므로, 변경된 위치를 명시적으로 안내한다(예: "약속 여정에 새 D-day가 추가되었습니다").
  - 사용자설정 테마 pane(8b)의 "테마 변경은 즉시 적용·저장" — 저장 버튼을 누르지 않아도 즉시 반영되는 예외적 흐름이므로, 변경 시점에 낭독으로 확인시켜야 한다.
- **적용 방식**: `aria-live="polite"`를 지정하여, 사용자가 현재 작업 중인 요소의 초점을 유지한 채로 변경 사항이 음성으로 자연스럽게 안내되도록 한다.
- **연결 지점**: 이 스펙은 1.2의 5분 되돌리기·경합 처리, 1.1의 실시간 알림 공유와 직접 연결되며, 시각적으로 표시되는 정보가 반드시 청각적으로도 동등하게 전달되어야 한다는 원칙을 따른다.

## 2.3 다크 모드 고대비 가독성

약속 영수증, 행운 편지 등 종이 질감을 살린 감성 컴포넌트는 다크 모드에서도 라이트 배경(종이 질감)을 의도적으로 유지하는 디자인 원칙을 가진다. 이때 접근성이 훼손되지 않도록 아래 기준을 따른다.

- **명도 대비 기준**: 텍스트와 배경 간 명도 대비를 4.5:1 이상으로 유지한다(WCAG AA 기준 충족).
- **휘도 톤다운**: 배경 밝기를 소폭 낮춰(톤다운) 다크 모드 전체 화면과의 휘도 차이로 인한 눈 피로를 방지한다.
- **적용 컴포넌트**:
  - 일정계획의 약속 여정 영수증(6a) — "라이트/다크 동일 크림" 배경을 유지한다고 명시되어 있어, 다크 모드에서도 명도 대비 기준을 별도로 검증해야 한다.
  - 행운편지 편지함 무대(5a) — 실제로 "무대 배경이 밝아 흰 글자가 묻히던 문제 → 다크 배경 + 밝은 글자로 분기"한 이력이 있는 컴포넌트다. 즉 행운편지는 종이 질감 유지형이 아니라 다크 모드 전용 배경으로 전환하는 예외 컴포넌트이며, 전환 시에도 대비 기준은 동일하게 적용한다.
  - 추억피드 헤더(4a, feed-hero) — "다크에서도 양피지 배경(어두운 글자)"을 유지하도록 설계되어 있어, 종이 질감 유지형 컴포넌트의 대표 사례다.
  - 추억 여권의 영수증 도장 영역(4c) — 도장 색(빨강/초록)이 다크 모드 종이 배경 위에서도 4.5:1 대비를 유지해야 한다.

# 3. 키보드 조작 및 인터랙션 명세

## 3.1 포커스 트랩 (Focus Trap)

모달·바텀시트가 열려 있는 동안 키보드 초점이 배경 콘텐츠로 이탈하지 않도록 제한한다.

- **적용 대상**: 공통 모달 정책(9b)에 정의된 모든 중앙 모달·바텀시트가 대상이다.
  - 중앙 모달: 알림(7a), 사용자설정(8a/8b), 참여 멤버 리스트(3d), 추억 기록 글쓰기(4d), 새 D-day 만들기(6d), 업로드 확인(6c), 방 변경, 방 코드 공유
  - 바텀시트: 추억 여권 상세(4c, 94vh)
  - 생일 선택 휠 모달(1d)처럼 모달 위에 다시 뜨는 중첩 모달도 동일하게 자체 포커스 트랩을 가져야 한다.
- **진입 시 동작**: 모달이 열리면 키보드 초점을 모달 내부 첫 번째 요소로 강제 이동시킨다.
- **순환 제한**: Tab 이동은 모달 내부 요소 사이에서만 순환하며, 모달 바깥 요소로는 이동하지 않는다.
- **종료 시 동작**: ESC 키를 누르면 모달이 닫히고, 초점은 해당 모달을 열었던 트리거 버튼으로 복귀한다.
- **예외 처리 — ESC 전파 차단**: 추억 여권 상세(4c) 위에서 인생4컷 여정 모달(6d)이나 전체화면 사진 갤러리를 다시 연 상태로 ESC를 누르면, 최상위 레이어만 닫혀야 한다(추억피드 명세의 "ESC 전파 차단" 항목과 동일). 포커스 트랩 구현 시 ESC 핸들러를 레이어별로 분리하지 않으면 상세 화면 전체가 함께 닫히는 회귀가 발생하므로 반드시 레이어 스택 단위로 처리한다.
- **인라인 전환의 예외**: 행운편지 작성 카드(5a)는 팝업 모달이 아니라 탭 내부 토글로 펼쳐지는 인라인 컴포넌트이므로 포커스 트랩 대상이 아니다. 다만 펼쳐졌을 때 첫 입력 요소(받는 사람 선택)로 초점을 이동시키는 것은 동일하게 적용한다.

## 3.2 레이어 간섭 방지

모달이 열려 있는 동안 스크린 리더가 배경 콘텐츠까지 함께 탐색하며 혼선을 일으키지 않도록 차단한다.

- **적용 방식**: 모달 활성화 시 뒤쪽 메인 콘텐츠 컨테이너 영역에 `aria-hidden="true"`를 동적으로 부여한다. 예를 들어 대시보드(3a)에서 알림 모달(7a)을 열면, V5 씬 배너·대표 커버 카드·증거 카드 등 배경 전체를 감싸는 컨테이너에 `aria-hidden`을 부여한다.
- **해제 시점**: 모달이 닫히면 `aria-hidden` 속성을 즉시 제거하여 배경 콘텐츠 접근을 원상 복구한다.
- **연결 지점**: 3.1의 포커스 트랩과 함께 적용되어야 완전한 모달 격리가 성립한다. 포커스 트랩만으로는 스크린 리더의 가상 커서 탐색까지 막을 수 없기 때문이다.

## 3.3 스킵 네비게이션 (Skip Navigation)

- **배경**: 앱 헤더(3a)는 좌측 로고·뒤로가기, 우측 4개 nav 탭(우정공간·추억피드·행운편지·일정계획) + 🔔 알림 + 아바타 드롭다운으로 구성되며, 메인 앱의 모든 화면에서 동일하게 반복된다. 키보드 사용자가 매번 이 헤더 전체를 순회해야 한다면 본문 도달까지 불필요한 탐색 비용이 발생한다.
- **적용 방식**: 페이지 최상단에 '본문 바로가기(Skip Navigation)' 링크를 배치하여, 키보드 사용자가 반복 영역을 건너뛰고 방 내부 콘텐츠(대시보드의 대표 커버 카드, 추억피드의 폴라로이드 카드 목록 등 각 탭의 실제 콘텐츠 시작 지점)로 즉시 이동할 수 있도록 한다.
- **모바일 하단 4탭도 동일 원칙**: 모바일(3b)은 헤더 대신 하단 4탭 내비게이션을 쓰므로, 스킵 링크의 목적지는 상단 콘텐츠 영역이 되어야 하며 하단 탭 자체를 건너뛸 필요는 없다(이미 화면 하단에 위치해 순서상 마지막에 오기 때문).
- **노출 방식**: 평상시에는 시각적으로 숨겨져 있다가, 키보드 포커스가 도달하는 순간(Tab 키 최초 입력 시) 화면에 노출되는 방식을 권장한다.

# 5. 명세 간 연결 요약

이 문서의 세 축은 독립적인 규칙이 아니라 하나의 설계 철학에서 파생된다.

- **수평적 구조(1장)**가 "특정 권한자 없이 전원이 동등하게 정보를 주고받는다"는 원칙을 세우면,
- **시각/청각 접근성(2장)**은 그 정보(승인 상태, 설정 변경, 감성 인증 기록)가 시각 능력과 무관하게 모든 멤버에게 동등하게 전달되도록 보장하고,
- **키보드 조작 명세(3장)**는 그 정보에 접근하는 조작 경로 자체가 마우스 사용자와 동등한 효율을 갖도록 보장한다.

즉, "모든 멤버는 동등하다"는 Clov.의 서비스 철학은 멤버 간 권한뿐 아니라, 서로 다른 감각·조작 방식을 가진 사용자 간의 동등한 경험으로도 일관되게 확장되어야 한다.
