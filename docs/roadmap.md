## 1. 전체 흐름 — 5단계 파이프라인

```
[설계·계약]   기획 → DB 스키마(05 통일본) → API 명세(api-spec)
   상태:      ✅ 완료 — API-CONTRACT.md 단일 계약으로 통일, DB 24테이블 확정
     │
     ▼
[0단계 셋업]  레포 3개 유지 · 지침파일 · 계약 1개 · main보호 · CI
   상태:      ✅ 완료
     │
     ▼
[1단계 워킹스켈레톤]  로그인 1개를 프론트→백→DB→CI 끝까지 관통 (리드 혼자)
   상태:      ✅ 완료
     │
     ▼
[2단계 기능 팬아웃]  4명이 기능 세로슬라이스를 각자 하네스로 개발
   상태:      ✅ 완료 — 우정공간·약속·추억·행운편지·상점·알림·인증 전 도메인 구현
     │
     ▼
[3단계 통합·배포]  기능 합치기 → 테스트 → 배포
   상태:      ✅ 배포 인프라 구성 완료(GCP·nginx·Docker·GitHub Actions) — 세부 운영은 `clov-api/deploy/DEPLOY.md` 참고
```

> **핵심 원칙**: 사람을 "프론트팀/백팀"으로 가르지 않고 **기능(세로)으로 나눈다**. 통합 = 기능마다 프론트+백이 붙어있다는 뜻이므로, 한 명이 기능 하나를 끝까지 책임진다.

## 3. 하네스 운영 — 3층 구조

AI를 여러 명·여러 도구로 굴리려면 아래 3층이 갖춰져야 한다(팀이 전원 Claude로 통일된 뒤에도 구조 자체는 그대로 유효하다).

### 1층. 에이전트가 "읽는" 것 (지침)
```
각 레포 AGENTS.md          ← HOW: 이 레포에서 어떻게 코딩하나
 └ CLAUDE.md → AGENTS.md   ← Claude용 포인터

단일 계약 (1곳)            ← WHAT: 프론트-백 공통 약속(API·DB) — docs/API-CONTRACT.md로 통일 완료
```
> **HOW(레포별)는 나눠도 되지만, WHAT(계약)은 반드시 한 곳.** `docs/API-CONTRACT.md`(SSOT)와 `clov-api`/`clov-web`의 동일 경로 파일은 그 문서를 가리키는 1줄짜리 포인터일 뿐이다.

### 2층. 사람이 "지키는" 것 (작업 규칙)
- **3레포를 한 부모 폴더에 clone** → 하네스를 부모 폴더에서 실행하면 AI가 프론트+백+계약을 다 본다.
- **이슈 1개 = 브랜치 1개** (`feat/<이슈번호>-<주제>` 또는 `fix/<이슈번호>-<주제>`), PR은 **작게** 자주.
- **계약(API·DB) 수정은 리더 승인만** → 갈라짐 방지(리더 부재 기간엔 팀 자체 판단으로 대체 가능하다고 확정됨 — `API-CONTRACT.md` 상단 참고).
- **AI가 만든 코드는 돌려보고 커밋** (생성물 그대로 밀지 않기).
- 기능이 프론트+백에 걸치면 **PR 2개**(백 먼저 머지 → 프론트).

### 3층. 기계가 "강제"하는 것 (안전망)
- **CI**: `clov-api`는 `./gradlew test`, `clov-web`은 build 체크 → 규약 못 지키면 머지 차단.
- **main 보호**: PR 필수 + CI 통과 필수 → 아무도 main을 실수로 못 깬다(`clov-api`·`clov-web` 둘 다 확인함).
- **단일 계약**: 프론트-백이 같은 약속으로 대화.

## 5. Git 운영 (3레포)

```
main (보호: PR 필수 · CI 통과 필수)
 └ feat/<이슈번호>-<주제>   ← 이슈 하나 = 브랜치 하나, 짧게 살고 빨리 머지
```
- 이슈는 **그 일이 사는 레포**에 만든다(백=clov-api, 프론트=clov-web, 계약 제안=web-design-repository).
- 전체 진행은 **org Project 보드 하나**로 세 레포 이슈를 모아 본다.
- 커밋 메시지: [Conventional Commits](https://www.conventionalcommits.org/)(`feat:`/`fix:`/`docs:` 등) + 이슈 번호.
- 이슈 제목 태그: `[api]` `[web]` `[계약 제안]`.

### main 보호 — 이미 켜져 있음
`clov-api`·`clov-web` 둘 다 `Settings → Branches`에 `Require a pull request before merging` + `Require status checks to pass`가 적용 중이다(2026-08-13, 직접 push를 시도해서 거부되는 것으로 확인함). `web-design-repository`는 이 규칙이 없어 계약 문서는 리더(또는 리더 부재 기간엔 팀)가 직접 main에 커밋하기도 한다.
