## 5. 발견한 오류

### 5-1. 개인정보 수정 드롭다운이 한 번 열면 다시 안 열리는 문제

`clov-header.js`의 "개인정보 수정" 메뉴 항목이 드롭다운을 닫을 때 `document.getElementById('clov-hdr-drop').style.display='none'`로 인라인 스타일을 직접 건드리고 있었다. 반면 드롭다운을 여는 아바타 버튼(`ClovHeader._toggleDrop`)은 `classList.toggle('open')`으로 CSS 클래스만 토글하는 방식이었다.

인라인 스타일은 클래스 기반 CSS 규칙(`.clov-hdr-dropdown.open { display:block }`)보다 항상 우선하기 때문에, "개인정보 수정"을 한 번이라도 클릭하면 그 뒤로는 아바타를 아무리 눌러 `open` 클래스를 토글해도 드롭다운이 다시 보이지 않았다.

**수정**: 해당 onclick을 `openProfileModal();document.getElementById('clov-hdr-drop').classList.remove('open')`로 교체 — 인라인 스타일 대신 클래스 제거 방식으로 통일하고, 모달을 열 때 `loadProfileModalData()`가 실행되도록 `openProfileModal()`을 거치게 했다.

### 5-2. 페이지 전역 클릭 핸들러가 거의 모든 클릭에서 에러를 던지던 문제

`desktop.js`의 `openModal()`과 `window.onclick`(화면 바깥 클릭 처리)이 존재하지 않는 엘리먼트(`mb-drop`, `dt-drop` — 현재 HTML엔 없음)를 null 체크 없이 `document.getElementById(...).style.display = 'none'` 형태로 참조하고 있었다. 이 엘리먼트가 없으므로 `getElementById`가 `null`을 반환하고, 그 뒤에 `.style`을 읽으려다 `TypeError`가 발생해 다음 코드가 실행되지 않았다.

`window.onclick`은 화면 어디를 클릭해도 실행되는 핸들러라서, 이 에러 때문에 아래 두 기능이 사실상 거의 항상 죽어 있었다:

- 모달 바깥(배경) 클릭 시 모달 닫기
- 월별 선택 팝오버(`month-picker-popover`) 바깥 클릭 시 닫기

**수정**: `mb-drop`/`dt-drop` 조회 결과를 null 체크 후 사용하도록 `openModal()`과 `window.onclick` 두 곳을 모두 수정. 동시에 헤더 드롭다운(`clov-hdr-dropdown.open`)도 이 두 지점에서 클래스 기반으로 같이 닫히도록 정리했다.

### 5-3. 캐시 버전 미갱신

위 수정들을 반영한 뒤에도 `index.html`이 `clov-header.js?v=4`, `desktop.js?v=20260703`, `desktop.css?v=21`처럼 예전 버전 번호를 그대로 참조하고 있어서, 이미 방문한 브라우저는 캐시된 예전 파일을 계속 쓸 수 있었다. `v=5`, `v=20260703b`, `v=22`로 올려 강제 갱신되도록 했다.

## 팀 공유 시 주의할 점

- 이 프로젝트는 `?v=` 쿼리로 캐시를 관리한다. `desktop.js`/`desktop.css`/`clov-header.js`를 수정하면 **반드시 `index.html`의 버전 번호도 같이 올릴 것** — 안 올리면 이미 방문한 브라우저에 변경사항이 반영되지 않는다 (이번에 실제로 이 문제가 있었다)
- 헤더 드롭다운(`clov-hdr-dropdown`)을 여닫을 때는 `style.display`가 아니라 반드시 `classList`(`open`)를 사용할 것 — 섞어 쓰면 인라인 스타일이 영구히 우선권을 가져가서 드롭다운이 고장난다
- `mb-drop`/`dt-drop`은 현재 HTML에 존재하지 않는 레거시 id다. 관련 코드를 더 추가할 경우 null 체크 없이 `getElementById(...).style`을 바로 쓰지 말 것
