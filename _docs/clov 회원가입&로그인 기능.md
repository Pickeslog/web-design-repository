# Clov 회원가입 & 로그인 기능 작업 정리

## 1. 작업 개요

이번 작업에서는 Clov 프로젝트의 사용자 진입 흐름인 **회원가입 페이지**와 **로그인 페이지**를 HTML/CSS/JavaScript 기반으로 구현했다.

핵심 목표는 단순한 입력 폼을 만드는 것이 아니라, Clov 서비스의 분위기인 **친구와의 약속, 추억, 기록이 자라는 공간**이라는 감성을 화면 전체에 반영하는 것이었다.

작업 파일은 다음과 같다.

- `signup.html`
- `login.html`

두 페이지는 서로 이동할 수 있도록 연결되어 있다.

- 회원가입 페이지 하단 `로그인` 클릭 시 `login.html`로 이동
- 로그인 페이지 하단 `회원가입` 클릭 시 `signup.html`로 이동

## 2. 회원가입 페이지

### 2-1. 회원가입 화면 구성

회원가입 페이지는 Clov의 초록 계열 브랜드 컬러를 중심으로 제작했다.

화면 중앙에는 glassmorphism 느낌의 카드 UI를 배치했고, 배경에는 은은한 초록색 오브젝트를 사용해 부드럽고 가벼운 분위기를 만들었다.

회원가입은 총 4단계 구조로 구성했다.

1. 기본 정보 입력
2. 약관 동의
3. 프로필 설정
4. 가입 완료

상단에는 진행 상태를 보여주는 step bar를 배치했다. 사용자가 현재 어느 단계에 있는지 직관적으로 알 수 있도록 active, done 상태를 시각적으로 구분했다.

### 2-2. 기본 정보 입력

기본 정보 입력 단계에는 다음 입력란을 구성했다.

- 이메일
- 전화번호
- 비밀번호

닉네임 입력란은 중간 작업 과정에서 제거했다. 현재 회원가입 흐름에서는 이메일을 기준으로 사용자를 식별하는 것이 더 간결하다고 판단했기 때문이다.

입력란은 모두 세로 방향으로 정렬했다. 처음에는 카드 높이를 줄이기 위해 이메일과 전화번호를 2열로 배치했지만, 입력 폼의 가독성과 일관성을 위해 다시 세로 정렬로 변경했다.

### 2-3. 입력값 검증

회원가입 페이지에는 JavaScript 기반의 간단한 입력값 검증을 추가했다.

이메일 검증:

- 이메일 형식에 맞는 값인지 확인
- 예: `example@email.com`

전화번호 검증:

- `010-1234-5678` 형식을 기준으로 확인
- 사용자가 `01058797023`처럼 숫자만 입력해도 `010-5879-7023` 형식으로 자동 변환

비밀번호 검증:

- 8자 이상인지 확인

처음에는 비밀번호를 영문+숫자 조합까지 확인하도록 강화했지만, 이후 요청에 따라 원래 기준인 **8자 이상**으로 되돌렸다.

### 2-4. 경고 문구 UX 개선

입력 검증 경고는 사용자가 불편하지 않도록 여러 차례 개선했다.

최종 동작은 다음과 같다.

- input box를 클릭만 하고 빈 값으로 다른 input으로 이동하면 경고가 뜨지 않음
- 값이 입력된 상태에서 형식이 틀린 채 포커스를 잃으면 경고 표시
- 정규표현식을 통과한 값이 들어오면 경고 또는 안내 문구가 표시되지 않음
- 다음 단계 버튼을 눌렀을 때 필수값이 비어 있으면 그때 경고 표시

즉, 사용자가 아직 작성하지 않은 상태에서는 조용히 넘어가고, 작성이 끝난 뒤 잘못된 값만 자연스럽게 알려주는 방식으로 정리했다.

경고 문구는 붉은 계열의 작은 캡슐 형태로 표시되도록 구현했다. 박스가 과하게 늘어나거나 레이아웃이 흔들리지 않도록 높이와 margin을 제어했다.

### 2-5. 비밀번호 보기/숨기기 기능

비밀번호 입력란에는 눈 모양 아이콘 버튼을 추가했다.

기능은 다음과 같다.

- 기본 상태: 비밀번호 숨김
- 눈 아이콘 클릭 시 비밀번호 보이기
- 다시 클릭 시 비밀번호 숨기기

비밀번호가 보이는 상태에서는 안내 문구가 다음과 같이 바뀐다.

> 조심하세요! 비밀번호가 보여요!

이 안내 문구도 항상 보이는 것이 아니라, 비밀번호가 실제로 보이는 상태일 때만 표시되도록 조정했다.

### 2-6. 비밀번호 강도 표시

비밀번호 입력란 아래에는 간단한 강도 표시 bar를 추가했다.

입력값에 따라 4개의 segment가 색상으로 채워진다.

판단 기준은 다음 요소를 활용했다.

- 8자 이상
- 12자 이상
- 대문자 또는 숫자 포함
- 특수문자 포함

이 기능은 실제 보안 정책이라기보다는 사용자가 더 안전한 비밀번호를 작성하도록 돕는 시각적 보조 요소로 구현했다.

### 2-7. 약관 동의 단계

두 번째 단계에는 약관 동의 UI를 구성했다.

포함 항목은 다음과 같다.

- 전체 동의
- 필수: 서비스 이용약관 동의
- 필수: 개인정보 처리방침 동의
- 선택: 마케팅 정보 수신 동의

필수 약관이 체크되지 않은 상태에서 다음 단계로 넘어가려고 하면 약관 박스가 흔들리는 애니메이션을 보여준다.

이를 통해 단순 alert보다 화면 안에서 자연스럽게 피드백을 받을 수 있도록 했다.

### 2-8. 프로필 설정 단계

약관 동의 후에는 사용자의 프로필 정보를 받는 단계를 추가했다.

프로필 설정 단계에는 다음 요소를 구성했다.

- 프로필 이미지 등록
- 프로필 이미지 미리보기
- 닉네임 입력
- 생년월일 입력

프로필 이미지는 원형 미리보기 UI로 구성했다. 사용자가 이미지를 선택하면 즉시 화면에 반영되어, 실제 서비스에서 내 프로필이 어떻게 보일지 빠르게 확인할 수 있다.

닉네임은 한글, 영문, 숫자를 허용하도록 구성했다. 대한민국 이름에는 외자 이름이나 4글자 이름도 있을 수 있기 때문에, 너무 좁은 정규표현식을 사용하지 않고 `1~12자` 범위로 넓게 허용했다.

닉네임 입력란 옆에는 케이크 아이콘 버튼을 배치했다. 이 버튼을 누르면 닉네임이 올바른 경우에만 카드가 180도 회전하며 생년월일 입력 카드로 전환된다.

생년월일 카드에서는 다시 닉네임 입력 카드로 돌아갈 수 있는 뒤로가기 버튼을 제공한다. 사용자가 닉네임을 잘못 입력했을 가능성을 고려해, 생년월일 단계에서도 이전 입력을 수정할 수 있도록 한 것이다.

생년월일 입력은 카드 내부에서 직접 타이핑하는 방식이 아니라, 입력란을 클릭하면 별도의 선택 모달이 뜨는 방식으로 변경했다.

생년월일 모달은 다음 구조로 구성했다.

- 년 선택
- 월 선택
- 일 선택

저장 버튼을 누르면 선택한 값이 `YYYY-MM-DD` 형식으로 생년월일 입력란에 반영된다.

### 2-9. 가입 완료 단계

네 번째 단계는 가입 완료 화면이다.

가입 완료 시 다음 요소를 표시한다.

- 축하 이모지
- 완료 체크 아이콘
- 가입 완료 메시지
- 우정공간 입장하기 버튼

사용자 이름은 별도 닉네임을 받지 않기 때문에 이메일의 `@` 앞부분을 활용해 표시하도록 했다.

### 2-10. OAuth2 연동 준비 UI

회원가입 페이지 하단에는 OAuth2 간편 회원가입 또는 로그인으로 확장할 수 있는 소셜 버튼 영역을 구성했다.

포함된 provider는 다음과 같다.

- 카카오
- 네이버
- 구글

초기에는 텍스트 버튼 형태였지만, 이후 간편 로그인 느낌이 더 직관적으로 보이도록 아이콘 중심의 원형 버튼으로 변경했다.

각 버튼은 hover 시 아래에 작은 라벨이 표시된다.

- 카카오 로그인
- 네이버 로그인
- 구글 로그인

브라우저 기본 tooltip이 뜨지 않도록 `title` 속성은 사용하지 않았다.

## 3. 회원가입 페이지 이스터에그

### 3-1. 클로버 로고 클릭 이벤트

회원가입 페이지 상단의 클로버 로고에는 클릭 이벤트를 추가했다.

일반 클릭 시에는 Clov 분위기에 어울리는 짧은 랜덤 메시지가 표시된다.

예시 문구:

- 오늘도 추억 한 잎 저장
- Clov.가 조용히 자라는 중
- 친구와의 약속을 기다려요
- 작은 기록도 오래 남아요

메시지는 초록색 계열의 작은 캡슐 UI로 표시되며, 주변 UI와 어울리도록 색상과 그림자를 조정했다.

### 3-2. 10% 확률 희귀 이벤트

클로버 로고 클릭 시 10% 확률로 희귀 이스터에그가 실행된다.

처음에는 클로버 아이콘 자체가 반으로 갈라지는 연출을 넣었지만, 이후 사용자의 요청에 따라 카드 자체가 반으로 갈라지는 연출로 변경했다.

현재 방식은 다음과 같다.

- 실제 카드에 `cracking` 클래스를 부여
- 카드의 `::before`, `::after` 가상 요소를 사용해 카드 양쪽 조각 생성
- 카드 내부 실제 입력값은 유지
- 연출 중 카드 내부 요소는 투명하게 처리
- 카드가 반으로 갈라졌다가 다시 붙는 애니메이션 실행

표시 문구는 다음 순서로 나온다.

1. `으아악..`
2. `Clov.가 사라진줄 알았나요? 😊`

이전에는 별도의 overlay layer를 카드 위에 씌우는 방식이었지만, 최종적으로는 별도 layer를 제거하고 카드 자체가 갈라지는 것처럼 보이도록 변경했다.

## 4. 로그인 페이지

### 4-1. 로그인 페이지 제작 배경

처음 생성한 로그인 페이지는 회원가입 페이지와 스타일이 너무 비슷해, 사용자가 코드 적용 여부를 헷갈릴 수 있었다.

그래서 로그인 페이지는 회원가입 페이지의 색상과 브랜드 톤은 유지하되, 레이아웃 자체는 확실히 다르게 구성했다.

최종 로그인 페이지는 다음 구조를 가진다.

- 왼쪽: 브랜드/추억 소개 패널
- 오른쪽: 로그인 폼 패널

회원가입 페이지가 중앙 카드형이라면, 로그인 페이지는 분할형 화면으로 차별화했다.

### 4-2. 왼쪽 브랜드 패널

왼쪽 패널은 진한 초록색 배경을 사용했다.

포함 요소는 다음과 같다.

- Clov. 브랜드 로고
- `오늘도 추억 보관 중` 배지
- 친구와 남긴 순간으로 돌아가는 메시지
- 작은 memory note 카드

이 영역은 로그인 화면에 감성적인 맥락을 부여하기 위한 시각 요소다.

단순히 로그인 폼만 보여주는 것이 아니라, 사용자가 Clov에 다시 돌아온다는 느낌을 주도록 구성했다.

### 4-3. 로그인 입력 폼

로그인 입력 폼에는 다음 항목을 배치했다.

- 이메일
- 비밀번호
- 로그인 유지 체크박스
- 비밀번호 찾기 버튼
- 로그인 버튼

이메일과 비밀번호는 기본적인 입력 검증을 수행한다.

로그인 버튼을 눌렀을 때:

- 이메일 형식이 맞지 않으면 이메일 input 흔들림
- 비밀번호가 비어 있으면 비밀번호 input 흔들림
- 정상 입력 시 예시 메시지 표시

실제 API 연동은 아직 적용하지 않았고, 프론트엔드 예시 동작까지만 구현했다.

### 4-4. 로그인 유지 체크박스

로그인 유지 체크박스는 체크 상태에 따라 텍스트 색상이 초록 계열로 변경된다.

이를 통해 사용자가 체크 여부를 더 명확히 인지할 수 있도록 했다.

### 4-5. 비밀번호 보기/숨기기

로그인 페이지에도 회원가입 페이지와 동일하게 비밀번호 보기/숨기기 기능을 추가했다.

눈 모양 아이콘을 클릭하면 비밀번호 input의 type이 변경된다.

- 숨김 상태: `password`
- 보임 상태: `text`

보임 상태에서는 다음 문구가 표시된다.

> 조심하세요! 비밀번호가 보여요!

### 4-6. 비밀번호 찾기 버튼

로그인 페이지에는 비밀번호 찾기 버튼을 배치했다.

현재는 실제 비밀번호 재설정 기능을 구현하지 않고, 추후 OAuth2 또는 인증 API 연동 단계에서 연결할 예정이라는 안내 메시지를 띄우도록 했다.

### 4-7. OAuth2 간편 로그인 UI

로그인 페이지 하단에도 OAuth2 간편 로그인 영역을 추가했다.

포함된 provider는 회원가입 페이지와 동일하다.

- 카카오
- 네이버
- 구글

소셜 버튼은 텍스트 없이 아이콘만 보여주며, hover 시 해당 provider의 로그인 라벨이 나타난다.

이는 실제 OAuth2 연동 전 단계에서 사용자에게 간편 로그인 가능성을 직관적으로 보여주기 위한 UI다.

## 5. 페이지 간 이동 구조

회원가입과 로그인 페이지는 서로 연결되어 있다.

회원가입 페이지:

```html
<a href="login.html">로그인</a>
```

로그인 페이지:

```html
<a href="signup.html">회원가입</a>
```

이 구조를 통해 사용자는 계정이 있으면 로그인 페이지로, 계정이 없으면 회원가입 페이지로 자연스럽게 이동할 수 있다.

## 6. UI/UX 개선 포인트

이번 작업에서 반복적으로 개선한 부분은 다음과 같다.

### 입력 안내 문구 정리

초기에는 input에 focus만 되어도 안내 문구가 표시되었다.

하지만 사용자가 입력값을 정상적으로 작성했는데도 안내 문구가 계속 뜨는 문제가 있었기 때문에, 최종적으로는 다음 기준으로 변경했다.

- 정상 값이면 문구 숨김
- 빈 값으로 이동하면 문구 숨김
- 잘못된 값을 작성한 뒤 이동하면 경고 표시
- 다음 단계 클릭 시 필수값이 비어 있으면 경고 표시

전화번호와 생년월일은 사용자가 숫자만 입력하거나 선택해도 화면에는 정해진 형식으로 보이도록 정리했다.

- 전화번호: `01058797023` → `010-5879-7023`
- 생년월일: 년/월/일 선택 후 `YYYY-MM-DD` 형식으로 반영

### 카드 높이 조정

전화번호 입력란이 추가되면서 회원가입 카드가 세로로 길어지는 문제가 있었다.

이를 해결하기 위해 다음을 조정했다.

- 불필요한 안내 문구 제거
- 로고 크기와 여백 축소
- step bar와 폼 사이 간격 조정
- input 간격 조정

### 로그인 페이지 차별화

로그인 페이지가 회원가입 페이지와 너무 비슷하다는 피드백이 있었다.

이를 반영해 로그인 페이지는 완전히 다른 화면 구조를 적용했다.

- 회원가입: 중앙 카드형 step UI
- 로그인: 좌측 브랜드 패널 + 우측 로그인 폼

## 7. 현재 구현 상태

현재 구현된 기능은 다음과 같다.

- 회원가입 4단계 화면
- 이메일 입력
- 전화번호 입력
- 비밀번호 입력
- 프로필 이미지 등록 및 미리보기
- 닉네임 입력
- 생년월일 선택 모달
- 비밀번호 보기/숨기기
- 비밀번호 강도 표시
- 입력값 검증
- 경고 문구 표시 제어
- 약관 동의
- 프로필 설정
- 가입 완료 화면
- OAuth2 간편 로그인 UI
- 로그인 화면
- 로그인 유지 체크박스
- 비밀번호 찾기 안내 버튼
- 로그인/회원가입 페이지 이동
- 클로버 로고 랜덤 메시지
- 10% 확률 카드 쪼개짐 이스터에그

## 8. 추후 연동 예정

현재 HTML 페이지는 프론트엔드 예시 구현 단계다.

추후 실제 프로젝트에서는 다음 기능을 백엔드와 연동할 수 있다.

- 회원가입 API 연결
- 로그인 API 연결
- 이메일 중복 확인
- 전화번호 인증
- 비밀번호 암호화 정책 적용
- 세션 또는 JWT 기반 로그인 유지
- 비밀번호 찾기 및 재설정 기능
- 카카오 OAuth2 로그인
- 네이버 OAuth2 로그인
- 구글 OAuth2 로그인

## 9. 발표 시 강조할 점

발표에서는 다음 내용을 강조하면 좋다.

1. Clov의 서비스 분위기에 맞춘 따뜻한 초록 계열 UI
2. 회원가입과 로그인 페이지의 명확한 화면 차별화
3. 사용자 입력 흐름을 방해하지 않는 검증 UX
4. OAuth2 연동을 고려한 간편 로그인 UI 구조
5. 프로젝트 분위기를 살리는 클로버 이스터에그
6. 실제 API 연동 전 단계에서 프론트엔드 흐름을 먼저 설계했다는 점

이번 작업은 단순한 HTML 폼 구현이 아니라, 사용자가 Clov에 처음 들어오는 순간을 어떻게 느낄지까지 고려한 진입 화면 설계 작업이다.
