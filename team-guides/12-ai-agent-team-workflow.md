# 팀원용 AI 에이전트 작업 흐름

## 문서 목적

이 문서는 팀원들이 Gemini 같은 AI 에이전트를 사용해 Clov. HTML 프로토타입과 화면명세 작업을 효율적으로 진행하기 위한 공통 작업 방식이다.

팀원이 AI를 잘 쓰려면 "화면 전체를 알아서 고쳐줘"가 아니라, 정해진 문서와 정해진 작업 단위를 주고 작은 범위로 검증해야 한다.

## 핵심 원칙

### 1. HTML 전체를 매번 넣지 않는다

`Clov - 추억피드.html`은 기준본이지만, AI에게 매번 전체 HTML을 붙여넣지 않는다.

대신 아래 문서를 먼저 제공한다.

- 서비스 요약
- 디자인 시스템
- 작업할 화면 문서
- 공통 모달/인터랙션 문서
- 필요한 경우 데이터/상태 문서

### 2. 한 번에 한 화면, 한 기능만 맡긴다

좋은 작업 단위:

- 추억피드 월 선택 팝오버 설명 보강
- 행운편지 작성 모달 UI 정리
- 일정계획 빈 상태 문구 추가
- 추억 카드 사진 없는 상태 개선

나쁜 작업 단위:

- 전체 HTML 예쁘게 바꿔줘
- Clov 전체 화면명세서 만들어줘
- 모든 오류 고쳐줘
- 디자인 다 개선해줘

### 3. 기준본과 참고본을 구분한다

기준본:

```text
Clov - 추억피드.html
```

참고본:

```text
Clov - 행운 편지.html
```

작업자는 반드시 기준본을 중심으로 작업하고, 참고본의 기능은 필요한 부분만 가져온다.

### 4. Clov. 핵심 구조 원칙을 매번 포함한다

AI가 화면을 바꾸다 보면 방장, 대표자, 1:1 전용, 그룹장 같은 개념을 임의로 만들 수 있다.

그래서 모든 작업 프롬프트에는 아래 원칙을 넣는다.

```text
- 우정공간은 인원 제한 없는 단일 구조다.
- 1:1 전용/1:N 전용 화면으로 나누지 않는다.
- 방장/대표자/초대한 사람 권한 개념은 없다.
- 모든 멤버는 동등하다.
- 핵심 차별점은 약속 완료 후 추억 작성 후보로 전환되는 흐름이다.
- 같은 약속에 대해 친구별로 다른 관점의 기록을 남길 수 있다.
```

## 팀원 작업 표준 절차

### 1단계. 작업 화면 정하기

아래 중 하나를 고른다.

- 우정공간 대시보드
- 추억피드
- 행운편지
- 일정계획
- 공통 모달/인터랙션

### 2단계. 읽힐 문서 고르기

공통으로 항상 읽힐 문서:

- `00-service-summary.md`
- `01-design-system.md`

화면별 추가 문서:

- 대시보드: `02-dashboard-screen.md`
- 추억피드: `03-memory-feed-screen.md`
- 행운편지: `04-lucky-letter-screen.md`
- 일정계획: `05-schedule-screen.md`
- 모달/인터랙션: `06-modal-and-interaction.md`

보강 문서:

- 화면 간 흐름 필요: `07-user-flow.md`
- 데이터/상태 필요: `08-data-and-state.md`
- 컴포넌트 분리 필요: `09-component-inventory.md`
- HTML 병합 작업 필요: `10-merge-plan.md`
- 프롬프트 작성 예시 필요: `11-claude-prompt-template.md`

### 3단계. 작업 목표를 한 문장으로 쓰기

예시:

```text
추억피드 화면에서 월별 아카이브와 월 선택 팝오버의 화면명세를 보강한다.
```

```text
행운편지 화면에서 작성 모달과 상세 모달을 기준본에 병합하기 위한 작업 지시서를 작성한다.
```

```text
일정계획 화면에서 약속 완료 후 추억 작성 후보로 이어지는 흐름을 명세서에 추가한다.
```

### 4단계. AI에게 맡길 산출물을 명확히 정하기

가능한 산출물:

- 화면명세서 초안
- HTML 수정안
- CSS 수정안
- JS 함수 수정안
- QA 체크리스트
- 팀 공유용 요약문
- GitHub Issue 초안
- React 컴포넌트 분리안

### 5단계. 완료 기준을 적는다

예시:

```text
완료 기준:
- 화면 목적이 명확해야 한다.
- 주요 UI 영역이 빠짐 없어야 한다.
- 사용자 액션과 상태가 표로 정리되어야 한다.
- Clov. 핵심 구조 원칙을 위반하면 안 된다.
- HTML 코드 설명이 아니라 화면명세서 문체여야 한다.
```

## AI 에이전트에게 시키면 좋은 일

### 화면명세서 작성

AI가 가장 잘하는 작업이다.

입력:

- 서비스 요약
- 디자인 시스템
- 화면별 문서

출력:

- 화면 목적
- UI 영역
- 액션
- 상태
- 예외 케이스
- 데이터 항목

### HTML 일부 수정

AI에게 맡길 수 있지만 범위를 작게 해야 한다.

좋은 요청:

```text
행운편지 탭 영역만 수정해줘.
다른 탭과 JS 함수는 건드리지 마.
```

주의:

- 전체 HTML을 한 번에 재작성시키지 않는다.
- 기준본의 다른 기능을 삭제하지 않게 한다.
- 수정 후 어떤 부분을 바꿨는지 요약하게 한다.

### CSS 보정

AI가 비교적 잘한다.

좋은 요청:

```text
다크모드에서 추억 카드 내부 텍스트 가독성만 보정해줘.
색상 토큰은 기존 CSS 변수를 우선 사용해.
```

### JS 함수 병합

AI에게 맡길 수 있지만 충돌 검수가 필요하다.

주의:

- 같은 함수 이름 중복 확인
- `window.onclick` 덮어쓰기 확인
- `keydown` 이벤트 중복 확인
- 모달 ID 중복 확인

## AI 에이전트에게 맡기면 위험한 일

- 전체 HTML을 처음부터 다시 작성
- 서비스 구조를 새로 기획
- 권한 구조를 임의로 추가
- 1:1/그룹 화면을 분리
- 방장/관리자 개념 추가
- 기준본과 참고본을 임의로 섞기
- 검증 없이 기존 기능 삭제

## 사용한 기준 문서

- 00-service-summary.md
- 01-design-system.md
- 03-memory-feed-screen.md

## 작업 내용

- 월별 아카이브 명세 작성
- 월 선택 팝오버 상태 정리
