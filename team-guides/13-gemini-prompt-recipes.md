## 문서 목적

이 문서는 팀원들이 Gemini AI 에이전트에 바로 붙여넣어 사용할 수 있는 프롬프트 예시를 제공한다.

## 공통 프롬프트 헤더

모든 작업 시작 시 아래 문장을 먼저 넣는다.

```text
너는 Clov. 프로젝트의 화면명세서와 HTML 프로토타입 작업을 돕는 AI 에이전트야.

Clov.는 "약속이 추억으로 자라는 친구 전용 기록공간"이야.

중요 원칙:
- 우정공간은 인원 제한 없는 단일 구조다.
- 1:1 전용/1:N 전용 화면으로 나누지 않는다.
- 방장/대표자/초대한 사람 권한 개념은 없다.
- 모든 멤버는 동등하다.
- 핵심 차별점은 약속 완료 후 추억 작성 후보로 전환되는 흐름이다.
- 같은 약속에 대해 친구별로 다른 관점의 기록을 남길 수 있다.

HTML 전체를 새로 만들지 말고, 내가 지정한 화면과 범위 안에서만 작업해줘.
```

## 1. 화면명세서 작성 프롬프트

사용 상황:

- 팀원이 화면명세서를 처음 작성할 때

```text
아래 문서를 기준으로 [화면명] 화면명세서를 작성해줘.

읽어야 할 문서:
- 00-service-summary.md
- 01-design-system.md
- [화면별 문서]
- 필요 시 06-modal-and-interaction.md
- 필요 시 08-data-and-state.md

산출물 형식:
1. 화면 목적
2. 사용자 진입 경로
3. 주요 UI 영역
4. 컴포넌트 목록
5. 사용자 액션
6. 상태값
7. 예외 케이스
8. 데스크톱/모바일 차이
9. 데이터/API 참고 항목
10. UX 주의사항

주의:
- HTML 코드 설명처럼 쓰지 말고 실제 화면명세서 문체로 작성해줘.
- Clov. 핵심 구조 원칙을 위반하는 표현은 쓰지 마.
- 방장, 관리자, 대표자, 1:1 전용 같은 표현을 넣지 마.
```

## 2. HTML 일부 수정 프롬프트

사용 상황:

- 특정 화면의 HTML 일부만 고칠 때

```text
기준본은 `Clov - 추억피드.html`이야.
아래 작업 범위만 수정해줘.

작업 화면:
[예: 행운편지 탭]

작업 목표:
[예: 편지 작성 버튼과 상세 모달 진입 구조를 추가]

수정 범위:
- HTML: [수정할 영역]
- CSS: [필요한 클래스]
- JS: [필요한 함수]

건드리지 말아야 할 것:
- 추억피드 월 선택 팝오버
- 일정계획 Clover Growth Path
- 다크모드 토글
- 기존 탭 전환 함수

완료 후 아래 형식으로 보고해줘:
1. 수정한 영역
2. 추가한 클래스/ID
3. 추가 또는 수정한 함수
4. 기존 기능과 충돌 가능성
5. 브라우저에서 확인해야 할 클릭 테스트
```

## 3. 병합 작업 프롬프트

사용 상황:

- `Clov - 행운 편지.html`의 기능을 기준본에 가져올 때

```text
기준본은 `Clov - 추억피드.html`이고, 참고본은 `Clov - 행운 편지.html`이야.

목표:
기준본을 유지한 채 참고본에서 행운편지 작성/상세 모달 기능만 병합하고 싶어.

반드시 유지할 기준본 기능:
- 추억피드 월별 아카이브
- 월 선택 팝오버
- 추억 더보기 바텀시트
- 일정계획 Clover Growth Path
- 다크모드 토글

참고본에서 가져올 기능:
- 행운편지 작성 버튼
- 데스크톱/모바일 편지 작성 모달
- 데스크톱/모바일 편지 상세 모달
- To/From 입력
- 이모지 선택
- 실시간 미리보기
- 편지 목록 클릭 상세 보기
- 즐겨찾기 빈 화면 스타일 개선

먼저 코드를 바로 수정하지 말고, 병합 순서와 충돌 위험을 정리해줘.
그 다음 내가 승인하면 수정안을 제시해줘.
```

## 4. 오류 검수 프롬프트

사용 상황:

- AI가 수정한 HTML이 깨졌는지 확인할 때

```text
아래 HTML 수정 내용을 검수해줘.

검수 기준:
- div 열림/닫힘 개수
- 중복 ID
- 중복 함수명
- window.onclick 덮어쓰기 여부
- keydown 이벤트 충돌 여부
- 모달 ID와 openModal 호출 ID 일치 여부
- 데스크톱/모바일 양쪽 기능 누락 여부
- Clov. 핵심 구조 원칙 위반 여부

출력 형식:
- 치명적 문제
- 수정 필요
- 확인 필요
- 문제 없음
```

사용 상황:

- 팀 작업을 이슈로 나눌 때

```text

작업 화면:
[화면명]

작업 목표:
[목표]

참고 문서:
- [문서 목록]

완료 조건:
- [체크리스트]

출력 형식:
- 제목
- 배경
- 작업 내용
- 완료 조건
- 참고 문서
- 주의사항
```

## 6. 팀 공유 요약 프롬프트

사용 상황:

- Discord에 공유할 때

```text
아래 작업 내용을 Discord 팀 공유용으로 정리해줘.

톤:
- 너무 길지 않게
- 팀원이 바로 다음 행동을 알 수 있게

포함할 항목:
```

## 7. React 이식 준비 프롬프트

사용 상황:

- HTML 프로토타입을 React 컴포넌트로 옮기기 전

```text
아래 화면명세와 HTML 구조를 기준으로 React 컴포넌트 분리안을 작성해줘.

포함할 항목:
- 컴포넌트 트리
- props 후보
- state 후보
- 서버 데이터 후보
- 이벤트 핸들러
- 재사용 가능한 공통 컴포넌트
- 우선 구현 순서

주의:
- 현재는 구현 코드보다 설계안을 원해.
- 기존 HTML의 레이아웃 의도를 최대한 유지해줘.
```

## 팀원 사용법

1. 공통 프롬프트 헤더를 붙인다.
2. 작업 목적에 맞는 레시피를 붙인다.
3. 관련 `.md` 문서 내용을 함께 넣는다.
4. 필요한 경우 HTML 일부만 넣는다.
5. 결과를 그대로 믿지 말고 체크리스트로 검수한다.
