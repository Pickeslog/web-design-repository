# AI로 HTML 디자인 작업하는 방법

## 문서 목적

이 문서는 팀원들이 Gemini 같은 AI 에이전트로 HTML 화면 구성을 개선할 때 따라야 할 실전 절차를 설명한다.

목표는 "AI에게 예쁘게 해달라고 맡기는 방식"이 아니라, 작은 작업 단위로 분석하고, 개선안을 고르고, 수정하고, 검수하고, 기록해서 git에 올리는 방식으로 일하는 것이다.

## 전체 흐름

```text
1. 작업 화면 정하기
2. 참고 문서 고르기
3. AI에게 먼저 분석만 시키기
4. 개선안 2~3개 받기
5. 사람이 방향 선택하기
6. 선택한 범위만 HTML/CSS/JS 수정시키기
7. 체크리스트로 검수하기
8. 작업 기록을 md로 남기기
9. git add / commit / push 하기
10. Discord에 공유하기
```

## 왜 바로 수정시키면 안 되는가

나쁜 요청:

```text
이 HTML 예쁘게 바꿔줘.
```

문제:

- AI가 기존 기능을 지울 수 있다.
- 추억피드, 행운편지, 일정계획을 마음대로 섞을 수 있다.
- 방장/관리자/대표자 같은 금지 개념을 만들 수 있다.
- 모바일이나 다크모드를 놓칠 수 있다.
- 수정 범위가 너무 커져서 사람이 검수하기 어렵다.

좋은 요청:

```text
행운편지 탭의 편지 카드 디자인만 분석해줘.
아직 코드는 수정하지 마.
가독성, 모바일 크기, 다크모드 대비, 버튼 위치만 확인해줘.
```

## 처음 프롬프트 작성 공식

처음 프롬프트에는 아래 7가지를 반드시 넣는다.

### 1. 역할

AI가 어떤 관점으로 답해야 하는지 정한다.

예시:

```text
너는 Clov. 프로젝트의 UI/UX 개선을 돕는 AI 에이전트야.
```

### 2. 서비스 원칙

Clov.의 금지 구조를 막기 위해 매번 넣는다.

```text
중요 원칙:
- 우정공간은 인원 제한 없는 단일 구조다.
- 1:1 전용/1:N 전용 화면으로 나누지 않는다.
- 방장/대표자/초대한 사람 권한 개념은 없다.
- 모든 멤버는 동등하다.
- 핵심 차별점은 약속 완료 후 추억 작성 후보로 전환되는 흐름이다.
- 같은 약속에 대해 친구별로 다른 관점의 기록을 남길 수 있다.
```

### 3. 기준 파일

어떤 파일을 기준으로 볼지 정한다.

```text
기준본은 `Clov - 추억피드.html`이야.
```

### 4. 참고 문서

AI가 읽어야 할 문서를 지정한다.

예시:

```text
참고 문서:
- 00-service-summary.md
- 01-design-system.md
- 03-memory-feed-screen.md
- 06-modal-and-interaction.md
```

### 5. 작업 범위

작업할 화면과 영역을 좁힌다.

예시:

```text
작업 화면: 추억피드
작업 영역: 월 선택 팝오버
```

### 6. 작업 목표

"예쁘게" 대신 구체적인 목표를 쓴다.

좋은 목표:

- 모바일에서 카드 가독성을 높인다.
- 다크모드에서 버튼 대비를 개선한다.
- 빈 상태 안내 문구를 더 명확하게 만든다.
- 월 선택 팝오버의 클릭 흐름을 더 직관적으로 만든다.

나쁜 목표:

- 예쁘게 해줘.
- 고급스럽게 해줘.
- 전체적으로 개선해줘.

### 7. 산출물 형식

AI가 어떤 형태로 답해야 하는지 지정한다.

예시:

```text
아직 코드는 수정하지 말고 아래 형식으로 분석해줘.

1. 현재 문제점
2. 개선 방향
3. 수정해야 할 HTML/CSS 범위
4. 건드리면 안 되는 기능
5. 개선안 3가지
```

## 1단계: 분석만 시키는 프롬프트

아래 템플릿을 복사해서 사용한다.

```text
너는 Clov. 프로젝트의 UI/UX 개선을 돕는 AI 에이전트야.

기준본은 `Clov - 추억피드.html`이야.

중요 원칙:
- 우정공간은 인원 제한 없는 단일 구조다.
- 1:1 전용/1:N 전용 화면으로 나누지 않는다.
- 방장/대표자/초대한 사람 권한 개념은 없다.
- 모든 멤버는 동등하다.
- 핵심 차별점은 약속 완료 후 추억 작성 후보로 전환되는 흐름이다.
- 같은 약속에 대해 친구별로 다른 관점의 기록을 남길 수 있다.

참고 문서:
- 00-service-summary.md
- 01-design-system.md
- [작업 화면 문서]
- 06-modal-and-interaction.md

작업 화면:
[예: 추억피드]

작업 영역:
[예: 추억 카드 / 월 선택 팝오버 / 행운편지 카드 / 일정 카드]

작업 목표:
[예: 모바일에서 카드 가독성을 높이고 다크모드에서도 버튼이 잘 보이게 개선]

아직 HTML/CSS/JS는 수정하지 마.
먼저 아래 형식으로 분석만 해줘.

1. 현재 문제점
2. 사용자 입장에서 불편한 점
3. 디자인 시스템과 어긋나는 점
4. 개선 방향
5. 수정이 필요한 HTML/CSS/JS 범위
6. 건드리면 안 되는 기존 기능
7. 개선안 3가지
```

## 2단계: 개선안 중 하나 선택하기

AI가 개선안 3가지를 주면 팀원이 하나를 고른다.

선택할 때 볼 기준:

- Clov. 감성과 맞는가
- 현재 HTML 구조를 적게 건드리는가
- 모바일과 다크모드를 같이 고려하는가
- 기존 기능을 삭제하지 않는가
- 팀원이 검수할 수 있을 만큼 범위가 작은가

선택 프롬프트:

```text
2번 개선안으로 진행할게.

단, 수정 범위는 아래로 제한해줘.

수정 가능:
- [수정할 HTML 영역]
- [수정할 CSS 클래스]

수정 금지:
- 다른 탭 화면
- 기존 탭 전환 JS
- 월 선택 팝오버 JS
- 일정계획 Clover Growth Path
- 다크모드 토글 JS

먼저 실제 수정 전, 어떤 파일의 어느 영역을 바꿀지 작업 계획만 다시 정리해줘.
```

## 3단계: 수정 요청 프롬프트

작업 계획이 괜찮으면 그때 수정안을 요청한다.

```text
좋아. 위 작업 계획대로 수정안을 작성해줘.

조건:
- 기준본의 기존 기능을 삭제하지 마.
- 새 ID를 만들 경우 중복 가능성을 확인해줘.
- 기존 CSS 변수를 우선 사용해줘.
- 모바일과 다크모드 상태를 같이 고려해줘.
- JS를 수정해야 한다면 어떤 함수만 바꿨는지 명확히 표시해줘.

완료 후 아래 형식으로 보고해줘.

1. 수정한 HTML 영역
2. 수정한 CSS 클래스
3. 수정한 JS 함수
4. 기존 기능과 충돌 가능성
5. 브라우저에서 확인해야 할 클릭 테스트
```

## 4단계: 검수 요청 프롬프트

AI가 수정안을 준 뒤에는 다시 검수를 시킨다.

```text
방금 수정안 기준으로 자체 검수를 해줘.

검수 기준:
- div 열림/닫힘 구조가 깨질 가능성
- 중복 ID
- 중복 함수명
- window.onclick 덮어쓰기 여부
- keydown 이벤트 충돌 여부
- 모달 ID와 openModal 호출 ID 일치 여부
- 데스크톱/모바일 기능 누락 여부
- 다크모드 가독성
- Clov. 핵심 구조 원칙 위반 여부

출력 형식:
1. 문제 없음
2. 수정 필요
3. 확인 필요
4. 사람이 브라우저에서 눌러봐야 할 항목
```

## 5단계: 사람이 체크리스트로 검수하기

AI 검수만 믿지 않는다.

반드시 아래 문서를 보고 직접 확인한다.

```text
14-html-prototype-review-checklist.md
```

특히 HTML 수정이면 반드시 확인:

- 탭 전환
- 모달 열기/닫기
- 월 선택 팝오버
- 다크모드
- 모바일 화면
- 기존 기능 삭제 여부

추천 위치:

```text
web-design-repository/work-logs/
```

2026-06-26-lucky-letter-merge-plan.md

## git에 올리는 가정 절차

작업이 끝나면 아래 순서로 올린다.

### 1. 변경 상태 확인

```bash
git status
```

확인할 것:

- 내가 수정한 파일만 있는지
- 원하지 않는 파일이 섞이지 않았는지
- 임시 파일이 들어가지 않았는지

### 2. 변경 내용 확인

```bash
git diff
```

확인할 것:

- 기준본 기능이 삭제되지 않았는지
- 수정 범위가 작업 목표와 맞는지
- 문서 기록이 같이 들어갔는지

### 3. 파일 추가

예시:

```bash
git add screen-spec-source/15-ai-design-work-guide.md
git add work-logs/2026-06-26-memory-feed-card-improvement.md
```

HTML까지 수정했다면:

```bash
git add "화면구상html/Clov - 통합기준본.html"
```

### 4. 커밋

커밋 메시지 예시:

```bash
git commit -m "docs: add AI design workflow guide"
```

화면 개선 커밋 예시:

```bash
git commit -m "design: improve memory feed card layout"
```

행운편지 병합 커밋 예시:

```bash
git commit -m "design: merge lucky letter modal prototype"
```

### 5. 원격 업로드

```bash
git push origin main
```

주의:

- 팀 규칙상 바로 main에 push하지 않는다면 브랜치를 만든다.

브랜치 예시:

```bash
git checkout -b design/memory-feed-card
git push origin design/memory-feed-card
```

### 6. Discord 공유

공유 템플릿:

```md
## 작업 공유

작업 화면:

작업 내용:

변경 파일:

검수 결과:

확인 필요한 점:

다음 작업:
```

## 팀원에게 한 줄로 설명하기

```text
AI에게 바로 "예쁘게 고쳐줘"라고 하지 말고,
먼저 분석만 시키고, 개선안 3개를 받은 뒤, 우리가 하나를 선택해서 작은 범위만 수정시키고,
체크리스트로 검수한 다음 작업 기록 md를 남기고 git에 올리면 됩니다.
```
