## 1. ★ 스테이지 마크업만 옮기고 "전역 인프라"를 빠뜨린다 (가장 크게 터짐)

프로토타입은 **한 페이지 안에 전역 CSS가 다 들어있다.** 화면 스테이지만 복사하면, 그 화면이 기대던 전역 규칙이 프로덕션엔 없어서 연쇄로 깨진다.

빠뜨리기 쉬운 것:

| 전역 인프라 | 안 옮기면 |
|---|---|
| `modal-overlay` / `modal-box` | 모달이 오버레이 없이 **페이지에 그대로 쏟아진다** |
| `modal-form-group input/textarea` (테두리·radius·폰트) | 입력창만 스타일 없이 맨몸으로 렌더 |
| 버튼 클래스 | 버튼이 브라우저 기본 모양 |
| **기본 팔레트 변수** | 색이 전부 어긋나거나 안 보임 |

**프로덕션에는 전역 모달 시스템이 없다.** 각 화면의 `.proto.css` 안에 스코프해서 넣는 방식으로 해왔다(`letters.proto.css`·`schedule.proto.css`에 실제로 그렇게 들어있다).

**대처**: 옮길 스테이지가 쓰는 클래스를 전부 뽑아서, 프로덕션에 **그 클래스 정의가 있는지** 하나씩 확인한다.

```bash
# 프로덕션에 그 클래스가 정의돼 있나
grep -rn "modal-overlay" clov-web/src/
```

## 2. 프로덕션엔 전역 `box-sizing` 리셋이 없다

프로토타입은 보통 `* { box-sizing: border-box }`를 깔고 시작한다. **프로덕션 `index.css`는 `#root`에만 걸어놨다**(`index.css:77`).

**증상**: `width:100%` + `padding`을 함께 준 요소가 부모를 삐져나가고, `overflow:hidden`에 **오른쪽이 잘린다.**

**대처**: 이식 스코프 안에 리셋을 직접 넣는다.

```css
.proto-<화면> * { box-sizing: border-box; }
```

> 실제 사고: 일정계획 모달 오른쪽이 잘렸다(#67).

## 3. `color-scheme` — 다크 OS에서 native 컨트롤이 검게 뜬다

`index.css:20`에 `color-scheme: light dark`가 있다. 그래서 **사용자 OS가 다크면 `<input type="date">`·`<textarea>` 같은 native 컨트롤이 어둡게 렌더된다.** `background:#fff`만 줘도 완전히 안 고쳐진다(달력 아이콘·스크롤바 등은 여전히 다크).

**대처**: 종이 미감 화면은 팔레트에 `color-scheme: 'light'`를 함께 박는다.

```jsx
// pages/schedule/Schedule/palette.js 실제 예시
export const SCHEDULE_LIGHT_PALETTE = { colorScheme: 'light', /* --card-bg 등 */ }
// Schedule.jsx:216
<main className="proto-schedule" style={SCHEDULE_LIGHT_PALETTE}>
```

## 4. 앱 테마 규칙 — 다크가 기본이다

- **다크 = 클래스 없음(기본)** · **라이트 = `body.light-mode`** (`src/lib/theme.js`)
- **`body.dark-mode`는 이 앱에서 쓰지 않는다.** 프로토타입에서 그대로 옮겨오면 **죽은 코드**가 된다.

**"종이" 화면(편지·여권·폴라로이드·영수증)은 항상 라이트로 고정**하는 것이 지금까지의 결정이다. 다크 대응을 만들지 말고 라이트 팔레트를 못박는다.

> 실제 사고: 행운편지가 **기본(다크) 팔레트를 정의하지 않아** 크림색 종이 위 밝은 글씨가 묻혔다. `body.light-mode`에만 팔레트를 넣었던 게 원인.

## 5. `@scope`를 쓸 때 — 루트 요소 자신에는 안 먹는다

`.proto.css` 스코프 방식이 파일마다 다르다. **둘 다 정상이니 그 화면이 쓰는 방식을 따르면 된다.**

| 방식 | 파일 |
|---|---|
| 클래스 접두(`.proto-X ...`) | `feed` · `dashboard` · `roomlist` · `notifications` |
| `@scope (.proto-X) { }` | `letters` · `schedule` |

`@scope`를 쓸 때 주의:

- **`@scope (.proto-X){}` 안의 규칙은 하위 요소엔 먹지만 루트(`.proto-X`) 자신에게는 안 먹는다.** 팔레트 변수를 루트에 정의해도 무시된다.
  → **팔레트는 JSX `<main style={...}>` 인라인으로 주는 게 확실하다**(캐스케이드·HMR과 무관하게 항상 이김).
- **★ 스코프 안 셀렉터에 `.proto-X`를 쓰면 그 규칙은 통째로 죽은 코드가 된다.** 스코프 안 셀렉터는 암묵적으로 `:scope `가 앞에 붙는 **상대 셀렉터**라, `@scope (.proto-letters) { .proto-letters .foo { } }`는 "`.proto-letters` 안의 `.proto-letters` 안의 `.foo`"를 찾는다. 루트는 하나뿐이니 아무것도 매칭되지 않는다. Chromium 실측(2026-08-06): `.r{}` · `.r .t{}` · `body.light-mode .r{}` 전부 **미적용**, `.t{}` · `:scope{}` 만 적용.
  → 특히 위험한 건 **"반드시 먹어야 하는 규칙이라 `@scope` 밖에 뒀다"고 주석까지 달아둔 코드가 실제로는 블록 안에 있는 경우**다. `letters.proto.css`에 이런 죽은 규칙이 17개 있었다(모바일 크기 축소 블록, `.letter-read-btn` 전체 스타일, 루트 패딩·`min-height` 등 — `clov-web` #345/#353에서 발견). **"특이도가 높으니 이 규칙이 이긴다"는 추론이 스코프 안에서는 정반대**가 되니 주의.
  → `@scope` 블록이 어디서 닫히는지는 `grep '^}'`로 찾으면 **중첩된 `@media`의 닫는 `}`에 속는다.** 주석을 걷어낸 뒤 중괄호 깊이를 세서 확인할 것.
- **`@scope` CSS는 Vite HMR 반영이 애매하다.** 안 바뀌는 것 같으면 하드 리로드(Ctrl+Shift+R).

## 6. CSS 주석에 `*/`를 넣으면 빌드가 깨진다

```css
/* mp-*/space.css 참고 */   ← ❌ "*/"에서 주석이 조기 종료된다
```

lightningcss가 **"dangling combinator"** 로 빌드 실패한다. 주석에 경로·셀렉터를 적을 때 `*/`가 들어가지 않게 쓴다(`mp-* / space.css`처럼 띄우거나 `mp-` 로만).

## 7. 공용 컴포넌트의 호버 색이 이긴다 (특이성 동률)

`Button.css` 같은 공용 CSS는 **나중에 주입된다.** 특이성이 같으면 공용 쪽이 이긴다.

```
.clov-btn--action:not(:disabled):hover { color: #b6e08a }   ← (0,3,0), 나중 주입
.proto-feed .clov-btn.feed-write-btn { color: #2e5233 }     ← (0,3,0), 먼저 주입 → 진다
```

**증상**: 평소엔 맞는데 **마우스를 올리면** 다크용 연초록이 크림 버튼 위에 얹힌다.

**대처**: 이식 스코프의 **호버 규칙에서 색을 다시 못박는다**(`!important` 말고 특이성으로).

```css
.proto-feed .clov-btn.feed-write-btn:hover { color: #2e5233; }  /* (0,4,0) → 이김 */
```

## 8. 전역 `h1, h2` 리셋이 제목을 덮어쓴다

`index.css`에 `h1, h2 { font-family: var(--heading); color: var(--text-h) }`가 있다. 프로토타입 제목이 다른 폰트·색이면 **그대로 옮겨도 전역 리셋에 먹힌다.**

**대처**: 해당 제목에 `font-family`·`color`를 명시하거나, 원본처럼 `div`로 두면 무영향이다.

---

## 9. 모달 `max-height` 하드캡을 확인한다

프로토타입 원본 값을 안 보고 관례값(`min(86vh, 720px)` 같은)을 쓰면 **콘텐츠가 잘려 스크롤이 생긴다.**

> 실제 사고: 여권 상세가 720px 하드캡에 잘렸다. 원본은 `94vh`였다(#62).

## 10. native `<input type="date">`는 클릭해도 피커가 안 열린다

투명하게 덮은 date 오버레이는 **텍스트를 클릭해도 피커가 안 뜬다**(달력 아이콘만 열리는데 그마저 `opacity:0`이면 안 보인다).

**대처**: 클릭 시 `showPicker()`를 직접 호출한다.

## 11. 공통 `<Header>`를 빠뜨린다

방 내부 화면은 전부 공통 헤더를 쓴다. 이식하다 보면 이것만 빠진다.

```jsx
<Header variant="room" roomId={roomId} activeTab="letter" />
```

`activeTab`이 그 화면 것으로 맞는지도 확인한다.

---

## 12. 이모지는 정본 대조 대상이 아니다

**UI 아이콘은 tabler 웹폰트를 쓰고 이모지는 쓰지 않는다**(2026-07-26 확정). 프로토타입 `02-main`에 이모지가 남아 있어도 **그대로 옮기지 않는다.**

```jsx
<i className="ti ti-camera-plus" aria-hidden="true" />
```

- 새 SVG를 손으로 그리지 않는다. tabler에 있는 이름을 쓴다.
- **쓰기 전에 그 아이콘 이름이 실존하는지 확인할 것**(`ti-handshake`는 없다 → `ti-user-plus`로 대체한 적 있음).
- 단, **사용자가 입력하는 콘텐츠**(방 이름 등)의 이모지는 막지 않는다. 이건 UI 크롬과 기준이 다르다.

## 13. 다 만든 뒤 — 검증

```bash
npm run lint && npm run build
```

- **로그인 게이트 뒤 화면**(방 내부 전부)은 로그인해서 직접 눈으로 본다. 프로토타입을 옆 탭에 띄우고 **나란히 대조**하는 게 가장 빠르다.
- 라이트/다크 **양쪽** 확인. 다크가 기본이라는 걸 잊기 쉽다.
- 창을 좁혀 **모바일 폭**도 한 번 본다.
- 브라우저 콘솔 에러 0건.

### 테마 토글 직후 색을 측정하면 안 된다

`getComputedStyle`을 테마 전환 직후에 부르면 **CSS `transition` 중간값**이 나온다. 측정으로 확인할 거면 `* { transition: none !important }`를 잠깐 주입하고 reflow 후 재측정한다.

## 14. 코드 위치를 인용하기 전에 import 체인을 따라간다

**같은 이름의 파일이 두 군데 있을 수 있다.** 이슈·리뷰에 경로를 적을 때 실제로 앱이 쓰는 파일인지 확인한다.

> 실제 사고: `ProtectedRoute.jsx`가 `src/components/`와 `src/routes/` 양쪽에 있었고 **라우터가 쓰는 건 `routes/` 쪽**이었다. 리뷰 코멘트에 잘못된 경로를 적었고, 그게 이슈로 옮겨가고, 작업자도 엉뚱한 파일을 고쳤다. 브라우저에서 "동작을 안 하는데?"를 보고서야 발견했다.

```bash
grep -rn "from './routes/ProtectedRoute'" clov-web/src/router.jsx
```
