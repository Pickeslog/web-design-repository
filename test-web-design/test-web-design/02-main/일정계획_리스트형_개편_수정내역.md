# 일정계획 상세 카드 — 리스트형 개편 수정내역 (0703)

## 변경 목적
기존 "제안하기 / 일정 맞추기 / 약속 확정 / 만남" **4단계 계획 느낌**과 단계별
아코디언(문구 클릭 시 세부 일정 펼침)을 걷어내고, **자유롭게 추가 가능한 일정
리스트**로 바꿨다. 항목이 많아지면 로드맵처럼 **모아보기**로 압축해서 본다.

## 수정 파일

## 1. 동작 요약 (일정 상세 카드 = `.growth-detail` 내부)

- **일정 리스트**: 각 항목은 `번호 노드 + 편집 가능한 한 줄 텍스트 + 삭제(×)`.
  이전의 "라벨: 상세" 2단 구조와 클릭-아코디언은 삭제.
- **＋ 일정 추가** 버튼: 누르면 항목이 리스트 맨 아래에 하나씩 추가됨
  ("새 일정을 입력하세요" 기본값 → 클릭해서 바로 편집).
- **번호 노드 포커스**: 번호 버튼을 누르면 그 일정만 강조되고 **나머지는 잠시
  들어감(흐려지고 축소)**. 같은 번호를 다시 누르면 해제.
- **모아보기(로드맵)**: 항목이 **5개 이상**이면 헤더에 `모아보기` 버튼 노출.
  누르면 번호 노드가 가로 로드맵으로 압축됨. 로드맵의 노드를 누르면 다시
  목록으로 돌아오며 해당 일정에 포커스. 헤더의 `목록으로`로도 복귀.
- 데스크톱 ↔ 모바일 뷰 **양방향 실시간 동기화** 유지.

## 2. 데이터 저장 방식 (하위 호환)

- 일정 메모(`schedule.content`)에 `<li>` 항목이 있으면 **리스트 카드**로,
  없으면(자유 텍스트) **기존 메모장(`.spotlight-note`)** 으로 렌더 → 기존
  데이터 안 깨짐.
- 기존 `<li><strong>라벨:</strong> 상세</li>`는 태그를 벗겨 `라벨: 상세` **한 줄
  항목**으로 자동 변환되어 표시됨.
- 항목 추가/삭제/수정은 `<h3>제목</h3><ul><li>…</li></ul>` 형태로 다시 직렬화해
  `content`에 저장.

### desktop.js 주요 함수
- `parseScheduleItems / serializeScheduleItems` — content ↔ 항목 배열 변환
- `buildScheduleStepsInner` — 리스트/로드맵 내부 HTML 생성 (단일 소스)
- `renderScheduleNoteHtml` — 리스트 카드 or 자유 메모장 분기
- `refreshScheduleSteps` — dt/mb 두 컨테이너를 동시에 다시 그림(동기화)
- `focusScheduleItem` / `toggleScheduleRoadmap` — 포커스·모아보기 토글
- `addScheduleItem` / `deleteScheduleItem` / `saveScheduleItemText` — 항목 CRUD
- 상태: `scheduleUiState[id] = { focus, roadmap }`
