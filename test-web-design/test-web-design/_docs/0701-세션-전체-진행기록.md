## 작업 1 — 전체화면 레이아웃 + 스크롤바 제거

### 문제
- `body`에 padding이 있어 좌우에 여백이 생김
- `.desktop-window`가 850px로 제한돼 헤더가 가득 차지 않음
- `.main-content` 스크롤바가 항상 표시됨

### 해결
`02-main/index.html` `<head>`에 인라인 CSS 오버라이드 추가.

```css
body { padding: 0 !important; overflow: hidden !important; height: 100vh; }
.split-workspace { max-width: 100% !important; height: 100vh; gap: 0 !important; }
.view-section { flex: 1; height: 100vh; gap: 0 !important; }
.desktop-window { width: 100% !important; height: 100vh !important; border-radius: 0 !important; border: none !important; box-shadow: none !important; }
.window-content { height: 100vh !important; }
.main-content { scrollbar-width: none; -ms-overflow-style: none; }
.main-content::-webkit-scrollbar { display: none; }
```

공유 CSS인 `desktop.css`는 수정하지 않고 페이지 단위로 오버라이드.

## 작업 2 & 3 — 공유 헤더 컴포넌트 (`clov-header.js`)

### 목적
index.html, schedule.html, makerooms.html 세 파일이 각자 헤더를 가지고 있어 중복이 심함. 하나의 JS 컴포넌트로 통합.

### 생성 파일
`02-main/components/clov-header.js`

### 공개 API

```js
window.ClovHeader = {
  init(cfg),       // cfg.type: 'main' | 'sub' | 'home'
  toggleDark(),    // 독립 다크 모드 토글
  applyDark(bool), // 외부에서 동기화 호출
  _toggleDrop(btn) // 드롭다운 내부 토글
};
```

### 렌더 타입별 동작

| type | 사용 페이지 | 특징 |
|------|------------|------|
| `main` | index.html | 탭 4개, 알림, 다크토글, 프로필 드롭다운 |
| `sub` | schedule.html | 뒤로가기 버튼, 제목, 아바타 |
| `home` | makerooms.html | 로고, 메일/벨 버튼, 다크토글, 아바타 |

### 다크 모드 호환성
기존 localStorage 키 3개(`clov_theme`, `clov_darkMode`, `clov_dark`)를 모두 읽어 하위 호환 유지.

### 적용 파일 변경 내용

**`02-main/index.html`**
```html
<!-- 기존 <header>...</header> 블록 → -->
<div id="app-header"></div>
<script>ClovHeader.init({ type: 'main', activeTab: 'space' });</script>
```

**`06-schedule/schedule.html`**
```html
<div id="app-header"></div>
<script>ClovHeader.init({ type: 'sub', backHref: '#', backOnclick: 'goBack()', backLabel: '우정공간', title: '📅 일정계획', avatarLabel: '🍀' });</script>
```

**`03-rooms/makerooms.html`**
```html
<div id="app-header"></div>
<script>ClovHeader.init({ type: 'home', avatarLabel: '김', showMail: true, showBell: true });</script>
```

### 버그 수정

- `switchDesktopTab()` 호환: nav 버튼에 `dt-nav-item` 클래스 추가
- `openModal()` null 참조: `mb-drop` / `dt-drop` 요소 없을 때 null 체크 추가
- makerooms.html의 `body.dark` → `body.dark-mode` 마이그레이션 (5개 셀렉터)

## 작업 4 — `profile_edit.html` 카드 통합

### 문제
5개 섹션(아바타, 기본정보, 연락처, 비밀번호변경, 계정관리)이 각각 `.card`로 분리돼 있어 너무 쪼개진 느낌.

### 해결
아바타 + 기본정보 + 연락처 + 비밀번호변경 + 저장 버튼을 하나의 `.card`로 통합. 섹션 구분은 `.divider` + `.card-title`로 처리.

**계정 탈퇴(위험 구역) 카드는 분리 유지.**

```html
<div class="card">
  <!-- 아바타 -->
  <div class="avatar-section">...</div>
  <div class="divider"></div>
  <!-- 기본 정보 -->
  <div class="card-title section-gap">👤 기본 정보</div>
  ...
  <div class="divider"></div>
  <!-- 연락처 -->
  <div class="card-title section-gap">📬 연락처</div>
  ...
  <div class="divider"></div>
  <!-- 비밀번호 변경 -->
  <div class="card-title section-gap">🔒 비밀번호 변경</div>
  ...
  <button class="btn-save">✅ 변경사항 저장</button>
</div>
<!-- 위험 구역 별도 카드 -->
<div class="card" style="margin-top: 16px;">...</div>
```

## 작업 5 — 일정계획 새 D-day 모달 인라인화

### 문제
일정계획 탭의 "➕ 새 D-day 만들기" 버튼이 `schedule.html`로 페이지 이동하도록 구현돼 있었음.

### 해결
`desktop.js`의 `openScheduleModal()` 함수를 수정해 이미 `index.html`에 있는 `dt-schedule-modal`을 열도록 변경.

```js
function openScheduleModal(viewType, scheduleId) {
    // 기존: window.location.href = 'schedule.html?...'
    // 변경: 모달 폼 초기화 후 openModal() 호출
    openModal(`${prefix}-schedule-modal`);
}
```

## 작업 6 — 일정 생성 모달에 본문(body) 필드 추가

### 문제
기존 모달은 제목 + 날짜만 입력 가능했음. 사용자가 약속 계획, 준비물 등을 미리 작성할 수 없었음.

### 변경 파일
- `02-main/index.html` — `dt-schedule-modal`에 textarea 추가
- `02-main/js/desktop.js` — `openScheduleModal()`, `saveSchedule()` 수정

### 추가된 textarea

```html
<div class="modal-form-group">
    <label>본문 <span style="color:var(--text-muted);font-weight:400;">(선택)</span></label>
    <textarea id="dt-input-schedule-body"
        placeholder="약속에 대한 계획, 준비물, 메모 등을 자유롭게 적어보세요."
        style="height:120px;"></textarea>
</div>
```

### 저장/로드 로직

- **저장**: `textarea.value.replace(/\n/g, '<br>')` → `sch.content`
- **로드(수정 시)**: `sch.content.replace(/<br>/gi, '\n').replace(/<[^>]+>/g, '').trim()` → textarea
- 수정 모드에서 본문이 비어있으면 기존 `sch.content` 유지

## 작업 7 & 8 — 성장 카드 → 4컷 사진 스트립 + 인증 로직

### 기획 배경
10~20대에서 인기 있는 인생네컷(4컷 사진 부스)의 세로 필름 스트립 형태로 약속 성장 과정을 시각화.

### 새 카드 구조

```
┌──────────────────────┐
│ 제목         D-8 pill │  ← strip-header
├───┬──────────────┬───┤
│ ░ │  frame 1    │ ░ │  ← 약속 씨앗
│ ░ ├─────────────┤ ░ │
│ ░ │  frame 2    │ ░ │  ← D-day 새싹
│ ░ ├─────────────┤ ░ │
│ ░ │  frame 3    │ ░ │  ← 만남 클로버
│ ░ ├─────────────┤ ░ │
│ ░ │  frame 4    │ ░ │  ← 추억 꽃 (인증 프레임)
└───┴─────────────┴───┘
│  약속을 향해 가는 중  │  ← strip-footer
└──────────────────────┘
```

좌우 `strip-perf` = 필름 천공(8개 span), 카드 폭 148px 고정.

### 프레임 상태 (CSS 클래스)

| 클래스 | 조건 | 표시 |
|--------|------|------|
| `strip-frame--past` | 단계 날짜 경과 (프레임 1~3) | ✓ 녹색 아이콘 |
| `strip-frame--growing` | 현재 진행 중 단계 | 이모지 + pulse 애니메이션 |
| `strip-frame--locked` | 날짜 미도래 | 이모지 32% dim |
| `strip-frame--open` | 약속 당일 이후 (프레임 4만) | 📷 인증하기 버튼 |
| `strip-frame--done` | 사진 업로드 완료 (프레임 4) | 사진으로 프레임 채움 |

### 인증 로직

프레임 1~3 (약속 씨앗, D-day 새싹, 만남 클로버):
- 날짜가 지나면 → `strip-frame--past` (✓ 표시, 업로드 없음)
- 현재 단계 → `strip-frame--growing` (pulse 강조)
- 미래 → `strip-frame--locked`

프레임 4 (추억 꽃):
- `sch.date <= today` 조건이 충족될 때만 📷 업로드 버튼 표시
- 당일이 지난 후에도 업로드 가능 → 완료

### 업로드 함수

```js
function uploadStagePhoto(viewType, scheduleId, stageKey, inputEl) {
    const file = inputEl.files[0];
    if (!file) return;
    const reader = new FileReader();
    reader.onload = function(e) {
        const sch = groupsData[activeGroup].schedules.find(s => s.id == scheduleId);
        if (!sch) return;
        if (!sch.stagePhotos) sch.stagePhotos = {};
        sch.stagePhotos[stageKey] = e.target.result; // base64
        renderScheduleList('dt');
        renderScheduleList('mb');
    };
    reader.readAsDataURL(file);
}
```

### Footer 상태 문구

| 상태 | 문구 |
|------|------|
| 인증 전, 당일 미도래 | 약속을 향해 가는 중 |
| 당일 이후, 미인증 | 📷 인증하면 완성이에요 |
| 인증 완료 | 🌸 추억이 완성됐어요 |
