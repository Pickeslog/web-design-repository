## 3. 헤더 프로필 드롭다운 재오픈 버그

**증상**: 드롭다운을 한 번 열고 특정 경로로 닫으면, 그 뒤로는 `classList`가 `open`으로 정상 토글되는데도 화면에 다시 안 나타남 (`class`는 `open`인데 실제 `display: none`).

**원인**: `desktop.js`의 `openProfileModal()`이 드롭다운을 닫으려고 `[id$="-drop"]` 셀렉터를 썼는데, 의도한 레거시 `mb-drop`/`dt-drop` 외에 `clov-hdr-drop`("-drop"으로 끝남)까지 잡아서 `el.style.display = 'none'`으로 **인라인 스타일**을 남겼음. 인라인 스타일이 `.clov-hdr-dropdown.open { display: block }` 규칙보다 항상 우선하기 때문에, 이후 아무리 `open` 클래스를 토글해도 다시 열리지 않았음.

**수정**: 인라인 스타일 대신 클래스 기반으로 통일.
```js
function openProfileModal() {
    document.querySelectorAll('.clov-hdr-dropdown.open').forEach(el => el.classList.remove('open'));
    ...
}
```

## 4. 사용자설정 모달 신설 (반복 리디자인)

기존 "개인정보 수정" 드롭다운 항목을 "⚙️ 사용자설정"으로 바꾸고, 그 안에 개인정보 수정 + 라이트모드/다크모드 전환을 통합. 세 번의 구조 개편을 거쳐 최종 형태로 정착:

1. **1차**: 별도의 "사용자설정" 목록 모달 → 클릭 시 "개인정보 수정" 모달 또는 "테마" 모달을 별도로 오픈 (모달 위에 모달이 뜨는 방식)
2. **2차**: 목록 모달이 "따로 뜨는 게 별로"라는 피드백에 따라, 프로필 카드 안에 나열형 내비게이션을 넣는 방식으로 통합 (Discord 계정 설정 화면 참고)
3. **3차(최종)**: 프로필 카드 안이 너무 꽉 차 보인다는 피드백 → **미니 아바타 헤더 + 좌측 내비게이션 레일(`.settings-rail`) + 우측 콘텐츠(`.profile-form-panel`)** 구조로 분리. Slack/Notion 설정 모달과 동일한 패턴이며, 향후 설정 항목이 늘어나도(`계정`/`화면` 같은 카테고리 라벨 아래 항목만 추가하면 됨) 확장 가능하도록 설계

**최종 구조** (`#dt-profile-modal`):
- 좌측 레일: 30px 미니 아바타 + 이름, 그 아래 `계정`(개인정보 수정) / `화면`(라이트모드·다크모드) 카테고리 내비게이션. 레일과 콘텐츠 영역이 각각 독립적으로 스크롤됨(`height: 100%; overflow-y: auto`)
- 우측 콘텐츠: `switchSettingsPane('account' | 'theme')`로 전환되는 두 개의 pane
- 하단 액션바(`#dt-profile-modal-actions`)는 **패널 전환과 무관하게 항상 같은 자리에 유지** — 내용만 계정 탭(계정 탈퇴/취소/저장하기)과 테마 탭(닫기)으로 바뀜. 처음엔 탭 전환 시 액션바 자체를 숨겼다가, "테마 탭에서 빈 공간이 뜬다"는 피드백으로 공유 방식으로 변경
- 헤더의 별도 ☀️/🌙 다크모드 토글 버튼은 제거하고 사용자설정 안으로 완전히 흡수 (`renderMain()`에서 `darkBtn(true)` 호출 삭제)
- `setThemeMode(mode)`는 index.html에서는 기존 `toggleDarkMode()`(아이콘 슬라이드 애니메이션 등 페이지 고유 로직 포함)를 그대로 재사용, `toggleDarkMode`가 없는 페이지(예: makerooms.html)에서는 `ClovHeader.applyDark()`로 폴백

## 5. 다크모드 팔레트 교체 — 미드나잇 올리브

기존 다크모드가 순검정에 가까운 네온 그린(`#090d0a` / `#00bd45`)이라 아이보리 라이트모드(`#fffdf3`)와 어울리지 않는다는 문제 제기. 5가지 팔레트 후보(웜 차콜/딥 코코아/미드나잇 올리브/딥 포레스트/딥 네이비)를 스와치로 비교한 뒤 **미드나잇 올리브**로 결정.

| 변수 | 기존 | 미드나잇 올리브 |
|---|---|---|
| body 배경 | `#090d0a` | `#14150e` |
| 카드 배경 | `#151f18` | `#1e2016` |
| 포인트색(accent) | `#00bd45` | `#9ccc65` |
| 주요색(primary) | `#007c2e` | `#5a7a3e` |
| 본문 텍스트 | `#f0fdf4` | `#eef0e2` |
| 버튼 배경 | `#1da858` | `#7c9c52` |

**적용 범위**: `02-main/css/desktop.css`의 `body.dark-mode` 전체, `03-rooms/makerooms.html` · `join_room.html` · `invite.html`의 각자 `body.dark-mode` 블록(변수명 체계가 파일마다 달라 각각 매핑해서 반영: `--primary-green` ↔ `--primary`, `--text-color` ↔ `--text` 등)

**남은 화면**: `04-feed`, `05-letter`, `06-schedule`, `07-notification`, `08-profile`은 아직 예전 네온 그린 그대로 — 필요 시 이어서 통일 작업 진행.

## 6. `clov-header.js` 다크모드 하드코딩 폴백 버그

**증상**: `02-main`은 올리브로 바뀌었는데 `03-rooms`(makerooms.html)는 몸통 배경은 올리브인데 헤더만 여전히 예전 색.

**원인**: `clov-header.js`의 다크모드 CSS 규칙들이 페이지가 정의한 변수를 안 거치고 하드코딩된 옛 색으로 바로 떨어지는 폴백 체인 누락 버그였음.
```css
/* 수정 전 — --header-bg를 거치지 않고 바로 하드코딩값으로 떨어짐 */
body.dark-mode .clov-hdr { background: var(--header-glass-bg, rgba(9,13,10,.82)); }
/* 수정 후 */
body.dark-mode .clov-hdr { background: var(--header-glass-bg, var(--header-bg, rgba(20,21,14,.82))); }
```
로고/아바타 색상(`.clov-hdr-logo`, `.clov-hdr-avatar`)도 동일한 패턴의 버그(`var(--primary-green, #4ade80)`처럼 `--primary` 폴백 누락)가 있어 함께 수정. 하드코딩 기본값 전부(`#4ade80`→`#9ccc65`, `#1e3a27`→`#2b3020`, `#f0fdf4`→`#eef0e2`, `#151f18`→`#1e2016`, `#1e2f24`→`#2a2c1e`, `#22c55e33`→`#6b8f4733`)를 올리브 계열로 교체.

`makerooms.html`이 `clov-header.js`를 버전 쿼리 없이 로드하고 있어 브라우저 캐시로 혼선이 있었던 것도 발견 — `?v=9` 캐시 버스팅 추가.

## 7. `makerooms.html`에 사용자설정 모달 이식

"rooms에서도 프로필 누르면 사용자설정이 나왔으면" 요청에 따라, `index.html`과 동일한 구조(미니 아바타 레일 + 계정/화면 탭)를 `makerooms.html`에도 추가.

- 공용 컴포넌트로 뽑아내지 않고 **독립적으로 복제 구현** — makerooms의 기존 CSS 변수 체계(`--primary`/`--accent`/`--text`/`--muted`/`--border`/`--active-bg`)에 맞춰 새로 작성. 폼 필드는 이 페이지에 이미 있던 `.field-wrap`/`.text-input`/`.err-msg` 클래스 재사용
- 다크모드 전환은 `ClovHeader.applyDark()` 직접 호출 (이 페이지가 원래 쓰던 다크모드 토글과 동일 메커니즘)
- `ClovHeader.init()`의 `dropdownItems`에 "⚙️ 사용자설정" 항목 추가
- **참고**: index.html 쪽 구현은 건드리지 않음. 두 파일에 로직이 중복되므로 추후 사용자설정 내용을 또 고치면 양쪽 다 반영 필요 — 기능이 안정화되면 `clov-header.js`처럼 공용 컴포넌트로 분리하는 것도 고려할 만함

## 8. 우정공간 미리보기 모달에 편지함/알림 탭 추가

"rooms와 main의 알림/편지함을 같게 공유하자"는 요청 → rooms 목록 화면(전체 방 요약)과 main(특정 방 상세)의 데이터 성격이 다르다는 점을 확인한 뒤, 방 카드 클릭 시 뜨는 **미리보기 모달**(`#room-preview-modal`, 방에 실제로 들어가기 전 단계)에 "정보/편지함/알림" 탭을 추가해 그 방의 실제 편지·알림을 미리 볼 수 있게 함. 헤더의 전체 방 요약 아이콘(편지함/알림)은 그대로 유지 — 서로 다른 용도(전체 훑어보기 vs 특정 방 상세)라 판단.

- `rooms` 배열의 10개 방 각각에 `letters`/`notices` 목업 데이터 추가 (방 테마에 맞는 내용)
- 탭 전환 시 안읽음 항목이 있으면 탭 옆에 빨간 점(`.preview-tab-dot.show`) 표시
- 편지/알림이 없는 방은 빈 상태 문구 표시
- "OO가 보낸 편지" 형태의 조사(이/가) 오류 발견 후 "OO님이 보낸 편지"로 수정 (이름 받침 유무와 무관하게 항상 자연스러운 문장이 되도록)

## 검증 방법

이번 세션의 모든 변경사항은 `preview_start`로 로컬 정적 서버를 띄운 뒤, `preview_eval`로 DOM 상태(클래스, computed style, localStorage)를 직접 확인하는 방식으로 검증함. 스크린샷 도구가 세션 중간부터 타임아웃이 잦아 시각적 캡처 대신 구조적 검증(요소 위치, 색상값, 표시 여부)에 의존한 구간이 있음 — 실제 브라우저 육안 확인은 팀에서 한 번 더 거치는 것을 권장.
