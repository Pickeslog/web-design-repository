# 0710 — 약속 영수증 · 작성 모달 · 다크모드 문제 해결 작업기록

> 대상: 본선 `test-web-design/02-main/`
> 검증: 정적 서버(8890) + DOM/computed-style 비교. (02-main은 헤드리스 스크린샷이 타임아웃되는 함정이 있어 스크린샷 대신 라이트/다크 computed 값 diff로 검증)

일정계획의 "약속(D-day)" 작성/표시 UI를 영수증 스타일로 다듬고, 다크모드 가시성·일관성 문제를 순서대로 잡은 기록. 각 건을 **문제 – 원인 – 솔루션**으로 정리한다.

---

## 1. 추억피드 사진 모아보기 갤러리 배경

- **문제**: 갤러리 오버레이 배경에 투명도가 들어가 뒤 화면이 비쳐 눈이 아픔.
- **원인**: `.sg-overlay` 배경이 `rgba(10,22,16,0.92)` 반투명 + `backdrop-filter: blur(8px)`.
- **솔루션**: 불투명 단색 `#0a1610`로 교체, 불필요해진 blur 제거. (`space.css`)

---

## 2. 글쓰기/수정에 "약속 여정 영수증" UI 도입

- **문제(요청)**: 밋밋한 입력 폼 대신, 우리가 만든 약속 여정 영수증 UI를 글쓰기/수정에 넣자.
- **1차 — 라이브 프리뷰(A안)**: 폼은 유지하고 위에 영수증 프리뷰를 붙여 입력 즉시 D-day 도장·DATE·바코드가 실시간 반영. `updateSchedulePreview()` 신설(`schedule.js`), 제목·날짜·본문 `oninput` 연결.
- **2차 — 영수증 위에서 바로 작성(B안, 최종)**: 프리뷰 방식 대신 **영수증 자체를 입력 화면**으로 전환.
  - 핵심 설계: 실제 입력 id(`dt-input-schedule-title/date/body`)를 영수증 요소로 이동 → 저장 로직(`saveSchedule`) 무수정 동작.
  - 제목=영수증 타이틀 인풋, 날짜=DATE 셀 위 투명 date 피커 오버레이(클릭 시 달력), 본문=영수증 MEMO 편집(툴바 유지).
  - `updateSchedulePreview`는 날짜 파생값(친절 날짜·D-day·도장 문구/색)만 갱신하도록 정리.

---

## 3. 모달을 영수증 종이 한 장으로 (액자·흰 영역 제거)

- **문제**: 영수증이 초록 "액자(매트+테이프)"로 감싸져 나뉘어 보이고, 바깥에 흰 모달 영역이 남음.
- **원인**: `.growth-detail`의 초록 데스크 배경+테이프(`::before/::after`), `.modal-box`의 흰 배경(`--card-bg`)+패딩.
- **솔루션**(`.schedule-editor` 스코프): 액자 배경/그림자/라운드 제거, 테이프 숨김, 종이 폭 100%. 모달 배경을 종이색 `#faf6ee`로, 패딩 0, `overflow:hidden`, 텍스트 다크 고정. → 제목·영수증·버튼이 하나의 크림 표면.

---

## 4. 다크모드 텍스트 가시성 (작성 모달)

- **문제**: 크림 종이 위에서 일부 텍스트/아이콘이 흐림.
- **원인**: 모달은 라이트/다크 공통 크림인데, 테마 변수를 쓰는 요소가 다크에서 밝은색이 됨. 특히 툴바 아이콘 `.rich-btn`(=`var(--primary-green)` → 다크에서 옅은 올리브).
- **솔루션**: 툴바 아이콘 `#2e5233` 고정, 구분선·MEMO/DATE 라벨·placeholder 대비 상향. 본문 텍스트는 종이 기본색 `#1c1a17`로 이미 진함. (대비 8~16:1 확보)

---

## 5. 버튼 톤 일관성 (전역)

- **문제**: "초록 액션 버튼"이 제각각(`--primary-green` #1b4332 / `#357a58` / `#2e5233`)이라 톤이 갈리고 다크 적응도 제각각.
- **원인**: 주버튼 토큰(`--btn-primary-bg`/`--button-text`)을 쓰는 버튼이 소수뿐.
- **솔루션**: 일반 화면 솔리드 초록 CTA를 주버튼 토큰으로 통일 — `.letter-write-btn`, `.room-copy-row button`, 선택 pill `.growth-density/.journey-density/.feed-sort`의 `.active`. (라이트 `#357a58`/흰색, 다크 `#7c9c52`/`#12150a`로 `.btn-main`과 일치)
- **의도적 제외**: 극장 포스터/오버레이(항상 어두운 시네마 서피스), 위험 빨강(`.btn-danger` #b23b3b, `.receipt-actions .danger` #c0392b), 크림 종이 버튼 3형제(`.btn-memory-write`·`.btn-schedule-new`·`.feed-write-btn` — 다크 미적응이 **의도된 디자인**).

---

## 6. 월별 추억 아카이브 헤더 다크 가시성

- **문제**: `.feed-hero` 헤더의 제목/부제목이 다크모드에서 안 보임.
- **원인**: 피드 콘텐츠 영역 배경은 다크에서도 **밝은 양피지색(`rgb(244,234,216)`)** 인데, `base.css`가 다크에서 제목/부제목을 **흰색**으로 덮어써서 밝은 배경에 흰 글자.
- **솔루션**: `.feed-hero`를 프로스티드 판(흰 0.72/0.54)으로 강화 + 제목 text-shadow, 다크모드 제목/부제목 색을 **어둡게(`#22322a`)** 정정. (대비 ~12.6:1)

---

## 7. 작성 모달 다크모드에서 버튼이 튐

- **문제**: 크림 모달인데 취소/저장 버튼만 다크 토큰을 따라가 어두운 올리브로 튐.
- **원인**: 모달 표면은 고정 크림인데 `.btn-main/.btn-sub`는 테마 토큰을 사용.
- **솔루션**: `#dt-schedule-modal` 스코프로 버튼 색 라이트 고정 — 저장 `#357a58`/흰색, 취소 `#e7f0ea`/`#2e5233`.

---

## 8. "＋단계 넣기" 버튼 글자 저대비

- **문제**: 초록 배경에 진초록 글자(라이트/다크 공통).
- **원인**: 다크 가시성용 `.schedule-editor .rich-btn { color:#2e5233 }`가, `rich-btn`+`rich-btn-steps` 두 클래스를 가진 이 버튼의 흰 글자(`#fff`)까지 덮어씀.
- **솔루션**: `.schedule-editor .rich-btn-steps { background:#357a58; color:#fff }` 명시로 우선 적용.

---

## 9. 작성 모달, 다크에서 제목/종이/버튼 구획이 나뉘어 보임

- **문제**: 다크에서만 세 구획 경계가 보임.
- **원인**: `base.css`의 `body.dark-mode .growth-detail`(어두운 데스크 `#20261d`)이 내 `.schedule-editor .growth-detail`(배경 제거)보다 **specificity가 높아**(type 선택자 `body`) 이겨서, 어두운 배경이 종이 뒤/가장자리로 배어나옴.
- **솔루션**: `body.dark-mode .schedule-editor .growth-detail { background:none }`로 더 높은 specificity 오버라이드.

---

## 10. 약속 여정 영수증(표시용)이 다크에서 라이트와 다름

- **문제**: 실제 약속 여정 영수증이 다크에서 액자가 어두운 올리브, 삭제 버튼이 살몬색 등으로 라이트와 달라짐. (라이트처럼 보이게 원함)
- **원인**: `base.css`의 **다크 전용 receipt 오버라이드 블록** — 액자 `#20261d`, 종이 `#f4ecdc`, 테이프/지그재그/도장 그림자를 다크용으로 교체. (삭제 버튼은 배경 transparent라 바뀐 종이색이 비쳐 살몬처럼 보임)
- **솔루션**: 이 다크 receipt 블록을 **제거**해 영수증을 **테마 무관(항상 라이트 종이)** 으로. 편집 모달·표시용 영수증 모두 라이트/다크 **차이 0건** 확인.

## 확정 원칙 (재발 방지)
- **영수증(약속 여정/편집)은 테마 무관 라이트 종이 외형**을 쓴다. 다크용 receipt 오버라이드를 다시 넣지 말 것.
- **크림 종이 버튼**(`.btn-memory-write`·`.btn-schedule-new`·`.feed-write-btn`)의 다크 미적응은 **의도된 디자인** — "고치지" 말 것.
- 솔리드 초록 CTA는 `--btn-primary-bg`/`--button-text` 사용. (극장/오버레이·위험 빨강은 예외)
