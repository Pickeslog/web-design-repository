# 0703 전역 테마 / 일정계획 / 추억피드 UI 수정 작업 기록

## 작업 목적

`makerooms.html` 모달화 병합 이후, 배경 테마 통일과 일정계획·추억피드 화면의 UX 문제를 이어서 손봤다.
외부 파일 병합이 아니라 기존 코드를 직접 수정한 작업들이다.

---

## 1. 전역 배경 테마 — 아이보리로 통일

각 화면이 배경색 변수를 제각각(`--body-bg`, `--bg-color`, `--bg`) 다르게 쓰고 있어서, 공통 테마 파일을
새로 만들어 전체 화면에 링크했다.

### 신규 파일

`02-main/css/global-theme.css`

```css
:root {
    --body-bg: #fffdf3;
    --bg-color: #fffdf3;
    --bg: #fffdf3;
    --bg-gradient: linear-gradient(145deg, #fffdf3 0%, #fffaf0 45%, #fdf6e3 100%);
}
```

- 전체 12개 화면(`01-auth` ~ `08-profile`)의 `<head>`, 각 페이지 자체 `<style>` 블록 **뒤에** 링크 —
  나중에 로드되는 CSS가 이겨서 라이트모드 값만 덮어씀
- `body.dark-mode { --body-bg: ... }`처럼 클래스가 붙은 규칙은 명시도가 `:root`보다 높아서 다크모드는
  각 페이지 원래 값 그대로 유지됨
- **예외 처리**: `01-auth/login.html`, `signup.html`은 배경을 변수가 아니라 그라데이션·궤도(orb) 색을
  하드코딩해서 써서, 이 두 파일만 그라데이션 자체의 색상 값을 직접 아이보리 톤으로 수정
- **추가 발견**: `02-main/index.html`(우정공간 홈)은 `body` 배경이 안 보이는 구조였다 —
  `.window-content`/`.main-content`가 화면 전체를 덮고 `--bg-gradient`라는 별도 변수(크림→세이지그린)를
  써서, 처음엔 이 변수를 놓쳐 아이보리 적용이 안 됐음. `global-theme.css`에 `--bg-gradient` 오버라이드를
  추가해서 해결

## 2. 일정계획 — "새 D-day 만들기" 버그 수정

### 발견한 문제

버튼(`➕ 새 D-day 만들기`)이 호출하는 `openScheduleModal()`이 실제로는 존재하지 않는
`schedule_detail.html` 페이지로 이동시키고 있었다. 반면 `dt-schedule-modal`이라는 완성된 모달
(제목/날짜/본문 입력 + `saveSchedule()` 저장 로직)이 DOM에 이미 있었지만 전혀 연결되어 있지 않았다.

### 수정 내용

- `openScheduleModal(viewType, scheduleId)`: 페이지 이동 대신 기존 `dt-schedule-modal`을 열도록 교체
  - 신규 생성: 폼을 비우고 "D-day 새로 세기" 타이틀
  - 수정: 기존 제목/날짜를 채우고 "약속 정보 수정하기" 타이틀
- `saveSchedule`: "본문(선택)" textarea 값이 그동안 완전히 무시되고 있었는데, 실제로 `content`에
  저장되도록 연결 (미입력 시 기존 기본 문구 유지)

### 프리셋 칩 제거

날짜 입력 아래 있던 "1주 후 / 2주 후 / 1개월 후 / 3개월 후" 빠른 선택 칩을 삭제했다.
`applyDatePreset()` 함수와 관련 CSS(`.date-preset-row`, `.date-preset-chip`)도 함께 정리.

### 과거 날짜 생성 방지

새 약속은 오늘 이전 날짜로 만들 수 없도록 이중으로 막았다.

- `openScheduleModal`: 신규 생성 모드에서 날짜 입력창에 `min = 오늘` 설정 (수정 모드는 제한 없음)
- `saveSchedule`: `min` 속성을 우회해도 저장 시점에 재검증 — 신규 생성 + 과거 날짜면
  "새 약속은 오늘 이후 날짜로만 만들 수 있어요" 경고 후 저장 차단
- 오늘 날짜를 `yyyy-mm-dd`로 반환하는 `getTodayDateStr()` 헬퍼 신규 추가

## 3. 추억피드 — 그리드 레이아웃 및 월별 필터 UI 정리

### 카드 그리드 폭 조정 (반복 조정)

`.feed-grid`(`dt-full-feed-zone`)에 여러 차례 걸쳐 다음과 같이 조정했다.

1. 2열 그리드에 `max-width: 760px; margin: 0 auto;` 추가 — 양쪽 여백 생성, 카드 폭 축소
2. 여백이 너무 넓다는 피드백으로 `max-width: 760px → 820px`로 조정
3. **2열 → 3열**로 변경 (`grid-template-columns: repeat(3, minmax(0,1fr))`), 3열에 맞춰
   `max-width: 820px → 980px`로 확대
4. 카드 간격(`gap`) 요청으로 `28px 20px → 32px 28px`로 확대 (세로 간격, 가로 간격)

### 월별 선택 팝오버 — "전체보기" 버튼 추가

📅 아이콘을 눌러 여는 월별 선택 팝오버(`#month-picker-popover`)에 연도 네비게이션과 12개월 그리드는
있었지만 전체 보기로 돌아가는 버튼이 없었다. 헤더와 월 그리드 사이에 `전체보기` 버튼을 새로 추가했다.

- 클릭 시 `setFeedMonth('all')` 호출 — 필터를 전체로 되돌리고 팝오버 자동으로 닫힘
- 전체 상태일 땐 초록색 active 스타일로 표시 (`renderMonthPicker()`에 토글 로직 추가)
- `04-feed/feed.html`, `02-main/index.html` 양쪽 다 반영

### feed-month-rail 제거

📅 팝오버로 월별 탐색이 이미 가능해서, 중복 기능이던 가로 스크롤 월별 칩 목록(`feed-month-rail`)을
완전히 삭제했다.

- HTML: rail div와 이를 감싸던 `.feed-month-picker-wrap` 제거, 📅 버튼을 `.feed-controls`에 직접 배치
- JS: `renderFeedMonthControls`에서 rail을 채우던 로직 삭제, "전체 · N개" 요약 텍스트 갱신 로직은 유지
- CSS: `.feed-month-rail`, `.feed-month-btn*`, `.feed-month-picker-wrap` 삭제,
  `.feed-controls`를 grid → flex(`space-between`)로 단순화

## 4. 검증 내용

매 수정마다 `node --check`로 JS 문법 확인, 브라우저 프리뷰로 동작 확인.

- 아이보리 배경: `getComputedStyle`로 라이트/다크 모드 실측값 확인 (`#fffdf3` / 원래 다크 톤 유지)
- D-day 모달: 생성/수정 양쪽 플로우, 본문 저장, 과거 날짜 차단까지 실제 데이터로 확인
- 추억피드 3열 그리드 + gap 값 `getComputedStyle`로 확인
- 월별 팝오버 "전체보기" 버튼: 클릭 시 `activeFeedMonth`가 `'all'`로 바뀌고 팝오버가 닫히는 것 확인
- rail 제거 후에도 달력 버튼·필터 탭 정상 동작, 콘솔 에러 없음

## 팀 공유 시 주의할 점

- 배경색을 다시 바꾸고 싶으면 `02-main/css/global-theme.css` 한 파일만 고치면 전체 화면에 반영된다
  (단, `login.html`/`signup.html`은 예외 — 그 파일 안의 그라데이션 색상을 직접 고쳐야 함)
- 일정계획 D-day는 신규 생성 시 과거 날짜가 막혀있다 — 테스트 데이터를 과거 날짜로 넣어야 한다면
  수정 모드(`openScheduleModal('dt', id)`)로 우회해야 한다
- 추억피드 월별 탐색은 이제 📅 팝오버 하나로 통일됐다 — rail 관련 코드는 완전히 삭제됐으니 복원 시
  이 문서의 "이전 구조" 설명을 참고할 것
