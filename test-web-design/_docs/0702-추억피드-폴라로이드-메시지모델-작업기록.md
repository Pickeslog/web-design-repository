# 0702 추억피드 폴라로이드 카드 / 게시자-메시지 모델 / 다중 사진 업로드 작업 기록

## 최종 상태 요약

추억피드 게시글 구조를 "참여자별 각자 전체 기록"(`participants[].text`) 방식에서
**게시자 1명(`authorId`) + 친구 한 줄 메시지(`messages[]`)** 방식으로 전면 교체했다.
카드/상세 모달을 폴라로이드 톤으로 재설계하고, 글쓰기·수정 양쪽에서 여러 장 사진 업로드를 지원하도록 확장했다.

작업 순서:

1. `screen-spec-source/` 문서를 실제 구현(`test-web-design/`)에 맞게 정리
2. 추억피드 폴라로이드 카드 + 상세 모달 구현 (`추억피드 폴라로이드 구현명세.md` 기준)
3. 글쓰기 모달(`wm-*`)의 미작동 버그 수정 + 새 데이터 모델 연동
4. 해시태그 입력 필드 추가
5. 친구가 올린 글에 메시지를 남길 수 있도록 시드 데이터 보강
6. 게시자 본인도 자기 글에 메시지를 남길 수 있도록 변경
7. 수정 모드 + 글쓰기 모달 양쪽에 다중 사진 업로드 추가

## 2. 추억피드 데이터 모델 교체 — participants[].text → authorId + messages[]

### 변경 전
- 게시글 하나에 참여자마다 각자의 전체 기록(`text`)이 존재
- 카드에서 참여자 탭을 눌러 "누구의 기록을 볼지" 전환하는 구조
- Clov의 "친구별 관점 기록" 차별점을 이 구조로 구현하고 있었음

### 변경 후
- 게시글은 게시자(`authorId`) 한 명의 제목/본문만 가진다
- 참여자(`participants[]`)는 "누가 함께했는가"만 나타내는 정체성 목록으로 단순화 (`id`, `name`, `icon`, `type`)
- 친구들은 게시글당 1인 1개의 **한 줄 메시지**(`messages: [{ authorId, text }]`)만 남길 수 있다
- **게시자 본인도** 자기 글에 메시지를 남길 수 있도록 확장 (처음엔 게시자를 메시지 목록에서 제외했다가, "내가 게시한 글에도 메시지를 남기고 싶다"는 요청으로 제외 필터를 제거)

### 마이그레이션
- `normalizeMemoryPost()`가 최초 렌더링 시 과거 `participants[].text`를 자동으로 `messages[]`로 1회 이관
- 기존 시드 데이터를 손대지 않고도 솔/민/준의 기존 한줄 코멘트가 "친구 한 줄 메시지"로 자연스럽게 이어짐

### 권한
| 액션 | 권한 |
|---|---|
| 제목·본문 수정/삭제 | 게시자만 |
| 한 줄 메시지 작성 | 참여 멤버 각자 (게시자 포함) |
| 메시지 수정·삭제 | 그 메시지 작성자 본인만 |

관련 함수 (`02-main/js/desktop.js`):
`normalizeMemoryPost`, `getMemoryHashtags`, `renderMemoryCard`, `openMemoryDetail`, `renderMemoryDetailModal`,
`updateMemoryPost`, `requestDeleteMemoryPost`/`confirmDeleteMemoryPost`,
`saveMemoryMessage`, `startMemoryMessageEdit`/`saveMemoryMessageEdit`/`cancelMemoryMessageEdit`, `deleteMemoryMessage`

## 3. 카드 · 상세 모달 UI 재설계

`추억피드 폴라로이드 구현명세.md`(첨부 참고 HTML `Clov 추억 폴라로이드.html`) 기준으로 재구현.

### 피드 카드 (`renderMemoryCard`)
순서: 참여자 아바타 레일(게시자만 민트 링) → 구분선 → 대표 사진(클릭 시 상세 모달, 🔍 자세히 힌트) → 캡션(작성자 라벨 + ···더보기 + 제목 + 48자 본문 미리보기) → 해시태그 → 구분선 → 날짜·장소 / 💬 메시지 수

### 상세 모달 (`memory-detail-sheet`를 재사용, 기존엔 죽어있던 바텀시트를 중앙 정렬 2열 모달로 교체)
- 좌: 대표 사진, 우: 제목/본문/태그 (또는 게시자 수정 폼)
- 하단: 친구 한 줄 메시지 목록 (타인 메시지=읽기전용, 타인 미작성="아직 메시지 없음", 내 메시지=수정·삭제, 내 미작성=입력창+등록)
- 액션바: 게시자=수정/삭제/닫기, 그 외=닫기만 (삭제는 확인 단계 거침)

### 필터 로직 정리
"내 기록"/"친구 기록" 필터를 `authorId` 기준으로 재정의 — 과거엔 사실상 동작하지 않던 필터였음.

## 4. 글쓰기 모달(`wm-*`) 버그 수정

피드 헤더의 "✏️ 글쓰기"/대시보드의 "✏️ 추억 기록하기" 버튼이 실제로 호출하는 모달은
`dt-post-modal`(구버전, `addNewDesktopPost()`)이 아니라 `index.html`에 별도로 있던
`wm-*` 모달(사진 업로드 + "함께한 친구" 참여자 칩 포함)이었다.

문제: `saveWritePost()`가 어디에도 정의되지 않은 `window._clov` 브릿지 객체를 참조하고 있어
**저장이 항상 무음 실패**하고 있었고, 로직도 옛 `participants[].text` 복제 방식 그대로였다.
사진 URL도 `url('...')`로 이중 래핑되어 있어 실제로는 깨지는 코드였다.

수정:
- `window._clov` 참조 제거, `desktop.js`의 전역(`groupsData`, `activeGroup`, `renderFeeds`, `activeEvidenceIndexes`, `CURRENT_USER_ID`)에 직접 연결
- 참여자 칩에서 "나"는 제외 (게시자는 항상 자동 포함, 칩은 "함께한 친구"만 고르는 용도)
- 저장 시 `authorId: CURRENT_USER_ID`, `messages: []`로 생성해 상세 모달의 메시지 기능과 바로 호환
- 사진 배경 이중 `url()` 래핑 버그 수정
- "친구 1명 이상 선택 필수" 제약 제거 (혼자만의 기록도 허용)

## 5. 해시태그 입력 필드 추가

글쓰기 모달 본문/참여자 사이에 해시태그 입력창 추가.

- `#한강 #시험끝`처럼 띄어쓰기·쉼표 구분 입력, `#` 자동 접두, 중복 제거, 최대 5개
- 미입력 시 기존처럼 `#소중한순간 / #내기록·#친구기록 / #날짜` 자동 태그로 대체 (기존 폴백 로직 유지)

## 6. 친구가 올린 글에 메시지 남기기 — 시드 데이터 보강

`normalizeMemoryPost`의 기본 로직은 `authorId`가 없으면 항상 "나"를 게시자로 지정했다.
그 결과 기존 시드 게시글 12개가 전부 "내 글"이 되어, 친구가 쓴 글이 하나도 없어
"친구 글에 메시지 남기기" 시나리오를 실제로 체험할 방법이 없었다.

수정:
- 시드 게시글 3개를 친구가 올린 글로 명시 지정: "성수 스터디 카페"(솔), "부산 당일 여행"(민), "졸업식 날"(준)
- `DATA_VERSION`을 `3` → `4`로 올려서, 기존에 로컬에 저장된 옛 데이터를 쓰던 브라우저도 자동으로 새 시드를 받도록 처리

## 7. 다중 사진 업로드 — 수정 모드 + 글쓰기 모달

기존엔 대표 사진 1장만 업로드할 수 있었다. `post.bg`(단일 문자열)를 유지하면서
`post.photos: string[]` 배열을 추가하고, 과거 데이터는 `normalizeMemoryPost`에서 `photos[0]`로 1회 이관(`bg`는 계속 동기화).

멀티 사진을 어떻게 보여줄지는 두 방향(① 대표사진 1장 + 모달 필름스트립, ② 카드 자체를 그리드/스와이프)을 두고
①을 채택했다 — 대시보드에 이미 있는 "카메라 필름 스트립" 넘기기 UI와 톤이 이어지고, 피드 카드의 폴라로이드 느낌(대표사진 1장)도 유지되기 때문.

### 상세 모달 수정 모드
- 사진 영역이 썸네일 묶음 + "📷 추가" 타일로 바뀜, `<input type="file" multiple>`로 여러 장 한 번에 선택 (최대 6장)
- 선택한 사진을 모두 불러오면 **`showProofResultModal()`을 재사용해 "이미지 업로드 완료" 안내 모달**을 띄움
  (일정계획 인생4컷 업로드 완료 모달과 같은 함수/톤 재사용)
- 개별 사진 ✕ 삭제 가능, "저장"을 눌러야 실제 게시글에 반영 (취소 시 원래대로)

### 글쓰기 모달(`wm-*`)
- 기존 "대표 사진 1장" 업로드 박스를 동일한 썸네일 묶음 + 추가 타일 UI로 교체
- 업로드 완료 시 수정 모드와 동일하게 `showProofResultModal()` 재사용

### 보기 모드 / 카드
- 사진이 2장 이상이면 상세 모달 하단에 작은 썸네일 스트립이 생겨 클릭으로 넘겨볼 수 있음
- 피드 카드는 대표사진(1번째) 우상단에 "📷 N" 배지로 여러 장 있음을 표시

관련 코드: `getPostPhotos` 역할을 하는 `normalizeMemoryPost`의 `photos` 정규화,
`handleMemoryEditPhotoUpload`/`removeMemoryEditPhoto`/`setMemoryDetailPhotoIndex`(수정 모드),
`previewWriteImg`/`removeWriteImg`/`_renderPhotoStrip`(글쓰기 모달, `index.html` 내 인라인 스크립트)

## 8. 검증 내용

브라우저 미리보기(정적 서버, `localhost:8890`)에서 확인:

- 폴라로이드 카드 렌더링, 상세 모달 2열 레이아웃(데스크톱)·1열 스택(좁은 화면) 모두 확인
- 게시자 수정 → 카드/모달 즉시 반영, 삭제 → 피드 카드 수 감소 및 대시보드 필름 스트립도 갱신
- 친구가 올린 글("성수 스터디 카페" 등)에서 "나"가 메시지 작성/수정/삭제 정상 동작
- 게시자 본인 글에서도 메시지 작성/수정/삭제 정상 동작
- 글쓰기 모달: 참여자 칩에서 "나" 제외 확인, 칩 해제 후 저장 시 참여자 목록에서 정상 제외
- 해시태그 입력 파싱(`한강, #피크닉  야간산책` → `#한강 #피크닉 #야간산책`) 정상
- 다중 사진: 수정 모드·글쓰기 모달 양쪽에서 업로드 완료 모달 → 저장 → `photos` 배열 정상 저장,
  카드 "📷 N" 배지·상세 모달 필름스트립 정상 표시, 6장 제한 및 "추가" 버튼 숨김 정상
- `node --check js/desktop.js` 통과, 브라우저 콘솔 에러 없음
- `DATA_VERSION` 버전업으로 기존 localStorage 사용자도 새 시드 자동 반영 확인
