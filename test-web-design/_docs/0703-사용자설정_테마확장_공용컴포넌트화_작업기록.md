## 1. 행운편지 — 작성 기능 재작성 (김대훈 작업본)

기존 `submitLetter`가 세 번 중복 정의되어 있었고, JS의 "나중에 정의된 함수가 이긴다" 특성 때문에 실제로 살아있던 버전은 **편지를 저장하지 않고 성공 토스트만 띄우는 미완성 스텁**이었다. 김대훈 작업본의 완결된 버전으로 교체했다.

- 받는 사람을 자유 입력 대신 **멤버 칩에서 선택**(`selectLetterRecipient`, `selectedLetterRecipient` 상태)하는 방식으로 변경, "모두에게" 토글(`toggleLetterToAllBtn`) 지원
- 보내는 사람은 항상 `localStorage.clov_profile`의 내 이름 (자유 입력 시절엔 스푸핑 가능했음)
- 편지 내용 글자수 제한(한글 500자/영어 1000자, `handleLetterContentInput`/`updateLetterContentCountDisplay`)
- 저장 시 실제로 `groupsData[activeGroup].letters`에 추가 + `localStorage` 반영 + `renderLetters()` 리렌더링까지 완결
- 중복 정의돼 있던 `toggleLetterToAllBtn`/`selectLetterEmoji`/`updateLetterPreview`/구버전 `submitLetter` 전부 제거
- 편지함 모달에 **"보낸 편지함"** 필터 탭 추가 (`getFilteredLettersWithIndex`/`renderLetters`/`setLetterFilter`에 `sent` 분기 추가, `letter.isMine` 기준)

## 2. 우정편지 테마 — 선물상자 / 우체통 전환 (신동수 작업본)

`letter-box-trigger` 버튼 안에 기존 선물상자 SVG와 신동수 작업본의 우체통 SVG를 **둘 다 렌더링**해두고, `.letter-box-visual-giftbox`/`.letter-box-visual-mailbox` 클래스로 하나만 보이도록 전환한다.

- 우체통: 회전문(`rotateX`)·깃발(`rotate`) 3D 애니메이션, 편지 도착 시(`has-mail` 클래스) 깃발이 올라가고 내부 편지가 보임 — `renderLetters()`에서 `groupsData[activeGroup].letters.length` 기준으로 `has-mail` 토글
- 상태: `localStorage.clov_letterBoxTheme` (`giftbox` 기본값 / `mailbox`), `setLetterBoxTheme(theme)`으로 전환 + 토스트
- 사용자설정 → 화면 → **"우정편지 테마"** 섹션에서 선택 (아래 7번 참고)

## 3. 일정계획 — 다가오는 일정 배너 (김규비 작업본)

우정공간 홈 화면 상단의 "다가오는 일정" 배너를 **단일 카드 → 3열 그리드**로 개편했다 (`updateScheduleUI()`).

- `dt-schedule-banner-container`(3열 grid)에 다가오는 일정 최대 3개 표시, 미래 일정을 날짜순으로 채우고 부족하면 지난 일정으로 채움
- **빈 슬롯**: 일정이 3개 미만이면 남은 칸에 반투명 점선 카드("➕ 새로운 약속 만들기")가 뜨고 클릭하면 생성 모달이 열림
- D-day 뱃지에 `getDdayAccent()` 색상 + 워터마크 번짐 효과(`::before` 블롭) 적용
- **일정 수정 시 과거 날짜 제한**: `openScheduleModal` 편집 모드에서 `dateInput.min`을 생성 때처럼 오늘로 고정. `saveSchedule`은 "이미 저장된 날짜를 그대로 두는 것"은 허용하고 "새로 과거 날짜로 바꾸려는 시도"만 막도록 처리 — 그래야 이미 지난 일정의 제목만 고치는 것까지 막히지 않는다
- 일정 작성/수정 모달을 리치에디터(SVG 툴바: 제목/굵게/글머리/번호/구분선)로 교체, 모달 680px 확장 + 본문 최대 280px 독립 스크롤. 부수적으로 **기존 수정하기가 항상 빈 칸으로 열리고 저장하면 서식이 사라지던 버그**도 innerHTML 기반으로 바꾸며 같이 해결됨

## 4. 참여자별 추억 증거 카드 — 빨랫줄 / 겹침 카드 전환 + 원형 아바타 (신동수 작업본)

### 겹침 카드(코드플로우) 테마
`renderEvidenceViewer()`가 테마에 따라 다르게 렌더링한다 (`getEvidenceCardTheme()`).

- **빨랫줄(기존, 기본값)**: 와이어 + 빨래집게, 카드 ±2단계까지 회전/축소
- **겹침 카드(신동수)**: 와이어/집게 완전히 숨김(`.cline-viewer.theme-coverflow .cline-wire, .cline-clip-svg { display:none }`), 카드 폭 210px에 `margin:0 -38px`로 겹치는 코드플로우 스타일, 중앙 100% → 양옆 86% → 72% → 가장 바깥 58%까지 **±3단계**로 확장 (기존은 ±2)
- 상태: `localStorage.clov_evidenceCardTheme` (`wire` 기본값 / `coverflow`), `setEvidenceCardTheme(theme)` 전환 시 `renderEvidenceViewers()` 재호출
- 사용자설정 → 화면 → **"참여자별 추억 증거 카드"** 섹션에서 선택 (아래 7번 참고)
- 이번엔 정적 배치만 포팅했고, 카드가 여러 칸을 건너뛸 때 하나씩 부드럽게 지나가는 연속 슬라이드 애니메이션(88ms 스텝)은 포함하지 않음 — 필요 시 추가 가능

### 원형 아바타 디자인
`renderMemoryCard()`의 참여자 아이콘을 캡슐(알약)+이름 텍스트 → **완전한 원(28×28px)**으로 교체. `.presence-tile`(`padding:4px 10px 4px 4px` → `padding:0; width/height:28px; border-radius:50%`), `.presence-dot`(22px 고정 → `width/height:100%`), 이름 요약 텍스트(`<span class="presence-name-label">`)는 카드 템플릿에서 제거. 이 함수는 우정공간 홈 대시보드와 추억피드 양쪽에서 공통으로 쓰여 두 곳 다 한 번에 반영된다.

## 5. 하단 필름 스트립 — 드래그/휠 스크롤 (신동수 작업본)

`.cline-film-strip`/`.cline-film-frames` 디자인과 상호작용을 신동수 작업본 그대로 포팅했다. 위쪽 폴라로이드 스테이지(빨래집게/와이어 제거, 연속 슬라이드 애니메이션)는 포함하지 않고 필름 스트립 자체만 범위로 잡았다.

- **라벨 디자인**: "과거"/"현재" 텍스트를 세로쓰기(`writing-mode: vertical-rl`) + 필름통 느낌 박스(테두리/그림자/텍스트 그림자)로 교체
- **드래그로 스크롤**: `initEvidenceInteractions()`— `pointerdown`/`pointermove`/`pointerup`을 윈도우 레벨로 위임해 `.cline-film-frames.scrollLeft`를 직접 조작, 드래그 중엔 `window.isFilmDraggingPreventClick` 플래그로 `setEvidenceIndex()` 클릭이 씹히지 않게 함(드래그 끝나면 50ms 뒤 해제)
- **마우스 휠 → 가로 스크롤 변환**: 세로 휠 입력을 필름 스트립 위에서 가로 스크롤로 변환
- **이미지 네이티브 드래그 방지**: `-webkit-user-drag:none` + `dragstart` preventDefault로 브라우저 기본 이미지 드래그와 커스텀 드래그가 충돌하지 않게 함
- `.cline-film-track` 래퍼 추가로 필름 내용이 중앙 정렬되는 구조로 변경
- 창 크기 변경 시 현재 프레임 재중앙정렬(`window resize` 핸들러, `behavior:'instant'`)

## 6. 알림 — 멤버 퇴장 알림 + 가입 신청 거절 세션 전용 처리

- **`simulateMemberLeave()`** 신규: `clov_acceptedMembers`(가입 승낙으로 합류한 동적 멤버) 중 한 명을 무작위로 제거하고, `groupsData[activeGroup].notifications`에 `"{이름}님이 {방이름}에서 나갔습니다."` 알림을 추가해 **🔔 알림 → 친구들 알림** 탭에서 확인 가능하게 함. 멤버 목록 모달에 "🙋‍♂️ 가입 신청 테스트" 옆에 "👋 멤버 퇴장 테스트" 버튼 추가. 이 프로토타입은 localStorage 기반 단일 클라이언트라 실제 다른 사용자의 퇴장을 감지할 방법이 없어, 기존 가입신청 테스트와 같은 시뮬레이션 방식으로 구현했다
- **가입 신청 거절 — 세션 전용 처리**: `rejectJoinRequest`가 더 이상 `localStorage`의 `status`를 `'rejected'`로 영구 기록하지 않고, `notiSessionOverrides`(메모리 변수)에만 기록한다. 화면에는 거절된 것으로 보이지만 실제 저장값은 여전히 `pending`이라 **새로고침하면 다시 대기 상태로 리셋**된다. `renderJoinRequestsNoti()`/`pending` 카운트 계산 모두 `notiSessionOverrides[id] || req.status`로 오버라이드를 우선 적용하도록 수정. 삭제(`deleteJoinRequest`)는 오버라이드도 같이 지움. **수락(accept)은 그대로 영구 저장** — 실제로 멤버가 합류하는 액션이라 세션 한정으로 두지 않았다

## 7. 사용자설정 모달 — 신규 테마 섹션 + 공용 컴포넌트화

### 신규 테마 섹션
"화면" 탭에 라이트모드/다크모드 아래로 3개 섹션 추가:
- **배경** — 배경 테마 변경 (준비중 배지, `notifyThemeComingSoon()`으로 안내 토스트만)
- **우정편지 테마** — 🎁 선물상자 / 📮 우체통 (2번 참고)
- **참여자별 추억 증거 카드** — 🧷 빨랫줄 / 📸 겹침 카드 (4번 참고)

좌측 내비게이션 라벨을 "라이트모드 · 다크모드"에서 **"테마 설정"**으로 변경 — 섹션이 늘어나면서 기존 라벨이 더 이상 내용을 정확히 설명하지 못했다.

프로필 사진 필드도 새로 추가: 좌측 레일 아바타(`settings-rail-identity`)는 순수 표시 전용으로 바꾸고(버튼 → `div`, 클릭 불가), "기본 정보" 섹션 이름/닉네임 위에 클릭 가능한 64px 원형 업로드 필드를 신설. 파일 input은 이 새 필드로 옮기고, `loadProfileModalData`/`updateProfilePreview`/`handleProfileAvatarUpload` 전부 레일 쪽과 새 필드 쪽을 동시에 동기화하도록 수정.

### 공용 컴포넌트로 분리 (`clov-profile-modal.js`)
`02-main/index.html`과 `03-rooms/makerooms.html`에 모달 HTML(~150줄)과 JS 함수(~220줄)가 완전히 중복돼 있어서 매번 두 파일을 수동으로 동기화해야 했다. `clov-header.js`/`clov-modal.js`와 같은 패턴의 공용 컴포넌트로 뽑아냈다.

- `ClovProfileModal.init()` 한 번 호출로 모달 HTML을 `document.body`에 주입하고, `openProfileModal`/`switchSettingsPane`/`setThemeMode`/`setLetterBoxTheme`/`setEvidenceCardTheme`/`saveProfileModal` 등 관련 함수 전부를 전역 등록
- 페이지에 없는 기능(예: makerooms.html엔 행운편지/증거카드 뷰어가 없음)에 의존하는 함수는 `typeof renderEvidenceViewers === 'function'` 식으로 가드 처리 — 설정값은 저장되고, 그 페이지에 해당 UI가 없으면 그냥 아무 시각적 효과가 없을 뿐 에러는 안 남
- **두 페이지의 CSS 클래스 체계가 서로 다른 문제**: index.html은 `.modal-form-group`+`<label>`+무클래스 `<input>`+`.btn-sub`/`.btn-main`, makerooms.html은 `.field-wrap`+`.field-label`+`.text-input`+`.profile-footer-btn`. 두 페이지가 완전히 별도 스타일시트를 쓰기 때문에(서로의 클래스를 몰라도 충돌 없음), 컴포넌트의 모든 폼 요소에 **두 체계의 클래스를 동시에** 부여하는 방식으로 해결(예: `class="modal-form-group field-wrap"`). makerooms.html에는 `.is-coming-soon`/`.theme-coming-soon-badge` 두 개만 새로 CSS 추가
- `setThemeMode`는 `toggleDarkMode()`가 있으면 그걸 쓰고(index.html), 없으면 `ClovHeader.applyDark()`로 폴백(makerooms.html) — 페이지마다 다크모드 상태 관리 방식이 달랐음
- **발견한 버그**: `ClovProfileModal.init()`이 `<body>` 상단(행운편지 우체통 요소가 파싱되기 전)에서 호출되다 보니, 저장된 우체통 테마가 새로고침 시 적용이 안 되는 문제가 있었다. `document.readyState === 'loading'`이면 `DOMContentLoaded` 이후로 테마 적용을 미루도록 수정
- 부가 효과: makerooms.html에도 이제 배경/우정편지 테마/증거카드 테마가 전부 노출된다(전엔 라이트/다크모드만 있었음). 로컬스토리지 공유라 방 목록 화면에서 바꾼 테마가 우정공간 진입 후에도 그대로 적용됨

- 일정계획: 배너 3열 렌더링, 빈 슬롯 클릭 시 생성 모달, 과거 날짜로 수정 시도 시 저장 차단 + 기존 날짜 유지한 채 제목만 수정은 허용되는 것까지 각각 확인
- 우정편지/증거카드 테마: 전환 시 클래스·DOM 구조 변경, 새로고침 후 유지까지 확인
- 필름 스트립: 실제 pointer 이벤트로 60px 드래그 → scrollLeft 이동 확인, wheel 이벤트로 가로 스크롤 변환 확인, 드래그 중 클릭 무시/드래그 후 정상 클릭 둘 다 확인
- 멤버 퇴장 알림: 실제 알림 문구("OO님이 단짝친구에서 나갔습니다.") 렌더링 확인
- 가입신청 거절: 거절 직후엔 화면에 반영되지만 localStorage엔 `pending`으로 남아있고, 새로고침하면 수락/거절 버튼이 다시 뜨는 것까지 확인
- 공용 컴포넌트: index.html/makerooms.html 양쪽에서 모달 오픈, 테마 전환, 아바타 업로드 동기화, 콘솔 에러 없음 확인
