## 작업 9 — 방 프로필 편집: 테마 색상 스와치 추가

**진행 과정** (사용자 피드백에 따라 반복 조정):
1. "테마 배경 색 선택을 주는 건 어떨까" → 큐레이션된 프리셋 스와치 방식 제안·합의
2. 기존 3색(포레스트·틸·올리브) + 3색(세이지·딥그린·민트) = 6색으로 시작
3. 모달 세로 길이 확장(`max-height` 720px→760px) + 2색 추가(라임그린·카키) = 8색
4. "색깔 구성이 너무 비슷하다" → 뒤 4색을 색상군이 다른 팔레트로 교체: 오션블루·라벤더·코랄·앰버
5. 로즈·슬레이트 추가 → 10색, 슬레이트 제거 → **최종 9색**(포레스트·틸·올리브·세이지·오션블루·라벤더·코랄·앰버·로즈)
6. 스와치 가운데 정렬(`justify-content: center`)

**데이터 모델**: `room.tone`(인덱스) 필드 추가, 기존 방은 `id` 기반 시드로 하위호환. `ticketTone(room)`이 저장된 tone 우선 사용

**검증**: 각 단계마다 브라우저에서 스와치 렌더링·선택·저장·목록 카드 반영 확인, 좁은/넓은 뷰포트에서 정렬 대칭 확인, 콘솔 에러 0

## 작업 11 — 다크모드 텍스트/버튼 대비 문제 수정

**문제**: `.greeting`(인사말), `.req-head`(요청한 방), `.btn-edit`(편집 버튼)가 배경 없이 색상/테두리만으로 표시 → 실제 배경(이 파일의 로컬 변수가 아니라 나중에 로드되는 `global-theme.css`의 우드/종이 텍스처 배경, 다크모드 시 짙은 그라디언트)과 대비가 무너짐

**해결**: 세 요소에 불투명 배경 칩/패널 추가
- `.greeting`, `.req-head`: 알약형 칩(`--active-bg` 배경 + `--border` 테두리)
- `.btn-edit`: 투명 배경 → 불투명 `--card-bg` + 그림자 + `--input-bdr` 테두리

**검증**: 다크모드 대비비 11.77:1~14.29:1(WCAG AA 4.5:1 크게 상회), 라이트모드 정상, 콘솔 에러 0
