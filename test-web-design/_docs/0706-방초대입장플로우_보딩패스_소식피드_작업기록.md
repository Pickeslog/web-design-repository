## 1. 개요

`design_handoff_room_invite_flow` 명세의 **B/C/D(확정 hifi)** 와 **A(초대/입장 플로우 규칙)** 를 대상 코드베이스(순수 바닐라 JS)에 재현. 핵심 원칙은 **"방장(owner)이 없다 — 모든 행동은 멤버 누구나 가능하되 소식/알림에 흔적이 남는다(권한이 아니라 투명성)".**

전체를 2단계로 진행:
- **Phase 1** — 비주얼 확정분: D 보딩패스 카드, B 소식 피드 미리보기, C 방 프로필 편집, A-6 초대 시트
- **Phase 2** — 플로우 규칙: A-1 요청한 방, A-2 삭제 4갈래, A-3 잠자는 방, A-4 추억에서 고르기, A-5 수락 P1 보강, A-7 예외 처리

### 작업 중 발견·수정한 이슈
1. **`filter: drop-shadow` + CSS `mask` 조합이 헤드리스 스크린샷을 30초 행** (실브라우저는 정상) → 티켓을 **그림자 래퍼 + 마스크 본체 2단 구조**로 분리해 해결(그림자도 더 견고).
2. 티켓 헤더(`.tk-head` position:relative)가 편집 컨트롤을 덮음 → `.edit-controls`에 `z-index:4`.
3. `renderList` forEach 내부 지역변수 `grid`(HTML 문자열)가 바깥 `grid`(DOM) 를 섀도잉 → `detailGrid`로 개명.
4. 부활한 방이 원래 생성일로 정렬돼 뒤 페이지로 감 → 부활 시 `createdAt = new Date()`로 최상단 표시.

## 4. 아직 안 한 것 (A-8 · 명세엔 있으나 미구현)

- **A-8 회원탈퇴 익명화** — 계정 삭제 시 작성자 표기를 **"언노운"** 으로 익명화(추억·편지·폴라로이드는 보존). → 회원탈퇴 플로우와 엮여 미착수.

### 프로토타입 한계로 "흉내" 수준인 것
- **A-3 dormant** 는 `localStorage`로 영속하지만, 활성 `rooms` 자체는 인메모리(리로드 시 하드코딩 시드로 복원)라 **dormant만 지속**. 실제 서버 저장은 아님.
