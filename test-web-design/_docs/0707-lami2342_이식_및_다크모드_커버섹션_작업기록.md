### 5-3. `cover-summary`(우정공간 대표 커버) 다크모드 적용 — ⚠️ 원인 발견했으나 적용 실패, 미해결

**원인 분석 결과**: `.cover-summary`, `.title-input-box`, `.member-highlight-card`의 배경색은 `index.html` `<head>` 안 인라인 `<style>` 블록(6/30~7/1 세션의 "사진 카드 스타일 변경(겹침 & 폴라로이드 느낌)" 작업에서 추가된 것으로 추정)에 `!important`로 항상 흰색(`#ffffff`)이 하드코딩되어 있어, 다크모드에서도 절대 안 바뀌는 구조였음.

**시도한 조치**: `index.html`의 해당 `<style>` 블록에 `body.dark-mode` 스코프 + `!important`로 아래 오버라이드를 추가:
```css
body.dark-mode .cover-summary {
  background: var(--card-bg) !important;
  border-color: var(--border-color) !important;
}
body.dark-mode .title-input-box,
body.dark-mode .member-highlight-card {
  background: rgba(255, 255, 255, 0.06) !important;
  border-color: rgba(255, 255, 255, 0.14) !important;
}
body.dark-mode #dt-title-count { background: rgba(156, 204, 101, 0.16) !important; color: var(--accent-green) !important; }
body.dark-mode button[title="대표 사진 변경하기"] { background: rgba(156, 204, 101, 0.12) !important; border-color: rgba(156, 204, 101, 0.22) !important; }
body.dark-mode .member-highlight-card > div:last-child { background: rgba(156, 204, 101, 0.16) !important; color: var(--accent-green) !important; border-color: rgba(156, 204, 101, 0.25) !important; }
```
(이 블록은 실제로 `index.html`에 저장되어 있음 — 롤백 안 함)

**문제**: 브라우저에서 정식 `toggleDarkMode()`로 다크모드를 켜고 확인한 결과, `.cover-summary`의 computed `background-color`가 여전히 `rgb(255, 255, 255)`(흰색)로 나옴 — 내가 추가한 다크모드 규칙이 적용되지 않음.

**여기까지 확인한 것**:
- 내가 추가한 CSS 텍스트가 실제로 서빙되는 페이지에 정확히 존재함(DOM `<style>` 태그 내용으로 직접 확인)
- `body.dark-mode` 클래스가 실제로 `<body>`에 붙어 있음(`classList.contains('dark-mode') === true`)
- `var(--card-bg)`가 이 요소 위치에서 정상적으로 `#1e2016`(유효한 다크 색)로 resolve됨 (invalid var 무효화 문제 아님)
- `element.matches(selector)`로 이 요소에 실제 매치되는 모든 CSS 규칙을 전수 스캔한 결과, `.cover-summary`의 배경을 설정하는 매치 규칙은 단 2개뿐:
  1. `base.css`의 `body.dark-mode .cover-summary`(그라디언트+`rgba(249,253,250,0.94)`, `!important` 아님)
  2. 내가 추가한 `body.dark-mode .cover-summary`(`var(--card-bg)`, `!important`)
- CSS 명세대로면 내 규칙(같은 우선순위 티어에서 `!important` + 동일 specificity)이 이겨야 하는데, 실제 computed 값은 이 두 후보 중 **어느 쪽과도 일치하지 않는 순백색**(`rgb(255,255,255)`)이었음 — 즉 내가 못 찾은 제3의 소스가 있거나, CSSOM 스캔 방식 자체에 놓친 부분이 있다는 뜻
- 심지어 브라우저에서 CSSOM으로 `.cover-summary { background:#fff !important }` 규칙 자체를 **직접 삭제**(`sheet.deleteRule()`)했는데도 흰색이 그대로 유지됨 — 이건 그 규칙이 원인이 아니었다는 뜻이라 더 미궁

**추가로 발견한 부수적 문제 (근본 원인과 무관, 세션 중 발생한 테스트 아티팩트)**:
localStorage에 `clov_theme=dark`와 `clov_darkMode=false`라는 **서로 다른 두 개의 다크모드 관련 키**가 동시에 존재하는 것을 발견. 이전 테스트에서 `document.body.classList.add('dark-mode')`를 JS로 직접 호출한 것 때문에 생긴 혼선으로 추정되며, 정식 `toggleDarkMode()` 함수 호출 전에는 반드시 이 두 키를 지우고 재현해야 함. (이 자체가 앱의 실제 버그인지, 아니면 내 테스트가 만든 일시적 혼선인지는 미확인 — 재개 시 `clov_theme`/`clov_darkMode` 두 키의 관계와 어느 쪽이 진짜 소스인지부터 코드에서 확인 필요)

## 6. 미해결 이슈 — 재개 시 확인할 것

1. **`clov_theme` vs `clov_darkMode` 두 로컬스토리지 키의 실제 관계**를 `nav.js`/`desktop.js`의 `toggleDarkMode()` 정의부터 먼저 읽고, 어느 게 실제 소스인지, 두 값이 왜 따로 노는지 확인
2. `.cover-summary` 배경이 왜 두 후보 규칙 중 어느 것도 아닌 순백색으로 고정되는지 — CSSOM에서 안 잡히는 다른 소스가 있는 것으로 보임. 브라우저 실제 DevTools의 "Computed" 패널에서 직접 winning rule을 확인하거나(이 세션 도구로는 안 됨), `getComputedStyle` 대신 요소를 실제로 스크린샷/시각 확인해서 진짜 눈으로 보이는 색까지 재확인 필요
3. 위 미스터리가 풀리기 전까지는 `index.html`에 추가한 다크모드 오버라이드 블록이 **파일에는 저장돼 있지만 실제로 효과가 없는 상태**이므로, 사용자에게 "아직 안 고쳐졌다"고 투명하게 알려야 함
