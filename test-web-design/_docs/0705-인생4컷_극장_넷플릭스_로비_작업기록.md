## 1. 우정공간 일정 배너 클릭 — 해당 일정으로 스포트라이트 이동

기존엔 대시보드 일정 배너(`#dt-schedule-banner-container`)를 클릭하면 `일정계획` 탭으로만 이동하고, 정작 어떤 일정을 봐야 하는지는 첫 번째(가장 가까운) 카드로 임의 노출됐다. 배너가 3칸 그리드로 서로 다른 일정을 보여주는데도 클릭 결과가 항상 똑같았던 것.

- 배너 렌더링(`updateScheduleUI()`)의 `onclick`을 `switchDesktopTab('schedule')` 단독 호출에서 `switchDesktopTab('schedule'); selectScheduleChip('dt', ${sch.id})`로 교체
- `selectScheduleChip()`은 이미 존재하던 함수(일정계획 탭 내 D-day 칩 선택용)를 그대로 재사용 — 새 함수를 만들 필요 없이 배너가 어떤 일정을 가리키는지만 넘겨주면 해당 카드가 스포트라이트로 펼쳐지고 뷰가 그 카드 상단으로 스크롤된다

## 2. 인생4컷 극장 — "모아보기" 코르크보드 모달을 영화관 연출로 전면 교체

`모아두기 버튼 연출 방법/design_handoff_fourcut_theater/` 폴더에 팀이 준비해둔 디자인 핸드오프(README + `.dc.html` 프로토타입)를 검토 후 그대로 이식했다. 완성된(4/4) 인생4컷들을 "영화관에 입장해서 감상"하는 몰입형 연출로, 기존 코르크보드 갤러리 모달을 완전히 대체.

### 로비(포스터)
- `#dt-fourcut-gallery-modal` 안쪽을 코르크보드 그리드(`renderFourCutGalleryCard`, `fourCutPinRotation` — 삭제됨) 대신 **영화 포스터형 히어로 배너**(`.fourcut-poster`)로 교체
- 완성작들의 '만남' 컷이 3.6초 간격으로 크로스페이드되는 슬라이드쇼(`fourCutStartPoster`), 우상단 "지금 상영 · {제목}" 칩, 마퀴 전구 장식, 하단 "TODAY · N편 상영" 바
- 트리거 버튼(`.fourcut-gallery-btn`, 일정계획 탭 상단)을 "모아보기" → **"입장하기"**(티켓 아이콘)로 변경

### 극장 (풀스크린 오버레이, `#dt-fourcut-theater`)
모달 안이 아니라 `position:fixed; z-index:500`인 별도 오버레이로 구현(디자인 핸드오프의 "풀스크린 권장" 반영, 모달 박스 크기에 갇히지 않도록).

- **입장하기**(`fourCutEnter`) → 좌석 통로로 돌리인, 하우스 조명 유지, "착석하기" 버튼 등장
- **착석하기**(`fourCutSit`) → 앞좌석 튀어오름 → 소등 → 커튼 열림 → 3·2·1 카운트다운 → 스크린 점등 + 필름스트립(4단계 인증사진) 상영. 타이밍/이징 전부 핸드오프 스펙 그대로(`cubic-bezier(.2,.7,.3,1)` 등), `prefers-reduced-motion`이면 카운트다운 생략
- **◁ / ▷**(`fourCutNav`) → 재렌더 없이 DOM 직접 갱신(제목/날짜/카운터/4프레임 이미지) + 필름 어드밴스 전환
- **나가기**(`fourCutExit`) → 오버레이만 페이드아웃, 로비는 그 뒤에 그대로 있으므로 별도 복원 불필요(아래 3번 참고)

## 3. 버그 — "나가기 후 재입장하면 커튼이 안 닫혀있음" (3단계에 걸쳐 원인 파악)

가장 시간을 많이 쓴 부분. 사용자가 여러 차례 재현 스크린샷을 보내줘서 단계적으로 좁혀나갔다.

1. **1차 수정**: `fourCutResetTheater()`가 커튼/스크린/조명 등 각 요소의 `getAnimations().forEach(a=>a.cancel())` 후 인라인 스타일을 초기값으로 다시 못박도록 함. 논리적으론 맞았지만 실제 재현 시 여전히 깨짐 — 재입장(`fourCutEnter`)에서만 리셋하고 **나가기(`fourCutExit`) 시점엔 리셋을 안 해서**, 나가기와 재입장 사이 타이밍에 따라 이전 상영 상태가 새어나올 여지가 있었음
2. **2차 수정**: `fourCutAnim()` 헬퍼 자체가 새 애니메이션을 걸기 전에 항상 기존 애니메이션을 `cancel()`하도록 중앙화(같은 요소를 입장/착석/넘기기 여러 단계가 겹쳐서 건드리는 경우의 컴포지트 불확실성 제거). `나가기`에서도 즉시 하드 리셋하도록 수정
3. **최종 해결**: 그래도 실사용 환경에서 재현된다는 피드백을 받고, 사용자가 제안한 "새로고침한 것처럼 만들면 되지 않을까"를 그대로 채택 — **극장 내부 마크업을 최초 1회 캡처(`fourCutCaptureTheaterTemplate`)해두고, 나가기(`fourCutExit`)마다 그 원본으로 `innerHTML`을 통째로 갈아끼움**(`fourCutResetChildren`). 새로 만들어진 DOM 노드는 애니메이션 이력이 아예 없으므로 "되돌릴 이전 상태"가 존재하지 않게 됨 — 새로고침과 동일한 효과를 이 컴포넌트 단위로만 재현

실제로 `curtl.style.transform`이 `"none"`(완전 원본값)이고 해당 엘리먼트가 새 객체(`isNewNode: true`)임을 확인해 검증함.

## 4. 넷플릭스풍 로비 개편 (여러 차례 시행착오)

- **포스터 위에 버튼/칩 배치**: "완료된 약속"/"다가오는 약속" 칩과 "입장하기" 버튼을 원래 포스터 아래 별도 줄에 있던 것을, 넷플릭스 히어로 배너처럼 **포스터 이미지 위(타이틀/태그라인 바로 아래)로 직접 얹음**(`.fourcut-poster-actions`)
- **완성작 카드 줄 (`.fourcut-row`) — 추가 → 제거 → 재추가**: 처음엔 얇은 썸네일+텍스트로 만들었다가 "카드로 나눈 게 보기 싫다"는 피드백에 완전히 제거. 이후 "전체를 넥플릭스처럼, 아래 목록도 있으면 좋겠다"는 재요청을 받고, **이번엔 모달 전체를 다크 테마로 통일**하고 카드도 넷플릭스 "Trending Now"처럼 이미지 위에 그라디언트 캡션으로 제목을 얹는 방식(`.fourcut-row-card`/`.fourcut-row-thumb`/`.fourcut-row-scrim`/`.fourcut-row-badge`)으로 다시 만듦. 카드 클릭 시 `fourCutEnterAt(index)`로 해당 완성작으로 바로 입장
- **모달 전체 다크 테마화**: `.modal-box.fourcut-gallery-modal` 배경을 라이트 카드 기본 스타일에서 포스터와 이어지는 어두운 그라디언트로 교체, 헤더 텍스트(`h3`/서브타이틀/닫기 버튼)도 밝은 색으로 변경
  - **부수 발견 버그**: 전역 규칙 `.modal-box h3 { color: var(--primary-green); }`(다른 라이트 모달들을 위한 규칙)이 동일 특이도(0,1,1)로 소스 순서상 더 뒤에 있어서 내가 새로 만든 `.fourcut-lobby-headtext h3` 색상 지정을 조용히 덮어쓰고 있었음. `.modal-box.fourcut-gallery-modal .fourcut-lobby-headtext h3`로 특이도를 명시적으로 올려서 해결, 더 이상 안 쓰는 중복 규칙(`.fourcut-gallery-head h3`)은 삭제
- **나가기 버튼 위치**: 극장 좌상단 → 하단 가운데(‹ 1/2 › 내비 바로 위, `bottom:70px`)로 이동 — 사용자 편의 요청

## 5. 캐시 버전 번호 — 이번에도 반복된 실수

`desktop.js`/`desktop.css`를 여러 차례 고치면서 `index.html`의 `?v=` 번호를 안 올린 채로 "고쳤다"고 안내한 적이 있었음(0704 작업기록에도 이미 같은 주의사항이 적혀 있었는데 또 반복). 사용자가 "새로고침하면 되는데 안 하면 커튼이 안 닫혀있다"고 보고한 것의 상당 부분이 실은 **아직 반영 안 된 옛 코드를 보고 있었던 것**으로 드러남. 이후로는 `desktop.js`/`desktop.css` 중 하나라도 고치면 그 즉시 버전을 올리는 것으로 재확인. 현재 `desktop.css?v=67`, `desktop.js?v=20260705j`.

## 6. 스크롤 트리거 애니메이션 — 두 번 시도, 최종 CSS 방식으로 정착

"스크롤 내리면 나오는 애니메이션을 적용해보자"는 요청에 "전체 약속 보기" 카드 목록(스케줄 탭, `renderScheduleList`)에 적용을 시도했다.

1. **1차: JS `IntersectionObserver`** — 카드가 화면에 한 번 보이면 fade-in. 그런데 이 카드 목록은 **가로 캐러셀**이라, 처음 가로 스크롤 범위 밖에 있던 카드는 옵저버가 "보인 적 없음"으로 판단해 **영구적으로 투명(opacity:0)** 상태로 남는 심각한 회귀가 발생(전체 10개 중 2개만 보이는 사고). 즉시 전면 되돌림
2. **2차: CSS `animation-timeline: view()`** — JS 옵저버 없이 스크롤 위치에 애니메이션 진행률을 직접 연결하는 최신 CSS 기능으로 재구현. 기본적으로 **block(세로)축**을 기준으로 삼기 때문에, 가로 캐러셀 스크롤 위치와 무관하게 "그 줄이 세로로 화면에 들어오면" 다같이 나타나 1차의 버그가 구조적으로 재발할 수 없음
   - 처음엔 카드(`.growth-card`) 하나하나에 걸었는데, 각 카드에 이미 `hover`/`is-selected` 상태의 `transform`이 있어서 겹치지 않으려고 `opacity`만 애니메이션했더니 효과가 너무 미미해서 "눈에 안 띈다"는 피드백을 받음
   - **최종**: 개별 카드가 아니라 캐러셀 줄 전체(`.growth-card-rail`)에 애니메이션을 걸어서, 카드별 상태와 부딪힐 일이 없이 `translateY(40px)` 슬라이드업 + 페이드인을 큼직하게 적용(`animation-range: entry 0% entry 90%`)
   - `@supports not (animation-timeline: view())` 폴백으로, 이 기능을 지원 안 하는 브라우저에서 요소가 영영 안 보이는 일이 없도록 안전장치 마련(1차 사고의 재발 방지 차원에서 필수로 넣음)

## 검증 내용

- 이번 세션 내내 프리뷰용 헤드리스 브라우저 탭이 `document.hidden === true`로 고정되는 현상이 반복 발생 — WAAPI 애니메이션이 실시간으로 진행되지 않고, 새로 만든 순수 `IntersectionObserver` 테스트도 3초간 콜백이 전혀 안 오는 것으로 확인됨(`preview_screenshot`도 매번 타임아웃). 이는 테스트 도구 자체의 렌더링 파이프라인 한계로 판단, 코드 검증은 `getComputedStyle`/`getBoundingClientRect`/`transition:none` 강제 후 즉시 값 확인 등 애니메이션에 의존하지 않는 방식으로 대체
- 극장 커튼 리셋: 나가기 직후(애니메이션 대기 없이) `curtl.style.transform`이 즉시 닫힌 값(`translateX(0)`)으로 돌아오는지, 재입장 후 화면/좌석/조명이 모두 초기 상태인지 확인
- 로비 카드 줄: 완성작 2개로 테스트 시 카드 2장이 올바른 제목/썸네일로 렌더링되고, 클릭 시 해당 완성작이 정확히 선택되어 입장하는 것 확인
- `.modal-box.fourcut-gallery-modal .fourcut-lobby-headtext h3` 특이도 수정 후 헤더/서브타이틀/닫기 버튼 색상이 실제로 밝은 색으로 계산되는지 `getComputedStyle`로 확인
- `growth-card-rail`에 스크롤 애니메이션 적용 후 카드 16개(데스크톱+모바일) 전부 `opacity:1`로 정상 노출되는지, hover/`is-selected`의 기존 `transform`(-3px)이 그대로 살아있는지 확인

## 팀 공유 시 주의할 점

- **`desktop.js`/`desktop.css`를 고치면 `index.html`의 `?v=` 번호를 반드시 같이 올릴 것.** 이번 세션에서도 두 번이나 이 실수로 "고쳤다는데 반영이 안 된다"는 혼선이 있었다
- **극장(`#dt-fourcut-theater`) 안쪽 요소를 새로 추가/수정할 땐 `fourCutCaptureTheaterTemplate()`가 페이지 로드 후 최초 1회 캡처한 마크업이 "나가기"마다 그대로 복제된다는 점을 기억할 것.** 즉, 극장 내부 DOM은 매번 새 노드로 교체되므로 특정 노드에 커스텀 데이터를 임의로 붙여두는 방식은 나가기 후 사라진다
- **`fourCutAnim()` 헬퍼는 항상 호출 시점에 기존 애니메이션을 취소하고 새로 시작한다.** 같은 요소를 여러 단계(입장/착석/넘기기)에서 건드릴 때 이 규칙을 깨지 말 것 — 안 그러면 컴포지트 순서에 따라 최종값이 불확실해지는 문제가 재발할 수 있다
- **스크롤 트리거 애니메이션을 새로 추가할 땐 절대 개별 캐러셀 아이템에 `IntersectionObserver` 기반 "한 번 보이면 노출" 방식을 쓰지 말 것.** 가로 스크롤 밖에 있던 아이템이 영구적으로 안 보이게 되는 사고가 이미 한 번 났다. `animation-timeline: view()` + 필요시 컨테이너 단위 적용 + `@supports not (...)` 폴백 조합을 기본값으로 삼을 것
- **인생4컷 극장 관련 함수는 전부 `desktop.js`의 `fourCut*` 접두사로 모여있다**: `fourCutMemories`(완성작 목록 조회), `fourCutStartPoster`/`fourCutStopPoster`(포스터 슬라이드쇼), `fourCutCaptureTheaterTemplate`/`fourCutResetChildren`/`fourCutResetTheater`(리셋), `fourCutRenderScreen`/`fourCutSpawnDust`(상영 콘텐츠), `fourCutEnter`/`fourCutEnterAt`/`fourCutSit`/`fourCutNav`/`fourCutFilmAdvance`/`fourCutExit`(단계 전환)
- 기존 코르크보드 갤러리 관련 코드(`renderFourCutGalleryCard`, `fourCutPinRotation`, `.fourcut-gallery-grid`/`.fourcut-gallery-card` 등 CSS)는 전부 삭제됨 — 관련 문의가 오면 "인생4컷 극장"으로 완전히 대체됐다고 안내할 것
