# 0710 — 경험치 · 저장 공간 · 기록 모달 문제 해결 작업기록

> 대상: 본선 `test-web-design/02-main/`
> 검증: 정적 서버(8890) + DOM/computed + `localStorage.setItem` 패치로 용량 초과 상황 시뮬레이션. (02-main은 헤드리스 스크린샷이 타임아웃되어 스크린샷 대신 상태값으로 검증)

팀원(kimgyubi) XP 문서 검토 → 안전한 XP 버그만 이식 → 그 과정에서 드러난 "기록하기 모달이 안 닫히는" 저장 공간 문제까지 연쇄로 해결한 기록. 각 건을 **문제 – 원인 – 솔루션**으로 정리한다.

---

## 1. 경험치(XP) 100% 초과 표기 버그

- **문제**: 방치형 보상 등 한 번에 큰 XP를 받으면 게이지가 100%를 넘겨 150%처럼 비정상 표기.
- **원인**: `grantXP`의 레벨업 판정이 **단일 `if`** ([space.js](../02-main/js/space.js) `grantXP`)라, 진행도에서 100을 **한 번만** 빼서 남은 초과분이 여전히 100 이상이면 처리되지 않음. (예: 50% + 200XP → level+1, 진행도 150 그대로)
- **솔루션**: `while` 루프로 **초과분만큼 연속 레벨업** 후 남은 잉여만 진행도로 이월. 만렙 초과분도 정리.
  - 팀원 버전과 달리 ①티어 판정은 본선의 정확한 `newTier > oldTier` 유지(팀원의 `%111`은 경계 건너뛰면 누락) ②레벨업 토스트 유지(팀원은 토스트 제거 방향이라 미적용).
- **검증**: `Lv.3(50%)+200XP → Lv.5(50%)`, `Lv.5(90%)+320XP → Lv.9(10%)`, 진행도 항상 <100%.

---

## 2. "기록 남기기"를 눌러도 모달이 안 닫힘

- **문제**: 추억 기록하기에서 "기록 남기기"를 눌러도 모달이 유지되고, "변경사항 저장에 실패했어요. 저장 공간을 확인해주세요" 토스트만 뜸.
- **원인 (2단)**:
  1. **근본**: 사진(base64)이 많이 쌓여 localStorage(~5MB) 포화 → 저장(`setItem`)이 `QuotaExceededError`로 실패.
  2. **직접**: `saveWritePost` 실행 순서상 `saveGroupsData()`는 예외를 try/catch로 삼키지만(토스트만), 그 **뒤에 호출되는 `grantXP` 안의 `localStorage.setItem`이 무방비**([space.js](../02-main/js/space.js))라 예외를 다시 던짐 → `saveWritePost`가 마지막 줄 `closeWriteModal()`([index.html](../02-main/index.html) `saveWritePost`)에 도달하기 전에 중단 → **모달이 안 닫힘**. (게시글은 메모리에만 남고 저장 안 돼 새로고침 시 사라지는 유령 글)
- **솔루션**:
  - `grantXP`의 직접 `setItem` → **안전 래퍼 `saveGroupsData()`** 로 교체(실패해도 throw 안 함). 모든 grantXP 경로(클릭/일정/게시글)가 안전해짐.
  - `saveGroupsData()`가 **성공/실패(boolean) 반환** ([utils.js](../02-main/js/utils.js)) → 호출부가 실패를 감지 가능.
- **검증**: setItem이 quota 에러를 던지도록 패치 후 저장 → 예외 안 던짐 · 모달 닫힘 · 게시글 롤백.

---

## 3. 저장 실패 시 유령 글 / 근본 원인(용량) 자동 회복

- **문제**: 저장 실패 시 게시글이 메모리에만 추가돼 화면엔 보이지만 새로고침하면 사라짐. 근본적으로 저장 공간이 부족.
- **원인**: 기존 사진 재압축 인프라(`compactStoredPhotos`)가 **4컷 저장 경로에만** 연결돼 있고, 글쓰기 저장 경로엔 회복 로직이 없었음.
- **솔루션**: `saveWritePost`에 4컷과 동일한 **"저장 실패 → 재압축 → 1회 재시도 → 그래도 실패 시 롤백"** 패턴 적용.
  1. 조용히(토스트 없이) 저장 시도
  2. 실패 → `compactStoredPhotos()`로 기존 저장 사진 재압축(데이터 보존)해 공간 회수
  3. 재시도 성공 → 정상 등록 + XP + 모달 닫힘
  4. 그래도 부족 → 방금 글 **롤백**(유령 글 방지) + 안내 + 모달 닫힘
- **검증**: ①정상 저장 ②첫 실패→재압축→재시도 성공(영구 저장) ③재압축해도 실패→롤백, 세 시나리오 모두 모달 닫힘.

---

## 4. 저장 용량 절감 (근본 예방) + 화질 재조정

- **문제**: 애초에 사진이 커서 저장 공간이 금방 참.
- **원인**: 업로드 압축이 1080px·JPEG 0.7이고 한 게시글 사진 상한이 30장이라, 게시글당 저장량이 큼.
- **솔루션 & 최종값** ([utils.js](../02-main/js/utils.js), [index.html](../02-main/index.html)):
  - 사진 장수 상한 **30 → 15장** (상수 `WM_PHOTO_LIMIT` + 라벨)
  - 업로드 압축: 처음 900px·0.62로 낮췄다가, 사용자 요청으로 **화질을 다시 올려 1000px·0.72** 로 확정.
  - 압축 상수는 `compactStoredPhotos`도 공유하므로 재압축 회수량에도 반영.
- **검증(합성 이미지)**: `1000px/0.72` → 1000×700·JPEG·38KB. 원본(1080/0.7=42KB) 대비 **8% 작고 화질은 동등~약간 높음**. 장수 상한 절반과 합쳐 게시글당 최대 저장량 대폭 감소.

## 확정 원칙 (재발 방지)
- **`groupsData` 저장은 항상 `saveGroupsData()` 안전 래퍼로** — 직접 `localStorage.setItem`을 쓰면 quota 초과 시 throw되어 뒤 로직(모달 닫기 등)이 중단됨.
- **큰 데이터를 넣는 저장부는 "재압축→재시도→롤백" 패턴** 을 따른다(4컷·글쓰기 공통).
- 저장 실패는 조용히 삼키지 말고 사용자에게 명확히 안내하고, 유령 데이터는 롤백한다.
