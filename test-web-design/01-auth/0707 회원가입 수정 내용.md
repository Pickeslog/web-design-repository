## 2. 1차 수정 — "새로고침하면 카드 뒤 배경이 안 움직인다" 버그

### 원인 조사 과정
- 처음엔 브라우저의 `backdrop-filter` 컴포지팅 지연 문제로 추정 → `.bg-canvas`/`.orb`/`.card`에 `will-change`, `transform:translateZ(0)` 등 GPU 레이어 강제 프로모션 적용. **효과 없었음.**
- 재조사 결과 **진짜 원인**: 3D 스택 카드 효과를 만드는 `.card-wrap::before`(카드 뒤에 겹쳐 보이는 올리브색 카드)가 **완전 불투명한 단색 그라데이션**이었음. 유리 카드의 `backdrop-filter`가 실제로 블러링하는 대상이 뒤에서 드리프트하는 오브(orb) 애니메이션이 아니라 이 고정된 불투명 카드였기 때문에, 카드 바로 뒤 영역만 정적으로 보였던 것.
- `.card-wrap::before` 배경을 반투명(`rgba`) + `backdrop-filter:blur(6px)`로 변경해서 오브 움직임이 비치도록 1차 수정.

### 결과
사용자 확인 결과 여전히 위화감이 있어("UI가 너무 많이 망가져서 어디부터 손대야 할지 모르겠다"), 부분 수정 대신 페이지 전체를 재설계하기로 결정.

## 3. 2차 수정 — 회원가입 페이지 전면 재설계

### 요청 사항
- 3D 느낌(스택 카드, 플립 카드) 과감히 제거, 현업 스타일(플랫 디자인)로 재구성
- 정규표현식 검증 실패 시 경고 문구 대신, **로그인 페이지(`login.html`)와 동일한 방식**으로 입력창이 빨개지며 좌우로 흔들리는 UX로 통일

### 참고한 기준: `login.html`
- 색상 토큰: `--forest #073b24`, `--leaf #16874b`, `--mint #50d990`, `--cream #f7fbf6`, `--paper #fff`, `--text #0e2d1d`, `--muted #638772`, `--line rgba(22,135,75,.18)`, `--glow rgba(80,217,144,.22)`, `--warn #b45309`
- 검증 실패 시 `shake(id)` 함수로 `shakeInput` 키프레임(테두리 빨개짐 + 좌우 흔들림)만 적용, 별도 경고 문구 없음
- 비밀번호 보이기 상태일 때만 뜨는 "조심하세요! 비밀번호가 보여요!" 안내는 유지되는 패턴

### 디자인 변경 내용
| 항목 | 이전 | 이후 |
|---|---|---|
| 카드 구조 | `.card-wrap::before`로 카드 뒤에 겹친 카드(3D 스택) | 제거, 단일 플랫 카드 |
| 유리 효과 | `backdrop-filter` 글래스모피즘 | 제거, 불투명 흰 카드(`var(--paper)`) + 은은한 그림자 |
| 배경 | `.bg-canvas` + 3개 오브 드리프트 애니메이션 | 제거, 로그인과 동일한 정적 radial-gradient 배경 |
| 닉네임 ↔ 생년월일 전환 | `perspective` + `rotateY(180deg)` 3D 플립 카드 | 단순 크로스페이드(opacity + translateY, 3D 없음), `flipped` 클래스/JS 함수명은 유지 |
| 로고 클릭 이스터에그 | 팝업 메시지(90%) + 카드 쪼개짐 연출(10% 희귀 이벤트) | 카드 쪼개짐 연출 제거, 팝업 메시지만 유지 |

### 검증 로직 변경 내용
- 이메일 검증: `checkEmail` 등 실시간(oninput/onblur) 경고 문구 로직 전부 제거 → `validateStep0()`에서 제출 시점에만 정규식 검사, 실패 시 `shake('email')`

## 6. 3차 수정 — 스텝 인디케이터 애니메이션

**요청**: 다음 단계로 넘어갈 때 스텝 바(진행 표시 점)가 색이 한번에 확 바뀌지 말고 점점 차오르는 느낌으로.

- `.step-dot`을 트랙(회색 배경)으로 두고, 내부에 `::after` 채움 레이어를 추가
- `::after`는 기본 `transform:scaleX(0)`(transform-origin:left), `.active`/`.done` 클래스가 붙으면 `scaleX(1)`로 전환 — `transition:transform .55s cubic-bezier(.22,.7,.32,1)`
- 완료된 단계는 민트색(`--mint`), 진행 중인 단계는 리프색(`--leaf`)으로 채워짐
- 기존처럼 색이 즉시 바뀌는 대신 왼쪽→오른쪽으로 차오르는 시각 효과로 변경됨

## 7. 4차 수정 — 프로필 단계를 사진 / 닉네임·생년월일로 분리

**요청**: 기존 3단계(프로필: 사진+닉네임+생년월일을 한 화면에서 처리)를 반으로 쪼개서, 사진을 먼저 등록받고 "다음" 버튼으로 넘어간 뒤, 별도 화면에서 닉네임+생년월일을 받고 "프로필 저장하기"로 마무리.

### 구조 변경
- 4단계 위저드 → **5단계**로 확장 (`step-0`~`step-4`), 스텝 바 점도 4개 → **5개**로 증가
- **Step 2 (사진)**: "프로필은 무엇으로 하실건가요? / 친구들이 알아볼 수 있는 사진을 골라주세요." — 사진 업로드만, 버튼 텍스트 "프로필 저장하기 →" → **"다음"**으로 변경
- **Step 3 (닉네임·생년월일)**: "닉네임과 생년월일을 알려주세요 / 친구들에게 보여질 이름과 생일(선택)을 정해주세요." — 두 입력란만 배치, 버튼 "프로필 저장하기 →" (여기서 저장 및 다음 단계 이동)
- **Step 4**: 기존 가입 완료 화면 (인덱스만 3→4로 이동)

### 함께 정리한 것
- 이전에 "사진 선택하면 닉네임 입력란이 슬라이드다운으로 펼쳐지는" 임시 UX(직전 세션에서 추가)는, 이제 단계 자체가 나뉘었으니 불필요해져서 제거 (`showProfileFields`, `.profile-fields`/`.profile-hint` 관련 CSS·JS 삭제)
- `validateStep2`(구, 닉네임 검증) → `validateStep3`으로 이름 변경, 로직은 동일(닉네임 정규식 실패 시 `shake('nickname')`)
- `goStep(n)`의 가입완료 저장 로직 트리거 조건 `n===3` → `n===4`로 변경

## 8. 5차 수정 — Enter 키 내비게이션 (회원가입 + 로그인 공통)

**요청**: input에서 Enter를 누르면 다음 input으로 이동하고, 마지막 input까지 값을 다 채운 뒤 Enter를 누르면 다음 단계/제출로 넘어가는 기능.

- 공통 헬퍼 함수 `enterNext(event, nextId, submitFn)` 추가 (signup.html, login.html 양쪽에 동일하게 작성)
  - `nextId`가 있으면 해당 id 요소로 포커스 이동
  - 없으면(마지막 input) `submitFn()` 실행 — 기존 검증 함수를 그대로 재사용하므로 값이 유효하지 않으면 기존과 동일하게 `shake()`만 발생하고 다음 단계로 진행되지 않음
- **로그인**: 이메일 → Enter → 비밀번호 포커스 → Enter → `login()` 실행
- **회원가입 1단계**: 이메일 → Enter → 비밀번호 포커스 → Enter → 다음 단계
- **회원가입 3단계**(닉네임/생년월일): 닉네임 → Enter → 다음 단계로 저장. 생년월일은 읽기 전용(모달로만 입력)이라 체이닝 대상에서 제외
- 브라우저에서 실제 `KeyboardEvent('keydown', {key:'Enter'})`를 디스패치해 검증 — 유효한 값일 때만 다음 단계/로그인 완료(메인 화면 리다이렉트)까지 확인, 유효하지 않으면 흔들림만 발생하고 진행되지 않는 것도 확인

## 9. 6차 수정 — 약관 동의 체크박스 키보드 접근성 (Enter 안 먹는 버그)

**문제**: 약관 동의 항목들이 `<div onclick>`으로만 구현돼 있어 애초에 `tabindex`가 없는 상태 → 키보드로 포커스 자체가 불가능해서 Tab으로 이동도, Enter/Space 입력도 전혀 먹히지 않았음.

### 수정 내용
- 전체동의/필수 2개/선택 1개, 총 4개의 `.terms-row`에 `tabindex="0"`, `role="checkbox"`, `aria-checked` 속성 추가
- 키보드 핸들러 `handleTermsKey(event, action)` 추가:
  - **Space**: 네이티브 체크박스 관례에 맞춰 해당 항목 체크/해제 토글
  - **Enter**: 다음 단계로 진행(`goStep(2)`) — 필수 항목 미동의 시 기존과 동일하게 약관 박스가 흔들리며 진행 차단
- `toggle()`/`toggleAll()`/`updateAllCheck()` 함수에서 `aria-checked` 속성도 함께 갱신하도록 수정
- `.terms-row:focus-visible`에 아웃라인(글로우 박스섀도) 추가해서 키보드 포커스가 시각적으로 보이도록 함
- `KeyboardEvent` 디스패치로 검증: Space로 토글, Enter로 다음 단계 진입까지 정상 동작 확인 (`aria-checked`/`classList`/`active` 클래스 상태 기준)
