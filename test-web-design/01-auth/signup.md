# 회원가입 (Sign up) — 화면 명세서

> **위치**: `01-auth/signup.html` (독립 페이지). 의존: `../02-main/css/global-theme.css`·`success-overlay.*`.
> **최종 갱신**: 2026-07-10 · **실제 구현 기준**(팀원 개선본 이식 — 5단계 위저드·단계 진행바·약관 키보드 접근성·성공 오버레이).

---

## 1. 화면 목적

신규 계정을 **단계별 위저드**로 생성한다. 한 화면에 몰아넣지 않고 계정 → 약관 → 확인 → 프로필 순으로 나눠 부담을 줄인다.

---

## 2. 진입 · 이탈 경로

**진입**: 로그인 화면의 "회원가입" 링크.
**이탈**: 가입 완료 → 성공 오버레이 → **로그인(`login.html`)**. 각 단계에서 "← 이전으로" 이동.

---

## 3. 화면 레이아웃

```
┌───────────────────────────────┐
│  ●───●───○───○───○   (단계 진행바) │
│                                │
│        [ 현재 단계 뷰 ]           │
│                                │
│   [← 이전으로]      [다음 단계 →] │
└───────────────────────────────┘
```
- 상단 **step-bar**(5개 점)로 진행 상태 표시(active/done).

---

## 4. 단계(뷰)별 상세

| 단계 | 내용 |
|---|---|
| **① 계정** | 이메일 + 비밀번호(표시토글 + 보임 시 보안 경고) |
| **② 약관 동의** | [필수]/[선택] 약관. 각 항목 **펼쳐보기 토글**(키보드 접근성: `aria-expanded`) |
| **③ 확인** | 프로필 **사진 등록**(선택) — `signup.html:302-343`의 profile-picker |
| **④ 프로필** | 닉네임 + 생년월일(선택) — "친구들에게 보여질 이름" |
| **⑤ 완료** | 가입 완료 → 성공 오버레이 → 로그인 |

> ### ⚠️ 프로덕션은 ③ 사진 단계를 가져오지 않는다 — 의도된 편차 (리더 확정 2026-07-27)
>
> `clov-web`의 가입은 **4단계**다(`Signup.jsx` `STEP_COUNT = 4`). **목업의 ③ 사진 단계는 일부러 뺐고, 앞으로도 가져오지 않는다.** 프로필 사진은 **가입 후 사용자설정**에서 등록한다.
>
> **근거 1 — 계약이 먼저 그렇게 정했다.** `docs/API-CONTRACT.md` §4: *"프로필 이미지는 **가입 시 받지 않는다**(기본 이미지). 가입 후 `POST /users/me/profile-image/presign`으로 업로드."*
>
> **근거 2 — 지금 구조로는 기술적으로 막힌다.** `POST /users/me/profile-image/presign`은 인가가 **"본인"** 이다(계약 §5). 사진 단계는 가입 API 호출 **전**이라 그 시점엔 계정도 토큰도 없어 **401**로 막힌다. 억지로 하려면 파일을 메모리에 들고 있다가 가입 성공 후 업로드하는 **가입 트랜잭션 밖의 후처리 흐름**이 필요하고, "계정은 생겼는데 사진만 실패" 케이스까지 따로 다뤄야 한다.
>
> **근거 3 — 사진은 선택 항목**이라 가입 단계를 하나 늘려 이탈을 만들 이유가 약하다.
>
> 되돌리려면 **계약 §4를 먼저 고치고**(SSOT 선행) 위 후처리 흐름을 설계한 뒤 착수해야 한다. 화면만 만들면 안 된다.
>
> 관련: clov-web #145(이 편차를 버그로 보고 올라온 이슈 — 위 이유로 close)

## 5. 사용자 액션 & 상태 전이

| 액션 | 결과 |
|---|---|
| 다음 단계 → | 유효성 통과 시 다음 뷰로, 진행바 갱신 |
| ← 이전으로 | 이전 뷰로(입력 유지) |
| Enter | 다음 입력/단계로 이동 |
| 약관 펼쳐보기 | 약관 본문 토글(키보드 지원) |
| 가입 완료 | 성공 오버레이 → 로그인 이동 |

- **상태**: 현재 단계 인덱스(0~4), 각 단계 입력값, 약관 동의 여부.

---

## 6. 데이터 / 저장

- 가입 입력값(이메일·비번·닉네임·생일·약관 동의)을 단계 진행 동안 보관, 완료 시 계정 생성 흐름으로.

---

## 7. 예외 / 경계 케이스

- **필수 미입력 / 필수 약관 미동의**: 다음 단계 진행 차단(안내).
- **비밀번호 보임 상태**: 보안 경고 문구.
- **이전 이동 시 입력 유지**: 되돌아와도 값 보존.
