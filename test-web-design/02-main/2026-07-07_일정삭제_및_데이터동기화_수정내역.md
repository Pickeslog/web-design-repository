# 🍀 2026-07-07 일정계획 삭제 및 생성/수정 데이터 영구 저장 오류 해결 내역

본 문서는 2026년 7월 7일에 진행된 일정계획 삭제 버튼 작동 및 데이터 동기화 오류 해결 내역을 기록한 문서입니다.

## 1. 일정계획 삭제 및 저장 시 데이터 영구 보존 동기화
- **문제점**:
  1. 기존 D-day 일정을 수정 모달 혹은 리스트의 즉시 삭제 버튼으로 삭제(`deleteSchedule`)하거나, 새로 생성 및 수정(`saveSchedule`)할 때, 인메모리 객체인 `groupsData`는 수정되었으나 브라우저의 로컬 스토리지(`localStorage`)로 데이터를 영구 저장해주는 `saveGroupsData()` 호출이 누락되어 있었습니다. 이로 인해 페이지를 새로고침하거나 다른 탭으로 이동할 때 변경된 데이터가 유지되지 않고 원본으로 부활하는 현상이 있었습니다.
  2. `js/utils.js` 내부에서 정의된 `saveGroupsData` 유틸리티 함수가 전역 객체인 `window`로 노출되지 않아, 개별 탭의 독립 스크립트인 `js/schedule.js` 등 외부 영역에서 호출할 수 없는 상태였습니다.

- **개선 내용**:
  1. **`js/utils.js` 전역 스코프 바인딩 및 모달 함수 널 가드(Null-guard) 추가**:
     - `utils.js`의 `saveGroupsData` 함수를 `window.saveGroupsData = saveGroupsData;` 코드를 통해 전역 객체에 명시적으로 노출시켰습니다.
     - `openModal`과 `closeModal` 함수에서 대상 엘리먼트 존재 여부를 사전에 체크하는 방어 코드(`if (!el) return;`)를 적용했습니다. 이를 통해 모바일 D-day 모달(`mb-schedule-modal`)이 화면상에 없어 발생하던 `TypeError`를 근원적으로 제거했습니다.
  2. **`js/data.js` 전역 변수 노출**:
     - 타 탭 파일 간의 데이터 조회 및 조작 시 `ReferenceError`가 나지 않도록, 인메모리 핵심 상태 값인 `selectedScheduleIds`, `groupsData`, `activeGroup`을 명시적으로 전역 `window` 객체에 바인딩했습니다.
  3. **`js/schedule.js` 방어적 데이터 동기화 연동**:
     - 스코프 한계로 인해 `saveGroupsData is not defined` 런타임 오류가 발생할 수 있는 잠재적 위험을 완전히 차단하기 위해, `deleteSchedule`과 `saveSchedule` 내부에서 단순히 `saveGroupsData()`를 호출하는 대신 **`typeof window.saveGroupsData === 'function'` 조건식으로 실행 여부를 사전에 안전 검증**하도록 변경했습니다.
     - 전역 함수가 조회되지 않는 예외적인 경우에도 기능이 100% 무중단 실행되도록, **`localStorage.setItem('clov_groupsData', JSON.stringify(groupsData))`로 직접 데이터를 로컬스토리지에 저장하는 폴백(Fallback) 안전장치를 추가**했습니다.
     - `schedule.js` 내부에서 전역 `selectedScheduleIds`를 호출할 때 `window.selectedScheduleIds`로 지시하여 식별자 참조 안전성을 극대화했습니다.
  4. **`js/schedule.js` 내 불필요 모바일 코드 전면 정리 및 정규화**:
     - 데스크톱 전용 뷰 포트 환경에 집중하기 위해, 모바일 화면을 처리하기 위한 불필요한 배너 조작 로직 및 `renderScheduleList('mb')` 호출부를 모두 걷어냈습니다.
     - `renderScheduleList`, `saveScheduleContent`, `deleteScheduleFromModal`, `toggleScheduleSidebar`, `scrollGrowthCards` 등의 제어 로직이 오직 데스크톱(`dt`) 뷰 환경에서만 동작하도록 가드를 적용했습니다.
     - `openScheduleModal`, `saveSchedule`, `uploadStagePhoto` 내의 잔존 모바일 뷰 렌더링 호출을 모두 폐기하고 데스크톱 모달로 통일했습니다.
  5. **D-day 삭제 기능의 전면 철거 및 단일화 재설계 (처음부터 새로 만들기)**:
     - 복잡하게 얽혀 있던 기존 `deleteSchedule`과 `deleteScheduleFromModal` 함수를 모두 삭제하고, 처음부터 다시 **`window.deleteSchedule(scheduleId)` 단 하나의 통합 삭제 인터페이스로 정제하여 개발**했습니다.
     - 모달 속 삭제 버튼은 HTML 상에서 `onclick` 매핑을 제거하고, 모달을 오픈하는 **`openScheduleModal` 실행 시점에 대상 일정의 ID를 가지고 있는 삭제 이벤트 핸들러를 동적으로 바인딩(Dynamic Binding)**하도록 변경하여 가독성과 무결성을 극대화했습니다.
  6. **`index.html` 브라우저 강력한 캐싱 해제 (Cache-busting)**:
     - 수정한 자바스크립트 소스 코드(`data.js`, `utils.js`, `schedule.js`)가 브라우저에 즉각 무중단 반영되도록 `index.html`에서 로드하는 스크립트 버전 파라미터를 고유 캐시 버전 번호인 `v=20260707_3`으로 인크리먼트했습니다.

## 2. 2차 수정: groupsData, activeGroup 전역 변수 참조 오류 예외 해결
- **문제점**:
  - `data.js` 내에 `let`으로 정의된 핵심 변수(`groupsData`, `activeGroup`)가 `window` 전역 객체에 바인딩되었음에도 불구하고, 독립 스크립트인 `schedule.js` 내에서 식별자 `groupsData`와 `activeGroup`을 직접 참조하면서 `ReferenceError: groupsData is not defined` 런타임 오류가 발생하여 삭제 기능이 정상적으로 실행되지 않는 현상을 확인했습니다.
- **개선 내용**:
  - `js/schedule.js` 내부에서 `groupsData` 및 `activeGroup` 변수를 사용하는 모든 부분(삭제, UI 업데이트, D-day 근접값 연산, 업로드 가드 체크 등 15군데)을 명시적으로 `window.groupsData`와 `window.activeGroup`을 참조하도록 변경하여 식별자 유실 및 싱크 어긋남 버그를 완벽하게 차단했습니다.

## 3. 3차 최종 결정 사항: 일정 삭제 기능 지연(보류) 기록
