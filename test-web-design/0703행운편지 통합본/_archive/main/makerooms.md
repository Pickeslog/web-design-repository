## 화면 구성 (3개 패널 전환)

데스크톱 브라우저 뷰와 모바일 앱 뷰를 한 페이지에 나란히 띄워 비교할 수 있게 했습니다. 한 화면 안에서 `showPanel(view, name)`으로 목록 → 생성 폼 → 완료 패널을 전환합니다.

### 데스크톱 전용 카드 그리드 (모바일과 다른 레이아웃)
한동안 "웹/모바일에서 똑같은 구조"를 원칙으로 삼았는데, 막상 써보니 데스크톱에서는 모바일과 같은 좁은 한 줄 리스트를 그냥 늘려놓은 모양이라 허전했습니다. 그래서 방 목록만큼은 데스크톱 전용으로 다시 설계했습니다.

- **마크업은 그대로, CSS로만 분기**: `renderRoomList`가 만드는 HTML 구조(JS)는 데스크톱/모바일이 완전히 동일합니다. `.desktop-window` 스코프 CSS만으로 같은 `.room-row`를 모바일에서는 가로 한 줄로, 데스크톱에서는 세로형 카드로 다르게 그립니다(`flex-direction: column`, 사진/이름/소개글/D-day를 `order`로 재배치).
- **그리드 래퍼**: `.room-list`를 그대로 두면(JS가 `innerHTML`을 갈아끼우는 대상이라 지울 수 없음) `display: contents`로 투명하게 만들고, 그 부모 `.room-grid`에 `grid-template-columns: repeat(auto-fill, minmax(260px, 1fr))`를 줘서 방 카드들과 "+ 새 우정공간 만들기" 타일이 같은 그리드의 칸으로 나란히 배치됩니다.
- **편집 모드 컨트롤은 카드 위에 떠 있는 형태로**: 가로 리스트에서는 삭제·순서·수정 버튼이 본문과 한 줄에 나란히 있었지만, 세로 카드에서는 그게 어색해서 `position: absolute`로 카드 우측 상단에 띄우고, 카드 자체는 `padding-top`을 늘려 내용과 겹치지 않게 했습니다.
- **FLIP 애니메이션도 2차원으로 확장**: 가로 리스트에서는 위/아래(`top`)만 비교하면 됐지만, 그리드에서는 순서가 바뀌면 칸이 가로로도 이동할 수 있어서 `animateReorder`가 이제 `top`과 `left`를 모두 비교해 `translate(x, y)`로 이동시킵니다.
- **소개글은 2줄까지 보여줌**(`-webkit-line-clamp: 2`): 가로 리스트에서는 한 줄 말줄임이었지만, 카드는 세로 공간이 넉넉해서 소개글+활동시각을 두 줄까지 보여줍니다.
- **방 만들기/완료 패널은 폼이라 그리드의 영향을 받지 않게** `#dt-panel-create`, `#dt-panel-success`에 별도로 `max-width: 420px`을 줘서 좁게 유지했습니다.

### 1. 우정공간 목록 (기본 화면)
- 방마다 대표 사진/아이콘, 이름·레벨, 소개글을 한 줄로 보여줍니다.
- 다가오는 약속(D-day)이 있는 방만 사진 영역에 강조색 테두리를 주고, 오른쪽에 `D-3 · 토요일 약속` 같은 칩을 별도로 띄웁니다. 약속이 없는 방은 칩 없이 비워둡니다 — 인기/방장 같은 위계가 아니라 "지금 행동할 일이 있는가"만 강조 기준으로 삼았습니다.
- 맨 아래 점선 테두리의 "+ 새 우정공간 만들기" 버튼으로 생성 폼 패널로 이동합니다.

### 편집 모드 (iOS 리스트 편집 패턴)
- 목록 위 툴바의 "편집" 버튼을 누르면 각 방 행에 빨간 삭제 버튼(`room-delete-btn`, ⊖)과 ▲▼ 순서 이동 스테퍼가 나타나고, 버튼은 "완료"로 바뀝니다(`toggleEditMode`). 평소에는 두 컨트롤 다 렌더링되지 않아 목록이 깔끔합니다.
- **삭제**: 빨간 ⊖ 버튼을 누르면 `confirm()`으로 한 번 더 확인한 뒤 `roomsData[view]`에서 제거합니다(`deleteRoom`). 마지막 방을 지우면 자동으로 편집 모드가 종료됩니다.
- **순서 변경**: ▲▼는 이전 버전과 동일하게 배열 안에서 이웃 항목과 자리를 바꿉니다(`moveRoom`). D-day 임박도와는 무관한, 사용자가 직접 정한 순서이며 알림 모달의 D-day 정렬에는 영향을 주지 않습니다(알림은 항상 임박도 기준으로 따로 정렬).
- 편집 모드에서는 행을 눌러도 방으로 이동하지 않습니다 — 삭제/순서 변경에만 집중하는 iOS Mail·미리알림 앱의 편집 모드와 동일한 동작입니다.
- **등장 애니메이션**: 삭제 버튼은 살짝 튕기듯 커지며 나타나고(`editControlPopIn`, scale 0.4→1), 순서 스테퍼는 오른쪽에서 옆으로 미끄러져 나타납니다(`editControlSlideIn`, translateX 10px→0). 행마다 `index * 30ms`만큼 시차를 둬서 위에서 아래로 순서대로 나타나는 느낌을 줍니다.
- **이동 애니메이션 (FLIP)**: ▲▼로 순서를 바꿀 때 목록이 그냥 순간이동하지 않고, 위/아래로 자리를 바꾼 두 방이 실제로 미끄러지듯 이동합니다(`animateReorder`). 매번 `innerHTML`을 통째로 다시 그리기 때문에 DOM 노드 자체로는 위치를 추적할 수 없어서, 각 방에 고유 `id`(`nextRoomId()`)를 부여하고 `data-room-id`로 이전/이후 위치(`getBoundingClientRect().top`)를 비교한 뒤 그 차이만큼 `translateY`를 줬다가 0으로 트랜지션하는 FLIP 기법을 썼습니다.
- **"완료" 종료 애니메이션**: "완료"를 누르면 곧바로 목록을 다시 그리지 않습니다. 먼저 현재 떠 있는 삭제 버튼/순서 스테퍼/수정 버튼에 `.exiting` 클래스를 붙여 등장 애니메이션의 역방향(축소+페이드, 옆으로 밀리며 페이드)으로 사라지게 하고, 그 트랜지션이 끝나는 시점(`180ms` 뒤, `cubic-bezier(0.22, 1, 0.36, 1)`)에야 `renderRoomList`로 실제 DOM에서 제거합니다(`toggleEditMode`). 그래서 편집 컨트롤이 뚝 끊기지 않고 부드럽게 빠져나갑니다.
- **수정 (`openRoomEditor` / `saveRoomEdit`)**: 편집 모드에서 삭제·순서 버튼과 함께 연필 아이콘 버튼(`room-edit-btn`)이 나타납니다(이때는 D-day 칩 대신 이 버튼이 그 자리에 나타남 — 편집 중에는 임박도보다 관리 작업이 우선이라고 판단). 누르면 이름/소개글 수정용 바텀시트가 뜨고, 이름은 생성 폼과 동일한 정규식(`ROOM_NAME_REGEX`)으로 검증합니다. 저장하면 `roomsData[view]`의 해당 방 객체를 직접 갱신하고 목록을 다시 그립니다.
- **마지막 활동 시각**: 각 방 객체에 `lastActive` 필드(예: `'2시간 전'`)를 추가하고, 소개글 줄에 `"{intro} · {lastActive} 활동"` 형태로 같이 보여줍니다. 어떤 방이 조용한지(`'1주 전'`) 한눈에 비교할 수 있습니다. 새로 만든 방은 `'방금'`으로 시작합니다.

### 2. 우정공간 만들기 폼
- "← 목록으로" 링크로 언제든 목록 패널로 돌아갈 수 있습니다.
- **대표 사진/아이콘**: 점선 테두리 정사각 영역 클릭 시 사진 URL을 입력받아 미리보기에 반영(기존 `triggerPhotoUpload` 패턴 재사용).
- **우정공간 이름** (필수): 한글/영문/숫자 2~20자 정규식 검증(`/^[가-힣a-zA-Z0-9\s]{2,20}$/`). `SignUp.html`의 실시간 검증 패턴과 동일합니다.
- **소개글** (선택, 60자 이내): 비워두면 목록에서 "소개글을 아직 안 적었어요"로 표시됩니다.
- **최대 인원 12명**: 안내 문구를 "인원 제한 없이..."에서 "최대 12명까지 함께할 수 있고..."로 바꾸고, 생성되는 방 객체에 `maxMembers: MAX_ROOM_MEMBERS`(=12)를 같이 저장합니다. `DB 설계.md`의 `FRIENDSHIP_ROOMS`/`ROOM_MEMBERS`는 여전히 인원 수를 구조적으로 제한하지 않는 N:N 테이블이라, 12명 캡은 DB 제약이 아니라 **앱 단의 정책값**입니다 — 셋로그가 4~6인을 DB가 아니라 서비스 정책으로 제한하는 것과 같은 방식입니다.

### 3. 생성 완료 패널
- 방 이름을 포함한 완료 메시지와, 새로 생성된 **방 전용 초대 코드**(`CLOV-XXXX` 형식)를 보여줍니다.
- 기존 "🤝 친구 초대코드" 모달의 `personal_invite_code`(개인 식별 코드)와는 다른, 이 우정공간에만 쓰이는 코드입니다 — DB 설계상 `ROOM_INVITES.invite_code`에 해당합니다.
- 복사 버튼은 `navigator.clipboard`를 우선 사용하고, 지원하지 않는 환경에서는 입력값을 선택(select)하는 방식으로 대체합니다.
- "우정공간 목록으로"를 누르면 새로 만든 방이 목록 맨 위에 추가되고, 목록 패널로 돌아갑니다.

## 헤더 / 내비게이션

메인 프로토타입(`Clov - 0629 ...html`)과는 의도적으로 다르게 구성했습니다. 메인 프로토타입의 우정공간/추억피드/행운편지/일정계획 4개 탭은 모두 **특정 우정공간에 들어간 뒤에만 의미가 있는 방 전용 기능**인데, 이 페이지(`makerooms.html`)는 아직 어느 방에도 들어가지 않은 "방을 고르는" 단계라 그 탭들을 그대로 가져오면 맞지 않았습니다.

- **데스크톱/모바일 공통**: 로고 옆에 계정 단위 기능인 **편지함**(`ti-mail`)과 **알림**(`ti-bell`, 안 읽은 알림이 있을 때 작은 점 배지)만 두고, 방 전용 탭은 모두 제거했습니다. 모바일 하단 탭바도 같은 이유로 없앴습니다.
- **다크모드 토글**: 메인 프로토타입과 동일한 48×26 필(pill) 형태로 맞췄습니다(`dark-mode-toggle-btn`). 내부 아이콘만 Tabler(`ti-sun`/`ti-moon`)로 바꿔 트렌드 리디자인과의 일관성을 유지했습니다.
- 실제 우정공간 안으로 들어가면(목록의 방 클릭 시) 그제서야 메인 프로토타입의 4개 탭 헤더가 나타나는 흐름을 전제로 합니다.

### 편지함 모달
- 방 단위로 갇혀 있던 행운편지를 **모든 우정공간을 가로질러 모아 보여주는 계정 단위 인박스**입니다. 각 항목에 어느 방(`letter-room` 배지)에서, 누가(`from`) 보냈는지를 함께 표시합니다.
- 더미 데이터는 `lettersData[view]` 배열이며, `{ room, from, content, time }` 구조입니다. 실제 서비스에서는 `LUCKY_LETTERS` 테이블에서 `receiver_id = 나`인 행을 `room_id` 기준으로 방 이름과 함께 조인한 결과에 대응합니다.

### 알림 모달
- 방 단위로 흩어진 일정(D-day)을 **가장 임박한 순으로 정렬해 모아 보여주는 계정 단위 알림**입니다. 별도 더미 데이터를 두지 않고, `roomsData[view]`에서 `dday`가 있는 방만 추려 `dday.count` 오름차순으로 정렬해 그 자리에서 렌더링합니다 — 방 목록과 항상 같은 데이터를 보장하기 위해서입니다.
- 데모용으로 "고등학교 4총사"에도 `D-9` 일정을 추가해, 여러 방의 일정이 한 알림함에서 섞여 정렬되는 모습을 확인할 수 있게 했습니다.

두 모달 모두 닫기 버튼(`✕`)뿐 아니라 어두운 배경(오버레이) 클릭으로도 닫힙니다.

## 애플(iOS/macOS) 스타일 패스

이전 트렌드 리디자인(플랫·아이콘 폰트) 위에, 애플 특유의 질감 요소들을 더했습니다.

- **헤더 프로스트 글래스**: `backdrop-filter: blur(20px) saturate(1.5)`로 반투명 유리 느낌을 복원했습니다(직전 플랫 리디자인에서 뺐던 블러를 의도적으로 다시 적용).
- **다크모드 토글 → 진짜 슬라이딩 스위치**: 정적인 필 버튼 대신, iOS 설정 화면처럼 동그란 노브가 좌우로 이동하는 실제 토글로 바꿨습니다(`.toggle-knob`, `transform: translateX()`).
- **방 순서 이동 버튼 → 스테퍼 필**: 개별 버튼 두 개였던 ▲▼를 하나의 캡슐 안에 위/아래로 합치고 가운데 헤어라인으로 구분했습니다 — iOS의 +/- 스테퍼 컨트롤과 같은 형태입니다.
- **편지함/알림 → 바텀시트**: 모바일에서는 화면 아래에서 올라오는 시트(둥근 위쪽 모서리 24px + 상단 그래버 바)로, 데스크톱에서는 macOS 시트처럼 가운데 정렬된 글래스 패널로 분기했습니다. 둘 다 `backdrop-filter` 블러 배경 위에 떠 있습니다.
- **방 카드**: 모서리를 20px로 키우고, 위쪽에 옅은 하이라이트(`inset 0 1px 0 rgba(255,255,255,.5)`)를 줘 살짝 입체감 있는 유리 카드 느낌을 더했습니다.

이 시각 효과들은 실제 브라우저 `backdrop-filter` 지원에 의존하므로, 구형 브라우저에서는 블러 없이 반투명 배경만 보일 수 있습니다.

## 데이터 구조 (더미)

```js
roomsData[view] = [
  { id, name, level, intro, photo, dday: { count, label } | null, lastActive }
]
```
`id`는 `nextRoomId()`로 발급하는 전역 고유값으로, 배열 순서가 바뀌어도(FLIP 애니메이션) DOM 요소를 추적하기 위한 키로 씁니다.
데스크톱/모바일 뷰가 같은 화면을 보고 있다는 걸 보여주기 위한 미리보기 파일이라, 두 뷰의 방 목록은 `dt`/`mb` 키로 독립적으로 관리합니다. 실제 서비스에서는 한 백엔드 데이터를 공유합니다.

## 의도적으로 포함하지 않은 것

- **친구 코드 즉시 입력란**: 방 생성과 동시에 상대 코드를 받는 것보다, 방을 먼저 만들고 초대 코드를 공유하는 흐름이 더 단순하다고 판단해 제외했습니다. 친구 코드를 직접 입력해 연동하는 흐름은 기존 "🤝 친구 초대코드" 모달에서 이미 처리합니다.
- **그래프/진행 바/클로버 채움 같은 성장 표현**: 그래프와 막대는 활동이 줄면 시각적으로 "내려가는" 인상을 줘서 제외했습니다. 목록에서는 레벨 숫자만 담백하게 표시합니다.
- **약속/일정 동시 등록**: 방 만들기와 약속 만들기를 한 화면에 묶지 않고, 방을 먼저 만든 뒤 일정계획 탭에서 약속을 등록하는 기존 흐름을 그대로 따릅니다. 그래서 새로 만든 방은 목록에 추가될 때 D-day 칩이 없는 상태로 시작합니다.
