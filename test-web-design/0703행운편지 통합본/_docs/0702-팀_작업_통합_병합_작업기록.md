# 0702 팀 작업 통합 병합 작업 기록

## 작업 목적

하루 동안 여러 갈래로 나뉘어 진행된 팀 작업(신동수, 김대훈, 그리고 사용자 본인의 인생4컷·추억피드 작업)을
`test-web-design` 하나의 기준본으로 합치고, 중복 스냅샷 폴더를 정리했다.

병합 대상이 된 스냅샷 폴더:

- `web-design-repository/`
- `김대훈/` (`home.html` + 작업기록만 남아있던 폴더)
- `0702신동수-수정파일/`
- `추억피드 게시물 + 인생4컷 디자인/`
- `추억피드+인생4컷 추가/`

모두 병합 완료 후 삭제했다.

## 1. 신동수 작업 병합 — Modal-First / 가입 신청 시스템

`0702신동수-수정파일/`에서 아래 항목을 `02-main/index.html`, `02-main/css/desktop.css`,
`02-main/js/desktop.js`, `03-rooms/join_room.html`, `07-notification/notification.html`에 반영했다.

- **Modal-First 정책**: 브라우저 기본 `alert()`/`confirm()`을 `clov-modal.js`의 `clovAlert`/`clovToast`로 전면 교체
- **방장 개념 전면 폐지**: 가입 신청 수락을 참여 멤버 누구나 할 수 있도록 변경
- **가입 신청 시스템 신규 구축**: `join_room.html`에서 즉시 입장 대신 승인 대기(`clov_joinRequests`) 상태로 전환 →
  알림에 전용 "🤝 가입 신청" 탭 + 빨간 배지 신설 → 수락 시 `clov_acceptedMembers`에 등록되어 참여 멤버 수 실시간 증가
- **참여 멤버 리스트 모달** 신규 추가 (`member-list-overlay`), 초대 코드 복사 버튼
- **우정공간 대표 커버 개편**: 1열 그리드, 글래스모피즘, 사진-텍스트 마스크 그라데이션, 업로드 이미지 형식 검증,
  D-day "0일차 → 1일차" 계산 보정

신규 컴포넌트: `02-main/components/clov-modal.js` (Modal-First 시스템의 기반)

### 김대훈 작업 관련

`김대훈/` 폴더엔 `home.html` + 작업기록 `.md`만 남아있고, 문서에 언급된 `desktop.js`/`desktop.css`/
`signup.html`/`profile_edit.html` 실제 변경 파일은 확보되지 않았다. `home.html`의 인라인 스크립트에 있던
"친구들 알림 탭 — 가입 요청 수락/거절" 로직을 확인했으나, 신동수 버전이 더 완결된 형태(전용 탭 + 배지 +
멤버 수 실시간 연동)로 이미 구현하고 있어 별도 이식은 하지 않았다. 행운편지 재작업, D-day HUD 동기화 수정,
테스트 패널, 회원가입 프로필 저장 로직은 소스 부재로 이번 병합에 반영되지 않았다.

## 2. 추억피드 데이터 모델 전면 교체

`추억피드 게시물 + 인생4컷 디자인/`(이후 `추억피드+인생4컷 추가/`로 재확인)에서 아래 작업을 병합했다.

### 데이터 모델

`participants[].text`(참여자별 개별 기록) 방식을 **게시자 1명(`authorId`) + 친구 한 줄 메시지(`messages[]`)**
방식으로 교체했다. `normalizeMemoryPost()`가 과거 데이터의 `participants[].text`를 최초 렌더링 시
`messages[]`로 1회 자동 이관한다.

| 액션 | 권한 |
|---|---|
| 게시글 제목·본문 수정/삭제 | 게시자만 |
| 한 줄 메시지 작성 | 참여 멤버 각자 (게시자 포함) |
| 메시지 수정·삭제 | 그 메시지 작성자 본인만 |

### UI

- 폴라로이드 카드(`renderMemoryCard`) 재설계: 참여자 아바타 레일(게시자만 민트 링) + 대표 사진(클릭 시 상세모달,
  🔍 자세히 힌트) + 캡션 + 해시태그 + 💬 메시지 수
- 상세 모달(`renderMemoryDetailModal`)을 중앙 정렬 2열 레이아웃으로 재구성 — 기존에 죽어있던
  `memory-detail-sheet`/`memory-detail-backdrop` 바텀시트 마크업을 재사용해 CSS만 2열 모달로 교체
- 친구 한 줄 메시지 목록: 타인 메시지=읽기전용, 타인 미작성="아직 메시지 없음", 내 메시지=수정·삭제, 내 미작성=입력창+등록
- **다중 사진 업로드** (최대 6장): `post.photos: string[]` 추가, 수정 모드·글쓰기 모달 양쪽 지원,
  2장 이상이면 카드에 "📷 N" 배지 + 상세 모달 하단 썸네일 스트립
- **해시태그 입력 필드** 추가 (`#한강 #시험끝` 형식, 공백/쉼표 구분, 최대 5개)
- 시드 데이터 3건("성수 스터디 카페"=솔, "부산 당일 여행"=민, "졸업식 날"=준)을 친구가 올린 글로 명시 지정 —
  친구 글에 메시지 남기는 시나리오를 실제로 테스트할 수 있도록 함
- `DATA_VERSION` 3 → 4로 올려 기존 localStorage 사용자도 새 시드 자동 반영

### 버그 수정

- **`window._clov` 참조 버그**: 글쓰기 모달(`saveWritePost`)이 존재하지 않는 `window._clov` 객체를 참조해
  저장이 무음 실패하던 문제. `index.html`은 원본에 이미 수정돼 있었으나, **`feed.html`엔 동일 버그가 남아있어서
  추가로 발견·수정**했다 (다중 사진 업로드 + 해시태그 입력까지 index.html과 동일하게 맞춤).
- `document.getElementById`가 파일 최상단에서 몽키패치되어 없는 id에 대해 더미 엘리먼트를 반환하도록 되어 있어,
  모달 최초 생성 로직이 깨졌던 문제를 `document.querySelector`로 우회 수정
- 참여자 id 하드코딩(`'me'`) 대신 실제 `type === 'mine'` 참여자의 id를 찾도록 수정 — 하드코딩된 값과
  실제 생성 id(`나-0` 등)가 달라서 "내 메시지 작성" 영역이 항상 "아직 메시지 없음"으로 잘못 표시되던 버그

## 3. 인생4컷(LIFE FOUR CUT) 상태 모델 재병합

1차 병합 때는 "LIFE FOUR CUT" 헤더 섹션(제목·필터탭)만 비교해 동일하다고 잘못 판단했다. 실제로는 **카드
내부 렌더링 로직 전체가 누락**되어 있었고, 사용자가 스크린샷으로 차이를 지적한 뒤 재작업했다.

### 실제로 빠져있던 것

- **3단계 상태 모델**: `locked / active / done` (`getGrowthStageStatus`, `getGrowthStageMessage`).
  기존엔 진행순서 기반의 단순 상태(`growing/past/open`)만 있었음
  - 1단계(제안하기): 항상 열림
  - 2단계(일정 맞추기): 1단계 사진 있어야 열림
  - 3단계(약속 확정): 2단계 사진 + `오늘 >= 약속일`이어야 열림 — 날짜 조건이 걸리는 유일한 단계
  - 4단계(만남): 3단계 사진 있어야 열림
- **REC 배지 + NOW SHOOTING/COMPLETE 헤더** (활성 단계 강조, 빨간 점 깜빡임 애니메이션)
- **🔒 잠금 아이콘** + "아직 열리지 않았어요" 안내 모달(`showStageLockedGuidanceModal`) — 잠긴 단계 클릭 시
  왜 안 열리는지 설명 문구 표시
- 컷 사이 **점선 퍼포레이션 + 양쪽 노치**, 상하단 **스캘럽(물결) 엣지** — 포토부스 티켓 느낌 CSS
- 카드 하단 **"clov. memories" 브랜딩** + 완성 시 "인생4컷 완성 🍀" 문구

### 병합 범위

`02-main/js/desktop.js`: `getGrowthStageStatus`, `getGrowthStageMessage`, `showStageLockedGuidanceModal`
신규 추가, `requestStagePhotoUpload`에 상태 체크 추가, 카드 렌더링(`article.growth-card.four-cut`) 전면 교체.
`02-main/css/desktop.css`: `.strip-kicker`, `.strip-rec-badge`, `.strip-perforation`, `.strip-lock-icon`,
`.strip-footer-brand` 등 관련 클래스 전체 교체.

기존 target에 있던 이미지 파일 형식 검증(`clovAlert` 경고)은 그대로 유지하며 새 상태 모델과 통합했다.

## 4. 저장소 정리

병합이 끝날 때마다 중복 스냅샷 폴더를 삭제했다. 유용한 설계 문서(`인생4컷_기획정리.md`,
`추억피드 폴라로이드 구현명세.md`, 작업기록 `.md`, 참고용 mockup HTML)는 삭제 전에 `_docs/`로 옮겨뒀다.

또한 `.claude/launch.json`이 존재하지 않는 Python(Windows Store 스텁)을 참조하고 있어 프리뷰 서버가
뜨지 않던 문제를 발견해, Node 기반 정적 서버(`.claude/static-server.js`)를 새로 작성하고 연결했다.
디렉터리 요청에 trailing slash 리다이렉트 처리를 추가해 상대경로 리소스(css/js)가 깨지지 않도록 했다.

## 5. 검증 내용

매 병합 단계마다 `node --check 02-main/js/desktop.js`로 문법을 확인하고, 브라우저 프리뷰로 실제 동작을 확인했다.

- 가입 신청 시뮬레이션 → 헤더 벨 배지 · 알림 탭 배지 동시 반영 확인
- 우정공간 대표 커버 1열 레이아웃 · 참여 멤버 모달 · 초대 코드 복사 확인
- 추억피드: 친구 글에 메시지 작성/수정, 내 글 메시지 수정, localStorage 영구 저장 확인
- 글쓰기 모달: 해시태그 파싱, 다중 사진 업로드, 저장 후 피드 반영 확인 (index.html · feed.html 양쪽)
- 인생4컷: NOW SHOOTING/REC 배지, 잠금 아이콘, 잠긴 단계 클릭 시 안내 메시지, 완성 브랜딩까지 —
  사용자가 제공한 스크린샷과 픽셀 단위로 동일한 결과 확인

## 팀 공유 시 주의할 점

- `04-feed/feed.html`과 `02-main/index.html`의 글쓰기 모달은 이제 완전히 같은 구조(다중 사진 + 해시태그 +
  `authorId`/`messages` 모델)다. 둘 중 하나만 고치면 다른 쪽이 다시 구버전 버그로 벌어질 수 있으니 항상 같이 수정할 것
- 인생4컷의 단계 상태는 `locked/active/done` 세 가지뿐이며, 3단계(약속 확정)만 날짜 조건이 걸린다는 규칙은
  `_docs/인생4컷_기획정리.md`에 원본 기획이 남아있다
- 김대훈 몫의 행운편지 재작업·D-day HUD 동기화·테스트 패널·회원가입 프로필 저장 로직은 소스가 없어 아직 미반영 상태다
