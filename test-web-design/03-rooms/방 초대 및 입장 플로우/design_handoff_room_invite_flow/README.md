# Handoff: 방 초대 & 입장 플로우 + 방 미리보기(소식) 개편

## Overview
Clov 우정공간의 **방 초대/입장 플로우**와 **방 미리보기 모달**을 개편하는 작업 명세다. 두 덩어리로 구성된다.

1. **초대/입장 플로우 규칙** — 방장이 없는(수평) 구조에서 방 생성·초대·가입 신청·수락/거절·나가기·삭제의 규칙을 확정. (엣지 케이스 P1~P7 포함)
2. **방 미리보기 모달 개편** — 지금 `정보 / 편지함 / 알림` 3탭이 "따로 노는" 문제를, **하나의 시간순 "소식" 피드**로 통합. 방 프로필 편집을 미리보기 안 ⚙️로 이동(룸리스트 사진 업로드 버그 제거). 방목록 카드의 D-day 버튼을 "약속 바로가기"로.

## About the Design Files
이 번들의 HTML 파일은 **HTML로 만든 디자인 레퍼런스(프로토타입)**다 — 최종 룩앤필과 동작 의도를 보여주는 것이지, 그대로 복사해 넣는 프로덕션 코드가 아니다. 실제 작업은 **대상 코드베이스(`test-web-design/`, 순수 바닐라 JS·프레임워크 없음)의 기존 패턴**으로 이 디자인을 재현하는 것이다. 이 저장소는 `file://`로 직접 열어 테스트하므로 `fetch()`로 조각을 불러오는 방식은 금지(기존 `pages/*.js`처럼 템플릿 문자열 + `innerHTML` 주입 패턴 유지).

## Fidelity
- `방 미리보기 소식 개편.html` — **하이파이(hifi).** 색·타이포·간격·상태가 최종안. 픽셀 단위로 재현.
- `방목록 상태 와이어프레임.html` — **로우파이(lofi).** 플로우/규칙 결정을 위한 스케치. 레이아웃·로직 가이드로만 쓰고, 스타일은 코드베이스 디자인 시스템을 따를 것.

## 핵심 원칙 (전체 관통)
> **방장(owner)이 없다.** 모든 방 행동은 "**참여 멤버 누구나 할 수 있되, 하면 방 소식(알림)에 흔적이 남는다**" — 권한이 아니라 투명성으로 푼다.

이 원칙이 아래 모든 규칙의 근거다. "누가 할 수 있나?" → 항상 "멤버 누구나". "몰래 바뀌면?" → 항상 "소식에 기록 + 알림".

## A. 초대 / 입장 플로우 규칙 (확정 스펙)

### A-1. 방목록의 "요청한 방" 섹션
- 내가 **가입 신청 중(수락대기)** 또는 **거절된** 방이 있으면, 방목록 **맨 위에 "요청한 방" 섹션**을 표시. 없으면 섹션 통째로 숨김(기존 목록 그대로).
- 대기/거절 카드는 **정렬·즐겨찾기·드래그 대상에서 제외**(아직 멤버가 아님).

### A-2. "삭제"는 상태별 4갈래 (버튼 라벨/문구를 상태별로 분기)
| 상태 | 동작 | 확인 문구 |
|---|---|---|
| 참여방 · 다른 멤버 남음 | **나가기** | "이 방에서 나갈까요? 남은 멤버에게 'OO님이 나갔어요'라고 알려져요." |
| 참여방 · 내가 마지막 멤버 | **나가면 30일 잠자기** | "지금 마지막 멤버예요. 나가도 바로 사라지지 않고 30일간 보관돼요. 그 안에 누구든 코드로 다시 들어오면 추억 그대로 되살아나요. 30일 아무도 안 오면 완전히 사라져요." |
| 수락대기 카드 | **요청 취소** | "입장 요청을 취소할까요? 아직 멤버가 아니라 '나가기'가 아니에요." |
| 거절된 카드 | **카드 지우기(+재요청)** | "이 카드를 지울까요? 원하면 같은 코드로 다시 요청할 수 있어요." (버튼: [재요청] primary / [지우기] 보조) |

### A-3. 잠자는 방(30일 소프트 삭제) — P2·P3 해결
- 마지막 멤버가 나가면 방을 **즉시 파괴하지 않고 30일 보관(dormant)**. 30일 내 누구든 코드로 재입장하면 **추억 그대로 부활**. 30일 후 완전 삭제.
- "내가 마지막인가" 판정은 버튼 렌더 시점이 아니라 **나가기 커밋 시점**에 서버(또는 데이터 계층)에서 처리 → 2명이 동시에 나가도 **0명 유령 방**이 안 생김.

### A-4. 방 정보 수정 (공동편집) — B/C 섹션에서 UI 상세
- **이름·소개글·대표사진**을 멤버 누구나 수정 → **방 소식 피드에 "OO님이 ~를 수정했어요" 기록.**
- 대표사진 기본값 = **테마 일러스트(소유자 없음)**, 그 외 "추억에서 고르기"(추억피드 사진), "업로드".
- 이름 변경은 막지 않되 반드시 알림. 소개글 = 공용 메모.
- **없음(MVP): 강퇴, 초대코드 재발급은 아래 A-6 참고.**

### A-5. 수락 / 거절 (이미 구현됨 — 유지) — P1 보강
- 위치: 알림 모달 **"가입 신청" 탭**(건수 배지) + "친구들 알림"에 대기 배너.
- 규칙: **참여 멤버 1명이 수락하면 즉시 입장.** 누구나 수락/거절. 처리 시 "OO님이 수락했어요" 소식 기록.
- **보강(P1 사생활):**
  - 가입 신청 카드에 **요청자 정체 + 초대 경로**("🔗 강한나님 초대로 신청") 표시.
  - 수락 직후 **되돌리기 창(5분)** — "박서준님 수락함 · 되돌리기 4:58". 강퇴가 없으므로 "방금 실수"를 되돌리는 유일한 안전장치.

### A-6. 초대 링크 / 코드 (6a 코드 위생)
- **방목록 카드에 초대 코드를 노출하지 않는다**(현재 "초대 코드: CLOV-XXXX" 노출 → 제거). 코드는 **미리보기의 "친구 초대하기"** 뒤로 숨김.
- "친구 초대하기" 시트:
  - **공유 링크** `clov.app/join/CLOV-1001` + [복사] + [링크 공유하기](native share). 링크 탭 시: 로그인 상태 → 그 방 **가입 신청(수락대기)**, 비로그인 → 로그인/회원가입 후 자동 신청.
  - **코드 병기** `CLOV-1001` + [복사] (링크 못 여는 사람 수동 입력용).
  - **코드 재발급** — 누구나 가능 + 알림. 유출되면 옛 코드 무효화.

### A-7. 예외 규칙 (전부 채택)
- 이미 신청한 방에 또 신청 → **차단** ("이미 신청했어요, 수락 기다리는 중").
- 이미 멤버인 방 코드 입력 → **신청 안 만들고 바로 그 방으로 이동** ("이미 참여 중인 방이에요").
- 한 명 수락 vs 다른 명 거절 동시 → **먼저 처리된 액션이 확정.** 늦은 클릭엔 "이미 처리된 신청이에요".
- 거절 후 재요청 → **허용**(제한 없음. 스팸이 실제 문제 되면 그때 쿨타임).
- 방 잠자기 시 그 방에 남은 대기 신청 → **자동 취소** → 요청자 카드는 "사라진 방" 처리.
- **가입 요청 7일 뒤 자동 만료** → 요청자에게 알림, 재신청 가능. (전원 잠수 시 무한 대기 방지)
- 정원 **최대 8명**(2026-07-27 정정 — 이 줄은 원래 "정원 상한 없음"이었으나 **오류**였다).
  - 정본 근거: 저장소 `CLAUDE.md` 핵심 서비스 원칙("우정공간은 최대 8명까지 참여하는 단일 구조") · 백엔드 `InviteService.MAX_ROOM_MEMBERS = 8`.
  - **판정 시점은 "수락" 때**다(신청 때가 아니라). 신청과 수락 사이에 인원이 변할 수 있어 최종 판정은 수락 시점이어야 한다. 초과 시 `409 ROOM_CAPACITY_EXCEEDED`이고 신청은 `PENDING`으로 남는다.
  - 구 스펙 `join_room.md`의 "8명 초과 시 신청 생성 자체를 차단"은 **채택하지 않는다**(신청 시점 사전 안내는 UX 개선 여지로 남김).

### A-8. 나간 멤버 · 회원탈퇴 · 자료
- **방 나가기**(계정 유지): 남긴 자료 그대로. 코드로 재입장하면 다시 멤버.
- **회원탈퇴**(계정 삭제): 작성자 표기가 **"언노운"으로 익명화** · 남긴 추억·편지·폴라로이드는 **그대로 보존**.
- 대표사진이 "추억에서 고른" 원본인데 그 추억이 삭제되면 → **테마 일러스트로 자동 폴백**.

### 안내 토스트 문구
- ⏳ 이미 신청했어요 · 수락을 기다리는 중이에요
- ✅ 이미 참여 중인 방이에요 — 바로 이동할게요
- 🙌 이미 처리된 신청이에요 (다른 멤버가 먼저 처리)
- 🫧 이 방은 사라졌어요 — 신청이 취소됐어요

## B. 방 미리보기 모달 개편 — "소식" 통합 피드 (hifi)
**대상:** `03-rooms/makerooms.html` 의 `#room-preview-modal`.

### 문제
현재 3탭(`정보`/`편지함`/`알림`) + 정보 탭의 "주요 알람" 요약이 **같은 "이 방에 무슨 일이 있었나"를 세 군데로 쪼개** 따로 논다.

### 해결: 무탭 원스크롤 + 소식 피드
미리보기 모달을 **탭 없는 한 스크롤**로 재구성. 위→아래 순서:
1. **헤더**: `🏡 {방이름}` + 우측 **⚙️(방 프로필 편집, C 섹션)** + ✕. (⚙️는 **원/배경 없이 아이콘만**, 색 `#357a58`)
2. **방 요약 행**: 48~54px 대표사진(라운드 15) + 소개글(굵게) + `Lv.N · 활동 N분 전`.
3. **멤버 아바타 줄**: 이니셜 원형 아바타(이모지 금지) 나열 + "N명 참여 중". (아바타: 22px 원, `#1b4332`/`#357a58`/`#6a7e73`/`#52b788` 순환)
4. **새 소식 N** 헤더(안읽음 수 빨강) + **소식 피드**(최근 2~3개) + "소식 더 보기".
5. **친구 초대하기**(점선 버튼) — A-6.
6. **우정공간 입장하기**(진녹색 채움 버튼).

### 소식 피드 = 편지 + 알림 + 가입/퇴장 + 정보수정 (하나의 시간순 리스트)
기존 `room.letters` + `room.notices`를 **하나의 activity 배열로 합쳐 시간 내림차순 정렬**. 항목 타입별 아이콘/색:

| 타입 | 아이콘(Tabler) | 아이콘칸 배경/글자 | 예시 타이틀 / 설명 |
|---|---|---|---|
| 편지 `letter` | `ti-mail` | `#e2f2ea` / `#2f7d4f` | "{from}님의 행운편지" / 본문 |
| 일정 `sched` | `ti-calendar-heart` | `#fbeecf` / `#b5851f` | "D-21 제주 여행" / 설명 |
| 가입 `join` | `ti-user-plus` | `#dfeef0` / `#2f7a86` | "{name}님이 합류했어요" |
| 퇴장 `member` | `ti-door-exit` | `#dfecee` / `#b45274` | "{name}님이 나갔어요" |
| 수정 `edit` | `ti-pencil` | `#eceae2` / `#8a7f66` | "{name}님이 소개글을 수정했어요" |

- **아이템 레이아웃**: `flex; gap 11px`. 아이콘칸 34×34 라운드10. 제목 13.5px/700(이름은 `#2f7d4f`), 설명 12.5px/`#6a7e73` 1줄 말줄임, 시간 11px/`#9aa89f` 우측.
- **안읽음(unread)**: 배경 `#f3f8f4`, 테두리 `#dcebe1`, 좌측 `inset 3px 0 0 #52b788`.
- **읽음**: 배경 `#fff`, 테두리 `#eef1ee`.
- 정보 탭의 "주요 알람" 블록은 **삭제**(피드 헤더 "새 소식 N"으로 대체). 멤버·코드 등 방 정체 정보는 요약 행/초대 시트로 흡수.

## D. 방목록 카드 — 보딩패스(탑승권) 카드 (hifi, 확정)
**대상:** `03-rooms/makerooms.html` `renderList()` — 기존 카드를 **탑승권(보딩패스) 형태로 전면 교체.** 은유: 각 방의 다음 D-day 약속으로 "떠나는 티켓". 지적사항이던 "반복감·무거움"과 "배경 충돌"을 해결한 최종안.

### 카드 구조 (위→아래)
컨테이너: `background:#fffdf7; border-radius:16px; box-shadow:0 12px 26px rgba(20,40,30,.2); overflow:hidden; position:relative`. **현재 선택된 방**은 `outline:2.5px solid #52b788`.

1. **티켓 상단(컬러 헤더)** `padding:14px 15px 0`
   - **반복감 방지 — 방마다 헤더 톤을 순환**(방 id 기반 3~4종): 포레스트 `linear-gradient(150deg,#22705a,#123f31)` · 틸 `#1f6b6b→#0f3d3d` · 올리브 `#4a6b3a→#2a4020`.
   - **라우트 행**(흰 글자): 좌 `오늘`(kicker 9px, 헤더톤 밝은색 예 `#a7d3bf`) + `CLOV`(15/800) · 중앙 방 성격 아이콘(`ti-plane`/`ti-calendar-heart`/`ti-camera` 등) 양옆 `┈` · 우 **목적지** = `D-{N}`(kicker) + 약속 요약(15/800, 예 "제주"). **약속 없는 방**은 `약속 없음 / 자유`.
   - **스카이라인**: 흰색 세로 막대(`background:#fffdf7`, 높이 12~26px 랜덤, width 7~11px) 바닥정렬 한 줄. 장식.
2. **승객 행(흰 배경)** `padding:12px 15px 4px; align-items:flex-start; space-between`
   - 좌: `우정공간`(9px `#9aa89f`) + 방이름(15/800 `#1e2e26`) + **아바타 미니줄**(22px 이니셜 원, 겹침 `margin-left:-7px`, `나`/`+N`).
   - 우: **새 글 배지**(있을 때, 빨강 칩 `#d95f5f`/흰10/800/radius9/`padding:1px 7px`) + **즐겨찾기 ★**(채움 `ti-star-filled #e6a23c` / 비활성 `ti-star #c8c2b4`, 17px). ⚠ **★와 목적지 D-day는 서로 다른 행**에 둘 것 — 한 코너에 겹치면 D-day 숫자가 가려짐(수정 완료된 규칙).
3. **디테일 그리드(2열)** `gap:7px 10px` — 라벨 9px `#9aa89f`/700 + 값 12/800 `#1e2e26`. 항목은 {다음 약속, D-DAY, 멤버, 레벨} 중 2개. **약속 없는 방**은 단일 셀 "다음 약속 / + 약속을 정해보세요"(`#8a9a5a`).
4. **절취선 + 노치** `border-top:2px dashed #e6dfcf; margin:0 12px`, 좌우 반원 노치.
   - ⚠ **배경 테마가 바뀌므로 노치를 고정색 원으로 두지 말 것.** `mask`(radial-gradient)로 카드 좌우에 **투명 구멍**을 뚫어 배경이 그대로 비치게 구현(어떤 테마에서도 자연스럽게). (목업은 편의상 단색 원 `#ddca9f` 사용했지만, 실제 구현은 mask 권장.)
5. **스텁**: 바코드 모티프(세로 검정 막대들, `#2a3a32`, **장식** — 실제 코드 노출 아님, 6a) + 우측 **"입장 ›"**(`#357a58` 11/800).

### 동작 (기능 동일)
- **카드 탭** → `showRoomPreviewModal(id)` (미리보기, 무탭 소식 화면 = B/C).
- **목적지(D-day)·"입장 ›" 탭** → `enterRoom(id)` + 그 약속으로 직행(`selectScheduleChip('dt', 일정id)` 재사용). `stopPropagation`으로 카드 탭과 분리.
- 즐겨찾기 ★ 토글, 새 글 배지, 멤버 수는 기존 데이터 그대로.

### 왜 이렇게 (지적 반영)
- **반복감·무거움**: 진한 D-day 버튼 반복 → 티켓 1장으로 통합, 헤더 톤을 방마다 달리해 단조로움 제거.
- **배경 충돌**: 카드가 아이보리 페이퍼(`#fffdf7`) + 강한 그림자로 어떤 배경 테마 위에서도 확실히 뜸. (검토했던 프로스티드 글래스는 복잡한 배경에서 대비가 흔들려 제외.)
- **코드 노출 제거**(6a): 카드에서 `초대 코드: CLOV-XXXX` 줄 삭제.

## Interactions & Behavior
- **카드 본체 클릭** → `showRoomPreviewModal(id)` (미리보기, 무탭 스크롤).
- **목적지·"입장 ›" 탭** → `enterRoom(id)` + 진입 후 해당 일정 스포트라이트. (이벤트 버블링 `stopPropagation` 필요 — 카드 탭 핸들러와 충돌 방지)
- **⚙️** → 미리보기 편집 서브뷰 전환(모달 내 뷰 스와핑, 페이지 이동 없음).
- **친구 초대하기** → 초대 시트(링크/코드/재발급).
- **가입 신청 수락** → 즉시 입장 처리 + 5분 되돌리기 토스트 + 소식 기록.
- **나가기** → A-2 상태별 확인창 → 처리 후 소식/알림 기록. 마지막 멤버면 잠자기(A-3).
- 소식 피드는 최근 순 정렬, 안읽음 상단 강조.

## State Management / 데이터 모델 변경
- **room 객체**(기존): `{id, name, level, intro, lastActive, dday, fav, newPosts, photo, createdAt, letters[], notices[], code}`.
- **소식 통합**: `letters[]` + `notices[]` (+ 신규 가입/퇴장/수정 이벤트)를 **하나의 `activity[]`로 병합**하거나, 렌더 시점에 두 배열을 `{type, icon, title, desc, time, unread, ts}`로 정규화해 시간순 머지. `ts`(정렬용 timestamp) 필드 추가 권장.
- **가입 신청**: `clov_joinRequests`(localStorage) — 기존 유지. 수락은 영구 저장, **거절은 세션 전용**(`notiSessionOverrides`, 새로고침 시 pending 복귀) — 기존 동작 유지. **7일 만료**(A-7)와 **5분 되돌리기**(A-5) 신규.
- **잠자는 방**: room에 `dormantUntil`(또는 `status: 'dormant'|'active'`) + 30일 타이머. 재입장 시 active 복구.
- **대표사진**: `groupsData[activeGroup].photo` (방 안) — 편집 결과 저장처. 룸리스트 `room.photo`와 동기화.
