# OAuth 404 트러블슈팅 + 초대 플로우 라이브 확인 — 2026-07-23 (오후)

> 오전에 잡은 초대→입장 3중 버그(#72·#73·#54)와 초대코드 A안 재설계(#55)는 별도 로그
> `2026-07-23-초대플로우-트러블슈팅-및-초대코드-구조개선.md`에 상세.
> 이 문서는 그 뒤 오후 세션 = **배포/재기동 이슈(OAuth 404)** 만 다룬다.

---

## 1. 증상
구글 로그인 시도 → Whitelabel Error Page 404:

```
No static resource oauth2/authorization/google
org.springframework.web.servlet.resource.NoResourceFoundException
```

즉 `/oauth2/authorization/google` 요청이 **Spring Security의 OAuth2 리다이렉트 필터가 아니라 정적 리소스 핸들러로** 흘러갔다. → OAuth2 클라이언트 필터가 아예 안 붙었다는 뜻.

## 2. 진단 (좁혀 들어간 순서)
1. **SecurityConfig** — `.oauth2Login(...)` 정상, 의존성 `spring-boot-starter-security-oauth2-client` 존재. 설정만 보면 필터가 붙어야 정상.
2. **설정값** — `application-secret.yaml`에 google client-id/secret 실재, `application.yaml`에 `spring.profiles.include: secret`. 등록값 정상. build/resources/main에도 secret 복사돼 있음.
3. **실행 중 8080 직접 프로빙** — 여기서 판가름:
   - `/oauth2/authorization/{google,naver,kakao}` → **전부 404**
   - `/api/v1/rooms` → 401(정상 인증요구), 서버는 살아있음
   - → 코드/설정 문제가 아니라 **OAuth2 필터가 없는 빌드가 떠 있다.**
4. **git log** — 최신은 #56(OAuth redirect env화). 실행 중 프로세스는 그 반영 전 빌드.
   → 결론: **옛 빌드가 8080을 점유** (핸드오프가 반복 경고하던 그 함정).

## 3. 해결
`git pull && ./gradlew clean bootRun` 재기동(리더 실행). 재기동 후:
- `/oauth2/authorization/{google,naver,kakao}` → **302** (정상 리다이렉트)
- `/login/oauth2/code/google` → 400 (인가코드 없음 — 정상 동작)

→ 해결.

## 4. 교훈 (반복되는 함정)
- **`/oauth2/authorization/*` 가 404 `No static resource` = 십중팔구 "옛 빌드가 떠 있음" 신호.** 코드/설정을 파헤치기 전에 "지금 8080이 최신 빌드냐"부터 확인.
- clov-api는 devtools여도 **머지된 설정/코드 반영엔 `clean bootRun` 재기동 필요.** clov-web(5173 HMR)과 다르다.
- 진단은 소스를 노려보는 것보다 **실행 중 서버를 엔드포인트 상태코드로 직접 프로빙**해 "필터가 붙었나"를 물리적으로 확인하는 게 빨랐다.
