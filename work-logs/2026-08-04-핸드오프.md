## 3. 알림 — 오늘 세 겹이 다 맞았다

```
계약     §13 MEMBER_LEFT 신설(#50) + 합류·수락을 FRIEND로 이동(#52)
백엔드   MEMBER_LEFT 발송(#124) + type을 FRIEND로(#128)
프론트   FRIEND_SUBTYPE_META에 3종 문구·아이콘(#250)
배포     web 3회차 · api 1회차 — 셋이 같은 시각에 살아 있다
```

### ★ 구조를 반드시 알고 손댈 것

| | |
|---|---|
| `type` | **어느 탭에 보일지.** `NOTICE` / `FRIEND` / `JOIN` 세 값 고정 |
| `subType` | **무슨 일이 있었는지** |

**`JOIN` 탭은 알림 테이블을 조회하지 않는다.** `Notifications.jsx`의 `enabled: activeTab !== 'JOIN'`이 그 자리고, 대신 가입신청 리소스를 부른다. 라벨도 `'가입 신청'`이다 — **알림 피드가 아니라 승인/거절하는 처리함이다.**

> **그래서 `type='JOIN'`으로 만든 알림은 화면 어디에도 안 뜬다.** `MEMBER_JOINED`·`JOIN_ACCEPTED`가 그 상태였고 오늘 `FRIEND`로 옮겼다.

**분류 기준** — 알림은 주제축("멤버에 관한 것끼리")이 아니라 **행동축("처리할 게 있나")으로 먼저 가른다.** 처리함은 비워야 하는 통이라 안 없어지는 정보성 항목이 섞이면 뱃지가 0이 되지 않고, 그때부터 사용자가 뱃지를 무시한다.

**`TYPE_JOIN` 상수는 남아 있고 그게 맞다** — 계약 §13에 `JOIN` 탭과 `JOIN_REQUEST` 정의가 살아 있다. 미사용이라고 지우지 말 것.

**현재 `FRIEND`에 있는 subType** — `MEMBER_JOINED` · `JOIN_ACCEPTED` · `MEMBER_LEFT` (+ 기존 추억·약속·레벨업)

### 확인 안 된 것 하나

`#250`이 `MEMBER_LEFT` 아이콘으로 **`ti-user-minus`** 를 썼다. Tabler 웹폰트 `2.47.0`을 CDN으로 쓰는 구조라(`index.html:15`) **없는 이름이면 에러 없이 빈 네모로 뜬다.** 번들에는 확실히 들어갔으니 **실제로 방 나가기 알림이 뜰 때 눈으로 볼 것.**

### 새 스킨 넣을 때 (이 순서를 지킬 것)

```
1. public/shop/skins/<mascot-id>/<skin-id>/  9장 + metadata.json

**조용히 깨지는 값 둘** — `category`가 `SKIN`이면 `ITEM_NOT_EQUIPPABLE`, `image_url` 오타면 `endsWith` 매칭이 실패해 **에러 없이 상태 전환만 사라진다.**

```sql
SELECT code, rarity, price, category, status,
       IF(category = 'COSTUME' AND image_url LIKE '/shop/skins/%', 'OK', '★ 확인') AS chk
FROM shop_items WHERE image_url LIKE '/shop/skins/%' ORDER BY sort_order;
```

### ⚠️ 에셋 내보내기 — 결함 하나는 멈췄고 하나는 6종 연속이다

| | 상태 |
|---|---|
| `metadata.json` `states` 절대 경로 | **멈췄다** — `senior-developer`부터 파일명 형식으로 나온다 |
| 캔버스 코너·최하단 **고립 픽셀** | **6종 연속** (옐로우 크루 · 수박껍질모자 · 오늘 4종) |

**판정은 "잔여물이 있느냐"가 아니라 "도구가 그걸 보느냐"에 건다.** `SpriteTool.cs`의 `ALPHA_THRESHOLD = 8`이 기준이다.

```
알파 ≤ 8   도구도 렌더도 못 본다   → 안 지운다 (수박껍질모자)
알파 > 8   Measure가 본다          → 지운다   (옐로우 크루 41 · 오늘 4종 9~37)
```

지우는 방법은 **`y < 12` 또는 `y >= 628` 두 띠에서 알파 ≤ 48만** 비우는 것이다. 본체는 어느 스킨도 그 띠에 안 닿는다(minY 22+, maxY ≤ 617). 지운 뒤 **bbox가 형제 범위로 돌아오는지**로 확인한다.

> **한 점이 두 값을 동시에 망친다.** `senior-developer`의 좌하단 코너(0, 639) 한 픽셀이 `minX=0`과 `maxY=639`를 같이 만들었다. **bbox가 캔버스 전체면 픽셀이 많은 게 아니라 구석에 하나 있는 것**일 때가 많다.

**경로 문제는 내보내기 쪽에서 멈췄으니 알파도 거기서 끝낼 수 있다.** 매번 손으로 잡는 건 이제 여섯 번째다.
