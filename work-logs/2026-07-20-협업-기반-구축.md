## 2. GitHub main 보호 규칙

`clov-api`, `clov-web` 양쪽 `main`에 `Protect main` ruleset을 설정했다.

- main 직접 push 금지, PR 필수
- force push 차단
- main 삭제 차단
- 대화 미해결 상태 병합 차단
- squash merge 사용
- 현재 Required approvals는 `0`으로 설정하여 혼자서도 PR 병합 가능
- `Require approval of the most recent reviewable push`는 Required approvals=0 환경에서
  자기 병합을 막으므로 해제했다.

> 팀원 협업이 안정화되면 Required approvals를 `1`로 올린다.

---

## 3. 로컬 시크릿 안전 조치

`clov-api`의 `application-secret.yaml`이 staging에 올라가 있던 것을 발견했다.

```text
git restore --staged src/main/resources/application-secret.yaml
```

- 실제 로컬 파일은 삭제하지 않고 Git staging에서만 제거했다.
- 확인 당시 파일 내용은 비어 있어, 확인 범위에서는 키 유출 흔적이 없었다.
- 실제 시크릿을 입력하기 전에 `.gitignore` 정책과 `application-secret.example.yaml` placeholder를
  PR로 반영해야 한다.

## 5. 하네스 PR 완료

기존 미커밋 작업을 건드리지 않기 위해, `project/` 바로 아래에 깨끗한 별도 클론을 만들었다.

```text
clov-api-harness/  — chore/collaboration-harness
clov-web-harness/  — chore/collaboration-harness
```

각 하네스 PR에 포함한 내용:

- `AGENTS.md`: 실행 명령어, 기술 스택, 코드·보안·협업 규칙
- `CLAUDE.md`: `AGENTS.md` 참조
- `docs/API-CONTRACT.md`: `web-design-repository/docs/API-CONTRACT.md` SSOT 포인터
- `.github/PULL_REQUEST_TEMPLATE.md`
- `.github/ISSUE_TEMPLATE/feature.md`, `bug.md`
- API: `.gitignore`의 로컬 시크릿 제외 규칙

| 저장소 | PR | 결과 |
|---|---|---|
| API | [#7](https://github.com/Pickeslog/clov-api/pull/7) | `main` 병합 완료, 이슈 #1 자동 종료 |
| Web | [#4](https://github.com/Pickeslog/clov-web/pull/4) | `main` 병합 완료, 이슈 #1 자동 종료 |
