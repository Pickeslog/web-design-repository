## 5. 남은 것 / 결정 대기

### ★ 알림 구조 — 유일한 병목 (리더)

`type`이 **탭 필터로 그대로 쓰인다**(`AND n.type = #{type}`). 그래서:

- `LEVEL_UP`을 새 `type`으로 추가하면 **어느 탭에서도 안 보이는 유령 알림**이 된다
- 레벨 값을 실을 `payload` 자리도 없다(`reference_id`는 BIGINT)
- **같은 뿌리로 `FRIEND` 탭이 영구 공백** — 알림 생성이 방 설정 변경(NOTICE)·가입 신청(JOIN) 두 곳뿐이라 추억·편지·약속은 알림을 안 만든다

이걸 정해야 api #62 → web #86이 풀리고 FRIEND 탭도 함께 해결된다.

**설계안 작성 완료** → `2026-07-24-알림-구조-설계안.md`. 결정할 것 4가지:

1. `sub_type` 컬럼으로 탭/이벤트 분리 (권고: 채택)
2. `payload` 지금 같이 넣을지 (권고: 넣음 — 알림이 4건뿐인 지금이 가장 쌈)
3. 방 설정 변경을 `NOTICE`→`FRIEND`로 이동, NOTICE 탭은 빈 상태 유지 (권고: 채택)
4. 하드코딩 가짜 공지 제거 (배포 전 필수)

> 실측: dev DB 알림 **총 4건, 전부 `JOIN`**. NOTICE·FRIEND 0건 → **마이그레이션 비용이 사실상 0.**
