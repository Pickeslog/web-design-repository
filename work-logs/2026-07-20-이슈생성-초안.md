## API-4. `[api] Security + JWT 기반 (토큰 발급·검증 필터)`

```markdown
## 목표
JWT 발급·검증 기반을 만들고 인가 규칙을 세운다.

## 계약 (읽고 시작)
- `docs/API-CONTRACT.md` §3 인가 2단 규칙 · §4 인증
- DB: `api-spec/05-db-unified-final.md` — `users`, `refresh_tokens`

## 작업
- [ ] **`build.gradle`에 jjwt 0.12.6 추가** (현재 누락 — 계약 §1이 요구)
      ```
      implementation 'io.jsonwebtoken:jjwt-api:0.12.6'
      runtimeOnly  'io.jsonwebtoken:jjwt-impl:0.12.6'
      runtimeOnly  'io.jsonwebtoken:jjwt-jackson:0.12.6'
      ```
- [ ] `JwtTokenProvider` — Access(단기, 예 30분) / Refresh(장기)
- [ ] JWT 인증 필터
- [ ] `SecurityConfig` — STATELESS, CSRF off, `BCryptPasswordEncoder`
- [ ] `refresh_tokens` 매퍼 (`revoked_at IS NULL` · 미만료 검증)

## 반드시 지킬 것 (도메인 불변식)
- ❌ **`role` 개념을 만들지 않는다.** `users`에 `role` 컬럼이 없고, 계약 §3이
  "방장/역할 없음"을 명시한다. JWT에 role claim을 넣지 않는다.
- 인가는 **2단 규칙**으로만:
  1. 공간 멤버십 — 요청자가 그 `room_id`의 `room_members`에 `status=ACTIVE`인가
  2. 작성자 본인 — 수정/삭제는 `writer_id`/`sender_id` 본인만
- jjwt는 **0.12.x 신 API** 사용: `subject()`·`expiration()` (구 `setXxx()` 금지)
- 비밀번호는 BCrypt 해시. 소셜 전용 계정은 `password` NULL

## 완료 기준
- [ ] 토큰 발급·검증 단위 테스트 통과

- [ ] `./gradlew test` 통과
```

## API-5. `[api] 소셜 로그인 3사 설정 (OAuth2 Client)`
라벨: `backend` `M1-스켈레톤`

```markdown
## 목표
카카오·네이버·구글 OAuth2 Client 설정을 코드에 반영한다.
콘솔의 기본 등록은 2026-07-20에 완료됐고, 팀원 테스트 계정 등록·카카오 시크릿 재발급은 잔여다.
이 이슈는 코드 반영과 실제 로그인 smoke test까지 다룬다.

## 배경 문서
- `web-design-repository/work-logs/2026-07-20-레포진단-및-카카오-OAuth설정.md` §5
- `web-design-repository/docs/OAuth-설정-체크리스트.md`
- 계약 §4 인증 · DB `users.oauth_provider` / `oauth_subject`

## 작업
- [ ] `application-secret.example.yaml` 골격 작성 (현재 **0바이트**)
      — DB 3종 + JWT secret + OAuth 3사 client-id/secret
- [ ] `application.yaml` — `registration` 3개 + kakao/naver `provider` 블록
- [ ] OAuth2 성공 핸들러 — 신규면 `users` 생성 후 JWT 발급
- [ ] OAuth 성공 뒤 프론트 전환 설계 확정 및 구현

## 3사 특이사항 (2026-07-20 콘솔 확인 결과)
| | client_id | user-name-attribute | provider 블록 |
|---|---|---|---|
| 카카오 | REST API 키 | `id` | 직접 작성 |
| 네이버 | Client ID | `response` | 직접 작성 |
| 구글 | Client ID | `sub` | 불필요(Spring 내장) |

- ⚠️ **카카오 Client Secret이 콘솔에서 ON**이다. `client-secret`을 반드시 설정에
  넣어야 한다. 누락 시 `invalid_client`.
- ⚠️ **네이버 응답은 `response`로 한 겹 감싸져 있다.** 파싱 코드 별도 필요.
      `{ "response": { "id": ..., "email": ..., "nickname": ... } }`
- ⚠️ **구글은 콘솔 설정 반영에 최대 수 시간** 걸린다. 저장 직후
  `redirect_uri_mismatch`가 나면 설정 오류가 아닐 수 있다.
- 콘솔에 등록된 Redirect URI (백엔드 8080, 프론트 5173 아님):
      `http://localhost:8080/login/oauth2/code/{kakao|naver|google}`

## 반드시 지킬 것
- ❌ 시크릿 값을 **커밋하지 않는다.** 이 레포는 **public**이다.
      `application-secret.yaml`은 gitignore, `.example`만 커밋.
- 소셜 전용 계정은 `password` NULL, `oauth_provider`/`oauth_subject`로 식별
- ⚠️ **이메일이 null인 경우 방어 코드 필요.** `users.email`이 `NOT NULL`이라
  그대로 INSERT하면 500이 난다. `400 OAUTH_EMAIL_REQUIRED`로 막는다.
  (카카오는 이메일 필수 동의라도 미인증 계정은 값이 안 올 수 있음)
- ❌ Access/Refresh Token을 프론트 redirect URL의 **query string에 넣지 않는다**.
  브라우저 히스토리·로그·Referer로 유출될 수 있다. 전달 방식(예: 보안 쿠키 또는
  일회성 교환 코드)은 구현 전에 팀 합의와 계약 반영이 필요하다.

## 완료 기준
- [ ] `/oauth2/authorization/{kakao|naver|google}` 접속 시 각 로그인 화면이 뜬다
- [ ] 로그인 성공 시 `users` row 생성 + JWT 발급
- [ ] `./gradlew test` 통과
```
