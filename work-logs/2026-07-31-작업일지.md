## 2. 하루의 줄기 — 이슈 하나가 계약 6곳을 열었다

출발점은 lami2342가 **07-27에 올린 #148**(추억 수정 모달 글자수 목업 정합)이었다.

```
목업 40자  ·  계약 §10 = 25자  ·  백엔드 DTO @Size(max=25)
```

**팀원이 틀린 게 아니라 계약이 틀렸다.** 25는 설계 판단이 아니라 어느 DTO에서 굳어진 숫자였다. 여기서 오늘의 작업 순서가 정해졌다.

```

```

그리고 이 한 번이 **"목업 숫자를 옮기는 자리"를 전부 다시 보게 만들었다** — 사진 개수, XP 보너스, 시작 골드, mascotType 허용값이 줄줄이 어긋나 있었다.

## 4. 막은 것 · 잡은 것

### ★ 배포 전에 막은 사고 — 제목 40자
프론트(#185)만 먼저 나갔으면 **26자부터 서버가 400을 던졌다.** 계약 → 백엔드 → 프론트 순서를 고정해서 막았고, 40 통과 / 41 거부를 **POST·PATCH 양쪽 테스트로** 못 박았다.

### ★ 재현해낸 프로덕션 버그 — 추억을 지우면 그 약속이 영구히 막힌다
약속에 연결된 추억을 지운 뒤 **같은 약속에 다시 쓰면 HTTP 500.** 소프트 삭제인데 **UNIQUE 키가 `deleted_at`을 빼고** 걸려 있어서 재삽입이 막힌다. 일회용 프로브 테스트로 재현하고 테스트는 지웠다. → **clov-api #98** 등록, kimgyubi1234 배정. 프론트 후속은 #200.

### ★ 되돌린 것 — 시작 골드 20,000
리뷰 없이 머지된 #99에 `SIGNUP_GRANT_AMOUNT = 20000`이 들어갔다. 카탈로그 총액 **42,260의 절반**이다. 가입 즉시 절반을 살 수 있으면 같은 날 확정한 **하루 500 규칙이 통째로 무의미해진다.** → #100으로 1,000 복구.

### 🔴 사진 개수는 네 곳이 다 달랐다
```
목업 30  ·  계약 8  ·  프론트 15  ·  백엔드 10        →  전부 8로 통일
```
**프론트 15 > 백엔드 10** — 즉 11장째 업로드는 이미 실패하고 있었다. 백엔드를 8로 내리자 XP 테스트가 깨졌는데(`보너스 10장까지`), 이건 오류가 아니라 **9·10번째 보너스 칸이 도달 불가였다는 증거**였다. 보너스 상한도 8로 맞췄다.

> **이번 주 세 번째다.** 세 건 다 원인이 같다 — **리더가 목업 숫자를 이슈에 옮길 때 계약·DTO를 안 봤다.** 상세는 핸드오프 §4.

크기를 상수로 더 키우는 대신 **설정으로 뺐다** — "작아 보인다"는 사람과 "가린다"는 사람이 동시에 있는 값이라 하나로 정할 수 없다. 테마·배경과 같은 방식(localStorage + `:root` 변수)이라 기기별로 남고, 첫 페인트 전에 적용돼 깜빡이지 않는다.

**여기서 내 실수 4건이 나왔다** — 어제 내가 주석에 적어둔 함정(`@Pattern` 동기화)이 **하루 만에 걸렸고**, 레지스트리 조회가 프로토타입 체인에 뚫려 있었고(`Object.hasOwn`으로 수정), #191이 꾸미기 패널을 놓쳤고, **#196 검증이 캐릭터 하나만 보고 일반화한 것**이었다(rob 900×510은 그때도 버튼 두 개를 덮고 있었다). 상세는 핸드오프 §11.

> **여러 값을 받는 자리는 대표값 하나로 검증하면 안 된다.**
