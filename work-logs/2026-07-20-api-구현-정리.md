## 현재 API 규칙

- Base path: `/api/v1`
- 성공: `{ "success": true, "data": ... }`
- 실패: `{ "success": false, "error": { "code", "message", "details?" } }`
- JSON ID는 문자열이다.
- Access Token은 30분, Refresh Token은 14일이다.
- Refresh Token 원문은 DB에 저장하지 않고 SHA-256 해시만 `refresh_tokens`에 저장한다.
- 역할(role), 방장, 관리자 개념은 없다.

## 인증 API

### 이메일 인증

| Method | Path | 비고 |
|---|---|---|
| POST | `/api/v1/auth/signup` | 가입 즉시 Access/Refresh/User 반환, 필수 약관 동의 필요 |
| POST | `/api/v1/auth/login` | 성공 시 Access/Refresh/User 반환 |
| POST | `/api/v1/auth/refresh` | Refresh 회전, 기존 Refresh revoke |
| POST | `/api/v1/auth/logout` | Refresh revoke, `data: null` |

주요 코드: `EMAIL_DUPLICATED`, `INVALID_CREDENTIALS`, `TERMS_REQUIRED`, `INVALID_TOKEN`, `TOKEN_EXPIRED`.

### 소셜 인증

| 단계 | Path | 비고 |
|---|---|---|
| 시작 | `/oauth2/authorization/{kakao|naver|google}` | Spring Security OAuth2 Client |
| 콜백 | `/login/oauth2/code/{provider}` | JWT를 URL에 넣지 않음 |
| 교환 | `POST /api/v1/auth/oauth/exchange` | 일회성 `code`를 Access/Refresh 또는 registrationToken으로 교환 |
| 동의 | `POST /api/v1/auth/oauth/consent` | 신규 소셜 계정의 약관 동의 후 사용자 생성 |

- OAuth 성공 후 프론트 이동 URL: `http://localhost:5173/oauth2/redirect?code=...`
- 일회성 code와 registrationToken은 개발 환경에서 60초 TTL 인메모리 저장소를 사용한다. 운영 다중 인스턴스 환경에서는 공유 TTL 저장소로 교체해야 한다.
- 이메일이 없는 소셜 프로필은 `OAUTH_EMAIL_REQUIRED`(400)으로 처리한다.
- 일회성 code의 무효, 만료, 재사용은 `OAUTH_CODE_INVALID`(401)이다.
