## 4. ★★ 재발 방지 — 이번에 확정된 함정 3개

### (1) 대시보드 CSS 정본은 `styles/space.css`다. `css/desktop.css`가 아니다

`02-main/index.html:7`이 로드하는 건 `styles/space.css?v=25`뿐이고, `css/desktop.css`를 참조하는 HTML은 `_archive/*`와 `04-feed/feed.html`뿐(= 구판). **두 파일에 같은 셀렉터가 있는데 값이 다를 수 있다.**

| 셀렉터 | 두 파일 관계 |
|---|---|
| `.theme-coverflow` | **다르다** — space.css(3447-3668)는 3D(perspective + rotateY ±25/35/45 + 슬라이드 전환 + 마우스 틸트), desktop.css(2757-2830)는 회전 없는 평면 |
| `.theme-diary` | 완전 동일(바이트 단위) |

마지막 수정: space.css `07-10` > desktop.css `07-07`. 3D coverflow는 `dca8c93`(07-08)에서 space.css에만 추가됐다. **PR #109가 desktop.css에서 가져와 3D가 빠진 채 머지됐다 → 후속 이슈 #114.**

### (2) stacked PR은 CI가 아예 돌지 않는다

`ci.yml`이 `on: pull_request: branches: [main]`이라 **main을 향한 PR에서만** 돈다. base가 feature 브랜치면 체크 0건이고 그대로 머지 버튼이 눌린다(#110이 그렇게 머지됐다). **base가 main으로 자동 재지정돼도 CI는 자동으로 안 돈다** — base 변경은 `pull_request.edited`인데 기본 트리거 타입이 아니다. 빈 커밋 push나 close→reopen이 필요하다.

### (3) 오래된 브랜치를 main에 올리면 그 사이 작업이 revert된다

diff의 삭제 라인 수가 유난히 크면 이걸 의심하고, 필요한 커밋만 cherry-pick할 것.
