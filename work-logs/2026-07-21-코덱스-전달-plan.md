> 사용법: clov-api에서 코덱스에 그대로 붙여넣는다. **room(#19) 다음**에 진행(`roomId` 부모). 어려운 도메인(인생4컷 stage 잠금) — 리더가 리뷰 강도를 높인다.

작업 전 `clov-api/AGENTS.md`, `web-design-repository/docs/AI-TEAM-HARNESS.md`·`DOMAIN-NAMING-REGISTRY.md`·`CODE-CONVENTION.md`, 그리고 계약 `docs/API-CONTRACT.md` §8·§9를 읽어.

## 목표
clov-api에 **plan(약속)+checklist 백엔드 슬라이스**를 구현한다. 이슈 **#24**. **약속 완료 = 추억 전환 유일 트리거**(`complete` → `memory_status=CANDIDATE`).

## 방식
auth 슬라이스(`domain/auth`)를 구조 그대로 복사하고 이름만 레지스트리 §2 `plan` 행의 확정값으로 치환한다. 공통은 재사용, 재생성 금지.

## 이름 (레지스트리 §2 — 확정값만)
- `domain/plan` · `PlanController`·`PlanService`·`PlanMapper`·`StagePhotoMapper`·`ChecklistController`·`ChecklistMapper` (+ XML)
- Entity: `Plan`(plans)·`PlanStagePhoto`(plan_stage_photos)·`PlanChecklist`(plan_checklists)
- XML namespace = 인터페이스 FQN, SQL id = 메서드명, `#{}`만.

## 엔드포인트 (계약 §8·§9 — 경로/요청/응답/에러코드 그대로)
**§8 plan**
- `POST /api/v1/rooms/{roomId}/plans` 등록(`SCHEDULED`/`memory_status=NONE`) · `GET .../plans` 목록(필터 `status`·날짜) · `GET /api/v1/plans/{planId}` 상세(체크리스트 포함) · `PATCH·DELETE /plans/{planId}`(작성자)
- `POST /plans/{planId}/complete` → `COMPLETED`·`memory_status=CANDIDATE` · `POST .../cancel`(CANCELED) · `POST .../skip-memory`(SKIPPED)
- **인생4컷 stage-photos**: `GET /plans/{planId}/stage-photos`(4단계 고정, state 서버계산) · `POST .../stage-photos/presign`(직전 단계 미완료 → `423 STAGE_LOCKED`) · `POST .../stage-photos` 등록(`stage`=PROPOSAL/SCHEDULING/CONFIRMED/MEETING). **수정/삭제 없음(증거)**, 재업로드 → `409 STAGE_ALREADY_UPLOADED`.

**§9 checklist**
- `POST /api/v1/plans/{planId}/checklists` 추가 · `PATCH /api/v1/checklists/{id}`(수정·`checked` 토글, 공동) · `DELETE /api/v1/checklists/{id}`

## 잠금 규칙 (반드시 — 이 도메인의 핵심)
- stage-photo는 **순차 잠금**: 직전 단계 DONE이어야 다음 단계 presign 허용(`423 STAGE_LOCKED`). state(LOCKED/ACTIVE/DONE)는 **서버 계산**. 업로드는 증거라 **수정/삭제 불가**, 재업로드 `409 STAGE_ALREADY_UPLOADED`.

## 규칙
- 최대 8명 단일 구조. `role`/방장 개념 만들지 마. MyBatis `#{}`만, JPA 금지. ID는 JSON 문자열. 계약·DB DDL·시크릿 건드리지 마.
