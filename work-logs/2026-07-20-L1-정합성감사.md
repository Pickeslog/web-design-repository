## 2. 발견 사항 (이슈 코멘트용 · 심각도순)

### 🔴 A. 약관/마케팅 동의를 저장할 DB 필드가 전혀 없다 — *API #2(DB) / 계약*
- 계약 §4는 signup에 "약관동의"를 명시하고, 화면은 **필수 2종(서비스 이용약관·개인정보 처리방침) + 선택 1종(마케팅)**을 수집한다. 그런데 `users`에도, 어디에도 동의 저장 컬럼/테이블이 없다(05-db 전수 검색 `약관|동의|consent|terms|agree|marketing|privacy` **0건**). `user_preferences`는 테마 전용.
- 특히 **마케팅 동의는 선택 항목이라 "동의 여부 + 시각"을 반드시 보존**해야 한다(법적 근거·철회 대응). 현 구조면 가입 시 받은 동의가 그대로 버려진다.
- **제안(택1, SSOT 먼저 수정)**:
  - ① `users`에 `terms_agreed_at`·`privacy_agreed_at`·`marketing_agreed_at` DATETIME NULL 추가 (간단, 버전 관리 약함)
  - ② `user_consents` 테이블 신설(user_id, consent_type, agreed, agreed_at, version) — 약관 개정 이력까지 대응
  - → 05-db 수정 후 API #2에 반영. 마케팅 철회는 프로필/설정에서 갱신.

### 🔴 B. 회원가입 시 프로필 이미지 업로드 경로 미정의(닭-달걀) — *계약 / API #6*
- 화면은 **계정 생성(step4) 전 step2**에서 이미지를 올린다. 그러나 업로드 수단 presign 엔드포인트(§5 `POST /api/v1/users/me/profile-image/presign`)는 **인가=본인**이라 가입 전 토큰이 없으면 못 쓴다.
- **제안(택1, 계약 명시)**:
  - ① 가입 시엔 이미지 생략 → 기본 이미지로 생성, 가입 직후 프로필수정에서 업로드 (구현 단순, 화면 흐름 조정 필요)
  - ② 미인증 임시 업로드 경로 신설(가입 완료 시 확정) — 유연하나 복잡

### 🟠 C. 계약 §4에 signup/login 요청·응답 JSON 본문 스키마가 없다 — *계약*
- 엔드포인트 표와 괄호 설명만 있고 **필드명·타입·응답 형태가 미명세**. 이대로면 코덱스(백)와 웹이 필드명을 제각기 지어내 연동 때 어긋난다.
- **제안**: §4에 요청/응답 예시 JSON 추가(응답 봉투 `{success,data}` 포함). 예:
  - `signup` req: `{ email, password, nickname, birthdate?, profileImageUrl?, agreements:{ service, privacy, marketing } }`
  - `login` req: `{ email, password }` / res: `{ accessToken, refreshToken, user:{...} }`
  - (필드명 최종 확정은 팀 합의 — 위는 초안)

### 🟡 D. 비밀번호 정책이 화면에만 있다 — *API #6*
- 화면 규칙 "8~20자, 영문/숫자/특수문자 중 2가지 이상"이 계약·백엔드에 없다 → 백엔드 `@Valid` 검증이 프론트와 어긋날 수 있다.
- **제안**: 계약 §4에 비밀번호 정책 1줄 명시 → 백/프론트 동일 규칙.

### 🟡 E. `personal_invite_code`는 폼에 없음 = 서버 생성 필수 — *API #6 (이미 언급)*
- NOT NULL·UNIQUE인데 입력 폼이 없다 → signup 시 서버 생성. 생성 규칙(길이·문자셋·충돌 재시도)이 미정. 이슈 #6 "생성 규칙 확인"과 연결.
