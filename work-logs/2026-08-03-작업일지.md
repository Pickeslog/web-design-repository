## 3. 렌더 박스가 흔들리던 것 — 도구로 고쳤다

마스코트는 `height`만 고정하고 `width: auto`다. **원본 비율이 상태마다 다르면 박스 폭이 같이 달라져 캐릭터가 좌우로 움직인다.**

```
크로비  366x640 ~ 1086x1448  →  박스 103~135px 널뛰기
```

배율 기준을 **알파 면적의 제곱근**으로 잡았다. bbox 높이로 맞추면 **웅크린 `pencil`이 부풀고, 줄에 매달린 `pulled`이 쪼그라든다.** 머리 폭은 벌린 팔·소품에 오염돼 못 쓴다(`smile`의 머리가 856px로 측정됐는데 실제로는 팔이었다).

| | 전 | 후 |
|---|---|---|
| crobi | 박스 103~135px · 8.5MB | **116px 고정** · 3.0MB |
| tako-gun | 640/1254 혼재 · 7.3MB | 640x640 고정 · 2.6MB |

`clov-web/scripts/mascot/`에 스크립트로 남겼다. **기본이 드라이런**이고 대조 시트로 눈으로 확인한 뒤 `-Apply`한다.

**★ 도구가 만들 수 있는 사고도 같이 막았다.** 이미 한 세트로 그려진 폴더에 돌리면 **면적 기준이 포즈별 소품의 잉크 양을 크기 차이로 오독한다.** 실측으로 `rob` 0.948~1.02, `kim-cheolsu` 0.99~1.09가 나왔다 — 멀쩡한 세트가 어긋난다. 캔버스가 이미 단일 규격이면 경고를 내도록 했다.

## 8. 오후 — 세 번째 스킨, 그리고 빌드 산출물에 들어온 에셋

롭의 에픽 스킨 '마지막 신호병'을 받았다. 오늘 세 번째 스킨이고, 배선은 **경로 한 줄**로 끝났다 — `hasFullStateSet` 구조를 아침에 만들어 둔 덕이다.

**★ 에셋이 `public/`이 아니라 `dist/`에 들어와 있었다.** `dist`는 빌드 산출물이라 `.gitignore` 대상이고 다음 빌드에서 통째로 지워진다. **git에 올라가지도 않고, 다음 `npm run build` 한 번이면 사라지는 자리다.** 옮긴 뒤 빌드해서 `dist`에 정상 복제되는 것까지 확인했다.

경로 오타는 에러 없이 default 한 장만 나오게 만드는 자리라, `Mascot.jsx`에서 배열과 상태 매핑을 **직접 파싱해** 대조했다 — 손으로 다시 적으면 검증이 아니다.

```
roots 3 x states 9  ->  27개 경로 전부 해석됨
```

가격은 **6,000**으로 정했다. 롭에게 스킨이 둘이 되면서 **등급 순서가 처음으로 실제 검증 대상이 됐다.**

| 실효가 | 등급 | |
|---:|---|---|
| 5,200 | EPIC | 롭 탐험가 |
| **6,000** | **EPIC** | **마지막 신호병** ← 상시 EPIC 최고 |
| 6,400 | EPIC | 첫눈 (EVENT) |
| 6,860 | LEGENDARY | 벚꽃 세트 (30% 할인) |

상시 EPIC 최고가 위, 기간 한정 EPIC 아래, 가장 싼 LEGENDARY 아래 — **어느 선도 넘지 않는다.** EVENT가 같은 등급 상시 상품보다 비싼 건 기존 카탈로그가 이미 지키던 규칙이라 EPIC 층에서도 따랐다.

등록 SQL에 **검증 쿼리를 두 개** 넣었다. 하나는 행 확인, 하나는 **위 표를 실효가 정렬로 다시 뽑는 것**이다. 앞으로 스킨이 늘어도 이 쿼리 하나로 순서가 검증된다.

## 9. ★ 같은 도구가 "돌려라"와 "돌리지 마라"를 둘 다 맞게 냈다

정규화 스크립트를 오후에 두 폴더에 돌렸는데, **판정이 갈렸고 둘 다 맞았다.**

| | 캔버스 | scale | 판정 |
|---|---|---|---|
| 마지막 신호병 스킨 | 이미 640x640 단일 | 0.937~1.111 | **안 돌린다** |
| 롭 본체 | **900x510 / 916x475 혼재** | 0.965~1.089 | **돌린다** |

**scale만 보면 둘이 구분되지 않는다.** 신호병 쪽 편차는 크기 차이가 아니라 포즈별 소품(돋보기·연필·종이)의 잉크 양이다. 도구가 **캔버스 균일성**만으로 둘을 갈랐다 — 아침에 그렇게 고쳐 둔 판정 기준이 **두 방향 다 맞게 동작한 첫 사례**다.

롭 본체가 왜 문제였나. 렌더 박스는 `max-width` 때문에 180px 정사각으로 고정이라 **박스는 안 흔들린다.** 흔들린 건 그 안에서 그려지는 그림이다.

```
900x510  비율 1.765  ->  180x102 로 그려짐
916x475  비율 1.928  ->  180x93  으로 그려짐
```

`object-fit: contain`이 세로 가운데 정렬이라, 상태가 바뀔 때 **롭이 8% 작아지면서 4px 내려앉았다.** 크로비 때(박스 자체가 103~135px 널뛰던 것)와 증상이 다르다.

적용 후 scale `0.994~1.003`, 하단 여백 `47~48px`로 수렴했다.

## 10. ★ "용량만 줄인 파일"이 사실은 그림 버그였다

정규화를 머지한 뒤, 리더가 같은 스프라이트를 **더 작은 파일로 다시 내보냈다.** 용량 최적화로 알고 받았는데 — 캔버스도 정렬도 이미 맞아서 정규화가 필요 없는 상태였다 — 픽셀을 대조해 보니 **바뀐 곳이 따로 있었다.**

```
file       다른픽셀   투명끼리   눈에보임   bbox
dizzy         7484        0       7484    (358,360)-(543,401)
pulled        7484        0       7484    (358,360)-(543,401)
scared        7484        0       7484    (358,360)-(543,401)
smile         7484        0       7484    (358,360)-(543,401)
```

**네 파일이 완전히 같은 값이다.** 우연일 수 없다. bbox 186x42가 **가슴 패널**(초록 LED가 달린 검은 바) 모양과 정확히 일치했다.

즉 **main에 들어가 있던 네 상태에는 가슴 패널이 없었다.** 나머지 다섯에는 다 있는 요소라, 상태가 넘어갈 때 롭 가슴에서 패널이 사라졌다 나타났다. 아홉 중 넷이다.

### 원본 보존이 판정 근거가 됐다

여기서 바로 물어야 할 게 있었다 — **내 정규화가 지운 건가?**

`normalize-sprites.ps1`은 배율·정렬만 건드리므로 도형을 지울 수 없다. 하지만 그건 논리이고, **증거는 원본에 있었다.** 덮어쓰기 전에 web-design에 보존해 둔 916x475 파일을 열어보니 **거기부터 패널이 없었다.** 정규화는 없는 걸 없는 채로 옮겼을 뿐이다.

> 도구 NOTES의 *"덮어쓰기 전에 고해상도 원본을 web-design-repository에 보존할 것"* 이 값을 한 자리다.
> **안 지켰으면 "내 도구가 지웠나"를 판정할 방법이 아예 없었다.** 원본이 없으면 비교 대상이 없다.

### 아카이브가 사본보다 나쁜 그림을 들고 있었다

패널 없는 판이 원본 자리에 남아 있으면, **나중에 거기서 다시 정규화할 때 이 버그가 되살아난다.** 원본이 정본 구실을 못 하는 상태라 아카이브도 같이 교체했다.

다만 4장만 덮었다. 나머지 5장은 clov-web 사본이 정규화로 배율이 바뀐 **파생본**이라, 원본을 남겨둬야 되돌아갈 기준이 생긴다.

### 요소를 더했는데 용량이 줄었다

내보내기 설정이 달라진 것으로 보인다. **여기서 정규화를 다시 돌리면 손해다** — 재인코딩이 759KB를 888KB로 되돌린다. 도구도 "이미 단일 규격, 웬만하면 돌리지 말 것"이라고 경고한다.

## 11. 배포 — 초록불을 인증 없이 검증했다

clov-web 6커밋을 배포했다. **clov-api는 배포하지 않았다** — 대기분이 마이그레이션 SQL 하나뿐이라 런타임 코드가 없다. 배포해봐야 스프링만 재시작되고, **그 레포는 헬스체크가 없어 그 사이 502가 난다**(§5). 얻는 것 없는 다운타임이다.

배포 로그의 초록불을 믿지 않고 실제 응답을 받아봤다. API는 인증이 걸려 밖에서 못 읽지만 **정적 자원은 토큰 없이 확인된다.**

| | |
|---|---|
| `public/` 자산 | 경로 그대로 GET — 바이트 수가 디스크와 일치하는지 본다 |
| `src/assets/` 자산 | Vite가 **내용 해시로 파일명**을 만든다. 로컬 `dist/assets/`의 해시 파일명을 배포 도메인에 그대로 요청해서 200이면 **그 내용이 올라간 것이 증명된다** |

```
/shop/skins/rob/last-signal-epic/default.png   200   246,970 bytes
dizzy-BH8FO9NI.png                             200   156,270 bytes
smile-BEcbywzy.png                             200   145,009 bytes
```

배포 로그에 경고가 하나 있었다 — `REACT_ENV_deploy-myeongjun` 시크릿이 없어 레포의 `.env.production`을 그대로 썼다. **팀 공용 도메인으로 나간다는 뜻**이고, 리더 배포라 의도한 동작이다.

에셋이 먼저 올라간 뒤 상점 SQL을 실행했다. **순서가 반대였으면 상점에 이름만 뜨고 그림이 깨졌다.** 검증 쿼리 여섯 칸이 전부 OK로 나왔다.

## 13. 다음에 또 쓸 것

- **스택 PR을 쓸 때는 base 브랜치를 머지 시 삭제되게 한다.** 안 그러면 GitHub이 리타깃을 안 해서 `MERGED`인데 코드가 main에 없는 상태가 된다
- **초록불의 의미를 워크플로마다 확인한다.** clov-web은 헬스체크가 있어 "서비스 정상"이고, clov-api는 "컨테이너가 떴다"까지다
- **여러 값을 받는 자리는 대표값 하나로 검증하지 않는다** — 스프라이트 배율을 bbox 높이로 잡았으면 웅크린 포즈가 전부 부풀 뻔했다
- **도구를 만들면 "쓰면 안 되는 경우"도 같이 넣는다.** 정규화 스크립트는 이미 정렬된 세트에 돌리면 오히려 어긋난다
- **DB에 값을 넣을 때 "틀려도 에러가 안 나는 컬럼"을 먼저 찾는다.** `category`·`image_url`이 그런 자리였고, 검증 쿼리로 판정까지 뽑게 했다
- **팀원이 남긴 "착수 전 확인 필요"는 대신 확인해주면 그대로 블로커가 풀린다** — #230의 토큰 정본 문제가 그랬다
- **★ 도구가 파괴적이면, 그 도구의 안전장치를 지킨 것이 나중에 무죄 증명이 된다** — 가슴 패널이 빠졌을 때 "정규화가 지웠나"를 판정할 수 있었던 건 덮어쓰기 전에 원본을 보존해 뒀기 때문이다. 원본이 없으면 비교 대상이 없어 논리로만 우기게 된다
- **"용량만 줄였다"는 말도 픽셀로 확인한다** — 네 파일이 정확히 같은 픽셀 수(7,484), 정확히 같은 사각형에서 달랐다. 우연이 아닌 값이 나오면 그 자리에 요소가 있다
- **에셋을 받으면 `public/`인지 먼저 본다** — `dist/`는 빌드 산출물이라 gitignore 대상이고, 다음 빌드 한 번이면 사라진다
- **판정 기준은 대표값이 아니라 원인에 건다** — 정규화 판정을 `scale`에 걸었으면 두 폴더를 구분 못 했다. `캔버스 균일성`에 걸었기 때문에 "돌려라"와 "돌리지 마라"가 둘 다 맞게 나왔다
- **배포 반영은 콘텐츠 해시로 인증 없이 증명할 수 있다** — Vite가 내용으로 파일명을 만드니, 로컬 `dist/assets/`의 해시 파일명이 배포 도메인에서 200이면 그 내용이 올라간 것이다
- **런타임 코드가 없는 커밋은 배포하지 않는다** — SQL 마이그레이션만 바뀐 clov-api를 배포하면 얻는 것 없이 재시작 다운타임만 생긴다
