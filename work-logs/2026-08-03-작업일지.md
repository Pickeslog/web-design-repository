## 2. 줄기 하나 — 스프라이트 9장이 기능이 됐다

시작은 "롭처럼 크로비도 여러 동작 되게 하자"였다. 앱은 **크로비 1종 / 롭 5종**만 갖고 있었고, 목업에는 **크로비 3종 / 롭 8종**이 있었다.

```
프로토타입에서 rob 9종 전량 이식  →  크로비·타코군·김철수 세트 완비  →  오닉스 신규
                                  →  상점 스킨(롭·김철수)까지 같은 구조 재사용
```

**한 번 만든 규칙이 계속 재사용됐다.** `MASCOT_STATE_SPRITES`에 9종이 다 있으면 `hasFullStateSet`이 참이 되어 연타·수면·드래그가 붙는데, 이 판정이 **캐릭터에도 스킨에도 똑같이** 걸린다. 그래서 오닉스도, 상점 스킨도 코드를 새로 안 짜고 붙었다.

| | 아침 | 저녁 |
|---|---|---|
| 상태 세트를 가진 캐릭터 | 1종(롭) | **5종 중 4종** (버거노인만 1장) |
| 상점 스킨 | 없음 | **2종** (롭 전설 · 김철수) |
| 장착 시 상태 변화 | 죽음 | **살아 있음** |

## 3. 렌더 박스가 흔들리던 것 — 도구로 고쳤다

마스코트는 `height`만 고정하고 `width: auto`다. **원본 비율이 상태마다 다르면 박스 폭이 같이 달라져 캐릭터가 좌우로 움직인다.**

```
크로비  366x640 ~ 1086x1448  →  박스 103~135px 널뛰기
```

배율 기준을 **알파 면적의 제곱근**으로 잡았다. bbox 높이로 맞추면 **웅크린 `pencil`이 부풀고, 줄에 매달린 `pulled`이 쪼그라든다.** 머리 폭은 벌린 팔·소품에 오염돼 못 쓴다(`smile`의 머리가 856px로 측정됐는데 실제로는 팔이었다).

| | 전 | 후 |
|---|---|---|
| crobi | 박스 103~135px · 8.5MB | **116px 고정** · 3.0MB |
| tako-gun | 640/1254 혼재 · 7.3MB | 640x640 고정 · 2.6MB |

`clov-web/scripts/mascot/`에 스크립트로 남겼다. **기본이 드라이런**이고 대조 시트로 눈으로 확인한 뒤 `-Apply`한다.

**★ 도구가 만들 수 있는 사고도 같이 막았다.** 이미 한 세트로 그려진 폴더에 돌리면 **면적 기준이 포즈별 소품의 잉크 양을 크기 차이로 오독한다.** 실측으로 `rob` 0.948~1.02, `kim-cheolsu` 0.99~1.09가 나왔다 — 멀쩡한 세트가 어긋난다. 캔버스가 이미 단일 규격이면 경고를 내도록 했다.

## 4. ★ MERGED인데 코드가 main에 없었다

lami2342가 `#114`를 올렸다. base가 `#112`의 피처 브랜치인 **스택 PR**이었고, 그 판단 자체는 옳았다 — `#112`의 `fanOut` 호출이 있어야 의미가 있는 변경이다.

그런데 `#112`가 **스쿼시 머지**되고 나서도 `fix/90-91-...` 브랜치가 **원격에 살아 있었다.** GitHub은 base 브랜치가 삭제될 때만 리타깃하므로, `#114`는 **이미 main에 반영된 옛 브랜치로 머지됐다.**

```
$ git grep -c "SUB_JOIN_ACCEPTED" origin/main -- src/main/java
0건
```

**PR은 MERGED로 표시되는데 코드는 main에 없다.** 델타를 재적용한 PR을 따로 만들었는데(#117), 그 사이 lami2342가 스스로 base를 바로잡아 `#115`로 다시 올렸다. **두 PR의 diff가 완전히 동일함을 대조하고 내 것을 닫았다.**

> 08-01의 *"`git log`의 0 commits ahead는 '같다'가 아니다"* 와 같은 계열이다. **머지 표시를 믿지 말고 내용으로 확인한다.**

## 6. 잡은 버그 둘

### 참여 멤버가 4명인데 5명이 보였다

`GET /members`는 계약 §6대로 **`ACTIVE`와 `LEFT`를 모두** 반환하고, 헤더 숫자 `memberCount`는 서버가 ACTIVE만 센다. **헤더가 맞고 목록이 틀렸다.**

같은 파일의 생일 배너와 `Feed`·`Letters`는 이미 거르고 있어서 **이 자리만 빠져 있었다.**

**표시보다 참여자 선택 쪽이 컸다** — `CreateMemoryModal`이 넘겨받은 멤버를 전원 기본 선택하므로, **나간 사람이 참여자로 자동 체크된 채 추억이 등록되고 있었다.**

### 합류 알림이 엉뚱한 사람 이름으로 떴다

"Dow As가 입장했는데 김명준님이 합류했어요"로 뜨던 것. accept API의 `userId`가 승인자인데 그걸 actor로 써서 났다(lami2342 `#112`).

공용 팬아웃으로 바꾸면서 **합류자 본인이 알림 대상에서 빠졌다** — 계약대로는 맞는 동작인데, 짝인 `JOIN_ACCEPTED`가 미구현이라 **"승인됐는데 아무 소식이 없는"** 빈자리가 생겼다. 리뷰에서 지적해 `#113`으로 분리했고 `#115`로 채웠다.

프론트도 두 subType을 못 읽어 기본 문구로 떨어지거나 actor가 뒤바뀐 문구가 나왔다. **`RoomPreviewModal`이 `type` 하나로만 문구를 골라서** `JOIN_ACCEPTED`가 "{수락자}님이 합류했어요"로 뜨는 자리였다 — `#228`에서 `subType` 분기로 고쳤다.

## 7. 상점 스킨 — 조용히 깨지는 값 둘

에셋과 프론트가 다 준비돼도 **`shop_items` 행이 없으면 상점에 아예 안 뜬다.** 카탈로그는 코드가 아니라 DB 데이터다.

등록 SQL에서 두 값이 틀리면 **에러 없이** 깨진다.

| | 틀리면 |
|---|---|
| `category`가 `SKIN` | 구매는 되는데 **장착이 막힌다**(`ITEM_NOT_EQUIPPABLE`) |
| `image_url` 오타 | 상태 전환만 사라지고 **default 한 장**만 나온다 |

가격은 카탈로그 수치로 정했다. 임시 7골드로 시작했지만, LEGENDARY 실효가가 6,860~12,000이고 여름밤 12,000은 `EVENT`(기간 한정)라, **상시 판매 최고가**를 이 아이템이 갖는 게 맞다고 보고 **9,800**으로 확정했다. 김철수는 UNCOMMON이라 **1,500**.

**데모용으로 가격을 내리지 않았다** — 되돌리기 전에 산 계정에는 `paid_price`에 낮은 값이 그대로 남는다. 대신 지갑을 채우는 스크립트를 만들었다.
