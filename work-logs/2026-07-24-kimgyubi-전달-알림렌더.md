## 지금 뭐가 문제인가

1. messageFor(36~41줄)가 subType을 안 봐서 FRIEND 알림이 전부
   "○○님의 새로운 활동이 있습니다"로 뭉뚱그려져. 추억·약속·레벨업 구분이 안 돼.
2. payload?.title / payload?.content / payload?.actorName (37·39·44~45줄)은
   계약에 없는 죽은 필드야. 항상 undefined. 이제 payload는 객체({level:3})로 와.
3. PROTOTYPE_NOTICES(21~24줄) 가짜 공지 2건이 실제로 화면에 떠. 제거해야 해.

## 할 일

### (1) messageFor를 subType 기반으로

계약 §13 카탈로그대로 문구를 만들어. 응답에 notification.subType, notification.actor,
notification.payload 가 있어.

  MEMORY_WRITE   → `${actor.nickname}님이 추억을 남겼어요`
  PLAN_CREATE    → `${actor.nickname}님이 새 약속을 만들었어요`
  PLAN_COMPLETE  → `${actor.nickname}님이 약속을 완료했어요`
  ROOM_UPDATE    → `${actor.nickname}님이 우정공간 정보를 바꿨어요`
  LEVEL_UP       → `우정공간이 Lv.${payload.level}이 됐어요! 🎉`   ← actor 없음!
  (그 외/모르는 subType) → 기존 제네릭 문구로 fallback

문구 톤은 프로토타입 알림 명세를 참고해서 다듬어도 돼. 위는 기준이야.

### ⚠️ LEVEL_UP 함정 두 개 — 이거 꼭 지켜

- LEVEL_UP은 actor가 null이야(방 전체 이벤트라 "누가"가 없음).
  actor.nickname을 그냥 읽으면 null.nickname으로 크래시나.
  반드시 subType === 'LEVEL_UP'을 먼저 분기해서 actor를 안 건드리는 경로로 보내.
- 레벨 값은 payload.level에 있어. payload는 객체야(JSON 아니라 이미 파싱됨).

### (2) 죽은 payload 코드 정리

payload?.title / payload?.content / payload?.actorName 쓰는 곳 다 걷어내.
titleFor(43~46줄)도 subType 기반으로 정리하거나 카드 구조에 맞게 단순화.

### (3) 가짜 공지 제거 + 빈 상태

- PROTOTYPE_NOTICES 상수랑 그걸 목록에 섞는 코드 제거.
- NOTICE(관리진 공지) 탭은 운영 공지 기능이 아직 없어서 비어.
  "아직 공지가 없어요" 같은 빈 상태를 보여줘(다른 탭 빈 상태 패턴 재사용).
