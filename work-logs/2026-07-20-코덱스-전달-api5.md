## 코덱스 전달 프롬프트 (복붙)

```
작업 전에 clov-api의 AGENTS.md와 web-design-repository/docs/API-CONTRACT.md §4-2(소셜 토큰 전달·동의)를 읽어.
그리고 work-logs/2026-07-20-레포진단-및-카카오-OAuth설정.md §5(3사 콘솔 확인 결과)와
docs/OAuth-설정-체크리스트.md도 읽어. 계약·DB 스키마는 임의로 바꾸지 마.

이슈 #5([api] 소셜 로그인 3사 설정 (OAuth2 Client))를 구현해.
콘솔 3사 등록·팀원 테스터는 이미 완료. 이 이슈는 코드 반영 + 토큰 전달 흐름이다.

[설정]
- application-secret.example.yaml: OAuth 3사 client-id/client-secret placeholder 추가(값 없이).
  실제 값은 application-secret.yaml/환경변수로만. 커밋 금지.
- application.yaml: spring.security.oauth2.client 에 registration 3개 + kakao/naver provider 블록.
  · redirect-uri 콘솔 등록값: http://localhost:8080/login/oauth2/code/{kakao|naver|google}
  · app.oauth2.redirect-url = http://localhost:5173/oauth2/redirect (프론트, 이미 있음)

[3사 특이사항 — work-log §5 확인 결과 그대로]
- 카카오: client-id=REST API 키, user-name-attribute=id, provider 블록 직접 작성,
  client-secret ON(설정에 반드시 넣기 — 누락 시 invalid_client)
- 네이버: user-name-attribute=response (응답이 response로 한 겹 감싸짐 → 파싱 별도), provider 블록 직접 작성
- 구글: Spring 내장(CommonOAuth2Provider), user-name-attribute=sub, provider 블록 불필요

[DB/엔티티]
- User에 oauth_provider, oauth_subject 필드 + UserMapper.findByOauth(provider, subject) 추가
- 소셜 계정은 password NULL. UNIQUE(oauth_provider, oauth_subject)로 식별(05-db uk_users_oauth)

[토큰 전달 — 계약 §4-2 그대로]
- OAuth2 성공 핸들러: (provider, subject)로 조회 → 일회성 코드(수명 ~60초·1회용) 발급
  → {app.oauth2.redirect-url}?code={oneTimeCode} 로 리다이렉트.
  ❌ accessToken/refreshToken을 URL에 직접 담지 마.
- POST /api/v1/auth/oauth/exchange { code }
  · 기존/동의완료: { authenticated:true, accessToken, refreshToken, user }
    (#4 JwtTokenProvider·RefreshTokenMapper, #6 토큰발급 로직 재사용)
  · 신규 소셜: { authenticated:false, registrationToken, profile{email,nickname,provider} }
  · 코드 무효/만료/재사용 401 OAUTH_CODE_INVALID / 이메일 미수신 400 OAUTH_EMAIL_REQUIRED
- POST /api/v1/auth/oauth/consent { registrationToken, agreements{service,privacy,marketing} }
  · service/privacy false 400 TERMS_REQUIRED
  · users 생성(동의 시각 기록, #6 로직 재사용) 후 { accessToken, refreshToken, user }
  · registrationToken 무효/만료 401 OAUTH_CODE_INVALID
- 일회성 코드·registrationToken 저장: 개발용은 만료 TTL 가진 인메모리 저장소로 충분(단일 인스턴스).
  프로덕션 다중 인스턴스는 공유 저장소 필요 — 주석으로 남겨.

[반드시 지킬 것]
- users.email NOT NULL — 소셜에서 이메일 못 받으면 INSERT 500 대신 400 OAUTH_EMAIL_REQUIRED로 막기
- role 개념 금지. base path /api/v1. MyBatis만(JPA 금지), SQL #{}. 시크릿 커밋 금지(public repo)
- SecurityConfig: /oauth2/**·/login/**·/api/v1/auth/** 는 이미 permitAll(#4). exchange/consent도 permitAll

[완료 기준]
- /oauth2/authorization/{kakao|naver|google} 접속 시 각 로그인 화면
- 로그인 성공 → 프론트로 code 리다이렉트 → exchange로 토큰 발급(신규는 consent 거쳐)
- ./gradlew test 통과(핸들러·exchange·consent 테스트)

작업 후 git diff로 범위가 이슈 #5와 맞는지 확인하고 결과를 보고해줘. 실제 시크릿은 절대 커밋하지 마.
```
