## 6. clov-api #98 — 추억 삭제 시 약속 영구 차단(500) 해소 + 약속 연결 변경/해제 PATCH

**사용자 지시**: "clov-api#98 착수해줘. 새 브런치부터 만들고 진행해야해" + 팀장이 이미 남긴 상세 코멘트(원인 분석·권장 방식 B안·주의사항 5개) 전달 → 구현 완료 후 **"이걸 참고해서 정말로 문제 없는지 검토해봐"**(`pr-리뷰-코멘트-프롬프트-템플릿.md` 방식 자체 리뷰 요구) → "PR만 하고 머지는 하지 않기로 했어. PR만 해줘".

**브랜치**: `feat/98-memory-delete-plan-status-planid-patch`

담당 도메인 밖(clov-api 백엔드)이지만, lami2342 조기 퇴근으로 팀장이 직접 인수인계 요청(§98 코멘트 "왜 부탁드리는지" — 해당 코드를 원래 만든 사람이라는 이유).

### (1) 삭제 시 `memory_status` 되돌리기
- `MemoryService.delete()`에서 soft delete 후 `revertPlanStatusIfEmpty(planId)` 호출 — 그 약속에 살아있는 추억이 0개면 `WRITTEN` → `CANDIDATE`
- 다른 멤버의 추억이 남아 있으면 건드리지 않음(핵심 원칙: 친구별 각자 기록), `NONE`으로는 절대 되돌리지 않음

### (2) 삭제 후 재작성이 500이 아니게(B안 + 되살리기)
- `findByPlanIdAndWriterId`가 이제 소프트 삭제분도 조회(uk_memories_plan_writer가 `deleted_at`을 모르는 게 근본 원인)
- 활성 행이 있으면 기존대로 `409 MEMORY_ALREADY_WRITTEN`, 삭제된 행만 있으면 **같은 행을 되살림**(새 INSERT 아님) — EXP/알림 재발급 없음(무한 채굴 방지)
- `DataIntegrityViolationException` 핸들러 신설 — 다른 유니크 제약도 같은 함정이 있어 경합 시 500 대신 `409 DUPLICATE_RESOURCE`

### (3) 약속 연결 변경/해제
- `PATCH /memories/{id}`에 `planId` 추가(연결/이동/해제), `providedFields`로 "안 보냄"과 "null"을 구분
- 다른 방 약속은 404(존재 자체를 숨김), 미완료는 409 `PLAN_NOT_COMPLETED`, 중복은 409 `MEMORY_ALREADY_WRITTEN`, EXP는 무관(팀장 확인사항)
