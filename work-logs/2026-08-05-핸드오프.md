## 2. ★★★ 골드 — 코드는 준비됐고 아직 안 돈다

### 오늘 확정된 값 (계약 §15-4·§10, `web-design#63`)

| 사유 | 금액 | 자체 제한 | 하루 최대 |
|---|---:|---|---:|
| `EARN_MASCOT` | 200 | 하루 10회 | 2,000 |
| `EARN_MEMORY` | 300 | **횟수 캡 없음** | 총 상한까지 |
| `EARN_MEMORY_FREE` | 200 | 하루 10회 + **본문 20자 이상** | 2,000 |

**유저 단위 하루 총 상한 `6,000`** (완주 약 9일 · 카탈로그 52,000 실측)

### ★ `#92`가 원안대로 머지됐으면 증상이 절반만 사라졌다

원 구현은 `createFree`(자유 추억 = 추억피드에서 약속 없이 쓰는 글)를 **지급 대상에서 명시적으로 제외**했다.

```
useCreateMemory.js:12   planId ? createPlanMemory : createMemory

약속 선택함  → POST /plans/{id}/memories   → createFromPlan()  → 지급
약속 없음    → POST /rooms/{id}/memories   → createFree()      → 원안은 0골드
```

리더가 보고한 증상이 정확히 이쪽이었다. 계약은 그 위험(*"혼자 무한히 쓸 수 있다"* — **정확한 진단이다**)을 "제외"가 아니라 **"사유 분리 + 횟수 캡 + 본문 길이"**로 막는 쪽으로 결론냈다.

### ★ 본문 20자 조건을 반드시 유지할 것

```java
// CreateMemoryRequest — 필수인 것은 title 뿐이다
@NotBlank @Size(max = 40) String title,
@Size(max = 100) String content,          // 최소도 @NotBlank도 없다
```

**제목 한 글자짜리 글도 정상 저장된다.** 20자 조건을 빼면 `"ㅇ"` 열 번에 2,000골드다.

> **★ 이 게이트가 "클릭 200 = 글 200"을 지탱한다.** 마스코트 교감과 자유 추억이 같은 200인 건 의도인데, **노력 차이를 금액이 아니라 게이트가 만든다.** 게이트를 없애면 두 값을 다시 갈라야 한다.
>
> ⚠️ **XP는 조건 없이 그대로 준다. 골드만 조건부다.** 20자 미만이어도 글은 정상 생성되고 `201`이 나간다 — **여기에 `400`을 만들지 말 것**(계약: *"글쓰기를 막는 건 골드 캡이 할 일이 아니다"*).

### ⚠️ 배포해도 화면은 조용하다

`#92`가 생성 응답에 `earnedGold`를 붙였지만 **clov-web이 그 필드를 안 읽는다.**

```jsonc
POST /rooms/{roomId}/memories → 201
{ /* MemoryDetail 전체 */, "earnedGold": 200 }
```

- `0`이 **정상값**이다 — 상한 초과 · 횟수 초과 · **본문 20자 미만** · 삭제 후 재작성(revive)
- 조회·수정 응답에는 **안 붙는다**(`@JsonInclude(NON_NULL)`) — 그때는 지급이 없어서 `0`을 보내면 캡에 걸린 `0`과 구분이 안 된다
- 화면은 `earnedGold > 0`일 때만 획득 연출을 한다(§12 마스코트와 같은 규약)

**골드 획득 연출과 배지 갱신이 `clov-web#178` 자리다.** 그게 붙기 전까지는 *"글을 썼는데 골드가 들어왔는지 모르겠다"*가 남는다. 잔액 자체는 `GET /shop/wallet`으로 올라간다.

### 남은 미결

- **약속 생성·완료에 골드가 없다** — `web-design#64`. 지금 설계는 "만들기 → 완료 → 작성" 한 덩어리에 300을 매기는데 **확정한 기록이 없다**

## 3. ★★ SQL — `EARN_` 합산의 이스케이프 함정

```sql
WHERE reason LIKE 'EARN!_%' ESCAPE '!'     -- ✅ 이렇게 쓴다
WHERE reason LIKE 'EARN\_%' ESCAPE '\'     -- ❌ MySQL 구문 오류
```

**MySQL은 문자열 리터럴 안의 백슬래시를 이스케이프 문자로 먼저 해석한다** — `\'`가 닫는 따옴표를 이스케이프해 문자열이 안 닫힌다. 오늘 실제로 냈다.

**증상이 크다.** `sumEarnedToday`는 `earnGold`의 첫 쿼리라, 깨지면 **추억 생성·마스코트 교감이 전부 `500`**이 된다. CI에서 테스트 10건이 깨졌고 **그중 7건은 골드와 무관한 기존 테스트**였다.

> **`ESCAPE` 절 자체는 반드시 있어야 한다.** 빼면 `_`가 임의의 한 글자로 매칭돼 `EARNX_...` 같은 사유까지 합산에 걸린다.
>
> **`ADMIN_GRANT`는 접두사가 달라 합산에서 빠진다** — 의도된 것이다. `EARN_` 계열로 주면 받은 날 정상 획득이 통째로 막힌다.

회귀 테스트 `adminGrantIsExcludedFromTheDailyEarnCap`이 이걸 지킨다 — 상한을 넘는 `ADMIN_GRANT` 10만을 오늘 원장에 넣고도 자유 추억 200이 지급되는지 본다. **접두사 합산 · `ESCAPE` 생존 · 쿼리 실행 여부를 한 번에 잡는다.**

## 4. ★ 검증 제약 — 로컬 통과가 무증거인 범위

오늘 `compileJava`·`compileTestJava`가 **세 번 다 통과했는데 CI는 세 번 다 다른 걸 잡았다.**

| CI가 잡은 것 | 왜 로컬이 못 봤나 |
|---|---|
| MyBatis XML의 SQL 구문 | **컴파일러가 XML 안의 SQL을 안 본다** |
| 테스트 DB FK 위반 | 실제 DB가 있어야 난다 |
| 테스트 기댓값 산술 | 실행해야 난다 |

> **로컬에 Docker가 없어 Testcontainers를 못 도는 동안 CI가 유일한 방어선이다.** 08-04의 "에러가 안 나는 결함"과 반대로 **요란하게 죽는 종류**라, 통합 테스트만 도달하면 반드시 잡힌다.

### ★ 지급 경로를 넓히면 테스트를 전수로 센다

"자유 추억도 골드를 준다" 하나가 **테스트 클래스 다섯에 지갑 정리를 요구했다.**

```
users DELETE 하는 테스트 14개 중 골드 경로를 타는 것 5개
  Memory · Exp · Room · Comment · NotificationFanOut   ← 다섯 다 정리 완료
```

`Comment`·`NotificationFanOut`은 본문이 `"Body"`·`"짧은 추억"`이라 **20자 미만이어서 우연히 통과**하고 있었다. 본문을 한 글자만 늘려도 조용히 깨진다.

## 7. ★ PR이 막히는 조건 — 어제 진단을 정정한다

어제 핸드오프의 *"GitHub은 `#92`를 한 번도 막은 적이 없다"*는 **07-31 06:34 이전까지만** 맞다. 그 시각에 첫 `CHANGES_REQUESTED`가 들어갔다.

```json
"required_approving_review_count": 0,
"required_review_thread_resolution": true,
"dismiss_stale_reviews_on_push": false     ← 어제 안 본 줄
```

**이 레포에서 PR이 막히는 조건은 셋이다.**

| | |
|---|---|
| `build` 체크 | 실패하거나 아직 도는 중이면 `BLOCKED` |
| 미해결 리뷰 스레드 | 인라인 코멘트 스레드를 남겨두면 막힌다 |
| **`CHANGES_REQUESTED` 리뷰** | **승인 개수 요구가 0이어도 막는다.** 그리고 `dismiss_stale_reviews_on_push: false`라 **작성자가 푸시해도 안 풀린다 — 리뷰어가 새 리뷰로 덮어야 한다** |

> **★ "요청만 처리되면 바로 머지된다"가 아니었다.** 작성자가 할 수 있는 일이 끝나도 **리뷰어가 한 번 더 움직여야 한다.** 그걸 모르면 양쪽이 서로를 기다린다.
>
> ```bash
> gh api repos/Pickeslog/clov-api/rules/branches/main    # 추측하지 말고 연다 — 그리고 필요한 줄까지 본다
> ```
