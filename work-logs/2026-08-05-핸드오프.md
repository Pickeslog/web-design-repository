## 3. ★★ SQL — `EARN_` 합산의 이스케이프 함정

```sql
WHERE reason LIKE 'EARN!_%' ESCAPE '!'     -- ✅ 이렇게 쓴다
WHERE reason LIKE 'EARN\_%' ESCAPE '\'     -- ❌ MySQL 구문 오류
```

**MySQL은 문자열 리터럴 안의 백슬래시를 이스케이프 문자로 먼저 해석한다** — `\'`가 닫는 따옴표를 이스케이프해 문자열이 안 닫힌다. 오늘 실제로 냈다.

**증상이 크다.** `sumEarnedToday`는 `earnGold`의 첫 쿼리라, 깨지면 **추억 생성·마스코트 교감이 전부 `500`**이 된다. CI에서 테스트 10건이 깨졌고 **그중 7건은 골드와 무관한 기존 테스트**였다.

> **`ESCAPE` 절 자체는 반드시 있어야 한다.** 빼면 `_`가 임의의 한 글자로 매칭돼 `EARNX_...` 같은 사유까지 합산에 걸린다.
>
> **`ADMIN_GRANT`는 접두사가 달라 합산에서 빠진다** — 의도된 것이다. `EARN_` 계열로 주면 받은 날 정상 획득이 통째로 막힌다.

회귀 테스트 `adminGrantIsExcludedFromTheDailyEarnCap`이 이걸 지킨다 — 상한을 넘는 `ADMIN_GRANT` 10만을 오늘 원장에 넣고도 자유 추억 200이 지급되는지 본다. **접두사 합산 · `ESCAPE` 생존 · 쿼리 실행 여부를 한 번에 잡는다.**

## 4. ★ 검증 제약 — 로컬 통과가 무증거인 범위

오늘 `compileJava`·`compileTestJava`가 **세 번 다 통과했는데 CI는 세 번 다 다른 걸 잡았다.**

| CI가 잡은 것 | 왜 로컬이 못 봤나 |
|---|---|
| MyBatis XML의 SQL 구문 | **컴파일러가 XML 안의 SQL을 안 본다** |
| 테스트 DB FK 위반 | 실제 DB가 있어야 난다 |
| 테스트 기댓값 산술 | 실행해야 난다 |

> **로컬에 Docker가 없어 Testcontainers를 못 도는 동안 CI가 유일한 방어선이다.** 08-04의 "에러가 안 나는 결함"과 반대로 **요란하게 죽는 종류**라, 통합 테스트만 도달하면 반드시 잡힌다.

### ★★ clov-api 배포에서 `401`은 "새 빌드가 떴다"를 뜻하지 않는다

오늘 `#92` 배포에서 응답이 이렇게 움직였다.

```
푸시 직후        401   ← 아직 옛 컨테이너다
워크플로 success  -
                 502   ← 옛 것이 내려가고 새 것이 뜨는 중
                 401   ← 새 컨테이너
```

**푸시 직후의 401을 "배포 완료"로 읽을 뻔했다.** 워크플로가 빌드·이미지 push·SSH·`compose pull`·재기동까지 도는 동안 **옛 컨테이너가 계속 401을 준다.**

> **★ `401` 하나는 "어떤 clov-api가 살아 있다"까지다.** `401 → 502 → 401` **순서**가 교체를 증명한다. **어제 핸드오프의 "초록불은 컨테이너가 떴다까지다"에서 한 칸 더 들어간 자리다** — 초록불도 못 믿고, 401도 그것만으로는 못 믿는다.
>
> 확인 순서는 이렇게 한다.
>
> ```bash
> gh run list -R Pickeslog/clov-api --branch deploy-myeongjun --limit 1   # success 확인
> curl -s -o /dev/null -w "%{http_code}\n" https://clovlabcalss.store/api/v1/rooms
> ```
>
> **502를 한 번 보고 401로 돌아오는 것까지 봐야 한다.** 502 지속은 편차가 크다(08-04 실측 17초~4분 30초, 오늘은 수 초). **고정 `sleep`이 아니라 폴링으로 기다린다.**

### ⚠️ clov-api는 내용까지 증명할 수단이 없다

clov-web은 인증 없이 **배포 번들에서 문자열을 찾을 수 있다.** clov-api는 그 수단이 없다 — springdoc이 있는데도 외부에서 안 닿는다.

```

```

**이 레포에서 PR이 막히는 조건은 셋이다.**

| | |
|---|---|
| `build` 체크 | 실패하거나 아직 도는 중이면 `BLOCKED` |

## 9. ★★ 한정 상품 — 오후에 둘을 넣었다. 규칙이 하나 생겼다

```
크로비 스킨  '새벽의 별빛 기록자'   COSTUME    · LEGENDARY 9,800 · 할인 80% → 1,960
배경         '은하수 아래 개발자의 밤'  BACKGROUND · LEGENDARY 9,800 · 할인 80% → 1,960
```

**둘 다 배포·SQL 실행까지 끝났다.** 에셋이 운영에서 서빙되는 것까지 확인했다(바이트 일치).

> ⚠️ **화면은 아무도 못 봤다.** 인증 뒤라 Claude가 못 본다. **상점에 뜨는지 · 사면 잠금이 풀리는지 · 배경을 고르면 별이 반짝이는지** 셋을 봐야 닫힌다.

### ★★★ "한정"을 표현하는 규칙 — 앞으로 이대로 한다

```
price          등급이 말한다 (계약 §15-4 규칙 그대로)
discount_rate  "한정"이 말한다
```

**정가를 올려서 한정을 표현하지 않는다.** 계약 §15-4가 *"등급도 같고 내용도 같으면 값도 같게"*인데, 한정 스킨은 아케이드 보스 롭과 **등급도 내용(상태 9종)도 같다.** 정가를 올렸으면 규칙을 어겼고, **다음 한정 상품마다 "얼마나 올릴까"를 근거 없이 정해야 했다.**

> ### ★★ 등급을 올릴 때 "한정"을 근거로 쓰지 말 것 — 같은 이유를 두 축에 쓰는 것이다
>
> 배경 쪽에서 이게 걸렸다. 기존 배경 4종이 `RARE 2,800`인데 이것만 LEGENDARY다. **근거는 "한정"이 아니라 "이 배경에만 CSS 효과 레이어가 붙는다"로 적었다** — *"등급도 같고 **내용도 같으면**"*이라 **내용이 다르면 등급이 달라도 된다.**
>
> **★ 그래서 조건이 붙는다** — `index.css`의 `[data-app-bg="developer-gemini-night"]` 별 반짝임을 빼면 **이 등급의 근거가 사라진다.** 그때는 `RARE 2,800`으로 내리는 게 맞다. SQL 주석과 `appBackground.js` 양쪽에 적어뒀다.

### ⚠️ 할인 해제는 SQL을 직접 돌려야 한다

`discount_rate`를 **실제로 쓰는 첫 사례**다(계약 §15-3이 *"운영 주체·주기 미정"*으로 둔 필드, `web-design#66`). 관리 화면이 없어서 **해제 SQL을 등록 SQL 파일 맨 아래에 주석으로 같이 넣었다.**

```
db/manual-migrations/2026-08-05-shop-crobi-dawn-starlight-archivist-skin.sql
db/manual-migrations/2026-08-05-shop-developer-gemini-night-background.sql
```

> **등록만 남기면 "어떻게 끝내지"를 나중 사람이 처음부터 만들어야 하고, 그러면 대개 안 끝난다.** "한정"이 영구 할인이 되는 경로가 이것이다.
>
> ⚠️ **해제해도 이미 산 사람의 가격은 안 바뀐다** — `paid_price`가 구매 시점 실효가를 박아둔다(§15-1 (4)). **되돌릴 수 없다.**
>
> ⚠️ **해제하면 카탈로그 총액과 완주 일수를 계약에서 같이 고친다.** 지금은 할인 덕에 55,920 / 약 9일로 계약값이 그대로 맞는다.

### ★ 배경 에셋 규격 (한 곳에 모아둔다)

```
배경        1920 × 1080   WebP   66KB ~ 431KB    public/backgrounds/<id>.webp
썸네일       512 × 512     PNG    26KB ~ 155KB    public/bg-thumbs/<id>.png
상점 카드    640 × 640     WebP   47KB ~ 139KB    public/shop/backgrounds/<id>.webp
```

⚠️ **한정 배경의 상점 카드만 1920×1080이다.** `.shop-art`가 `aspect-ratio: 1/1` + `object-fit: contain`이라 **위아래에 빈 띠**가 생긴다(세로 약 43%). 기능은 정상이고 **카드에서만 작게 보인다.** 640×640으로 다시 뽑아 파일만 교체하면 된다 — **이 환경에 이미지 변환 도구가 없어 못 했다.**

> **★ 애니메이션 배경은 안 한다.** GIF 15.4MB(720×405)를 정지 이미지 130KB(1920×1080)로 바꿨다 — **119분의 1이고 해상도는 오히려 올라갔다.** 애니메이션 WebP도 1920×1080 × 100프레임이면 3~8MB라 답이 아니다. **"한정" 느낌은 움직임의 양이 아니라 "다른 배경엔 없는 것"에서 온다.**

### ★ CSS 효과 레이어를 만질 때

```css
:root[data-app-bg='developer-gemini-night'] body::before,
:root[data-app-bg='developer-gemini-night'] body::after {
  position: fixed; inset: 0;
  z-index: -1;          /* 배경 위 · 콘텐츠 아래 */
  pointer-events: none; /* 없으면 화면 전체 클릭이 막힌다 */
}
```

**`z-index: -1`이 되는 이유** — `html`에 `background`가 없어서 `body` 배경이 **캔버스로 승격**되고 스택 맨 아래에 칠해진다. 그래서 음수 z-index 의사요소가 그 위, `#root`가 다시 그 위다.

> **`#root`에 `position`/`z-index`를 주는 방식은 쓰지 말 것.** 전역 쌓임을 건드리면 **모달(240~9600)과의 관계까지 다시 봐야 한다.**
>
> **★ 다른 배경에 안 붙는 것을 대조군으로 확인할 것.** 새 배경에서 보이는 것만으로는 증명이 안 된다 — `getComputedStyle(document.body, '::before').content`가 다른 배경에서 `none`이어야 한다.
