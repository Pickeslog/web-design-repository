### 백엔드 (`clov-api`)

커밋: `afc03f3 fix: 개발·배포 환경 분리 — profile group 정리 + prod client.url https (#81) (#82)`

`application.yaml`의 profile 설정:

```yaml
spring:
  profiles:
    group:
      dev: [db, secret]
      prod: [db, secret]
    active: dev
```

- 기존 `include: secret`를 제거했고, profile group으로 `secret`을 포함하도록 정리했다.
- `client.url`은 dev에서 `http://localhost:5173`, prod에서 `https://clovlabcalss.store`로 분리됐다.
- 실제 `application-secret.yaml`은 Git ignore 상태이며 추적되지 않는다.
- `bootJar`의 실제 secret 제외 수정(#80)은 최신 main에 이미 반영돼 있다.

## 배포 전 보완 필요 사항

### 1. systemd 운영 프로필 지정

`deploy/clov-api.env.example` 및 실제 VM `/opt/clov-api/clov-api.env`에 아래를 추가해야 한다.

```env
SPRING_PROFILES_ACTIVE=prod
```

현재 `application.yaml`의 기본값은 `dev`이고 `clov-api.service`는 프로필 인자를 별도로 주지 않는다. 따라서 이 환경 변수가 없으면 VM도 dev profile로 실행된다.

### 2. 백엔드 Dockerfile 정리

현재 `clov-api/Dockerfile`은 Git 미추적 파일이다.

또한 아래 exec 형식 `ENTRYPOINT`에서는 `${PROFILE}`이 셸 확장되지 않는다.

```dockerfile
ENTRYPOINT ["java", "-Dspring.profiles.active=${PROFILE}", "-jar", "/app.jar"]
```

문자열 `${PROFILE}`이 그대로 system property로 전달되며, 이는 `ENV SPRING_PROFILES_ACTIVE=prod`보다 우선할 수 있다. Docker로 백엔드를 배포할 계획이라면 이 부분을 수정하고 Dockerfile도 의도한 브랜치에 커밋해야 한다.

```bash

```

실제 secret 파일은 보이지 않고 `application-secret.example.yaml`만 보여야 한다.
