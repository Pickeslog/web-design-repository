## 1. ★★ "SSH 연결 추가"를 등록하지 않기로 했다

리더가 Claude Code의 *원격 머신에 연결하여 실행* 기능을 보고 "우리도 등록해볼까"라고 물었다. **재보니 둘 다 아니었다 — 이 VM에는 못 돌고, 그리고 필요가 없었다.**

### 1-1. 못 도는 이유 — VM이 너무 작다 (실측)

```
RAM     955MB 중 여유 442MB   ← 이미 swap 321MB 사용 중
Node    미설치
디스크   29G 중 86% 사용
```

이 기능은 **원격에 Claude Code를 설치해서 거기서 실행**한다. e2-micro에 Node를 얹으면 옆에서 도는 `api` 컨테이너(JVM)를 밀어낸다. **운영 서비스가 도는 박스**다.

### 1-2. ★ 필요 없는 이유 — 이미 되고 있었다

이 세션에서 로컬 Bash로 VM 명령을 일곱 번 돌렸다.

```bash
ssh -i ~/.ssh/gcp -o BatchMode=yes bubargi23@34.70.57.137 '<명령>'
```

`sudo -n`이 비밀번호 없이 통해서 `docker ps`·이미지·로그를 다 본다. **점검 목적이라면 원격 세션 등록이 필요 없다.**

오히려 등록하면 손해다 — 세션의 작업 위치가 원격이 되어 **로컬 세 레포를 같이 못 본다.** 지금은 "로컬에서 코드 보면서 필요할 때 VM 찔러보기"가 되는데 그 조합이 더 낫다.

> **★ 이 기능이 "인증 뒤 화면을 못 본다"를 풀어주지 않는다.** 그건 브라우저 로그인 문제라 머신 위치와 무관하다. 기능 설명만 보고 "원격에서 돌리면 뭔가 더 보이겠지"로 넘어가면 안 된다.
>
> 진짜 쓸모 있는 건 **더 큰 개발 머신**이 따로 있을 때다(집 데스크톱, 별도 dev VM). 1GB 운영 박스는 대상이 아니다.

### 1-3. ★★ 재보다가 나온 것 — 디스크가 차오르고 있었다

```
Images   44개 · 5.65GB 중 4.1GB 회수 가능 (72%)
디스크    4.1GB 남음        ← 회수 가능분과 거의 같다
```

**CI/CD가 배포마다 `:latest`를 갱신하면서 옛 이미지가 태그를 잃는데 아무도 안 지운다.** 차면 배포가 죽는다.

`docker image prune -f`(dangling만) 결과:

```
86% → 73%     여유 4.1G → 7.8G     3.99GB 회수
이미지 44개 → 5개 (39개가 dangling이었다)
web Up 17h · api Up 21h · certbot Up 8d   ← 무중단
```

> **`-af`로 갔어도 560MB밖에 더 못 얻는다.** 쌓인 게 사실상 전부 태그 없는 옛 빌드였다. **`-f`만으로 4.1GB 중 3.99GB를 회수하면서 롤백용 이미지는 남는다** — `-a`를 붙일 이유가 없다.

### 1-4. 같이 드러난 것 둘

**★ 계정이 둘이다.**

```
/home/bubaragi23    배포용 (이메일 철자와 같다). compose 파일이 여기 있다
/home/bubargi23     ~/.ssh/gcp 키가 들어가는 곳
```

`ls ~/*.yaml`이 비어 보여서 알았다. **키가 배포 계정이 아닌 쪽에 붙는다.**

**⚠️ 구성이 바뀌어 있었다.** 메모리와 07-28 기록은 *"프론트=컨테이너 · 백엔드=호스트 systemd"*인데, 실측하니 **셋 다 컨테이너**다.

```
web      kimmyeongjun998/react-app:latest        0.0.0.0:80,443
api      kimmyeongjun998/springboot-app:latest   0.0.0.0:8080
certbot  certbot/certbot
호스트 nginx·clov-api systemd 유닛은 없다(inactive)
```

**⚠️ 8080이 아직 인터넷에서 닿는다.** 07-29 핸드오프가 **우선순위 1번**으로 적고 SOCKS5 스캐너 프로브까지 받았던 항목인데 8일째 그대로다.

```
http://34.70.57.137:8080/api/v1/rooms   → 401   ← 밖에서 닿는다
```

API가 **평문 HTTP로 nginx를 우회해** 직접 노출돼 있다. GCP 콘솔에서 방화벽 규칙을 지워야 하고 **다운타임은 0**이다(방화벽은 외부 트래픽만 막고 컨테이너 간 내부 경로는 안 건드린다).

> ⚠️ **compose에서 `127.0.0.1:8080:8080`으로 바꾸는 방법은 쓰면 안 된다.** web 컨테이너가 `host.docker.internal`로 api를 부르면 루프백 바인딩에 안 걸려 프록시가 끊긴다.

## 2. ★★★ `#178` — "대기 중"인지 판단하려면 타임라인을 봐야 한다

어제 핸드오프 §0-2가 *"chacha 응답 대기 중"*이라고 적어뒀다. PR을 열어보니 **chacha의 수정 커밋이 이미 있어서** "어제 기록이 낡았다"고 보고했다. **그게 틀렸다.**

```
07-30 02:21  chacha 첫 커밋
07-31 06:37  리더 CHANGES_REQUESTED (말풍선이 거짓말한다)
08-03 00:51  chacha 수정 푸시          ← 07-31 리뷰에 대한 응답
```

### 2-2. ★★ 충돌 — 83커밋이 지나가 있었다

푸시하자 GitHub이 `mergeable`을 계산했고 **`CONFLICTING`**이 나왔다.

```
merge-base  2026-08-02        main이 83커밋 앞섰다
Mascot.jsx  main에서 12회 수정  스킨 배선 · 이스터에그 상태머신 · #313
```

> **★ 푸시 전에는 `mergeable=UNKNOWN`이었다.** GitHub은 이 값을 지연 계산한다. **"승인하면 머지된다"고 판단하기 전에 `mergeable`이 `UNKNOWN`인지 확인할 것** — 모른다는 뜻이지 괜찮다는 뜻이 아니다.

충돌은 `interactMutation.onSuccess` 한 덩어리였다. PR이 열린 뒤 main에 **클릭 반응 문구**(`pendingReactionRef`)와 **이스터에그 억제**(`eggModeRef`)가 들어와서, 한쪽을 고르면 다른 쪽이 죽는 모양이었다.

```jsx
onSuccess: (data) => {
  queryClient.invalidateQueries({ queryKey: ['room', roomId, 'level'] })
  queryClient.invalidateQueries({ queryKey: ['wallet'] })   // ← early return 위
  const reaction = pendingReactionRef.current
  pendingReactionRef.current = null
  if (eggModeRef.current !== 'default') return
  const gold = data?.earnedGold ?? 0
  const line = reaction?.text || pickLine()
  showBubble(gold > 0 ? `${line} (+${gold}G)` : line)
},
```

> ### ★★★ `['wallet']` 무효화를 early return **위**에 둔 것이 이 해소의 핵심이다
>
> `scared`/`angry`/`dizzy` 진행 중에도 **서버는 골드를 준다** — 말풍선만 안 뜬다. 아래로 내리면 그 경우 헤더 배지가 안 갱신돼서 **이 PR이 고치려던 증상이 이스터에그 상황에서만 되살아난다.**
>
> **충돌 해소는 "양쪽 줄을 다 남기기"가 아니라 "합쳤을 때 무엇이 언제 실행되는가"를 다시 재는 일이다.** 줄만 이어붙였으면 이 순서를 놓쳤다.

## 3. ★★ `#353` 리뷰 — 특이도가 진짜 위험이었는데, 안전했다

lami의 `@scope` → 클래스 접두 전환(`+391/-386`). **눈으로 390줄을 보는 대신 전/후 규칙을 1:1로 대조하는 스크립트를 썼다.**

```
letters.proto.css    160개 규칙   전부 등가
schedule.proto.css   222개 규칙   전부 등가
                     선택자 접두 · 선언 · @media 중첩 · 순서 전부 일치
```

### 3-1. ★★★ 왜 특이도가 위험이었나, 그리고 왜 괜찮았나

`@scope (.proto-X) { .foo {} }`에서 **스코프 루트는 특이도에 더해지지 않는다** — `.foo`는 `(0,1,0)`이다. 반면 `.proto-X .foo`는 `(0,2,0)`이라 **한 단계 오른다.**

그런데 승자는 안 바뀐다. 캐스케이드가 **특이도 → 스코프 근접성 → 소스 순서** 순으로 재기 때문이다.

| 경쟁 상대 | 변환 전 | 변환 후 | |
|---|---|---|---|
| 비스코프 `(0,1,0)` | **근접성으로 이김**(순서 무관) | 특이도로 이김 | 동일 |
| 비스코프 `(0,2,1)`<br>`body.light-mode .clov-btn--dashed` | 특이도로 짐 | `(0,2,0)` vs `(0,2,1)` → 여전히 짐 | 동일 |

> **★ PR 본문의 "소스 순서를 보존해서 승자가 안 바뀐다"는 결론은 맞지만 근거가 한 칸 모자랐다.** 순서는 동률일 때만 쓰이고, 여기서 실제로 일한 건 **근접성 → 특이도로 이유가 갈아끼워진 것**이다. 결과가 같아서 문제는 없어 코멘트로만 남겼다.
>
> **"결론이 맞으면 근거는 안 봐도 된다"가 아니다.** 근거가 틀리면 다음에 비슷한 변환을 할 때 같은 안전이 성립하지 않는데도 성립한다고 믿게 된다.

### 3-2. 예외와 부수 발견

`.ticket-cal*` 19개가 접두 없이 남았는데 **main에서도 `@scope` 밖**이었다(1168행에서 닫히고 1172행부터). 포탈되는 전역 DOM이라 맞다.

**PR이 주장한 "부수 발견"도 사실이었다** — `@scope`가 **1227/1333행**에서 닫히는데 **1216행 주석이 "`@scope` 밖·클래스 접두 방식으로 둔다"**고 적어놨다. 주석이 스코프 경계를 잘못 알고 있었다.

**`@scope`는 이 두 파일이 레포의 유일한 사용처였다** — 이 PR로 완전히 사라졌다.

## 4. ★★ 온보딩 가이드 구현 (`clov-web#357`)

어제 설계·시안(§12, `work-logs/2026-08-05-온보딩-시안/`)이 끝나 있어서 React로 옮기는 작업이었다. **688줄 추가, 삭제 0줄.** 기존 코드는 `RoomList.jsx` +4줄, `Header.jsx` +6줄만 건드렸다.

### 4-1. 결정한 것 — 모두에게 띄운다

어제 남겨둔 결정 하나. 방이 있든 없든 뜨고, **"다시는 안 보기"로 영구 해제**할 수 있다. 방이 없을 때만 띄우려면 `hasNoRooms`를 조건으로 걸면 되고 그렇게 주석에 적어뒀다.

### 4-2. 저장소를 둘로 나눈 이유

| 동작 | 범위 | 저장소 |
|---|---|---|
| 건너뛰기 · × · Esc | 이번 방문만 | `sessionStorage` `clov-guide-skipped` |
| "다시는 안 보기" | 영구 | `localStorage` `clov-guide-done` |
| 끝까지 보고 "시작하기" | 영구 | `localStorage` `clov-guide-done` |
| 프로필 → "가이드 다시 보기" | 둘 다 지움 | — |

**하나로 합치면 한쪽이 손해를 본다.** 급해서 건너뛴 사람은 다시 볼 기회가, 확실히 필요 없는 사람은 영구 차단이 필요하다. **되돌릴 길이 없으면 "다시는 안 보기"는 일방통행이 된다.**

> 기기-로컬인 건 백엔드가 없어서만이 아니다 — **"이 기기에서 이 화면을 처음 보는가"에 대한 답이라 계정보다 기기에 묶이는 게 자연스럽다**(`mascotSize.js`·테마·배경과 같은 판단).

### 4-3. ★ 린트가 잡은 것 — effect 안의 setState

"열릴 때마다 START 화면으로 되돌리기"를 `useEffect(() => { if (open) setStep(-1) }, [open])`로 썼다가 `react-hooks/set-state-in-effect`에 걸렸다.

**여는 쪽이 아니라 닫는 쪽에서 되돌리는 걸로 바꿔 effect를 없앴다.** 여는 경로가 셋(자동·스토어·START 버튼)이라 한 곳에 모으기 어려웠는데, 닫는 경로는 `close(permanent)` 하나로 모을 수 있었다.

```jsx
const close = useCallback((permanent) => {
  if (permanent) markGuideDone(); else markGuideSkipped()
  setStep(-1)
  closeGuide()
}, [closeGuide])
```

> **"상태를 언제 되돌릴까"를 여는 쪽에서 풀려고 하면 경로 수만큼 갈래가 생긴다.** 닫는 쪽이 하나면 거기서 되돌리는 게 짧다.

### 4-4. 시안에서 그대로 가져온 판단 셋

그때까지 단계 그림은 **은유**(클로버·동전)였다. 예뻤지만 **"그래서 화면 어디서 하는데?"가 안 풀렸다.**

| 단계 | 전 (은유) | 후 (미니 목업) |
|---|---|---|
| 1 우정공간이 뭐예요 | 클로버 | **방 목록 티켓 카드** — 아바타가 하나씩 들어온다 |
| 2 들어오는 길 | 화살표 둘 | **버튼 둘** — 번갈아 켜지고 `CLV-JOIN-` 에 커서가 깜빡인다 |
| 3 추억 → 골드 | 동전 | **헤더 배지 1,200 → 1,500** · 글이 채워지고 `+300 G` 가 떠오른다 |

### 12-1. ★★ 왜 스크린샷이 아닌가

1. 실제 화면은 **로그인 뒤**라 캡처가 번거롭고, 캡처해도 **화면이 바뀌면 바로 낡는다**
2. 사진을 픽셀 창 안에 넣으면 **미감이 깨진다**
3. 이미지가 늘면 **첫 화면이 무거워진다**

같은 팔레트로 **모양만** 흉내 내고 움직임은 CSS 다. **0KB 다.**

### 12-2. ★★ 아바타 크기를 전부 같게 그린 건 의도다

```css
.gm-avs i { width: 12px; height: 12px; }   /* 넷 다 같다 */
```

**"방장 없음 · 모두 같은 권한"을 글이 아니라 그림으로 말한다.** 하나만 크게 그리면 그 순간 대표자가 생긴다 — 서비스 원칙에 어긋난다.

같은 이유로 STEP 2 의 버튼 둘은 **번갈아** 켜진다. 한쪽만 강조하면 "두 가지 길"이 아니게 된다.

### 12-3. ⚠️ `prefers-reduced-motion` 은 끄는 게 아니라 **최종 상태를 주는 것**이다

애니메이션만 끄면 **아바타가 안 보이고 글줄이 빈 채로 멈춘다** — 정보가 사라진다.

```css
@media (prefers-reduced-motion: reduce) {
  .gm-avs i { opacity: 1; }        /* 0% 지점이 opacity:0 이었다 */
  .gm-line { width: 100%; }        /* 0% 지점이 width:0 이었다 */
  .gm-num.is-after { opacity: 1; } /* 오른 뒤 숫자가 보여야 한다 */
}
```

## 13. ★ 마스코트를 원본 그림으로 (`#373` → `#374`)

리더: *"마스코트들의 smile 이미지들이 들어가면 좋겠어 … 화질을 좀 개선해서"* → **"원본으로 하고 나열하자"** → **"조금씩 겹쳐서 나열"** → **"그러면 여기(4단계)도 원본으로"**

### 13-1. 왜 픽셀 변환을 안 썼나

**작게 그릴수록 픽셀 변환은 손해다.** 창 전체가 `image-rendering: pixelated` 라 축소하면 계단이 진다. 그래서 이 두 자리만 **`image-rendering: auto` 로 되돌렸다.**

> START 로스터는 **여전히 픽셀 변환**이다 — 거기는 132px 라 §12-6(1 소스 픽셀이 화면 2px 이상)을 만족한다. **같은 그림이라도 크기에 따라 처리가 갈린다.**

### 13-2. ★★ 겹쳐 세운 이유는 미감이 아니라 크기다

```css
.clov-guide-lineup img { width: 74px; height: 74px; object-fit: contain; object-position: bottom; }
.clov-guide-lineup img + img { margin-left: -21px; }
```

**안 겹치면 다섯이 한 명당 50px 남짓이라 얼굴이 안 보인다.** 겹치면 같은 폭에서 74px 로 선다. `object-position: bottom` 으로 발밑을 맞춰 **한 줄로 선 것처럼** 보이게 했다.

4단계(친구 소개)는 이름을 같이 보여야 해서 `repeat(3, minmax(0, 1fr))` 격자다.

> ⚠️ **`minmax(0, 1fr)` 이다.** 그냥 `1fr` 은 `minmax(auto, 1fr)` 이고 `auto` 바닥이 콘텐츠 최소폭이라, 이름이 길면 칸이 밀려 가로로 넘친다(`#338` 함정).

### 13-3. 지운 코드 — `guideMascotSprite`

가이드가 "내가 고른 마스코트"를 띄우던 자리가 **전부 5종 노출로 바뀌면서** 그 함수도 `['preferences']` 조회도 쓸 데가 없어졌다. **지웠다.**

> ⚠️ 처음엔 `_UNUSED_SHOWCASE_RES` 로 **이름만 바꿨다.** 눈속임이라 되돌려 제대로 지웠다. 복원이 필요할 때를 대비해 **정규화 규칙(`'robot' → 'rob'` · 모르는 값 → `'crobi'`)은 `guideMascot.js` 주석에 남겼다.**

**버거노인은 일부러 뺐다** — 고를 수 있는 마스코트가 아니라 **상점 주인**으로 갈 예정이라, 여기 세우면 "고를 수 있는 친구"로 잘못 읽힌다. smile 스프라이트도 없다.

## 15. 오늘 배운 것

- **★ 기능을 붙일지 정하려면 그 기능이 뭘 하는지부터 정확히 읽는다.** "SSH 연결 추가"는 원격에서 Claude Code를 **실행**하는 것이지 원격에 **접속**하는 게 아니었다. 접속은 이미 되고 있었다.
- **★ 커밋이 있다 ≠ 최신 요청에 답했다.** 리뷰가 여러 라운드면 요청 시각과 커밋 시각을 겹쳐 봐야 한다(§2).
- **★ `mergeable=UNKNOWN`은 "괜찮다"가 아니라 "아직 안 쟀다"다.** 그 상태로 머지 계획을 세우면 안 된다.
- **★ 충돌 해소는 줄을 잇는 게 아니라 실행 순서를 다시 재는 일이다**(§2-2의 early return).
- **★ 결론이 맞아도 근거가 틀렸으면 짚는다**(§3-1). 다음에 같은 안전이 성립하지 않는다.
- **★ 검증에서 스텁 값을 기본값으로 두면 폴백만 확인된다**(§5-2). 확인하고 싶은 것이 "고른 값이 반영되는가"라면 기본값과 다른 값을 넣어야 한다.
- **★ 0건은 "없다"와 "잘못 찾았다"를 구분하지 못한다** — 대조군을 같이 넣는다(§6).

### 오후에 더한 것

- **★★★ 반복해서 볼 물건은, 반복해서 보는 방법부터 만든다**(§9). 랩 페이지 하나가 나머지 다섯 라운드의 속도를 갈랐다. **먼저 만드는 게 돌아가는 길처럼 보이지만 아니었다.**
- **★★ 린트 경고를 끄기 전에 왜 그 규칙이 있는지 본다**(§9-1). Fast Refresh 경고를 껐으면 **랩이 고칠 때마다 리셋돼서 존재 이유가 사라졌다.**
- **★★ 998ms 는 우연이 아니다**(§9-2). 재본 숫자가 너무 반듯하면 우리 버그가 아니라 **환경 규칙**을 의심한다.
- **★★ 빌드 통과가 개발 서버 동작을 보장하지 않는다**(§9-3). `sed -i` 제자리 치환은 이 레포에서 쓰지 않는다.
- **★★ "확인만 해달라"는 요청도 필드 단위로 읽는다**(§8). 빠진 `nickname` 하나가 **에러 없이 화면을 비운다.**
- **★★ 이미 푼 문제를 다시 만들지 않는다**(§11-2). 마스코트 정사각 상자 규칙을 **하루에 세 번** 다시 발견했다. 앱에 이미 있던 규칙이다.
- **★ 작은 그림은 확대해서 판단하지 않는다**(§11-3). "이 마크 뭐야?"라는 질문이 곧 진단이었다.
- **★ 이름만 바꾸는 건 지우는 게 아니다**(§13-3). `_UNUSED_` 접두는 눈속임이다.
- **★★ `prefers-reduced-motion` 은 끄는 게 아니라 최종 상태를 주는 것**(§12-3). 끄기만 하면 정보가 사라진다.
- **★★★ 배포 순서는 "둘 다 success"로 증명되지 않는다**(§14). 컨테이너 이미지 생성 시각을 본다.
