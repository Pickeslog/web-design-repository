## 3. ★★ 재현해낸 프로덕션 버그 — 추억을 지우면 그 약속이 영구히 막힌다

`clov-web` #181 착수 검토 중 발견. **실제로 재현했다.**

```
1. 약속(memory_status=CANDIDATE)에 추억 작성  → 201, plan.memory_status=WRITTEN
2. 그 추억을 삭제                              → 200
3. 삭제 후 plan.memory_status                 → WRITTEN  ← 되돌아가지 않는다
4. 같은 약속에 다시 작성                        → HTTP 500 INTERNAL_ERROR
```

**409가 아니라 500이다.** 사용자는 "서버 오류가 발생했습니다"만 보고 이유를 알 수 없다.

### 원인 — 세 곳이 어긋나 있다

| | |
|---|---|
| **① 유니크 키가 soft delete를 모른다** | `uk_memories_plan_writer (plan_id, writer_id)` — `deleted_at`이 없다. 삭제된 행이 자리를 계속 차지 |
| **② 서비스 체크는 삭제분을 못 본다** | `findByPlanIdAndWriterId`가 `deleted_at IS NULL`로 거른다 → **체크는 통과하고 INSERT에서 DB가 막는다** |
| **③ 제약 위반 핸들러가 없다** | `GlobalExceptionHandler`에 `DataIntegrityViolationException` 핸들러 부재 → 500 |

그리고 `delete()`가 `memory_status`를 안 되돌린다 — `createFromPlan`은 `updatePlanMemoryStatusWritten`을 부르는데(`MemoryService.java:85`) **삭제에는 짝이 없다**(`:247`).

→ **clov-api #98**에 약속 연결 변경·해제와 함께 담았다. **같은 로직이라 따로 내면 세 번 고치게 된다.**

> **되돌릴 때 주의** — 그 약속에 **다른 멤버의 추억이 남아 있으면 `WRITTEN`을 유지**해야 한다. 우정공간은 한 약속에 여러 명이 각자 기록을 남기는 구조다.

### #176 — 색은 같아졌는데 셋이 어긋난다

"전체 피드 보기"를 "글쓰기"와 통일하기로 했는데 **CSS 선택자만 묶어서** 색·테두리만 같아졌다.

| | 글쓰기 `dashed` | 전체 피드 보기 `action` |
|---|---|---|
| 폰트 | Space Mono 고정폭 | 상속(산세리프) |
| 좌우 패딩 | 12px | 6px |
| 호버 | `translateY(-1px)` | 없음 |

**JSX에서 `variant="dashed"`로 바꾸고 특례 CSS 두 줄을 지우면 넷이 자동으로 일치**하고 코드가 오히려 줄어든다. 지금은 JSX가 `action`인데 화면은 dashed라 다음 사람이 되돌릴 여지가 있다.

### ★ #155 — 이스터에그가 하루 교감 한도를 태운다

마스코트가 `<button onClick={() => interactMutation.mutate()}>`라 **클릭 1회 = API 1회**인데, 백엔드에 `DAILY_INTERACTION_LIMIT = 3`이 있다.

| 이스터에그 | 벌어지는 일 |
|---|---|
| **3연타 → dizzy** | 클릭 3번 = **하루 한도 전부 소진** |
| 드래그 → scared | 버튼 위에서 놓으면 click 발화 → 1회 소진 |
| 롱홀드 → angry | 위와 같음 |

게다가 `disabled={isPending}` 때문에 요청 도는 동안 버튼이 죽어 **연타 판정(900ms) 자체가 안 될 수 있다.** "교감(API)"과 "이스터에그(로컬 연출)"를 분리해야 한다고 적고, 수용 기준에 **"이스터에그를 봐도 교감 3회가 남아 있는지"** 를 넣어달라고 요청했다.

### #91 — `MEMBER_JOINED` 신설 확정

수락 시점에 **성격이 다른 알림 두 개**가 나간다. 수신자도 actor도 달라서 한 subType으로 겸할 수 없다.

| subType | 수신자 | actor |
|---|---|---|
| `JOIN_REQUEST` | 기존 멤버 | 신청자 |
| `JOIN_ACCEPTED` | **신청자 본인** | 수락자 |
| **`MEMBER_JOINED`**(신설) | **기존 멤버 전원**(합류자 제외) | **합류자** |

`JOIN_REQUEST`를 재사용하면 "가입 신청 N건"을 세는 순간 **이미 수락된 합류까지 신청으로 센다.**

> **덤 — `JOIN_ACCEPTED`는 구현이 0건이다.** `src/` 전체에 참조가 없다. **신청자 본인에게 "수락됐어요"가 나가는 알림이 아예 없다.**

## 9. ★ 검증 기법 — 다음에 또 쓸 것

- **역방향 검증** — 테스트를 추가했으면 **고친 코드를 되돌려 실제로 깨지는지** 확인한다. `expected:<201> but was:<400>`이 나와야 그 테스트가 진짜 가드다. 통과만 보면 아무것도 안 지키는 테스트를 넣을 수 있다
- **프로브 테스트** — 버그를 이슈로 올리기 전에 **일회용 테스트를 써서 실제 응답을 받아본다**(§3의 500). 다 쓰고 `git checkout --`로 걷어낸다. "500이 날 것이다"와 "500이 났다"는 다른 문장이다
- **`git log A..B`는 "앞선 커밋"이지 "같다"가 아니다** — 오늘 이걸 "main과 동일"로 잘못 읽어서 백포트가 필요하다고 오판했다. **squash 머지 때문에 SHA가 갈라진 브랜치는 커밋 로그가 아니라 `git diff A B --stat`으로 판단할 것**
- **로그인 게이트 화면 검증** — 백엔드 없이 5173에서 `api.defaults.adapter` 스텁으로 대시보드까지 띄웠다. 어댑터가 `client.js`의 **named export `api`**다(`default` 아님). 함정과 절차는 메모리 `clov-web-browser-verify-pitfalls` 참조
- **Browser pane이 안 보이면 스크린샷이 실패한다** — `not compositing frames`. DOM 읽기로 대체 가능하다(오늘 마스코트 렌더·설정 옵션 전부 DOM으로 확인)
- **PowerShell `Set-Content`는 한글 파일을 깨뜨린다** — 오늘 Java 소스 주석을 깨먹고 `git checkout --`로 복구했다. **한글이 든 파일은 Edit 도구로만 고칠 것**

### #178 — 캡에 걸리면 화면이 거짓말한다

```jsx
const INTERACTION_GOLD = 100          // 프론트 하드코딩

`earnGold`는 캡에 걸리면 **조용히 `return`하고 200 OK를 준다.**

```

## 13. ⚠️ 미결·주의

### ★ 배포를 안 했다 — main ≠ 서버

**`clov-api`의 CD 트리거는 `deploy-*` 브랜치다. main 머지는 배포가 아니다.**

```
main  654945c  ← 제목 40 · 시작 골드 1,000 · 사진 8 · 설정 검증 · 상점
  ├ deploy-myeongjun   FF 가능 (뒤처짐)
  ├ deploy-lami        FF 가능
  ├ deploy-kimgyubi    FF 가능
  └ deploy-chacha      ⚠️ 갈라짐 (squash 전 원본 커밋 3건)
```

**오늘 고친 것이 어느 서버에도 안 올라갔다.** 지금 도는 API는 **제목 25 · 시작 골드 20,000 · 사진 10 · 설정 검증 없음**이다.

`clov-web`은 CD가 아직 없어서(#182 미머지) main 머지가 서버를 안 바꾼다 — 그래서 #185·#192를 먼저 머지해도 안전했다. **다만 프론트를 빌드·배포하기 전에 API 배포가 먼저 나가야 한다.** 특히 사진 8장은 프론트가 이미 8인데 서버가 10이라 지금은 안전하지만, 반대로 뒤집히는 순서는 안 된다.

`deploy-chacha`용 머지 커밋은 로컬 브랜치 **`deploy-chacha-sync`**에 만들어 뒀다(main과 내용 동일, force 아님). **단 그 뒤 main이 더 나갔으니 밀기 전에 다시 만들 것** — `git checkout -B deploy-chacha-sync origin/deploy-chacha && git merge origin/main`.

```bash
git -C C:/gov/project/clov-api push origin origin/main:deploy-myeongjun
git -C C:/gov/project/clov-api push origin origin/main:deploy-lami
git -C C:/gov/project/clov-api push origin origin/main:deploy-kimgyubi
git -C C:/gov/project/clov-api push origin deploy-chacha-sync:deploy-chacha
```

> **★ `deploy-*` 브랜치는 절대 지우지 않는다.** 학원 프로젝트가 끝나면 **각자 그 브랜치로 개인 프로젝트를 이어간다**(사용자 확인 2026-07-31). 개인 작업이 쌓이기 시작하면 FF 대신 `git merge origin/main`으로 간다.

### 권한 — Claude가 못 하는 것

- **`gh pr merge`** · **`deploy-*` push** 둘 다 자동 승인 분류기에 차단된다 → **사용자가 직접 실행**
- 권한을 푸는 `update-config` 스킬 호출 **자체도 차단**된다. 풀려면 `.claude/settings.local.json`의 `permissions.allow`에 직접 추가(예: `"Bash(gh pr merge:*)"`)
