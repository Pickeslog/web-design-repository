> 이 문서는 자체완결이다. 앞선 대화 맥락 없이 이것만 읽고 작업할 수 있게 썼다.

## 1. 왜 GIF를 버렸나 — 이 판단을 뒤집지 말 것

리더가 애니메이션 GIF 배경을 만들어 넣었다. 실측값이다.

```
public/backgrounds/developer-gemini-night.gif
  15,453,713 B (15.4MB) · 720 × 405 · 약 102프레임
  public/shop/backgrounds/ 에도 같은 파일이 한 벌 더 있었다 (합 30.8MB)
```

**기존 배경과 비교**

| | 기존 10종 | 이 GIF |
|---|---|---|
| 용량 | 66KB ~ 431KB | **15.4MB** (최대치의 36배) |
| 해상도 | **1920 × 1080** | **720 × 405** |
| 색상 | WebP 트루컬러 | GIF 256색 |

**두 가지가 동시에 걸린다.**

1. **15.4MB는 JS 번들(639KB)의 24배다.** 배경 하나가 앱 전체보다 24배 무겁다.
2. **720×405를 1920×1080 화면에 깔면 2.67배 확대된다.** 그리고 이 앱은 **배경 위에 덮개나 블러가 없다** — `src/index.css`의 `body`가 `background-size: cover; background-attachment: fixed`로 원본을 그대로 노출한다. 확대가 눈에 띈다. **한정 상품인데 화질이 제일 나쁜 게 된다.**

**애니메이션 WebP로 변환하는 것도 답이 아니다.** 1920×1080 × 102프레임이면 여전히 3~8MB로 기존 배경의 10~20배다. 포맷을 바꿔도 "전면을 다 움직인다"는 비용은 안 사라진다.

> ### ★ 결론 — "한정" 느낌은 움직임의 양이 아니라 "다른 배경엔 없는 것"에서 온다
>
> **베이스는 기존 배경과 같은 급의 정지 이미지(1920×1080 WebP ~300KB)로 가고, 한정 배경에만 CSS 효과 레이어를 얹는다.** 합쳐도 ~300KB라 기존 배경과 같은 무게다.
>
> 부수 효과가 하나 더 있다 — **정지 이미지는 고해상도로 다시 뽑기가 훨씬 쉽다.** 720×405 원본 문제가 통째로 사라진다.

**GIF 두 파일은 커밋하지 않았다. 저장소에 넣지 말 것.**

## 2. 지금 구조 (읽고 시작할 것)

### 2-1. 배경은 CSS 변수 하나로 적용된다

`src/lib/appBackground.js`

```js
export const APP_BACKGROUNDS = [
  { id: 'default', name: '기본 (심플)', thumb: '/bg-thumbs/default.png', image: null },
  { id: 'lp-wood-desk', name: 'LP 우드 데스크', thumb: '...', image: '/backgrounds/lp-wood-desk.webp' },
  // ... 무료 5종 ...
  // 상점 유료 4종 — itemCode 가 shop_items.code 와 같아야 한다
  { id: 'spring-rain-city', name: '봄비 뒤 벚꽃 운하', thumb: '...', image: '...',
    itemCode: 'BACKGROUND_SPRING_RAIN_CITY' },
  // ...
]

export function applyAppBackground(id, { persist = true } = {}) {
  const root = document.documentElement
  const bg = APP_BACKGROUNDS.find((b) => b.id === id) ?? APP_BACKGROUNDS[0]
  if (bg.image) {
    root.style.setProperty('--clov-app-bg', `url("${bg.image}")`)
    root.style.setProperty('--clov-app-bg-size', 'cover')
    root.style.setProperty('--clov-app-bg-pos', 'center')
  } else {
    root.style.removeProperty('--clov-app-bg')   // 기본은 CSS 그라디언트로 폴백
    // ...
  }
  if (persist) localStorage.setItem('clov_appBgTheme', bg.id)
  return bg.id
}
```

`src/index.css`

```css
body {
  background-color: #f4ead8;
  background-image: var(--clov-app-bg, /* 기본 그라디언트 5겹 */);
  background-size: var(--clov-app-bg-size, auto);
  background-position: var(--clov-app-bg-pos, center);
  background-repeat: no-repeat;
  background-attachment: fixed;
}
```

### 2-2. 소유 잠금은 이미 있다 — 새로 만들지 말 것

```js
// appBackground.js — 판정은 여기 한 곳에서만 한다
export function isBackgroundUnlocked(bg, ownedCodes) {
  if (!bg?.itemCode) return true
  return ownedCodes instanceof Set && ownedCodes.has(bg.itemCode)
}
```

`Settings.jsx:138`의 `isLocked`가 이걸 쓴다. **`itemCode`만 넣으면 잠금은 자동으로 걸린다.**

> ⚠️ 이 잠금은 **보안 경계가 아니라 화면 안내다.** 선택값이 `localStorage`이고 적용이 CSS 변수라 콘솔로 얼마든지 바꿀 수 있다. **서버가 지켜야 할 건 '구매'뿐이고 그건 `shop_items`/`user_inventory_items`가 이미 지킨다. 여기에 서버 검증을 더 붙이려 하지 말 것 — 지킬 자산이 없다.**

### 2-3. 배경은 `equip`을 안 쓴다

선택값은 서버가 아니라 **기기-로컬**(`localStorage 'clov_appBgTheme'`)에 저장된다. `POST /shop/items/{id}/equip`을 부르면 `409 ITEM_NOT_EQUIPPABLE`이 맞게 떨어진다(장착은 `COSTUME`만). **상점이 답하는 건 "고를 수 있는가"(소유)까지고, "무엇을 골랐는가"는 기기가 갖는다.**

## 3. 만들 것

### ① 에셋 — 정지 이미지

```
배경    1920 × 1080   WebP   목표 ~300KB (기존 범위 66KB ~ 431KB)
        public/backgrounds/developer-gemini-night.webp

썸네일   512 × 512     PNG    목표 ~100KB (기존 범위 26KB ~ 155KB)
        public/bg-thumbs/developer-gemini-night.png
```

> **원본 GIF(720×405)에서 프레임을 뽑아 늘리지 말 것.** 확대라 화질이 안 나온다. **1920×1080으로 새로 생성한다** — 사계절 배경 4종을 만든 방식 그대로다.
>
> 상점 카드 그림(`public/shop/backgrounds/`)도 같은 정지 이미지를 쓴다. **상점 목록을 여는 사람이 큰 파일을 받게 하지 말 것.**

### ② `appBackground.js`에 항목 추가

```js
{ id: 'developer-gemini-night', name: '<표시 이름>',
  thumb: '/bg-thumbs/developer-gemini-night.png',
  image: '/backgrounds/developer-gemini-night.webp',
  itemCode: 'BACKGROUND_DEVELOPER_GEMINI_NIGHT' }
```

⚠️ **`itemCode`는 `shop_items.code`와 한 글자도 다르면 안 된다.** 다르면 산 사람도 영원히 잠긴 채로 보인다 — **에러 없이 조용하다.**

### ③ ★★ CSS 효과 레이어 — 이 배경에만 (이게 이 상품의 핵심이다)

> **★ 이 레이어가 LEGENDARY 등급의 유일한 근거다**(§3-④ 참조). 다른 배경 4종은 정지 이미지 한 장으로 `RARE 2,800`이고, 이 배경만 등급이 다른 이유가 **"다른 배경엔 없는 것이 있다"**이다. **이걸 빼면 등급을 RARE 2,800으로 내려야 한다.**

**목표**: 새벽 별빛에 맞는 은은한 반짝임·빛 흐름. **다른 배경 10종에는 영향이 없어야 한다.**

지금 `applyAppBackground()`는 CSS 변수만 세팅하고 **어느 배경이 선택됐는지를 CSS가 알 방법이 없다.** 그 통로를 하나 내야 한다 — 예를 들어 `root.dataset.appBg = bg.id`를 같이 세팅하고 CSS에서 `:root[data-app-bg="developer-gemini-night"]`로 거는 식이다. **방식은 맡긴다.**

> ### ⚠️ 함정 — 쌓임 순서
>
> `body::after`로 얹으면 **`#root`보다 위에 그려져 화면 전체를 덮는다.** `#root`에 `position`/`z-index`가 없어서(`src/index.css`) 의사요소가 나중에 칠해진다.
>
> 해결은 둘 중 하나다.
> - `#root`에 `position: relative; z-index: 1`을 주고 효과 레이어를 그 아래로 (⚠️ **전역 CSS 변경이라 다른 화면의 `position: fixed` 모달과의 관계를 확인할 것** — 모달 z-index는 240~9600이다)
> - **`background-image`를 다중 레이어로 쓴다** — `body`의 `background-image`에 효과 레이어를 앞에 얹고 `background-position` 애니메이션으로 움직인다. **전역 쌓임을 안 건드려서 이쪽이 안전하다.**
>
> **어느 쪽을 고르든 `pointer-events: none`을 잊지 말 것.** 클릭이 막히면 그건 조용히 안 죽고 요란하게 죽는다.

**제약**

- 추가 용량 **수 KB 이내** — 이미지 파일을 하나 더 받는 방식은 이 안의 취지에 어긋난다
- `prefers-reduced-motion: reduce`에서 애니메이션을 끌 것
- 다크 모드에서도 깨지지 않을 것

### ④ 상점 등록 SQL (`clov-api`)

`db/manual-migrations/2026-08-05-shop-developer-gemini-night-background.sql`

**같은 폴더의 `2026-08-05-shop-crobi-dawn-starlight-archivist-skin.sql`을 템플릿으로 쓴다.** 구조가 사전점검 → 등록 → 검증 4단계다.

```
code           BACKGROUND_DEVELOPER_GEMINI_NIGHT
category       'BACKGROUND'      ← 'SKIN' 아니다
rarity         'LEGENDARY'
price          9800
discount_rate  80                ← 한정 프로모션. 실효가 1,960
image_url      '/shop/backgrounds/developer-gemini-night.webp'
```

**리더 확정 2026-08-05.** 값을 이렇게 정한 근거가 셋이다. **SQL 주석에 그대로 옮겨 적을 것.**

### ★ 등급을 LEGENDARY로 올린 근거는 "한정"이 아니다

기존 배경 4종은 전부 **`RARE` 2,800**이다. **이 배경만 등급이 다르면 무엇이 다른지를 적어야 한다** — 계약 §15-4의 기준이 *"등급도 같고 **내용도 같으면** 값도 같게 둔다"*이기 때문이다.

```
사계절 4종   정지 이미지 한 장                      RARE      2,800
이 배경      정지 이미지 + 다른 배경엔 없는 효과      LEGENDARY 9,800
```

**근거는 §3-③의 CSS 효과 레이어다. 내용이 다르니 등급이 달라도 된다.**

> ⚠️ **"한정이라서 비싸다"로 적지 말 것.** 한정은 아래 `discount_rate`로 이미 표현하고 있어서, 등급 근거로도 쓰면 **같은 이유를 두 축에 쓰는 것**이 된다. 그러면 다음에 한정 상품이 나올 때 "그럼 이것도 등급을 올려야 하나"가 근거 없이 반복된다.
>
> **★ 효과 레이어를 안 만들거나 나중에 빼면 이 등급의 근거가 사라진다.** 그때는 RARE 2,800으로 내리는 게 맞다. SQL 주석에 그 조건을 같이 적을 것.

### 정가 9,800은 LEGENDARY 층 규칙 그대로다

같은 층에 아케이드 보스 롭(9,800)과 새벽의 별빛 기록자 크로비(9,800)가 있다. **새 가격대를 만들지 않는다.**

### 할인 80%는 크로비 한정 스킨과 같은 방식이다

```
정가          9,800   ← 등급이 말한다
discount_rate    80   ← "한정"이 말한다
실효가        1,960   ← 크로비 한정 스킨과 같은 값. 둘이 "한정 세트"로 묶인다
```

**가격 축과 프로모션 축을 분리한다.** 정가를 올려서 한정을 표현하면 §15-4를 어긴다.

⚠️ **바닥은 90%다.** `9,800 × 10% = 980 > 가장 싼 COMMON 900`. 91%면 882가 되어 최고 등급이 상점에서 제일 싼 물건이 된다.

⚠️ **할인을 쓰면 해제 SQL을 같은 파일 맨 아래에 주석 상태로 같이 넣는다.** 관리 화면이 없어서 끝내려면 SQL을 직접 돌려야 하고, 등록만 남기면 "어떻게 끝내지"를 나중 사람이 처음부터 만들어야 한다 — **"한정"이 영구 할인이 되는 경로가 이것이다.** `2026-08-05-shop-crobi-dawn-starlight-archivist-skin.sql`의 맨 아래 블록을 그대로 따라 쓸 것.

⚠️ **해제해도 이미 산 사람의 가격은 안 바뀐다.** `user_inventory_items.paid_price`가 구매 시점 실효가를 박아둔다(계약 §15-1 (4)). 되돌릴 수 없다.

## 4. 반드시 지킬 것

### ★★ 새 상품 넣기 전 `code` 충돌 확인

```sql
SELECT code, name, rarity, price FROM shop_items
WHERE code = 'BACKGROUND_DEVELOPER_GEMINI_NIGHT';
```

**0행이어야 새로 넣는 것이다.** 등록 SQL은 `ON DUPLICATE KEY UPDATE`라 **코드가 겹치면 기존 상품이 통째로 덮이고 에러가 안 난다.** 2026-08-04에 실제로 당했다 — `COSTUME_ROB_EXPLORER`가 시드 상품을 덮어써 EPIC 하나가 카탈로그에서 사라졌고, 총액을 쪼개서 재고 나서야 위치를 잡았다.

⚠️ **등록 SQL의 검증 쿼리로는 이걸 못 잡는다.** "1행 반환"이 신규든 덮어쓰기든 똑같다. 다만 `INSERT`의 **`affected rows`가 1이면 신규, 2면 덮어쓰기**다 — 이건 구분된다.

### ★ 기존 무료 배경 5종은 건드리지 말 것

`lp-wood-desk` · `clover-coast` · `neon-city` · `minimal-clover` · `botanical` + `기본(심플)`은 **`shop_items`에 행 자체가 없다.** 이미 배포돼서 다들 쓰고 있고, **무료였던 걸 유료로 바꾸는 건 뺏는 것이라 되돌릴 수 없다**(리더 확정 2026-08-04). *"판매 종료된 유료 상품(RETIRED)"*과 *"상점 밖 기본 제공"*은 다른 상태다.

### ★ `imageUrl`을 신원 확인에 쓰지 말 것

소유 판정은 **`code`로만** 한다. 썸네일 경로를 바꾸는 순간 **이미 산 사람의 소유가 풀린다.** 2026-08-04에 배경 카드 그림을 실제 그림으로 바꾸는 `UPDATE`를 돌렸는데, 만약 `imageUrl` 대조를 쓰고 있었으면 그 한 줄로 배경 4종이 전부 잠겼다.

### ★ 배포 순서

**에셋(`clov-web`)을 먼저 배포하고 SQL을 실행한다.** 반대면 상점에 이름만 뜨고 그림이 깨진다.

## 5. 검증

**코드**

- `npm run lint` · `npm run build`
- **기존 배경 10종을 하나씩 골라 CSS 효과가 안 붙는지 확인** — 이 한정 배경에서만 붙어야 한다
- 새 배경 선택 → 새로고침 → 유지되는지(`localStorage`)
- `prefers-reduced-motion: reduce`에서 애니메이션이 꺼지는지
- **클릭이 막히지 않는지** — 효과 레이어에 `pointer-events: none`

**용량**

```bash
ls -la public/backgrounds/developer-gemini-night.webp   # ~300KB 목표
ls -la public/bg-thumbs/developer-gemini-night.png      # ~100KB 목표
```

**SQL** — 등록 후 검증 4가 아래를 만족해야 한다(현재 기준값, 실행 시점에 다시 잴 것).

```
현재      skins_total 42,760 · other_total 11,200 · catalog_total 53,960 · active_items 18
추가 후   skins_total 42,760 · other_total 13,160 · catalog_total 55,920 · active_items 19
                                        (11,200 + 1,960)
```

**LEGENDARY 층 검증은 세 줄이 나와야 한다.**

```
아케이드 보스 롭            9,800  할인 0   → 9,800
새벽의 별빛 기록자 크로비   9,800  할인 80  → 1,960
개발자 제미나이의 밤(배경)  9,800  할인 80  → 1,960
```

> ⚠️ **실효가 1,960이 EPIC 최고가 6,000보다 낮은 줄이 둘 있는 것은 프로모션 중이라 정상이다.** 할인을 해제하면 셋 다 9,800으로 돌아온다.

> **★ 완주 일수는 안 바뀐다.** `(55,920 − 1,000) ÷ 6,000 = 약 9일`로 계약 §15-4에 적힌 9일이 그대로 맞는다. **할인 없이 넣었다면 61,800 + 9,800 = 71,600 / 약 12일이 되어 계약을 고쳐야 했다.** 총액이 바뀌었는데 일수가 그대로인 것을 이상하게 여기지 말 것 — 실효가로 재기 때문이다.

⚠️ **총액이 바뀌면 계약 §15-1의 총액과 §15-4의 완주 일수를 같이 고친다.** 완주는 `(총액 − 시작 1,000) ÷ 하루 상한 6,000`이다. **총액만 고치고 일수를 두면 그게 다음 판단을 왜곡한다.**

⚠️ **숫자는 계산하지 말고 잰다.** 2026-08-04에 카탈로그 총액을 하루에 세 번 틀렸는데 전부 "앞 값에 더해서"였다.

```sql
SELECT COUNT(*) AS active_items,
       SUM(ROUND(price * (100 - discount_rate) / 100)) AS active_catalog_total
FROM shop_items WHERE status = 'ACTIVE';
```
