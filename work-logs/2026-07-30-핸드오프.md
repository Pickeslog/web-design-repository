## 3. ⚠️ 배포 전에 잡은 사고 2건

### ★ (1) `.env.production`이 팀 도메인 → 개인 도메인으로 덮여 있었다

#168에 이 한 줄이 딸려 들어왔다.

```diff
-VITE_API_BASE_URL=https://clovlabcalss.store/api/v1
+VITE_API_BASE_URL=https://clovlab.store/api/v1     ← chacha 개인 서버
```

이 파일은 **팀 공용 운영 빌드가 읽는다.** 그대로 배포하면 상점만이 아니라 **로그인·방·추억·알림까지 팀 서비스 전체가 개인 서버를 바라본다.**

**프론트 이미지를 SMTP 때문에 push 안 해둔 게 우연히 방패가 됐다.** 그게 아니었으면 오늘 아침에 그대로 나갔다.

- 복구 = #171. `.env.production`·`.env.example` 양쪽에 재발 방지 주석을 넣었다
- **왜 안 보였나** — `.env.production`은 `npm run build`에서만 읽힌다. 개발 서버(5173)는 `.env.development`를 보고, 값이 본인 도메인이면 **본인 배포에서는 정상 작동한다.** 본인 환경에서만 안 깨지는 구조다
- 개인 도메인은 **`.env.production.local`**에 둔다 — `.gitignore`의 `**/.env.*`에 걸리고 Vite가 `.local`을 우선한다. **실제로 만들어 빌드해 확인했다**(주석에 단언을 썼으니 추측으로 두지 않았다)

### (2) `login-rise` 애니메이션이 조용히 끊겨 있었다

#167이 `@keyframes login-rise` → `login-slime-in`으로 **개명**했는데, 비밀번호 재설정 화면이 그 이름을 **다른 파일에서** 참조하고 있었다. 07-29 §16에서 코멘트로 안내했지만 **수정 없이 머지됐다.**

- 심각도는 낮다 — 기본 상태에 `opacity: 0`이 없어 블록은 정상 표시되고 **연출만 사라졌다**

## 4. 소셜 로그인 3사 — 원인이 전부 달랐다

팀원 개인 배포 점검 중 3사가 각각 다른 증상을 냈는데 **원인이 하나도 겹치지 않았다.**

| 제공자 | 증상 | 진짜 원인 |
|---|---|---|
| **구글** | `redirect_uri_mismatch` (로컬 5173) | 콘솔 URI 1이 **`https://localhost:8080`** — 백엔드는 `http://`를 보낸다 ✅ **해결** |
| **네이버** | "등록된 아이디만 로그인할 수 있습니다" | 앱이 **"개발 중" 상태** + 멤버 미등록. **리디렉션 URI 문제가 아니다** |
| **카카오** | 약관 동의 화면 | **에러가 아니다.** OAuth 성공 후 신규 가입 단계다 |

### ★ 구글 — 콘솔이 스킴을 자동으로 붙인다

`localhost:8080/...`을 스킴 없이 입력하면 콘솔이 **`https://`를 자동 삽입**한다. 구글은 `http`/`https`를 완전히 다른 주소로 치므로 400이 난다. **`localhost`에 한해 `http`가 허용**되므로 한 글자만 지우면 된다.

고친 뒤 브라우저로 확인했다 — `accounts.google.com/v3/signin/identifier`까지 도달하고 "Clov(으)로 이동"이 뜬다(에러 문자열 0건). **반영은 즉시였다**(콘솔 안내는 "5분~몇 시간").

현재 등록된 리디렉션 URI 5개: `localhost:8080`(로컬) · `clovlabcalss.store`(팀) · `clovfriend.shop` · `clovlab.store` · `clovlov.xyz`(팀원 3명). **구글은 공통 앱을 쓰고 등록도 끝나 있다.**

### ★ 네이버 — "사람마다 증상이 다르다"가 곧 진단이다

| 원인 | 누가 깨지나 |
|---|---|
| 리디렉션 URI 불일치 | **전원 똑같이** |
| 앱 "개발 중" 상태 | **멤버관리에 없는 사람만** |

사람에 따라 갈린다 = **계정 단위 허용목록**이다. URI 문제라면 로그인 창까지 못 갔을 것이고, 이 에러는 **아이디·비번을 넣은 뒤** 나온다.

그리고 앱 이름이 **`clovfriend-shop`**이었다 — 구글 URI 3의 도메인 `clovfriend.shop`과 같다(점 vs 하이픈). **그 팀원이 개인 네이버 앱을 따로 만든 것**으로 보인다. 문의 문구를 작성해 뒀다(§12).

### 카카오는 왜 신규 가입으로 떴나

계정 조회가 **이메일이 아니라 `provider + oauth_subject`** 기준이다.

```java
// OAuthAuthService.java:29
userMapper.findByOauth(profile.provider(), profile.subject())
```

**카카오 회원번호는 앱마다 따로 발급**된다. 앱이 다르면 같은 카카오 계정도 다른 사람으로 잡힌다. 이것도 §12의 client_id 대조로 확정된다.

### 진단 명령 — 서버가 실제로 뭘 보내는지 한 줄로

```bash
curl -s -i http://localhost:8080/oauth2/authorization/google | grep -i "^location:"
```

`client_id`와 `redirect_uri`가 한 번에 나온다. 브라우저를 거치지 않아 캐시·리다이렉트에 흔들리지 않는다. **팀원 진단에도 이게 제일 확실하다.**

## 5. 계약 §15 Shop·Wallet 신설 (#15 머지)

프론트(#168)가 이미 main에 있는데 `shop.js`가 **`(계약 §15)`를 인용하는 §15가 없었다.** 순서가 뒤집힌 상태를 메웠다.

**절 번호는 §15로 고정** — `shop.js`가 이미 그렇게 인용하고, §14(에러 코드)는 참조용이라 번호를 밀면 기존 §14 참조가 전부 깨진다. 그래서 §14 뒤에 붙였다.

**추측으로 쓴 줄이 없다.** 경로는 `ShopController`, 응답은 DTO 5개, 규칙은 `ShopService`, 상태코드는 `ErrorCode`, enum은 마이그레이션 SQL에서 옮겼고 **프론트 실호출 6개와 대조해 전부 일치**를 확인했다.

### ★ 시작 골드 20,000 → 1,000으로 확정

`ShopService` 주석이 답을 갖고 있었다.

> 시작 골드. **기존 원장 데이터(SIGNUP_GRANT=20000)와 맞춘 값.**

**설계값이 아니라 개발 DB 테스트 데이터에 코드를 맞춘 숫자**였다. 그런데 그 값이 경제 전체를 결정하고 있었다.

```
카탈로그 전체(시드 12종·할인 반영) = 42,260 G
시작 20,000  →  가입 즉시 절반 구매 가능  →  골드 획득 기능이 무의미
```

1,000은 **가장 싼 코스튬(600G) 하나를 즉시 사고 두 번째는 못 사는** 금액이다. 구매 → 장착 → 마스코트 변경 루프를 한 번 완주하게 하는 게 목적이고, 카탈로그를 사게 하는 돈이 아니다. §15-1 (2)에 "카탈로그 총액에 가깝게 올리지 말 것" 경고를 박았다.

### 나머지 결정

- **지갑은 첫 접근에 생성** — 가입 로직에 상점 의존을 넣지 않는다. 상점이 빠져도 가입이 안 깨진다. 그래서 **`GET /shop/wallet`은 읽기 전용이 아니다**(캐시·리트라이 설계에 영향)
- **구매 요청에 본문이 없다** — 금액을 보낼 수 없게 만드는 것이 검증보다 강하다
- **장착은 `COSTUME`만**, 슬롯 하나, 해제는 `itemId`를 받지 않는다
- **`rarity` 5등급 전부 유지** — 시드 12종이 5등급을 모두 쓴다(2·2·3·3·2). 추측이 아니라 확인했다

## 6. clov-api #88 CI 실패 — 프로덕션 버그가 아니었다

`81 tests, 1 failed`의 그 1건이 **테스트 단정문의 함정**이었다. 응답 JSON은 완벽히 맞다.

**범인은 `.value(java.util.List.of(false))`**다. Spring `JsonPathExpectationsHelper.assertValue`에서 actual이 List이고 **expected도 List면** "단일 원소 벗기기" 분기를 건너뛰고, 타입 불일치 분기로 가서 `JSONArray` → `ImmutableCollections$List12`로 **강제 재해석**을 시도한다. Jayway가 그 타입을 만들 수 없어 **`null`을 반환**한다.

expected 타입만 바꿔 실측했다.

| expected | 결과 |
|---|---|
| `List.of(false)` | ❌ `expected:<[false]> but was:<null>` (CI 메시지와 동일) |
| `false` | ✅ PASS |
| `Matchers.contains(false)` | ✅ PASS |

**고칠 건 `List.of(...)` 제거 한 줄.** 구매 테스트는 `$.data.item.owned`(필터 없는 확정 경로)라 `Boolean`이 그대로 와서 통과한다 — **필터 쓴 곳만 걸려서** 원인이 안 보였다.

> **CI 로그에는 expected/actual이 안 남는다**(줄번호만). 전문은 `build/test-results/test/TEST-*.xml`에 있다. 이걸 몰라서 못 찾았을 가능성이 크다.

### #165 — 사용자에게 사실과 다른 말을 한다 🔴

위험구역에 이 문구를 새로 넣었다.

> 계정을 삭제하면 우정공간·**추억**·설정이 **모두 사라지고** 되돌릴 수 없어요.

계약은 반대다. **§5:223** "탈퇴 = **익명화**, **기록 FK 보존**" · **§3:60** "**기록 보존** — 탈퇴=익명화".

**추억은 안 사라진다.** 친구 공간에 남고 작성자만 "언노운"이 된다. 양쪽으로 해롭다 — 지우려고 탈퇴하는 사람은 안 지워지고, 남기고 싶은 사람은 겁나서 못 누른다. 데이터 처리 안내라 정확해야 하는 문장이다.

부수적으로 초대코드가 `input` → `span`이 되면서 **`navigator.clipboard` 실패 시 대안이 사라졌다**(보안 컨텍스트 전용 + `.catch(() => {})`로 삼킴). http/https가 섞이는 지금 상황에서 밟을 수 있는 경로다.

검증해서 **문제없던 것** — tabler 아이콘 10종이 실제 CDN(`@tabler/icons-webfont@2.47.0`) CSS에 전부 존재, 고아 `id` 0건, `--active-bg`/`--danger` 라이트·다크 양쪽 정의, **히어로 full-bleed 음수 마진(`-20px -24px`)이 `.ps-panel` 패딩과 정확히 짝이 맞고 모바일 미디어쿼리가 그 패딩을 건드리지 않는다.**

### #176 — 제안보다 나은 판단이 나왔다

`backdrop-filter`를 제안했는데 그걸 **다크에만** 쓰고 **라이트는 고스트카드(`schedule-banner--ghost`)의 크림톤을 재사용**했다. 밝은 배경에서 블러만으론 부족한 게 맞고, 같은 파일에서 검증된 값을 가져와 새 색을 발명하지도 않았다.

**의심스러웠던 부분은 확인해서 해소됐다** — `.clov-btn--dashed` 규칙에 `border-width/style`을 추가한 게 기존 버튼을 바꾸나 했는데, `Button.css:44`가 **이미 `1.5px dashed`**라 no-op이고 `--action`에는 기본 `1px solid`를 바꾸는 데 실제로 필요했다.

**판단 대기** — "전체 피드 보기"(`action`, 단순 이동)를 "새 D-day 만들기"(`dashed`, 생성)와 **완전히 동일**하게 만들어서 위계가 사라졌다. 이슈 원안은 "배경색은 유지하되 톤만 조정"이었다. 세 갈래를 제시했다(그대로 가면 `variant`를 `dashed`로 바꾸는 게 일관 / 원안대로 / 행 테두리만 실선).

### #17 — 골드 획득이 무한 파밍이었다 🔴

`EARN_MASCOT` +100(방 단위 3회) · `EARN_MEMORY` +50(무제한) 제안.

**`EARN_MEMORY` 무제한이 치명적이다.** §10에 `plan_id` 없는 **FREE MEMORY**가 허용돼 있다(D3) — 약속·완료·다른 사람이 필요 없다. `MEMORY_ALREADY_WRITTEN`은 `(plan_id, writer_id)` 중복을 막지만 **NULL은 유니크 제약에 안 걸린다.**

```
22,260 ÷ 50 = 446
→ 한 글자짜리 추억 446개면 카탈로그 전체. 대기 시간 0.
```

**방 단위 캡은 캡이 아니다** — "한 방 8명"은 있어도 "한 사람 N방"은 없고 방은 혼자 만들 수 있다. 하루 300 × 방 개수가 된다.

## 9. 오늘 나온 교훈

- **★ 로컬 `main`이 뒤처지면 diff가 거짓말을 한다.** #176을 리뷰하려는데 4개 파일이 나왔다 — `gh`는 1개라고 했다. 그 사이 #175가 머지됐는데 `git pull`을 안 해서 `main...branch` diff에 남의 머지분이 섞였다. **리뷰 전 `git fetch origin main`은 선택이 아니다.** `gh`와 로컬이 다르면 로컬을 의심할 것
- **★ CSS는 없는 애니메이션 이름을 조용히 무시한다.** `lint`·`build`·화면 모두 통과하고 연출만 사라진다. `getComputedStyle().animationName`도 **없는 이름을 그대로 돌려주므로 못 잡는다.** `getAnimations().length`만 0으로 구분해낸다(실측: 깨진 상태 0 / 수정본 1). 자바스크립트라면 빌드가 잡아줬을 종류다
- **★ 규칙이 한 곳에만 있으면 우회가 생긴다.** `NotificationMapper`의 공용 팬아웃은 "본인 제외"를 하는데, invite 도메인이 **같은 팬아웃을 자체 SQL로 다시 쓰면서 그 조건을 빼먹었다**(#90). 그래서 수락자가 자기 합류 알림을 받았다. 공용 헬퍼 주석에 "각 도메인 서비스가 호출한다"고 적혀 있는데 invite만 안 탔다
- **본인 환경에서만 안 깨지는 설정이 가장 위험하다.** `.env.production`은 `build`에서만 읽히고, 값이 본인 도메인이면 본인 배포에서 정상 작동한다. **개인 값은 `.local`로 분리**하는 것이 규칙이어야 한다
- **숫자에 근거가 있는지 주석을 먼저 볼 것.** 시작 골드 20,000은 설계값이 아니라 테스트 데이터에 맞춘 값이었고, 그게 경제 전체를 결정하고 있었다. `ShopService` 주석에 그렇게 적혀 있었다
- **문서에 단언을 쓰면 실행해 보고 쓴다.** `.env.production.local`이 우선한다는 주석을 넣기 전에 실제로 만들어 빌드해 확인했다(`.local` 있으면 그 값, 지우면 팀 도메인). 07-29의 같은 교훈이 오늘도 유효했다
- **`gh` 인라인 한글은 JSON 파일로 우회한다.** 이슈·PR·리뷰 본문을 전부 `--body-file` 또는 `gh api --input <json>`으로 올렸고 한글이 안 깨졌다. #72 본문이 `?`로 깨진 그 함정을 피하는 법이다

## 10. ★ CI/CD 착수 준비 상태 — 수업 후 여기부터

수업 내용(Docker + GitHub Actions CI/CD)이 지금 프로젝트에 **정확히 비어 있는 칸**을 가리킨다. 조사해뒀다.

### 8칸 중 3칸이 이미 차 있다

| 수업 흐름 | Clov | 근거 |
|---|---|---|
| main에 push | ⚠️ **트리거 없음** — PR에서만 돈다 | `ci.yml: on: pull_request` |
| Actions 자동 실행 | ✅ 있음 (2레포) | `clov-api/.github/workflows/ci.yml`·`clov-web/...` |
| 빌드·테스트 | ✅ 있음 | `gradlew test`(Testcontainers) / `npm lint + build` |
| Docker 이미지 생성 | ❌ Dockerfile은 **있는데** Actions가 안 쓴다 | |
| Registry push | ❌ 없음 | |
| 서버 pull | ❌ 수동 | |
| `compose up -d` | ❌ **compose 파일이 레포에 없다** | |

**즉 CI는 있고 CD가 통째로 없다.** 그리고 오늘 `login-rise` 회귀가 조용히 들어간 것도 `on: push: [main]`이 없어서다.

### ⚠️ 선행 조건 — compose가 버전 관리 밖에 있다

`api-docker-compose.yaml`·`web-docker-compose.yaml`·`nginx/default.conf`·`init-letsencrypt.sh`가 **VM 홈에만 있다**(07-29 §15). `clov-api/deploy/`에 있는 건 systemd 시절 파일이다.

**마지막 두 단계는 이 파일 없이 만들 수 없다.** 이게 첫 작업이다. 그리고 덤이 붙는다 — compose를 레포에 넣고 도메인만 `.env`로 빼면 **팀원 간 배포 차이가 한 파일 세 줄로 수렴**한다.

### 수업에서 특히 챙길 것 3개

1. **"서버가 새 이미지 pull" 화살표에 이름이 없다.** 실제로 막히는 곳이다. `appleboy/ssh-action`(가장 흔함) / self-hosted runner / watchtower 중 강사님이 어느 쪽인지 확인. VM 한 대면 **SSH action**이 맞다
2. **Docker Hub보다 GHCR가 유리하다.** 레포가 **public**이라 `GITHUB_TOKEN`으로 그냥 인증된다 — 시크릿을 하나도 안 만들어도 된다
3. **★ 헬스체크 타임아웃 240초 이상.** 이 VM은 Spring 부팅에 **185~208초** 걸린다(07-29 §14①, 로컬의 40배). 강사님 예제 기본값(보통 30~60초)을 그대로 쓰면 **배포가 항상 실패로 뜬다**

### 착수 순서

| | 무엇 | 같이 처리할 것 |
|---|---|---|
| 1 | **compose·nginx를 `clov-api/deploy/docker/`로** | `ports: "8080:8080"` 제거 · nginx를 **디렉터리 마운트**로(inode 함정) · `proxy_pass http://api:8080` |
| 2 | **`on: push: [main]` 추가** | CD의 가장 싼 첫걸음 |
| 3 | **이미지 빌드 → GHCR push** | 태그를 **커밋 SHA**로 → 07-29 §14③ "이미지 ≠ 코드" 문제가 끝난다 |
| 4 | 서버 자동 pull (SSH action) | 헬스체크 240초 |

> **시크릿은 계속 마운트로 유지한다.** CD를 붙인다고 이미지에 굽지 말 것 — 07-29에 겨우 뺀 것이다.
