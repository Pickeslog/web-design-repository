### 연타 판정을 목업에서 의도적으로 벗어났다

목업은 `900ms에 3번`인데 **`1000ms에 5번`으로 바꿨다.** 900ms에 3번은 클릭 간격 450ms — "연타"가 아니라 보통 클릭 속도라 그냥 교감하려던 사용자가 계속 어지러워졌다. 목업에서도 크로비가 같은 값이었지만 앱에서는 상태 스프라이트가 롭에만 있어 이 코드에 도달하지 않았고, **크로비 세트가 채워지면서 기본 마스코트를 쓰는 모든 사용자가 밟게 됐다.**

콤보 중간 클릭에 흔들림(nudge)도 붙였다. 그전엔 말풍선도 스프라이트도 API도 없이 **완전 무반응**이라 5번을 눌러도 체감이 2~3번이었다.

`find`·`pencil`·`smile`은 **교감 API에서 분리**했다. 순수 연출인데 `onSuccess` 안에 있어서 **하루 3회 교감에 갇혀** 특정 포즈를 하루에 볼 확률이 37%였다. 이제 클릭당 43%다.

## 3. ★ 스프라이트 정규화 — 도구가 있다

`clov-web/scripts/mascot/`

```powershell
.\normalize-sprites.ps1 -Character <캐릭터>       # 드라이런(기본)
.\contact-sheet.ps1 -Dir <폴더> -Out check.png    # 눈으로 확인
.\normalize-sprites.ps1 -Character <캐릭터> -Apply
```

**왜 필요한가** — 마스코트는 `height`만 고정하고 `width: auto`라, 원본 비율이 상태마다 다르면 **박스 폭이 같이 달라져 캐릭터가 좌우로 움직인다.** 크로비가 103~135px를 널뛰었다.

**배율 기준은 알파 면적의 제곱근**이다. bbox 높이로 맞추면 웅크린 `pencil`이 부풀고 줄에 매달린 `pulled`이 쪼그라든다. 머리 폭은 팔·소품에 오염돼 못 쓴다.

**★★ 판정 기준은 `scale`이 아니라 `캔버스 균일성`이다.** 오후에 두 폴더에 돌렸는데 판정이 갈렸고 둘 다 맞았다.

| | 캔버스 | scale | 판정 |
|---|---|---|---|
| 마지막 신호병 스킨 | 이미 640x640 단일 | 0.937~1.111 | **안 돌린다** |
| 롭 본체 | 900x510 / 916x475 **혼재** | 0.965~1.089 | **돌린다** |

**scale만 보면 둘이 구분되지 않는다.** 캔버스가 이미 단일이면 렌더 결과가 이미 고정이고, 그때의 scale 편차는 크기 차이가 아니라 **포즈별 소품(돋보기·연필·종이)의 잉크 양**이다. 그 상태에서 돌리면 멀쩡한 세트가 어긋난다. 스크립트가 캔버스만 보고 경고를 내니 **경고가 뜨면 돌리지 말 것.**

**현재 상태** — `rob`·`crobi`·`tako-gun`·`kim-cheolsu`·`onyx`, **스킨 5종** 모두 정규화가 끝났거나 처음부터 단일 규격이다. **지금은 어느 폴더에도 `-Apply`할 이유가 없다.**

> 스킨은 다섯 다 처음부터 640x640으로 들어왔다. **에셋을 만드는 쪽이 규격을 지키면 이 도구는 안 쓰는 게 정상이다** — 롭 본체처럼 규격이 갈라졌을 때만 쓴다. 오늘 이 도구를 여섯 번 판단했는데 **`-Apply` 한 것은 한 번뿐이다.**

**★ 덮어쓰기 전에 원본을 `web-design-repository/test-web-design/02-main/assets/<캐릭터>/`에 보존할 것.** 이건 예의가 아니라 **디버깅 근거**다 — 오늘 스프라이트에서 요소가 사라졌을 때 "정규화가 지웠나"를 원본과 대조해서 판정했다(§5-③). 원본이 없으면 비교 대상이 없다.

Windows 전용(`System.Drawing`)이고 새 패키지를 안 쓴다. `.ps1`은 **UTF-8 BOM 필수**(PS 5.1이 ANSI로 읽어 파싱이 깨진다), `SpriteTool.cs`는 **ASCII만**(Add-Type 컴파일이 깨진다).

## 4. 상점 스킨 — 구조와 함정

**에셋** `clov-web/public/shop/skins/<mascot-id>/<skin-id>/` 9종 + `metadata.json` (규격은 `_template/README.md`)
**코드** `Mascot.jsx`의 `EQUIPPED_SKIN_STATE_SPRITES` 배열에 **경로 한 줄** 추가
**DB** `shop_items` 행 — 이게 없으면 상점에 아예 안 뜬다

`metadata.json`은 **런타임에서 안 읽는다.** 자산 인벤토리·DB 등록용이다.

### ★ 조용히 깨지는 값 둘

| | 틀리면 |
|---|---|
| `category`가 `SKIN` | 구매는 되는데 **장착이 막힌다** — `ShopService.equip`이 COSTUME만 허용 |
| `image_url` 오타 | `Mascot.jsx`가 `endsWith`로 매칭하는데 실패해 **상태 전환 없이 한 장**만 나온다 |

둘 다 **에러가 안 난다.** 등록 후 아래 **전수 검사**로 판정까지 확인할 것. 스킨이 늘수록 값이 커지는 쿼리다 — 새 것만 보지 말고 기존 것까지 같이 본다.

```sql
SELECT code, rarity, price, category, status,
       IF(category = 'COSTUME' AND image_url LIKE '/shop/skins/%', 'OK', '★ 확인') AS chk
FROM shop_items WHERE image_url LIKE '/shop/skins/%' ORDER BY sort_order;
```

### 현재 등록된 스킨 5종

| code | 등급 | 가격 | 마스코트 | 획득 |
|---|---|---:|---|---|
| `COSTUME_KIM_CHEOLSU_SAFETY` | UNCOMMON | 1,500 | kim-cheolsu | 1일 |
| `COSTUME_TAKO_GUN_ROV_PILOT` | RARE | 2,800 | tako-gun | 4일 |
| `COSTUME_ROB_LAST_SIGNAL` | EPIC | 6,000 | rob | 10일 |
| `COSTUME_CROBI_OCEAN_RESCUE` | EPIC | 6,000 | crobi | 10일 |
| `COSTUME_ROB_ARCADE_BOSS` | LEGENDARY | 9,800 | rob | 18일 |

**마스코트 5종 중 4종이 스킨을 갖는다**(버거노인만 없다 — 본체 상태 세트가 1/9라 순서가 다르다). 획득 일수는 시작 1,000 + 하루 상한 500(계약 §15-4) 기준이다.

**★ EPIC 두 줄이 같은 6,000인 것은 의도다.** 등급도 같고 내용(상태 9종)도 같으면 **값도 같게 둔다** — 값을 가르는 두 축이 모두 같은데 다른 값을 붙이면 그게 근거 없는 숫자다. 기존 카탈로그에도 벚꽃 세트·아케이드 보스가 둘 다 9,800으로 있다.
**중복으로 보고 한쪽을 바꾸지 말 것.**

### 가격 정하는 법

**실효가**(`price * (100 - discount_rate) / 100`)로 줄을 세워 **위아래 등급을 안 넘게** 잡는다.

```
RARE   1,000 미드나잇(50%)   1,680 네온후드(30%)   2,200 크로비파티   [2,800 ROV]
EPIC   3,360 골든프레임(30%) 5,200 롭탐험가        [6,000 마지막신호병] 6,400 첫눈(EVENT)
LEGEND 6,860 벚꽃세트(30%)   [9,800 아케이드보스]  12,000 여름밤(EVENT)
```

규칙 둘 —

1. **아래 등급 최고가 < 새 값 < 위 등급 최저 실효가.** 상태 9종을 다 가진 스킨이라 등급 안에서는 위쪽에 붙인다
2. **EVENT가 같은 등급 상시 상품보다 비싸다**(기간 한정 프리미엄). 단 **RARE에는 EVENT가 없어서** 이 제약이 안 걸린다 — 층마다 확인할 것

> **★ 할인 때문에 생긴 기존 교차는 건드리지 않는다.** 미드나잇(RARE) 실효가 1,000이 포레스트(UNCOMMON) 1,500보다 싼데, 정가로는 2,000 > 1,500이라 순서가 맞다. 검증 쿼리가 이걸 FAIL로 잡으면 오탐이다.

```sql
SELECT rarity, category, code, price, discount_rate,
       ROUND(price * (100 - discount_rate) / 100) AS effective_price
FROM shop_items WHERE rarity IN ('RARE','EPIC','LEGENDARY')
ORDER BY FIELD(rarity,'RARE','EPIC','LEGENDARY'), effective_price;
```

### ★ 폴더명을 오타로 보고 고치지 말 것

`tako-gun/rov-pilot-rare`는 **`rob-`이 아니라 `rov-`**다. ROV = 원격 조종 잠수정.
고치면 `image_url` 매칭이 실패해 **에러 없이 상태 전환만 사라진다.**

**데모용으로 가격을 내리지 말 것.** 되돌리기 전에 산 계정에는 `user_inventory_items.paid_price`에 낮은 값이 그대로 남는다. 대신 `clov-api/db/maintenance/grant-test-gold.sql`로 지갑을 채운다(`reason`은 `SIGNUP_GRANT` — `EARN_` 계열을 쓰면 하루 상한 500 합산에 잡혀 그날 정상 획득이 막힌다).

### ③ "용량만 줄인 파일"이 사실은 그림 버그였다

정규화 뒤 같은 스프라이트를 더 작은 파일로 다시 받았다. 용량 최적화로 알고 있었는데 픽셀을 대조하니 **네 파일이 정확히 같은 픽셀 수(7,484), 정확히 같은 사각형에서** 달랐다. 우연일 수 없는 값이었고, 그 사각형이 **가슴 패널** 모양과 일치했다 — main에 들어가 있던 네 상태에 그 요소가 없었다.

→ **"압축만 했다"도 픽셀로 확인한다.** 파일 크기만 보면 못 잡는다.
→ **원본 보존이 무죄 증명이 됐다.** 정규화가 지웠는지 물었을 때, 보존해 둔 원본에도 없다는 것이 근거였다.
→ 그래서 **아카이브가 런타임 사본보다 나쁜 그림을 들고 있으면 안 된다.** 거기서 다시 정규화하면 버그가 되살아난다.
