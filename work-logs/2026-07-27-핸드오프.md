## 3. ✅ #114 겹침 카드 — 완결 (P1·P2·P3 전부 머지)

구판 CSS에서 이식하는 바람에 3D가 통째로 빠져 있던 걸 정본 `space.css` 기준으로 되돌렸다. **단계별로 쪼개 3개 PR로 올렸고 전부 머지됐다.**

| 단계 | PR | 내용 |
|---|---|---|
| P1 | #130 | 정적 3D — `perspective:1000px` + `rotateY ±25/35/45°`, 호버는 transform 유지하고 밝기·z-index만 |
| P2 | #147 | 방향성 슬라이드 — keyframes 10개(`cf-deck-*` 2 + `cf-current-*` 4 + `cf-past-*` 4) |
| P3 | #149 | 마우스 틸트 — `--rotateX/--rotateY` ±18°/±15°, `is-3d-hovering` |

**P1·P2는 `Refs #114`, P3만 `Closes #114`.** 단계 이슈에서 중간 PR이 이슈를 닫으면 남은 단계가 유실된다(§12).

**P2 구현 메모** — 슬롯 `<div>`는 `key={cls}`로 고정돼 index가 바뀌어도 같은 DOM 노드가 재사용된다. 그래서 **클래스만 갈면 같은 방향 연속 클릭에서 CSS 애니메이션이 다시 안 돈다.** `.cline-cards`의 `key`를 `slide.seq`로 갈아 리마운트시켜 정본(innerHTML 재생성)과 같은 재시작을 만들었다. **정본의 `void el.offsetWidth` 리플로우 트릭은 React에서 쓰지 말 것.**

**P3 구현 메모** — 각도 기준점은 카드가 아니라 **부모 슬롯**이다. 카드 기준으로 재면 기울면서 사각형이 같이 움직여 서로를 밀어내며 떨린다(정본 주석의 jitter). 각도는 state가 아니라 **ref + CSS 변수 직접 쓰기**로 리렌더를 만들지 않는다. **정본과 의도적으로 다른 점: `pointerType === 'mouse'`일 때만 반응한다** — 터치는 포인터가 화면을 떠나는 이벤트가 없어 탭 한 번에 기울어진 채 굳는다(정본은 데스크톱 전용이라 안 드러났을 뿐).

P1에서 함께 처리: 빈 슬롯 클래스 `isDiary` → `isFanned`(정본 `space.js:1191`), 좁은 화면 ±3 슬롯 숨김.

**리더 눈 확인은 아직이다** — 설정 → 증거 카드 테마 "겹침 카드"(§13).

## 4. ★ 카드 기본 테마 드리프트 — 원인과 교훈 (#70)

명세가 정한 기본 테마(**겹침 카드**)가 **아무에게도 적용되지 않고 있었다.** 신규 가입자는 전원 빨랫줄로 시작했다.

`UserService.preferences()`는 설정 row가 없으면 **최초 조회 때 lazy insert**를 하는데, 그 insert가 `'clothesline'`을 하드코딩하고 있었다. **row가 한번 생기면 서버가 항상 값을 채워 주므로 프론트 fallback(`'stack'`)은 영영 도달하지 않는다.**

4곳이 전부 달랐다:

| 위치 | 값 |
|---|---|
| 명세(정본) `09-component-inventory.md:100` | 겹침 카드(coverflow, 기본) |
| 프로토타입(정본) `clov-profile-modal.js:847` | `'coverflow'` |
| 계약 예시 · 백엔드 insert | `clothesline` |
| 프론트 fallback | `stack` (도달 불가) |

**교훈 2개**

- **"프론트에 fallback이 있으니 기본값은 거기서 정해진다"가 틀릴 때가 있다.** 서버가 값을 채워 주는 필드는 프론트 fallback이 죽은 코드다. **기본값을 바꾸려면 서버를 고쳐야 한다.**
- **계약에 허용값 정의가 없으면 드리프트가 조용히 생긴다.** `memoryCardTheme`은 계약에 예시 한 줄만 있고 허용값·기본값 정의가 없었다. 이번에 표를 신설했다(`API-CONTRACT.md` §5). **enum성 필드는 예시가 아니라 표로 박을 것.**

**기존 row는 건드리지 않았다** — 자동 배정과 실제 선택을 구분할 방법이 없어 일괄 UPDATE하면 진짜로 빨랫줄을 고른 사람의 선택까지 지운다. 기존 사용자는 설정에서 직접 바꿔야 한다. (덮어쓰기가 필요하면 별도 SQL)

### #153 — "순수 리팩터링"인데 화면이 바뀌었다

`index.css`의 `box-sizing`은 **`#root`에만** 걸려 있고 `box-sizing`은 상속되지 않는다. 전역 `*` 리셋은 이 저장소에 없다. 그래서 `.proto-login *{box-sizing:border-box}` 한 줄이 화면 전체 박스 계산을 바꿨다.

**그런데 새 쪽이 맞다.** 목업 `login.html:18`이 전역 `border-box`를 깔고 시작한다:

| | 목업 의도 | 기존(Emotion) | #153 |
|---|---|---|---|
| `.memory-note` `min(280px,100%)` | 280 | **314** ✗ | 280 ✓ |
| `.input` `height:54px` | 54 | **56** ✗ | 54 ✓ |

**기존 Emotion 판이 목업과 34px 어긋나 있었고 #153이 그걸 고친 것이다.** 되돌리지 말 것. 다른 `.proto.css` 6개도 전부 같은 리셋을 갖고 있다(`schedule.proto.css:8-12`에 같은 이유의 주석이 있다).

조치는 **코드가 아니라 본문 정정**이었다 — "순수 리팩터링"이 아니라 "리팩터링 + 의도된 렌더링 수정 1건"으로 다시 쓰게 했다. #150의 합격 기준이 "화면이 전과 똑같은 것"이라 적어두지 않으면 추적이 안 된다.

### #154 — 소비형 함수를 effect 의존성에 넣으면 안 된다

```
handleLogin: setTokens(...)                → accessToken 바뀜
handleLogin: navigate(takeReturnTo())      → '/rooms/999/feed' 소비하고 이동   ← 1번째
effect:      accessToken 변경 감지          → navigate(takeReturnTo())          ← 2번째 (5.5ms 뒤)
                                             이미 지워져 fallback '/' 반환 → 덮어씀
```

`redirectedRef` 가드가 못 막은 이유: **마운트 시점(로그아웃)에 effect가 한 번 도는데 그때는 토큰이 없어 ref를 안 세우고 지나간다.** 그래서 나중에 토큰이 생겼을 때 ref는 여전히 `false`.

해법은 **"마운트 시점에 이미 로그인이었나"만 보게 하는 것**:

```jsx
const wasLoggedInOnMount = useRef(Boolean(useAuthStore.getState().accessToken))
useLayoutEffect(() => {
  if (!wasLoggedInOnMount.current || redirectedRef.current) return
  redirectedRef.current = true
  navigate(takeReturnTo(), { replace: true })
}, [navigate])
```

의존성과 `accessToken` 구독을 **둘 다** 뺀다. 로그인 성공 케이스는 `handleLogin`이 이미 책임진다.

> **`Signup.jsx:301`도 같은 패턴이다.** 나중에 Signup에 가드를 넣으면 똑같은 이중 소비가 재현된다.

## 10. ✅ 시크릿이 커밋에 딸려 들어갈 뻔했다 — 조치 완료

clov-api 커밋 중 **`git add` 대상이 아니었던 `src/main/resources/mapper/application-secret-server.yaml`(실제 Google OAuth Client ID/Secret)이 함께 커밋됐다.** 다른 세션이 스테이징해두고 파일만 지운 **유령 인덱스 항목**이 `git commit`에 쓸려 들어간 것이다.

**GitHub push protection이 막아서 원격에는 아무것도 올라가지 않았다.** 커밋을 되돌려(`reset --soft` + 해당 경로만 unstage) 내 파일만 다시 커밋했다.

**근본 원인**: `.gitignore` 규칙이 `src/main/resources/application-secret*.yaml`인데 문제 파일은 **`resources/mapper/` 아래**라 패턴을 비껴간다.

**조치 완료 — 구멍이 두 곳이었다.**

| 레포 | 무엇이 문제였나 | PR |
|---|---|---|
| **clov-api** | 규칙이 경로에 고정(`src/main/resources/...`)돼 한 단계 아래 사본을 못 잡았다. **추가로 `DEPLOY.md`가 만들라는 `clov-api.env`가 기존 `.env`/`.env.*` 어디에도 안 걸리고 있었다** | #79 (`b8f5fdc`) |
| **clov-web** | **Vite 기본 `.gitignore`에 `.env` 규칙이 아예 없다.** `*.local`이 `.env.local`만 우연히 걸러줄 뿐 `.env`·`.env.production`은 그대로 커밋된다 | #143 (`ab55198`) |

둘 다 `**/application-secret*.{yaml,yml}` · `**/*.env` · `**/.env.*`로 넓히고 `.example`은 negation으로 남겼다. **머지된 main에서 `git check-ignore`로 재확인했다** — 실제로 새어나갔던 `resources/mapper/...` 경로 포함 전부 IGNORED.

**교훈**: 공유 워킹트리에서는 `git add -A`뿐 아니라 **`git commit` 자체가 위험하다** — 내가 add하지 않아도 이미 스테이징된 것이 함께 커밋된다. **커밋 전에 `git status --short`로 스테이징 목록을 확인하고, 커밋 후 `git show --stat`으로 실제 포함 파일을 볼 것.**

- **이월 항목은 "다음 PR에 얹기"로 두면 또 넘어간다.** hover 색은 #128 → #129를 그냥 통과했다. 이번엔 별도 PR(#131)로 뺐다. **얹지 말고 분리할 것.**
- **CSS 특이성 동률은 주입 순서로 갈린다.** `.clov-btn--action:hover`(0,3,0)와 `.proto-*` 기본 색(0,3,0)이 동률이면 나중에 주입되는 `Button.css`가 이긴다. **프로토타입 스코프에서 공용 컴포넌트를 쓸 땐 호버 상태의 색까지 다시 못박아야 한다.**
- **같은 데이터를 화면마다 다른 쿼리 키로 받으면 중복 요청이 된다.** 대시보드만 `status` 필터를 키에 넣어 Schedule·Feed와 캐시를 못 나누고 있었다. **필터를 바꿀 일이 생기면 다른 화면이 같은 리소스를 어떤 키로 받는지부터 볼 것.**
- **투명 PNG 최적화는 "알파를 실제로 쓰는지"부터 확인한다.** `diary-memo.png`는 RGBA로 저장돼 있었지만 **투명 픽셀이 0개**였다. 인코더가 알파 평면을 뺀 걸 버그로 오해할 뻔했는데, 원본을 전수 검사하니 정상 최적화였다. 파일 이름·색 타입이 아니라 **픽셀을 봐야 한다.**
- **이미지 변환 품질은 "보이는 픽셀"만 재야 한다.** 전체 픽셀로 색차를 재면 알파=0 영역의 무의미한 RGB 때문에 최대 색차가 255로 나와 겁먹게 된다. **렌더 크기로 축소한 뒤 알파가 있는 픽셀만** 집계하면 실제 체감(평균 2/255)이 나온다.
- **Vite dev 서버는 없는 경로에 index.html을 200으로 준다.** 파일이 지워졌는지를 HTTP 상태코드로 확인하면 안 된다 — 지운 PNG 경로가 200을 반환해 잠깐 헷갈렸다. **`Content-Type`을 볼 것**(`text/html`이면 fallback, `image/webp`면 진짜 파일).

### 후반(이슈 감사 라운드)에서 나온 것

- **★ 같은 이름의 파일이 두 군데 있으면 "라우터가 import하는 쪽"을 확인하고 시작한다.** `ProtectedRoute.jsx`가 `src/components/`와 `src/routes/` 양쪽에 있었고, **router가 쓰는 건 `routes/` 쪽**이다. 리뷰 코멘트에 잘못된 경로를 적었고 그게 lami의 이슈 #137로 그대로 옮겨갔으며, 나 자신도 엉뚱한 파일을 고쳤다. **브라우저에서 "저장이 안 되네"를 보고서야 잡혔다** — 셀프 검증이 없었으면 그대로 머지됐을 것이다. **파일 경로를 인용하기 전에 import 체인을 한 번 따라갈 것.**
- **★ 공유 워킹트리에서는 `git add -A`뿐 아니라 `git commit` 자체가 위험하다.** 다른 세션이 스테이징만 해두고 파일은 지운 **유령 인덱스 항목**(실제 시크릿 yaml)이 내 커밋에 쓸려 들어갔다. GitHub push protection이 막아서 유출은 없었다. **커밋 전 `git status --short`로 스테이징 목록을 보고, 커밋 후 `git show --stat`으로 실제 포함 파일을 확인할 것.**
- **`.gitignore` 패턴은 "그 파일이 실제로 놓인 경로"로 검증해야 한다.** `src/main/resources/application-secret*.yaml`은 한 단계 아래(`resources/mapper/`)에 같은 이름 파일이 생기면 못 잡는다. 시크릿류는 `**/`로 시작하는 편이 안전하다.
- **리뷰에서 "별도 이슈로 빼주세요"라고 했으면 내가 만들지 않는다.** lami가 3분 먼저 올린 이슈와 내 이슈가 중복됐다(clov-api #73/#74 vs #75/#76). 먼저 올라온 쪽을 살리고 내 것을 닫았다. **이슈 생성 담당을 코멘트에 명시할 것.**
- **정본을 채택할 때 "전부냐 일부냐"를 명시한다.** 목업 방 이름 정규식에서 **길이만 채택하고 문자 종류는 뺐다**(§11). 이유를 계약에 적고 회귀 테스트로 못 박지 않으면, 나중에 누군가 "정본과 다르다"며 되돌린다.
- **한쪽만 바꾸면 창이 생기는 변경은 프론트를 양쪽 방어로 만든다.** 에러 코드 교체(#77)도 봉투 교체 때와 같다 — 프론트가 신·구 코드를 다 받으면 **머지 순서가 무관해진다.**

### 3단계(lami 2라운드)에서 나온 것

- **★ "순수 리팩터링"의 합격 판정은 눈이 아니라 숫자로 한다.** #153의 스크린샷 눈대조는 **입력칸 2px도, 메모지 33px도 못 잡았다.** `#root` 아래 전 요소의 `getBoundingClientRect()`를 브랜치별로 찍어 경로별 비교하면 바뀐 것이 목록으로 나온다. **0개면 순수 리팩터링이 증명되고, 0개가 아니면 그 목록이 곧 PR 본문에 적을 내용이다.** 남은 3화면(Signup 764줄 등)에 그대로 쓸 것.
  ```js
  (() => { const out=[]; const walk=(el,p)=>{ const r=el.getBoundingClientRect();
    out.push([p,el.tagName.toLowerCase(),+r.width.toFixed(2),+r.height.toFixed(2),+r.left.toFixed(2),+r.top.toFixed(2)]);
    [...el.children].forEach((c,i)=>walk(c,p+'/'+i)); };
    walk(document.getElementById('root'),''); return JSON.stringify(out); })()
  ```
- **★ 소비형 함수(`takeReturnTo`)를 effect 의존성이 건드리게 두면 이중 소비가 난다.** "한 번 읽고 지우는" 함수는 **누가 언제 부르는지 호출자가 하나여야** 한다(§8-2). 값이 사라진 뒤의 fallback이 조용히 정답을 덮어쓰기 때문에 크래시도 로그도 없다.
- **내가 만든 함수를 다른 데서 어떻게 부르는지 훑는다.** #146의 회귀는 `grep -rn "setTokens(" src/` 한 줄이면 보였다. **시그니처를 바꾸거나 기본값을 추가할 때** 이걸 돌리면 "내가 안 건드린 파일이 기본값을 밟는" 경우가 미리 나온다.
- **"못 한 검증"을 적어두면 리뷰어가 거기부터 판다.** #154는 "유효한 토큰 happy path는 계정이 없어 확인 못 함"이라고 솔직히 적혀 있었고, **버그가 정확히 거기서 났다.** 이 습관은 유지시킬 것.
- **계정이 없어 못 하는 검증은 대부분 axios 어댑터 스텁으로 된다.** `api.defaults.adapter`만 갈아끼우면 컴포넌트·핸들러는 진짜 코드가 그대로 돈다. 로그인 게이트 화면도 이 방식으로 실제 컴포넌트를 띄워 검증했다(§16).
- **정본을 베끼면 정본의 버그도 온다.** `success-overlay.css`의 `prefers-reduced-motion` 블록은 체크·텍스트만 끄고 **`infinite` 애니메이션 3개(낙엽·물결 앞뒤)를 빠뜨렸다.** 이식할 때 채워야 한다.
- **연출 문구가 "실제 동작"을 가리키는지 확인한다.** 성공 오버레이의 이스터에그 힌트 3종은 전부 `croby-mascot.js`(409줄)의 실동작을 안내하는데, 프로덕션 `Mascot.jsx`는 `onClick` 하나뿐이다. **그대로 이식하면 없는 기능을 광고하게 된다**(§15).

## 16. 로그인 게이트 화면을 백엔드 없이 검증하는 법

대시보드·로그인 등은 로그인 게이트라 그동안 "리더 로컬에서 눈으로" 확인해 왔다. **실제 컴포넌트를 띄워 자동 검증하는 방법**을 확립했다(#146·#153·#154·#114 P3에서 사용).

한 번의 스크립트 안에서 순서대로:

1. **앱이 실제 로드한 모듈 URL을 찾는다** — `performance.getEntriesByType('resource')`에서 `/src/api/client.js` 등을 필터. **HMR이 붙인 `?t=…` 스탬프가 있으면 그 URL로 import해야 한다.**
2. `api.defaults.adapter`를 스텁으로 교체(`{data:{success:true,data:…}, status:200}` — `client.js`가 봉투를 벗기므로 이 모양이어야 함)
3. `useAuthStore.setState({accessToken:'stub'})` — `setTokens`가 아니라 `setState`
4. `await router.navigate('/rooms/1')` → `await queryClient.resetQueries()`

### 함정 3개 (전부 실제로 걸렸다)

- **HMR `?t=` 때문에 모듈 인스턴스가 둘로 갈린다.** 그냥 `import('/src/stores/authStore.js')` 하면 앱과 **별개 인스턴스**가 만들어져, 토큰을 넣어도 앱의 `ProtectedRoute`는 `null`을 본다. **DOM과 `location.pathname`이 안 맞으면 이 증상이다.**
- **백엔드가 살아 있으면 가짜 토큰이 지워진다.** 8080이 401을 주면 `client.js`의 인터셉터가 `clear()`를 부른다. **어댑터 스텁을 토큰 주입보다 먼저** 할 것.
- **★ 프리뷰 창이 표시되지 않으면 전환 시계가 멈춘다.** 프레임을 합성하지 않아 CSS transition/animation이 `currentTime: 0`에 얼어붙는다. 그 결과 `getComputedStyle().transform`이 시작값에 고정되고, **전환은 캐스케이드에서 `!important`보다 위라 인라인 강제 지정조차 무시된 것처럼 보인다.** 형제에 새로 만든 프로브 div는 정상이라 "이 요소만 이상"해 보여 코드 버그로 오진하기 쉽다.
  **확인법**: `el.getAnimations()`에 `CSSTransition`이 `playState:'running'`인데 `currentTime: 0`이면 이 상황.
  **해결**: 읽기 전에 `transition: none !important`를 임시 주입한다. (같은 이유로 `requestAnimationFrame`도 안 돌아 **프레임 수 측정은 무의미하다.**)
