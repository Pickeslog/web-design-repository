**추적**: 프론트 → 네트워크 → 백엔드 순으로 좁혔더니 `/shop/*` **전체가 404**였다. 상점 도메인 자체가 `main`에 없었고, 구현은 `feat/96-shop-api` 브랜치에 머물러 있었다. 즉 프론트 버그가 아니라 **미머지 브랜치** 문제였다.

**처리**: main을 머지해 최신화한 뒤 이슈 번호에 맞춘 `feat/190-shop-api`로 정리해 PR #99로 올렸고 머지됐다.

### 리뷰에서 받은 지적 (CI 실패 1건)

`myeongjundev`가 원인을 정확히 짚어줬다. 81개 중 1개 실패였는데 **프로덕션 버그가 아니라 테스트 단정문 문제**였다.

```java
// 실패 — JSONPath 필터 결과(JSONArray)에 expected도 List를 넘기면
// JsonPathExpectationsHelper가 "단일 원소 벗기기" 분기를 건너뛰고 null과 비교한다
.andExpect(jsonPath("$.data.items[?(@.id=='13')].owned").value(java.util.List.of(false)))

// 통과
.andExpect(jsonPath("$.data.items[?(@.id=='13')].owned").value(false))
```

**교훈**: `.value()`에 `List`를 직접 넘기지 말 것. 여러 원소를 볼 땐 `Matchers.contains(...)` / `hasItem(...)`을 쓴다. 필터(`[?(...)]`)를 안 쓴 확정 경로는 Boolean이 그대로 와서 문제가 없기 때문에, 필터를 쓴 곳에서만 터진다.

## 7. clov-web — 마스코트 인터랙션 이식

`test-web-design/02-main`의 바닐라 상태 머신(`js/croby-mascot.js` 409줄 + `css/croby-mascot.css`)을 React로 옮겼다. 기존 `Mascot.jsx`는 클릭 시 교감 API 호출만 있었고, 주석에 "연타·방치 애니메이션·드래그는 범위 밖"으로 미뤄둔 상태였다.

### 옮긴 것

**공통** — 20초 무입력 시 sleepy, 클릭 시 흔들기 + 대사, 0.9초 내 3연타 시 dizzy, 방치 중 간헐적 혼잣말

**롭 전용** — 코드 에디터풍 타이핑 말풍선, `find`/`pencil` 특수 리액션(스프라이트 교체), dizzy 시 0/1 글리치, 머리 잡고 들어올리기(`lifted` → 150px 넘기면 `scared` → 3초 뒤 `angry` + 커서 파괴 연출)

**버거노인** — `burger-oldman.html`의 레이어 분리를 그대로 가져와 몸통(`body`)과 왼팔(`wave-arm`)을 나눴다. 클릭하면 점프하며 팔만 어깨 기준으로 흔드는 인사가 나가고, 숨쉬기·김·종이 흔들림(`feTurbulence`)도 함께 붙였다. 상태 애니메이션은 낱장 스프라이트가 아니라 **두 레이어를 감싼 stage에 걸어야** 팔이 몸통을 따라간다.

### 작업 중 고친 것

- **로컬 리액션이 서버 응답에 묶여 있으면 안 된다** — 응답이 늦게 오면 방금 띄운 대사를 덮어쓴다. 클릭 연출은 즉시 반응시키고, 교감 API는 레벨 갱신·한도 초과 안내에만 관여하게 분리했다.
- **드래그 연출이 통째로 죽어 있던 버그** — 드래그는 마운트 시 1회 등록한 window 리스너에서 도는데, 그 시점엔 preferences 응답 전이라 `mascotType`이 항상 `crobi`로 잡혔다. 롭 전용 분기(커서 파괴)가 전부 무시됐다. 최신 값을 ref로 따로 들고 읽도록 고쳤다.
- **스프라이트 규격** — `croby_sleepy.png`를 원본(1086×1448 / 1,075KB) 그대로 넣었다가, 화면엔 110px로 그리는 자리라 480×640 / 243KB로 리사이즈했다. 「버거노인 마스코트 적용 내역」의 리사이즈 규칙을 따랐다.

> 롭 `smile.png`는 원본 위젯도 `CHARACTERS` 레지스트리에 넣지 않은 예비 스프라이트라 뺐다.

세 건 모두 `Mascot.jsx`·`Mascot.css`를 만졌고, 내 브랜치는 같은 두 파일을 **전면 재작성**했다. 특히 자료구조가 다르다.

```js
// main — 캐릭터당 스프라이트 1장
const SPRITES = { crobi: crobiSprite, rob: robSprite, takoGun: ..., kimCheolsu: ... }

// 내 브랜치 — 캐릭터당 포즈 맵
const SPRITES = { crobi: { default, dizzy, sleepy }, rob: { default, dizzy, sleepy, lifted, ... } }
```

**그대로 머지하면 타코군·김철수와 크기 선택 기능이 지워진다.** 머지 전에 반드시:

1. main을 브랜치로 머지해 `SPRITES`를 **포즈 맵 구조로 합치고**, 타코군·김철수를 `{ default: ... }` 형태로 편입
2. 두 캐릭터는 포즈 스프라이트가 없으니 버거노인처럼 **공통 연출만** 타게 두기
3. 크기 선택(#201)이 내가 새로 만든 `.clov-mascot-stage`(버거노인 레이어)에도 적용되는지 확인 — 크기 관련 CSS가 `.clov-mascot-sprite`만 잡고 있으면 버거노인만 크기가 안 바뀐다

이 정리를 끝내기 전에는 PR을 열지 않는 게 낫다.

## 9. 검증 환경 메모 — 브라우저 패널의 타이머 스로틀링

마스코트처럼 **시간에 의존하는 연출**을 자동화로 검증할 때 겪은 함정이다. 이 세션의 브라우저 패널은 페인트 프레임을 받지 않아 타이머가 심하게 느려진다.

```
setInterval(fn, 55) 를 1초 동안 → 기대 18회 / 실제 2회
setTimeout(1000) 이 실제로는 1794ms
```

타이핑 대사가 한 글자씩 느리게 나오길래 버그로 의심했는데 환경 문제였다. 같은 이유로 `angry`처럼 1.4초짜리 짧은 상태는 폴링 간격을 좁혀도 놓치기 쉬워서, **한 호출 안에서 트리거와 관찰을 같이** 해야 잡힌다(호출 사이에 20초 idle이 지나 마스코트가 자버리는 일도 있었다).

CSS `transition`도 같은 이유로 컴퓨티드 값이 전 단계에 멈춰 보인다. 이땐 `* { transition: none !important }`를 주입하고 리플로우를 강제한 뒤 읽으면 실제 최종값이 나온다.
