# 코덱스 전달 — user 도메인 백엔드 (#15, 계약 §5)

> 담당: Codex(백엔드 레인). 리더 도메인 마지막. 프론트는 백 머지 후 Claude가 붙임.
> 골든레퍼런스: 이미 머지된 **`domain/auth`·`domain/room`** 구조 그대로 복사, 이름만 레지스트리 §2(`domain/user`, `UserController`·`PreferenceController`·`UserService`·`UserPreferenceMapper`)로.
> **주의: `User`·`UserMapper`는 `domain/auth` 소유(재사용)** — 옮기거나 새로 만들지 말고, 필요한 조회/수정 메서드만 auth의 `UserMapper`에 추가한다(레지스트리 확정). `is_anonymized` 등 컬럼은 DB05(schema) 기준.

## 만들 것 — `domain/user` 신규 (계약 §5)

| Method | Path | 반환 | 인가 |
|---|---|---|---|
| GET | `/api/v1/users/me` | `UserProfile` | 본인 |
| PATCH | `/api/v1/users/me` | `UserProfile`(보낸 필드만: nickname·profileImageUrl·birthdate) | 본인 |
| PATCH | `/api/v1/users/me/password` | `data:null` | 본인 |
| POST | `/api/v1/users/me/profile-image/presign` | Presign(§4-3) | 본인 |
| DELETE | `/api/v1/users/me` | `data:null`(익명화) | 본인 |
| GET | `/api/v1/users/me/preferences` | `Preferences` | 본인 |
| PATCH | `/api/v1/users/me/preferences` | `Preferences`(보낸 필드만) | 본인 |

### 응답 shape (계약 §5-1 그대로)
- **UserProfile** = `{ id, email, nickname, profileImageUrl, birthdate, personalInviteCode, isSocial, createdAt }` (id 문자열, isSocial = oauth_provider 존재 여부).
- **Preferences** = `{ darkMode, customColor, wallpaperIcon, dashboardBackground, letterTheme, memoryCardTheme, mascotType }` (테이블 `user_preferences`).
- **PATCH password** body `{ currentPassword, newPassword }` → 현재 비번 불일치 `401 INVALID_CREDENTIALS`, 성공 시 **기존 refresh 전부 revoke**(auth의 revoke 재사용).
- **DELETE /users/me** = 익명화: `is_anonymized=true`·닉네임 "언노운"·refresh 전부 revoke. **행 삭제 아님**(FK 기록 보존).
- **presign** body `{ contentType, fileSize }` → Presign(`uploadUrl`·`imageUrl`·`expiresIn`).

## 재사용 / 주의 (반드시)
1. **User/UserMapper(auth) 재사용** — `findById` 있음. 없는 것만 추가: `updateProfile`(nickname/profile_image_url/birthdate 부분수정), `updatePassword`, `anonymize`(is_anonymized·nickname). MyBatis `#{}`만·resultMap 컬럼 snake_case.
2. **비번**: auth의 `PasswordEncoder`로 currentPassword `matches` 검증. 성공 시 새 비번 인코딩 저장 + refresh revoke(auth `RefreshTokenMapper.revoke...` 재사용). 소셜계정(password NULL)은 비번 변경 대상 아님 처리.
3. **presign은 스토리지 미설치(#38)** → plan처럼 placeholder(`"pending-storage-signature"`·`"pending-storage-image-url"`, 300) 반환. **#38 후 실제 서명으로 교체**(이 PR에선 placeholder OK).
4. **`GET /users/me/rooms`는 만들지 마** — `GET /rooms`(#32)가 이미 "내 우정공간 목록"을 커버. §5의 `sort=` 변형이 필요하면 별도 이슈로 `GET /rooms`에 sort 파라미터 추가 제안(중복 엔드포인트 금지).
5. **`user_preferences` 테이블이 `src/main/resources/schema.sql`(테스트용)에 있는지 확인** — 없으면 DB05 기준으로 추가(없으면 preferences 통합테스트가 깨짐). 신규 유저 최초 조회 시 기본값 row 없으면 계약 기본값(letterTheme=postbox·memoryCardTheme=clothesline·mascotType=crobi 등) 반환 또는 lazy insert — 방식 택1해 일관되게.
6. **공유 DTO는 `global/dto` 재사용**(#33 교훈). UserProfile/Preferences는 user 고유라 `domain/user/dto`에 유니크명으로.

## 테스트 (통합, room/notification 수준)
- GET /users/me = UserProfile 필드 확인.
- PATCH /users/me 부분수정(닉네임만) 반영.
- PATCH password: 정상 변경 + **틀린 currentPassword → 401 INVALID_CREDENTIALS** + 변경 후 기존 refresh revoke 확인.
- DELETE /users/me: is_anonymized=true·닉네임 "언노운"·행 보존·refresh revoke.
- GET/PATCH preferences: 기본값 조회 + 부분수정 반영.
