## 1. clov-web #123 — 대시보드 이모지 제거 및 tabler 아이콘 교체

**배경**: 프로젝트 디자인 방향으로 이모지를 쓰지 않고 tabler 웹폰트 아이콘만 쓰기로 함. `Dashboard.jsx`에 이모지 7곳(레벨 티어 배지·대표사진 빈상태·증거카드 빈사진·D-day·글쓰기·초대 모달 2곳) 남아있었음.

**브랜치**: `feat/123-dashboard-remove-emoji`

**팀장 착수 전 리뷰 반영**: "이모지 안 쓰기를 누가 정했는지 출처 불명확" 지적 → 팀장이 프로젝트 표준으로 확정(프로토타입은 이모지 대조 대상에서 제외). 방법은 인라인 SVG 대신 이미 로드된 tabler 웹폰트 사용(`RoomList`·`Settings`가 이미 사용 중) 지적 반영. 티어 아이콘 7개는 "성장 계단감이 죽어 보이면 이모지 예외" 조건부로 진행 → 레벨바 스크린샷으로 문제없음 확인, 예외 없이 전부 교체.

**수정 파일**: `Dashboard.jsx`, `dashboard.proto.css`

- `TIERS` 배열 아이콘을 이모지에서 `ti-seeding`~`ti-diamond` tabler 클래스로 교체
- 대표사진/증거카드 빈 상태 → `ti-camera-plus`/`ti-photo-off`
- D-day·글쓰기·초대 모달 아이콘 전부 tabler로 교체, 접근성(`aria-hidden`·`aria-label`) 추가

**검증**: `npm run lint`/`npm run build` 통과. tabler-icons-webfont 2.47.0 CDN에서 사용한 아이콘 클래스 전부 실존 확인. 로그인 세션이 없어 화면은 DOM 글리프 렌더 확인으로 대체, 실제 화면은 사용자가 스크린샷으로 확인.

**커밋/PR**: `a9fd0f1`, `1f9aee2`... → PR [#124](https://github.com/Pickeslog/clov-web/pull/124)(`Closes #123`) → 머지(`5a1e4a1`).

## 2. clov-web #125 — 추억피드 카드 레이아웃·아이콘·다크모드 라벨 프로토타입 정합

**배경**: `Feed.jsx`가 프로토타입 대비 여러 군데 정합이 안 맞음(해시태그 많으면 카드 높이 들쭉날쭉, "🔍 자세히" 불필요, 이모지 잔존, 다크모드에서 헤더 라벨 안 보임, 글쓰기 버튼 스타일 다름, 참여자 아바타가 프로필 사진 무시). 원래 8개 항목이었으나 착수 전 리뷰에서 "친구 한 줄 메시지"(도메인 규칙 결정 필요)와 "약속 여정 모달"(신규 기능)이 성격이 다르다고 판단해 각각 #126·#127로 분리, 이 이슈는 되돌리기 쉬운 CSS·마크업 정합만 남김.

**브랜치**: `feat/125-feed-proto-parity`

**팀장 착수 전 리뷰 반영**: 클로버 이모지 중 옆에 "클로버로 보관됩니다" 문구가 붙은 2곳은 `ti-clover`, "사진 없음" 문구인 1곳만 `ti-photo-off`로 나눠야 한다는 지적, 헤더 라벨 불투명도를 대시보드 `.section-title-label`과 동일 값으로 맞추라는 지적 — 둘 다 반영.

**수정 파일**: `Feed.jsx`, `feed.proto.css`

- 해시태그: 처음엔 개수 고정 컷(3개)으로 했다가 사용자가 실제 화면에서 여전히 줄바꿈되는 걸 발견 → 실제 렌더 후 `offsetTop`으로 줄바꿈 여부를 측정해 첫 줄에 들어가는 만큼만 보여주고 나머지는 "+N"으로 묶는 방식(`MemoryFooterTags` 컴포넌트)으로 재작성
- `polaroid-card` 하단 패딩 52px → 10px(사용자가 처음부터 명시한 값을 내가 한 번 놓쳤다가 재확인 후 반영)
- "🔍 자세히" 제거, 클로버/사진없음 아이콘 문구별 분리, 헤더 라벨 값 대시보드와 통일, 글쓰기 버튼 프로토타입 스타일 적용, 참여자 아바타 프로필사진 반영
- **PR 리뷰에서 발견된 버그**: 태그 개수 리셋 로직이 배열 참조로 비교하고 있어 부모 리렌더(검색어 입력 등)마다 태그가 펼쳐졌다 접히는 플리커 버그 → `tags.join('|')` 내용 기준 키로 교체. `.feed-write-btn`에 로드 안 된 Space Mono 폰트 선언·불필요한 `!important` 있었던 것도 지적받아 제거(특이성으로 해결)

**검증**: `npm run lint`/`npm run build` 통과. 사용자가 실제 화면 스크린샷으로 매 단계 대조.

## 3. clov-web #126 — 친구 한 줄 메시지 목록을 방 멤버 전원 표시로

**배경**: #125 착수 전 리뷰에서 프로토타입처럼 방 멤버 전원을 메시지 행으로 보여주는 구조가 "1인 1메시지"를 전제한다는 게 드러남 → 리더가 "한 추억당 작성자 1인 1개"로 도메인 규칙 확정, 계약(`API-CONTRACT.md` §10) 갱신 + 백엔드 이슈(clov-api #68, PR #69) 생성. #68 머지 후 착수 가능해짐.

**브랜치**: `feat/126-feed-friend-messages`

**선행 조건**: clov-api #68 머지 대기 → 머지 확인 후 로컬 백엔드 재기동(`./gradlew.bat clean bootRun`, JAVA_HOME 미설정으로 한 번 실패 후 재시도) 하고 착수.

**팀장 착수 전 리뷰 반영**: 멤버 필터는 `status === 'ACTIVE'`로, LEFT·익명화 멤버 메시지는 "이전 멤버" 섹션으로 별도 표시(기록 보존 원칙), 409는 에러로 안 띄우고 조용히 재조회, 수정 취소 시 서버 값 복구 — 전부 반영.

**수정 파일**: `api/memory.js`, `hooks/useMemoryDetail.js`, `Feed.jsx`, `feed.proto.css`, `Dashboard.jsx`(멤버 목록 prop 전달만)

- `updateComment` API 신설(`PATCH /comments/{id}`)
- 메시지 목록을 ACTIVE 멤버 전원 행으로 재구성: 메시지 있으면 표시, 본인이고 없으면 인라인 입력창, 남이고 없으면 "아직 메시지 없음"
- 본인 메시지 인라인 수정(취소 시 서버 값 복구)·삭제
- LEFT·익명화 멤버 메시지 "이전 멤버" 섹션 분리
- `addCommentMutation`에 `onError` 추가 — 409면 조용히 재조회

**검증**: `npm run lint`/`npm run build` 통과. 실제 로그인 세션에서 생성→수정→취소→삭제 전 과정 직접 확인. 409 경로는 UI로 재현이 까다로워 인증된 세션 토큰으로 직접 중복 POST를 날려 서버가 정확히 `409 COMMENT_ALREADY_EXISTS`를 반환하는 것을 확정 확인, `onError`가 이미 검증된 `invalidateBoth()`를 재사용하는 구조임을 코드로 확인. 테스트 데이터는 전부 정리.

**커밋/PR**: `60a31d1` → PR [#129](https://github.com/Pickeslog/clov-web/pull/129)(`Closes #126`) → 머지(`5190d2f`).
