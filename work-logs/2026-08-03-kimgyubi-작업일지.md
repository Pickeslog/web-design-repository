### ★ 이 과정에서 발견·해결한 로컬 환경 버그

`./gradlew test`가 이 PC에서 그동안 항상 실패하고 있었다 — 테스트 클래스 전부가 `ClassNotFoundException`(`.class` 파일은 실제로 존재하는데도). 원인 추적:

- 프로젝트 경로가 `C:\Users\user\Desktop\공용\clov-api`인데 **"공용"이 한글**이고, 이 Windows 계정의 `sun.jnu.encoding`이 `MS949`였다
- Gradle 테스트 워커가 classpath를 `@argfile`(임시 텍스트 파일)로 넘기는데, 자바가 이 파일을 UTF-8이 아니라 MS949로 잘못 읽어서 "공용" 부분이 깨지고 `build\classes\java\test`/`main` 경로 자체를 못 찾은 것
- **다른 팀원들이 이 버그를 안 겪는 이유**: 각자 레포를 영문 경로에 두고 있어서. 이 PC만의 조건(한글 폴더명)이었다
- **해결**: Windows "베타: 세계 언어 지원을 위한 유니코드 UTF-8 사용"(제어판 → 지역 → 관리자 언어 설정) 활성화 + 재부팅. `sun.jnu.encoding`이 `UTF-8`로 바뀌었고, 영문 경로 동작은 전혀 안 깨짐(UTF-8은 ASCII 상위호환)
- 재부팅 직후 한 번은 Testcontainers가 "Docker 환경을 못 찾음"으로 실패했는데, Docker Desktop이 아직 안 뜬 상태에서 생긴 일시적 문제로 재시도하니 바로 성공
- **결과**: `./gradlew test` 전체 스위트(Testcontainers 포함)가 이 PC에서 처음으로 로컬에서 `BUILD SUCCESSFUL` — 이전엔 `compileTestJava`+CI로만 검증했었다
