## 3. clov-web #115 — 경험치 히스토리 오늘 것만 표시하도록 필터링

**브랜치**: `feat/115-exp-history-today`

**결정 과정**: 이슈 본문에 프론트/백엔드 비교표를 직접 작성해 근거를 남김 — 방 최대 8명 캡이라 전체 조회해도 부담 없고, 계약 개정·크로스 레포 조율 비용이 없는 프론트 필터로 결정.

**팀장 착수 전 리뷰 반영**: `isTodayMonthDay`는 `parseUtc`를 안 쓴다는 정정(선례로 잘못 인용할 뻔한 것을 바로잡음), "자정 넘으면 자동 갱신"이 아니라 "다시 열면 갱신"이 정확한 표현이라는 지적, 빈 상태 문구를 전체 0건/오늘만 0건으로 분리하라는 제안 — 전부 반영.

**수정 파일**: `Dashboard.jsx`

- `ExpHistoryModal`에서 `parseUtc`로 파싱한 뒤 브라우저 로컬 연/월/일로 비교(문자열 슬라이싱 금지 — KST 0~9시 경계 버그 방지)
- `parseUtc`의 `null` 결과를 필터에서 안전하게 제외
- 빈 상태 문구 분리(전체 0건 "아직 쌓인 경험치가 없어요" / 오늘만 0건 "오늘 쌓은 경험치가 없어요")

**검증**: `npm run lint`/`npm run build` 통과. 실제 KST 타임존 환경에서 `2026-07-25T23:30:00`(UTC 심야) 로그로 경계 케이스 재현 — 문자열 슬라이싱이면 `07-25`(오답), 구현은 `07-26`(정답)임을 스크립트로 직접 검증.

## 4. clov-web #117 — 레벨 게이지 즉시 반영 안 되는 버그 (쿼리 무효화 누락)

**배경**: 백로그 E항목. 추억 작성 등을 해도 레벨 게이지가 즉시 안 올라감 — 경험치 히스토리엔 정상 반영되는 걸 확인했으므로 백엔드는 정상, 프론트 캐시 무효화 누락으로 추정하고 조사.

**브랜치**: `feat/117-level-gauge-invalidation`

**조사 결과**: XP를 주는 뮤테이션 중 마스코트 교감(`Mascot.jsx`)만 `['room', roomId, 'level']`을 무효화하고, 나머지 4곳(추억 작성/약속 등록×2곳/약속 완료)은 전부 빠져 있었음. 팀장 착수 전 리뷰에서 5번째 누락 지점(`useMemoryDetail.js`의 사진 나중에 추가하는 경로)을 추가로 짚어줌 + 무효화 키를 `['room', roomId]` 프리픽스로 하라는 제안(같은 프리픽스로 `exp-logs`도 같이 갱신돼 #115의 30초 staleTime 문제도 같이 해결됨) — 둘 다 반영.

**수정 파일**: `hooks/useCreateMemory.js`, `hooks/useMemoryDetail.js`, `pages/schedule/Schedule/Schedule.jsx`, `pages/rooms/Dashboard/Dashboard.jsx`

- 5개 XP 지점 전부에 `queryClient.invalidateQueries({ queryKey: ['room', roomId] })` 추가(추억 작성/사진 나중 추가/약속 등록×2곳/약속 완료)
- `Schedule.jsx`의 `completeMutation`을 공용 `detailMutation` 헬퍼에서 분리(다른 취소/스킵/체크리스트 뮤테이션은 XP가 없어서 그대로 둠)

**추가 확인(코드 리뷰만, 수정 없음)**: `ExpService.grant`(레벨업 롤오버 로직), `RoomMapper.xml`의 `updateLevelAndExp`(파라미터 바인딩), `MascotService.getLevel`(조회 로직)을 전부 코드로 추적해 백엔드 레벨 계산 자체엔 버그가 없음을 확인 — 문제는 순수 프론트 캐시 무효화 누락이었음.

**검증**: `npm run lint`/`npm run build` 통과. 사용자가 실제 계정으로 추억 작성/사진 첨부/약속 등록·완료 각각 테스트해 즉시 반영 확인, 30초 이내 히스토리 모달에서도 방금 항목 확인.

## 5. clov-web #119 — 경험치 히스토리 사진 첨부 보너스 항목 묶어서 표시

**배경**: #117/#118로 히스토리가 즉시 갱신되기 시작하면서 드러난 부작용 — 추억 하나에 사진을 여러 장 올리면 `MEMORY_IMAGE_BONUS`가 장당 한 줄씩 쌓여 히스토리가 도배됨(최대 11줄까지 — 사진 상한 10 + 본문 1). 팀장이 정확한 수치를 확인해줌(처음엔 15줄로 추정했으나 정정).

**브랜치**: `feat/119-exp-history-image-bonus-group`

**팀장 착수 전 리뷰 — 핵심 결정 사항**: "같은 추억이면 전부 합칠지(가) vs 바로 인접한 것만 합칠지(나)" 중 (나)로 결정 — 최신순 정렬과 "언제 얻었는지"를 보존하기 위해서다(시간차를 두고 같은 추억에 두 번 사진을 올리면 각자 다른 그룹으로 남아야 함).

**수정 파일**: `Dashboard.jsx`

- `groupAdjacentImageBonus()` 함수 신설 — 정렬된 배열을 한 번 훑으면서 직전 행과 `actionType`·`referenceId`가 같으면(그리고 `referenceId`가 `null`이 아니면) 현재 그룹에 누적, 아니면 새 그룹 시작
- 그룹핑은 #116의 오늘-필터 결과 위에 적용(필터 먼저, 그룹핑 나중 — 순서 반대면 어제/오늘 항목이 섞일 수 있음)
- 그룹 크기 1이면 기존과 동일하게 렌더(`×1` 안 붙임), 2 이상이면 "사진 첨부 ×N +N"

**추가 확인(코드 리뷰만, 수정 없음)**: 사용자가 "사진 지워도 히스토리 개수가 안 줄어든다"고 관찰한 것에 대해, clov-api 전체를 검색해 XP 회수(`revokeXP`) 관련 코드가 전혀 없음을 확인 — API 계약(§12)에 "MVP는 회수하지 않는다"고 이미 명시된 의도된 동작이었음. 이번 이슈 범위 밖으로 명확히 함.

**검증**: `npm run lint`/`npm run build` 통과. 팀장이 제시한 시나리오(추억A 사진2장 → 추억B 사진1장 → 추억A 사진1장 추가)를 격리된 로직 테스트로 재현해 3개 그룹으로 정확히 분리되는 것 확인. `referenceId` null/다른 액션타입 혼재 케이스도 안전하게 안 묶이는 것 확인. 사용자가 실제 화면에서 ×4/×3/×5 등으로 정상 표시되는 것 스크린샷으로 확인.

**커밋/PR**: `35eb78d` → PR [#120](https://github.com/Pickeslog/clov-web/pull/120)(`Closes #119`) → 머지(`049f1ce`).
