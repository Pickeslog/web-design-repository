## 4. ★★★ 이번 세션 최대 교훈 — 다음 화면 착수 전 반드시 점검

**"프로토타입 화면 이식 시 스테이지 마크업만 옮기고 '전역 인프라'를 빠뜨리면 연쇄로 깨진다."**
행운편지에서 반복 발생 → 하나로 수렴. **Schedule 착수 전 아래를 먼저 훑을 것:**

1. **전역 클래스 이식 여부 확인** — 프로토타입이 쓰는 공용 클래스가 프로덕션 CSS에 정의돼 있나?
   - 모달 시스템: `modal-overlay`(fixed 배경)·`modal-box`(카드) → 미이식 시 모달이 오버레이 없이 인라인으로 쏟아짐
   - 폼/입력: `modal-form-group input/textarea`(테두리·radius·폰트) → 미이식 시 입력창 스타일 다름
   - 버튼: `btn-main`/`btn-sub` vs 앱 공통 `<Button>` — **통일은 공통 `<Button>`(variant primary/secondary/danger…) 사용**
   - 확인법: `grep -rl "\.classname" clov-web/src --include=*.css`
2. **`@scope (.proto-X){}` 규칙은 루트 요소(`.proto-X`) 자신엔 안 먹음** (하위 요소엔 먹음).
   - 팔레트 변수(`--card-bg`·`--text-color`…)를 루트에 정의해도 무시됨.
   - **해결 = 팔레트 변수를 컴포넌트 `<main style={{...}}>`에 인라인 CSS 변수로 직접 부여**(JSX라 확실·모든 하위 상속). 예: `letters` 화면 `LETTERS_LIGHT_PALETTE`.
3. **`index.css`에 `color-scheme: light dark`** → 다크 브라우저에서 native `<textarea>`/`<input>`이 검게 렌더. `background:#fff`만으론 불완전 → **`color-scheme: light`**(팔레트/인라인)로 근본 해결.
4. **앱 테마 방식** = 다크(클래스 없음, 기본) / 라이트(`body.light-mode`). `src/lib/theme.js`. **`body.dark-mode`는 안 씀** → 프로토타입에서 온 `body.dark-mode .X`는 죽은 코드. **"종이" 화면(편지·여권·폴라로이드)은 항상 라이트로 고정**이 정답(다크앱에서도 라이트 종이).
5. **@scope CSS의 Vite HMR 반영이 애매** — JSX 인라인은 즉시 반영되나 @scope CSS 변경은 하드리로드(Ctrl+Shift+R) 필요. **확실히 하려면 인라인이 최강**(캐스케이드·HMR 무관).
6. **디버깅 교훈**: 게이트 화면(로그인+방ID) 셀프 비주얼 검증 불가 상태에서 CSS 캐스케이드를 원격 추론하다 3회 헛발질(#63·#64·#65). **다음엔 처음부터 인라인 + 전역 인프라 점검부터.**
