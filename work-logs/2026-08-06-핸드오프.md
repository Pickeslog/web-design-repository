**여는 경로가 셋이다** — ① 방 목록 자동 ② 헤더 메뉴 「가이드 다시 보기」 ③ 랩 페이지.
**닫는 경로는 하나다** — 그래서 **단계 리셋은 `close()` 안에** 있다. 여는 쪽에서 리셋하면 안 된다(린트 `react-hooks/set-state-in-effect`에 걸린다).

### 2-2. ★★ 저장소 규칙 — 계정별이다

```
clov-guide-done:<userId>      localStorage    "다시 보지 않기"
clov-guide-skipped:<userId>   sessionStorage  "건너뛰기" (탭 닫으면 초기화)
```

- **`userId == null` 이면 안 띄운다.** `['me']`가 아직 안 왔을 때 띄우면 **"모르는 사람"의 키로 저장돼 진짜 사용자가 다시 못 본다**
- `dropLegacyGuideKeys()`가 접미사 없는 옛 키를 지운다. **이미 그 키를 가진 브라우저가 실제로 존재한다** — 함부로 지우면 안 되는 코드다

### 2-3. ⚠️ 마스코트를 만질 때 — 정사각 상자 규칙

**`height`만 주면 안 된다.** rob(900×510)이 132px 높이에서 **가로 233px**로 벌어진다(crobi 85px의 2.7배).

```css
height: 132px; width: auto; max-width: 132px; object-fit: contain;
```

> **앱의 `Mascot.css:88-103`이 같은 이유로 이미 쓰는 규칙이다.** 오늘 하루에만 세 번 다시 발견했다 — **마스코트를 새 자리에 세울 때는 이 규칙부터 확인한다.**

### 2-4. ⚠️ `image-rendering` 이 자리마다 다르다

| 자리 | 처리 | 이유 |
|---|---|---|
| 창 전체 (`svg`) | `pixelated` | 픽셀 미감 |
| START 로스터 | **픽셀 변환**(132px) | 1 소스 픽셀이 화면 2px 이상 → 계단이 의도로 읽힌다 |
| 4단계 친구들 (72px) | **원본 + `auto`** | 작아서 픽셀 변환이 손해 |
| 5단계 배웅 (74px) | **원본 + `auto`** | 〃 |

**같은 그림이라도 크기에 따라 처리가 갈린다.** 새 자리를 만들면 크기부터 재고 정한다.

## 3. ★★ 랩 페이지 — 가이드를 고칠 거면 여기부터 연다

```
http://localhost:5173/guide-lab.html      ← 로그인 불필요
```

바에 **1~5 단계 점프 · 다시 열기 · 저장소 비우기 · 폭 프리셋**이 있다. `labQueryClient`가 `['me']`를 미리 채워서 인증을 안 탄다.

**프로덕션 빌드에 안 들어간다** — `vite.config.js`에 `rollupOptions.input`이 없어 Vite가 `index.html`만 빌드한다. 확인함: `dist/`에 `index.html`뿐이고, 배포본 `/guide-lab.html`은 SPA 폴백(앱 index)이 뜬다.

> ⚠️ **`src/dev/guide-lab.jsx`(진입점)와 `GuideLab.jsx`(컴포넌트)를 합치지 마라.** 합치면 Fast Refresh가 모듈을 통째로 다시 실행해서 **한 줄 고칠 때마다 랩이 리셋된다** — 이 페이지의 존재 이유가 사라진다.

### 3-1. ⚠️ 탭이 뒤에 있으면 자동 조작이 어긋난다

`setTimeout`이 **1Hz로 스로틀**된다(브라우저 규칙). 랩 버튼은 그래서 **대기가 아니라 폴링**이다 — `STEP n / 5`가 보일 때까지 기다리고, 「다음」은 **위치가 아니라 글자로** 고른다. 다시 열기 전에 **`×`로 먼저 닫는다**(`openGuide()`는 단계를 리셋하지 않는다).


지금까지 **제목을 써도 저장이 안 됐을 가능성이 크다**(웹이 API보다 먼저 나가 있었다). 이번에 API가 따라잡았다.
→ **새로 편지를 써서 제목이 남는지** 본다. **이전 편지들의 제목은 비어 있다.**

### 4-3. 온보딩 가이드

- 계정별 키로 바뀌어서 **자동으로 다시 뜬다**

- 헤더 메뉴 「가이드 다시 보기」

### 4-4. `#178` 골드 배지

마스코트 교감 · 추억 등록 후 **헤더 골드가 즉시 오르는가**.

## 5. ⚠️ 검증 제약 — 로컬 통과가 무증거인 범위

### 5-1. ★ 인증 뒤 화면은 두 단계로 본다

① **임시 진입점**으로 컴포넌트만 (자격증명 불필요) → ② **어댑터 스텁**으로 진짜 화면 위에서

> **★★ 스텁을 토큰 주입보다 먼저 건다.** 8080이 살아 있으면 스텁 토큰을 지워버린다.
> **★ 스텁 값을 기본값으로 두면 폴백만 확인된다.** "고른 값이 반영되는가"를 보려면 기본값과 다른 값을 넣는다.

### 5-2. ★★ 번들 문자열 검색에는 **대조군**을 같이 넣는다

**0건은 "없다"와 "잘못 찾았다"를 구분하지 못한다.** 오늘 쓴 대조군: `clov-room-order` · `clov-auth`.

### 5-3. ★★ 배포 순서는 "둘 다 success"로 증명되지 않는다

VM에서 **컨테이너 이미지 생성 시각**을 본다. 오늘: api `03:34:49` → web `03:35:15`.

```bash

```

### 5-4. ⚠️ `sed -i` 를 쓰지 않는다

빌드가 통과해도 **개발 서버가 옛 코드를 계속 내려준다**(Vite 워처가 어긋난다). 오늘 `MockRoomCard is not defined`로 밟았다. 확인:


**파일을 직접 쓰는 도구를 쓴다.** 걸렸으면 `touch`로 푼다.

| 빈 문자열·공백만 → **`null` 정규화** | `LetterService.java:48` |
| **`null`이면 응답에서 키 자체가 생략** | `LetterResponse.java:10` `@JsonInclude(NON_NULL)` |
| 웹 입력 상한도 60 | `Letters.jsx:637` |
| 웹은 `undefined`도 같이 받는다 | `Letters.jsx:376` |
| broadcast 팬아웃 행 전부가 같은 제목 | `LetterService.java:58` |

> ⚠️ **응답에 키가 아예 없다** — `title === null` 만 검사하는 클라이언트는 못 잡는다. **`undefined`와 같게** 다뤄야 한다.
> ⚠️ **`maxLength`와 `@Size`는 같은 값이어야 한다** — 한쪽만 바꾸면 사용자가 다 쓴 제목이 서버에서 잘린다. 지금은 둘 다 60이다.

### 8-2. ✅ 잘 반영된 쪽 — `memberAvatars` 는 본보기다

`#76` 계약 항목에 **`nickname` 이 왜 필요한지**(사진 없는 멤버의 이니셜 폴백)와 **`IN` 절 경고**(N+1이 서버로 옮겨갈 뿐)가 같이 적혀 있다.
`clov-api#141` 리뷰에서 지적한 것이 **결정이 아니라 근거까지 문서에 남았다.** `title` 도 이 정도로 적으면 된다.

### 8-3. 왜 이게 문제인가

`AGENTS.md` 규칙: *"계약 변경은 이 파일이 아니라 SSOT에 리더 승인으로 반영한다."*

팀원에게 *"화면이 쓰는 응답 필드는 반드시 계약에서 확인한다, 추측하지 않는다"* 고 해놓고 **계약이 낡아 있으면 그 규칙이 무너진다.**

> **★ 코드 변경 없이 문서만 따라가면 되는 일이었다.** PR 하나(`#78`)로 끝났다 — **미루면 비싸지지만 바로 하면 제일 싸다.**
>
> ⚠️ **이 항목을 처음 쓸 때 `memberAvatars` 도 빠졌다고 적었는데 틀렸다.** 로컬 브랜치가 `#76` 머지 **전** main 기준이라 안 보였던 것이다. **계약을 확인할 때는 `git fetch` 후 `origin/main` 을 본다** — 작업 브랜치의 사본이 아니라.

### 8-4. ★ 다음에도 같은 자리에서 샌다

**계약 확장이 나갈 때 문서가 같이 안 나가는 건 오늘만의 사고가 아니다.** 오늘 둘 중 하나가 새어나갔다(50%).
`clov-task` 절차의 "끝내기 전 검증"에 **"계약을 넓혔으면 SSOT PR도 같이 올렸는가"** 를 넣을지 정해야 한다 — 지금은 어디에도 안 걸려 있다.
