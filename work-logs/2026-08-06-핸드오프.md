> ⚠️ **`src/dev/guide-lab.jsx`(진입점)와 `GuideLab.jsx`(컴포넌트)를 합치지 마라.** 합치면 Fast Refresh가 모듈을 통째로 다시 실행해서 **한 줄 고칠 때마다 랩이 리셋된다** — 이 페이지의 존재 이유가 사라진다.

## 5. ⚠️ 검증 제약 — 로컬 통과가 무증거인 범위

### 5-1. ★ 인증 뒤 화면은 두 단계로 본다

① **임시 진입점**으로 컴포넌트만 (자격증명 불필요) → ② **어댑터 스텁**으로 진짜 화면 위에서

> **★★ 스텁을 토큰 주입보다 먼저 건다.** 8080이 살아 있으면 스텁 토큰을 지워버린다.
> **★ 스텁 값을 기본값으로 두면 폴백만 확인된다.** "고른 값이 반영되는가"를 보려면 기본값과 다른 값을 넣는다.

### 5-2. ★★ 번들 문자열 검색에는 **대조군**을 같이 넣는다

**0건은 "없다"와 "잘못 찾았다"를 구분하지 못한다.** 오늘 쓴 대조군: `clov-room-order` · `clov-auth`.

### 5-3. ★★ 배포 순서는 "둘 다 success"로 증명되지 않는다

VM에서 **컨테이너 이미지 생성 시각**을 본다. 오늘: api `03:34:49` → web `03:35:15`.

```bash
ssh <vm> 'sudo docker ps --format "{{.Names}}\t{{.Status}}" && sudo docker images --format "{{.Repository}}\t{{.CreatedAt}}"'
```

### 5-4. ⚠️ `sed -i` 를 쓰지 않는다

빌드가 통과해도 **개발 서버가 옛 코드를 계속 내려준다**(Vite 워처가 어긋난다). 오늘 `MockRoomCard is not defined`로 밟았다. 확인:

```bash
curl -s "http://localhost:5173/src/components/OnboardingGuide/OnboardingGuide.jsx" | grep MockRoomCard
```

**파일을 직접 쓰는 도구를 쓴다.** 걸렸으면 `touch`로 푼다.

### 5-5. ★★★ 값이 안 변하면 **코드보다 시계를 먼저 의심한다**

프리뷰 창이 표시되지 않으면 합성을 안 해서 **CSS 전환과 스크롤 애니메이션이 멈추거나 느려진다.** 오늘 이걸로 **세 번** 오진했다.

| 증상 | 진짜 원인 | 확인법 |
|---|---|---|
| 3D 틸트가 `matrix(1,0,0,1,0,0)` 고정 | 전환 시계가 시작값에 얼어붙음 | **인라인 `style` 을 직접 읽는다** |
| 슬라이드가 "안 넘어간다" | 608px 에 **1.4초+** 걸리는데 1.1초에 읽음 | **멈출 때까지 폴링** |
| 화살표가 "씹힌다" | 같은 원인 | **`scrollBy` 를 가로채 호출 자체를 본다** |

그 외 둘:
- **`mouseleave` 를 합성해도 React 는 안 받는다** — `mouseout` + `relatedTarget` 으로 합성된다(`pointerleave` 도 같다)
- **`resetQueries()` 직후의 DOM 참조는 낡는다** — 그걸로 `scrollLeft` 를 읽어 오진했다

### 8-1. 메운 것 — `Letter.title` (§11-1)

`Letters.jsx:114` 주석이 **"계약 §행운편지"를 인용하는데 그 절에 `title`이 없었다.** 인용이 먼저 나가고 계약이 안 따라온 경우다.

**구현에서 확인한 값만 적었다 — 추측은 안 넣었다.**

| 사실 | 근거 |
|---|---|
| 선택 입력 · **≤ 60자** | `LetterSendRequest.java:10` `@Size(max = 60)` |
| 빈 문자열·공백만 → **`null` 정규화** | `LetterService.java:48` |
| **`null`이면 응답에서 키 자체가 생략** | `LetterResponse.java:10` `@JsonInclude(NON_NULL)` |
| 웹 입력 상한도 60 | `Letters.jsx:637` |
| 웹은 `undefined`도 같이 받는다 | `Letters.jsx:376` |
| broadcast 팬아웃 행 전부가 같은 제목 | `LetterService.java:58` |

> ⚠️ **응답에 키가 아예 없다** — `title === null` 만 검사하는 클라이언트는 못 잡는다. **`undefined`와 같게** 다뤄야 한다.
> ⚠️ **`maxLength`와 `@Size`는 같은 값이어야 한다** — 한쪽만 바꾸면 사용자가 다 쓴 제목이 서버에서 잘린다. 지금은 둘 다 60이다.

### 8-2. ✅ 잘 반영된 쪽 — `memberAvatars` 는 본보기다

`#76` 계약 항목에 **`nickname` 이 왜 필요한지**(사진 없는 멤버의 이니셜 폴백)와 **`IN` 절 경고**(N+1이 서버로 옮겨갈 뿐)가 같이 적혀 있다.
`clov-api#141` 리뷰에서 지적한 것이 **결정이 아니라 근거까지 문서에 남았다.** `title` 도 이 정도로 적으면 된다.

### 8-3. 왜 이게 문제인가

`AGENTS.md` 규칙: *"계약 변경은 이 파일이 아니라 SSOT에 리더 승인으로 반영한다."*

팀원에게 *"화면이 쓰는 응답 필드는 반드시 계약에서 확인한다, 추측하지 않는다"* 고 해놓고 **계약이 낡아 있으면 그 규칙이 무너진다.**

> **★ 코드 변경 없이 문서만 따라가면 되는 일이었다.** PR 하나(`#78`)로 끝났다 — **미루면 비싸지지만 바로 하면 제일 싸다.**
>
> ⚠️ **이 항목을 처음 쓸 때 `memberAvatars` 도 빠졌다고 적었는데 틀렸다.** 로컬 브랜치가 `#76` 머지 **전** main 기준이라 안 보였던 것이다. **계약을 확인할 때는 `git fetch` 후 `origin/main` 을 본다** — 작업 브랜치의 사본이 아니라.

### 8-4. ★ 다음에도 같은 자리에서 샌다

**계약 확장이 나갈 때 문서가 같이 안 나가는 건 오늘만의 사고가 아니다.** 오늘 둘 중 하나가 새어나갔다(50%).
`clov-task` 절차의 "끝내기 전 검증"에 **"계약을 넓혔으면 SSOT PR도 같이 올렸는가"** 를 넣을지 정해야 한다 — 지금은 어디에도 안 걸려 있다.

## 10. ★★★ 생일 기능 — 어디에 뭐가 있고, 왜 그렇게 됐나

오후에 통째로 나갔다. **다음 사람이 제일 헷갈릴 곳이라 근거까지 적는다.**

### 11-1. 어디에 있나

| 화면 | 무엇 | 파일 |
|---|---|---|
| 일정계획 | **황금 티켓**(D-7 이내) — 약속 티켓과 **한 슬라이드** | `Schedule.jsx` `BirthdayTicket` · `.slide-*` |
| 대시보드 | D-day 3칸에 생일 · **당일 축하 모달 + 폭죽** | `Dashboard.jsx` · `components/BirthdayCelebration/` |
| 추억피드 | 생일 당일 추억에 배지 [팀원] | `Feed.jsx` · `.memory-birthday-badge` |
| 행운편지 | 생일 당일 편지 CTA [팀원] | `Letters.jsx` · `.letter-birthday-nudge` |
| 공용 | `nextBirthdayDate` · `isSameMonthDay`(팀원) | `lib/datetime.js` |
| 공용 | 3D 기울임 — **두 티켓이 같은 훅을 쓴다** | `hooks/useTicketTilt.js` |
| 공용 | 마스코트 5종 | `lib/mascotShowcase.js` (가이드에서 옮겨옴) |

기준값 **`BIRTHDAY_LEAD_DAYS = 7`** — 대시보드와 일정계획 **두 곳에 각각** 있다. ⚠️ 한쪽만 바꾸면 대시보드엔 뜨는데 일정계획엔 없는 날이 생긴다.

### 11-2. ⚠️ 절대 하지 말 것 — `items` 에 생일을 섞기

일정계획의 `items`(=`GET /plans`)는 **stage-photos 조회 · 상세 선택 · 필터 개수 · 수정/삭제 버튼**을 전부 물고 있다. 가짜 Plan 을 끼우면 **에러 없이** 없는 id 로 API 가 나가고 필터 숫자가 틀어진다.
생일은 **별도 배열 + 별도 렌더**다. 회귀 검사 문구: *"생일이 몇 장 떠도 필터 개수는 그대로"*.

### 11-3. 슬라이드 규칙 (두 티켓 공용)

```
한 레일    생일이 앞, 약속이 뒤
선택       티켓이 주도하고 아래 필름스트립이 따라온다(양방향)
           생일 슬라이드는 약속 선택을 안 건드린다([data-plan-id] 만 본다)
엿보기     두 장 이상일 때 44px — 화살표보다 강한 신호
화살표     터치 기기에서만 접는다 (hover:none) and (pointer:coarse)
           ⚠️ max-width 로 가르면 안 된다 — 창 좁힌 데스크톱은 스와이프도 없다
첫 화면    생일이 있으면 생일부터. 멤버 미도착이면 판단을 미룬다
```

### 11-4. ⚠️⚠️ `clov-api` 의 `plan_type` 은 **만들었지만 안 쓰인다**

계약(`web-design#80`) → API(`#146`) → 마이그레이션 → 배포까지 다 갔는데, 그 직후 리더가 **"저절로 나타난다(표시 전용)"** 를 골라 쓸 자리가 없어졌다.

**지우지 마라.** `NOT NULL DEFAULT 'NORMAL'` 이라 있어도 해가 없고 계약 §8-1에 적혀 있다.

> **★ 되열 조건** — *"생일도 약속처럼 완료 처리하고 인생4컷을 붙이고 추억으로 남기고 싶다"* 가 되면. 그때는 **백엔드 작업 없이 프론트만** 하면 된다(`clov-web#381` 이 그 이슈다).

### 11-5. 설계 결정의 근거 (`clov-api#143`, 닫힘)

**"생일을 Plan 행으로 자동 생성하지 않는다."** 다시 논의가 나오면 이걸 먼저 읽는다.

- `plans.writer_id` 는 `NOT NULL` + FK 이고 목록 쿼리가 **INNER JOIN** 이다 → NULL 로 두면 **그 일정이 모든 목록에서 조용히 사라진다**
- **스케줄러 인프라가 0건**이고, 서버는 UTC라 "오늘"을 못 준다(KST 00~09시엔 어제)
- 시스템 계정을 writer 로 두면 **서비스 원칙**(특별 권한 개념 금지)에 걸린다
- 생일 데이터는 **이미 `GET /members` 의 `birthMonthDay` 로 내려온다**(계약 §6)
